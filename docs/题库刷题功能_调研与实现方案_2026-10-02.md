# 题库刷题功能：调研与实现方案

> 结论先行版。委托人诉求（原话）：
> 「让 medkit 模仿在线刷题软件，支持用户创建自己生产的题库，以及导入从网站下载的 md 题库，实现完整的刷题功能。」
>
> - 版本基线：MedKit `0.10.6`（`medkit/__init__.py:3`）
> - 调研日期：2026-10-02
> - 证据口径：每条结论标 `file:line` 或命令级证据；外部结论标来源 URL，并区分 `【已查证】`（一手文档/官方仓库）与 `【推断】`（本报告判断）。
> - 遵循 `docs/engineering/borrow-rules.md`：只借鉴思想做本地最小实现，不搬代码、不引重依赖、不夹带题目数据。

## 0. 一句话结论

**MedKit 已有「刷题」的外壳与全部底层件，但缺「试卷式作答」这一层核心。** 现有 `#tab-study`「刷题」实际是**知识点卡片式间隔重复**（正面显示知识点名，不是完整题目），不是在线刷题软件的「题干 + 选项 + 作答 + 判分」形态。要补的不是从零造轮子，而是**把已有三块能力接起来**：

| 已有能力 | 位置 | 现状 |
|---|---|---|
| 题库生产（题目结构化） | `core/orchestrator.py:1438` 落 `questions_final.json` | ✅ 完整，但产物是**项目级只读文件**，进不了「刷题」 |
| 试卷式交互答题引擎 | `render/qbank_html.py:1042` `export_paper_html()` | ✅ **已实现且相当完整**（作答/判分/答题卡/错题重练/localStorage 续答），但**封在导出的 HTML 文件里**，不在应用内 |
| 间隔重复调度 + 掌握度 | `core/scheduler.py` / `core/review.py` / `core/library.py` | ✅ 完整，但复习卡只承载**知识点**，不承载**题目** |
| 题库导入解析 | `core/library.py:1070` `parse_import_text()` | ⚠️ 已有 json/csv/md/txt 四格式，但落点是 `mistakes`（错题本），**不是题库** |

**所以本方案的核心判断是：新增一层「题库域」（bank domain），把用户自建/导入的题目作为一等数据存起来，把 `export_paper_html` 的答题引擎从「导出文件里的内联 JS」抽成「应用内视图 + 后端作答记录」，并让作答结果按现有路径回流错题本与掌握度。**

工期量级估计（`【推断】`，按 MedKit 的守卫强度，含测试）：分三期，最小可用闭环约 3 个 WP，完整形态约 8 个 WP。

### 0.1 调研期间已实测发现的一个真缺陷（一期必修）

> `parse_import_text` **不识别带列表符的选项行**，**连 MedKit 自己导出的 md 都读不回来**——选项全部丢失并被塞进题干，且**不报错、不告警**。

| 输入（`parse_import_text(text, "md")`） | `options` |
|---|---|
| `A. 吸烟`（无列表符） | `['A. 吸烟', 'B. 感染']` ✅ |
| `- A. 吸烟`（连字符） | `[]` ❌ |
| `* A. 吸烟`（星号） | `[]` ❌ |
| **`export_md()` 自己的输出** | `[]` ❌ |

唯一覆盖 md 导入的用例（`tests/test_syllabus.py:246`）恰好只测了**唯一能工作**的形态，所以长期假绿。根因是一行正则（`library.py:998` `_OPT_RE` 要求行首即字母），修法与误伤面已实测，**详细证据、根因、修法、守卫见 §5.7**。

## 1. 现状取证：为什么「刷题」现在不能算刷题

### 1.1 「刷题」tab 到底是什么

`medkit/web/index.html:82-105` 的 `#tab-study` 结构：

```
刷题
├── 科目（卡片：题目数 + 掌握率，点卡片过滤）
├── 复习计划（SM-2 间隔重复）
│   ├── study_progress  今日进度 X/Y
│   ├── rv_stats        今日到期/总卡/进行中/新卡
│   ├── rv_body         ← 复习卡列表
│   └── mem_area        ← 医学记忆卡
```

`medkit/web/js/learn-review.js:99-129` 的 `rvCard(c)` 揭示了本质——**卡片正面只有一行知识点名**：

```js
<div class="rv-q">${esc(c.kp_name || "(未命名知识点)")}</div>
<div class="qcard-tip">💡 先在脑中回忆这个知识点，再点卡片翻面看提示</div>
```

这不是「题目」而是「知识点提取练习」。它的数据源是 `core/review.py:140` `enqueue(kp_name, ...)`——入队的是 **kp_name**，没有题干、没有选项、没有答案键。判分是 `core/review.py:114` `grade_card()` 的 quality 0~5 自评（`lean-review.js:98` `GRADE3_MAP = {forget:0, fuzzy:2, got:4}`）。

**结论：`#tab-study` 是间隔重复复习器，不是刷题器。** 用户说「模仿在线刷题软件」，指的正是缺的这一块。

### 1.2 试卷式答题引擎已经存在，但位置不对

`medkit/render/qbank_html.py:1042` `export_paper_html()` 的 docstring 列出的功能（**全部已实现**）：

```
- X 型 checkbox + 集合判分（A1 修复）
- localStorage 实时保存作答 + 重开续答 + 答题卡 + 计时器（练习计时；可开启限时模式→到点自动判分）
- 判分后「错题重练」（localStorage 错题集，可返回全卷）
- 判分后「同步错题到学习中心错题本」（v0.7，POST /api/library/mistakes/sync-paper）
- 所有插值经 esc()（A4 修复）
```

配套实现细节（均 `【已查证】` 读码确认）：

| 能力 | 位置 | 关键设计 |
|---|---|---|
| 卷面指纹防窜卷 | `qbank_html.py:661` `const FP = QUESTIONS.map(q=>String(q.id||"")).join(",")` | 题目 id 序列为指纹；指纹变 → 不套旧答案（`R3S-04`） |
| 答案归一化比较 | `qbank_html.py:687` `answersEqual()` | 剥空白/逗号/顿号后排序比较，`"B D"` == `"BD"` |
| X 型集合判分 | `qbank_html.py:891-913` | 逐选项分三态：`right`（选对）/`miss`（漏选）/`wrong`（错选） |
| 判分防重入 | `qbank_html.py:827` `if(judged) return;` + `judged` 持久化 | 重开页面计时冻结 |
| 服务端渲染才允许注入 media | `qbank_html.py:630` `const SRV_Q = new WeakSet()` | **防 localStorage 篡改导致任意 HTML 注入面**——错题重练灌入的题目对象不在 WeakSet 里，media 自动失效 |
| 数值归一化 | `qbank_html.py:633` `const num=v=>...` | localStorage 里的 score/total 绝不直接拼 innerHTML |
| 成绩留存 | `qbank_html.py:862-867` | 最近 10 次跨会话，供「上次/最佳」 |
| 案例组分组判分 | `qbank_html.py:838,855-857,868-871` | 按 `case_id` 聚合 `t/n` |

**这套引擎的质量超出「从零写一个刷题页」的水平**，是 MedKit 已有的最成熟资产。问题只有一个：**它是 `export_paper_html()` 返回的一整个 HTML 字符串**，通过 `routers/projects.py:302` `GET /api/projects/{pid}/files/{name}` 下载/内联预览——**用户必须离开应用、打开一个静态 HTML 文件才能刷题**，作答记录困在浏览器 `localStorage` 里，应用侧一无所知（除了判分后手动点「同步错题到错题本」）。

### 1.3 题库是「项目级只读产物」

`core/orchestrator.py:1438,1467,1483-1497`：

```python
_write_json_atomic(base / "最终产物" / "questions_final.json", questions)
(base / "最终产物" / "qbank.md").write_text(qbank_md, encoding="utf-8")
(base / "最终产物" / "qbank.html").write_text(qbank_html_text, encoding="utf-8")
(base / "最终产物" / "押题卷.html").write_text(...)
```

题目结构（`core/schema.py:76` `QuestionItem`，`extra="forbid"`）：
`question / type / bloom / subtopic / options[] / answer / analysis / case_id / case_order / case_stem / group_kind / group / image_ref / data_table / source_type / source_year`

答案不变式（`schema.py:133-150`）：X 型字母升序且 2~4 个；非 X 型单字母。

**这套契约已经足够承载题库**。缺的是：
1. 没有「题库」这个可列举、可编辑、可增删题的**持久实体**（只有文件系统上的一个 json）；
2. `questions_final.json` 只读——用户不能手工加一道题、不能改一道题的答案；
3. 没有跨项目的题库概念（A 项目的题无法在 B 项目刷）。

### 1.4 导入解析已存在，但落点是错题本

`core/library.py:1070` `parse_import_text(text, fmt)`——支持 4 种格式，且 json 分支已兼容「本题库官方结构」（`stem/options[{label,text}]/answer/explanation/topic/module_name`，见 `library.py:1073-1075,1098-1108`）。md/txt 分支按题号切块后逐块走 `parse_question_text()`（`library.py:1001`，本地规则、零 LLM，支持 `【答案】`/`解析`/选项行标记）。

**这是本方案最省力的发现**：解析器已写好、已被测试覆盖，只是当前唯一消费方是 `POST /api/library/mistakes/import-text`（`routers/library.py:147`），把结果变成**错题**。要做「导入 md 题库」，只需让同一解析器的输出走另一条落库路径。

### 1.5 三条「作答 → 回流」通路已经存在

| 通路 | 入口 | 行为 |
|---|---|---|
| 押题卷判错回流错题本 | `core/library.py:641` `sync_from_paper()` + `routers/library.py:140` `POST /api/library/mistakes/sync-paper` | 按 `question_id` 优先去重（`C-04`），无 id 时退化到题干前 40 字 |
| 站点数据导入 | `core/library.py:571` `import_site_items()` | 幂等键 `sha1(subject|chapter|question[:80])`，重复导入**更新**而非新增 |
| 复习判分回流掌握度 | `routers/library.py:997` `review_grade()` → `lib.record_review(kp_name, quality)` | quality≥3 记成功提取，反写知识点掌握度 |

**这三条通路意味着「刷题 → 判错 → 错题本 → 掌握度 → 间隔重复」的闭环管道已经铺好，只等刷题端往里灌数据。**

                             │ 纯函数调用

**关键复用点**：`core/errorpipe.py:37` 的设计要点①已经确立了新域接入方式——「不新建存储层，复用 `library._store()` 的事务适配器与 `db.put_row`，自动继承 SQL/JSON 双轨、`BEGIN IMMEDIATE` 串行化、行级增量写」。题库域照抄这条即可，**不要另起炉灶**。

### 2.3 与「出题工坊」的关系（必须讲清，否则用户会困惑）

现在有两个会产生题目的入口，容易混淆：

| | 出题工坊（`#tab-bank`，现有） | 题库刷题（本方案） |
|---|---|---|
| 定位 | 从教材**生成**新题 | **管理与练习**已有题 |
| 输入 | 教材切片 + 教师重点 + LLM | 用户自建 / md 导入 / 工坊产出 |
| 产物 | `questions_final.json` + HTML/押题卷/Anki | 题库实体 + 作答记录 |
| 成本 | 烧 LLM token | 零 LLM |

**建议命名与导航**：现有 `#tab-bank` 改名「出题」或保留「题库」但加副标题「生成」，新功能占用一个明确名字如「练习」或「题库（我的）」。**不要在一个 tab 里塞两套心智模型**——`index.html:241-242` 现在写的是「上传教材与教师重点，配置出题参数，一键生成题库」，与「导入别人给的 md 题库来刷」是两件事。

## 3. 数据格式设计

### 3.1 题库域数据模型（新增两张表）

沿用 MedKit 的建表范式（`core/db.py:34` `_tbl()`）：`id TEXT PRIMARY KEY + data TEXT NOT NULL + 若干冗余查询列`，**权威数据在 `data` JSON，冗余列仅供 WHERE**（ADR-001）。

```python
# v9（题库域）：banks + bank_items 两张表
_V9_UP = [
    # 题库（deck 概念，对齐 Anki 的 deck / Quizlet 的 set）
    """
    CREATE TABLE IF NOT EXISTS banks (
        id TEXT PRIMARY KEY,
        data TEXT NOT NULL,
        name TEXT, subject TEXT, source TEXT,
        created_at TEXT, updated_at TEXT
    )""",
    "CREATE INDEX IF NOT EXISTS idx_bank_subject ON banks(subject)",
    # 题目（挂在题库下）
    """
    CREATE TABLE IF NOT EXISTS bank_items (
        id TEXT PRIMARY KEY,
        data TEXT NOT NULL,
        bank_id TEXT, qtype TEXT, topic TEXT,
        answer TEXT, created_at TEXT
    )""",
    "CREATE INDEX IF NOT EXISTS idx_bi_bank ON bank_items(bank_id)",
    "CREATE INDEX IF NOT EXISTS idx_bi_topic ON bank_items(bank_id, topic)",
]
```

**为什么题目单独一张表而不是塞进 `banks.data`**：一道题一行、按 `bank_id` 取，与 `mistakes` 同构；题库到千题级时不必整体读入（对齐 `library.py:1170` `_touch_knowledge_in` 的 V-09 定向取行思路）。

**`bank_items.data` 的字段**（**直接复用 `schema.QuestionItem`**，零新增契约）：

```jsonc
{
  "id": "q_<bank>_<seq>",          // 稳定 ID（学 genanki：改解析重生成不产生重复题）
  "bank_id": "bk_xxx",
  "question": "题干",
  "type": "A1",                     // A1/A2/X/B1/A3/A4（schema.TYPE_LABELS 同源）
  "bloom": "理解",
  "subtopic": "慢阻肺的诊断",
  "options": ["A 选项", "B 选项"],   // 纯文本；字母前缀由渲染层 _strip_letter 剥（qbank_html.py:122）
  "answer": "B",                    // 不变式由 QuestionItem._answer_invariants 校验
  "analysis": "解析",
  "case_id": "", "case_order": 0, "case_stem": "",
  "group_kind": "", "group": null,
  "image_ref": "", "data_table": "",
  "source_type": "", "source_year": "",
  // —— 题库域特有（QuestionItem 之外，但 extra="forbid" 只约束该模型，不放同一 Pydantic 类里）——
  "origin": "manual|md_import|paper|project",   // 来源，供溯源
  "origin_ref": {"pid": "", "file": "", "line": 0},
  "created_at": "...", "updated_at": "..."
}
```

**关键工程决定：把 `QuestionItem` 的校验用在导入与编辑的入口**（`QuestionItem.model_validate(raw)`），这样：
- X 型答案必须升序（`schema.py:145`）等在入口就拦住；
- 但**不把 `origin/origin_ref` 塞进 `QuestionItem`**——它 `extra="forbid"`，加字段要改契约类，而契约类被 medgen/medqc/medfix 全链共用，改它等于动生成链。**做法**：`BankItem` 是新模型，`question/type/options/answer/...` 字段用 `QuestionItem` 做嵌套校验。

### 3.2 作答记录表（第三张表）

```python
# v10（作答记录）：append-only，与 error_events 同精神（db.py:161 注释：
# 「不复用 mistakes 快照，因为快照可被用户编辑，会让跨轮次迁移矩阵失真」）
_V10_UP = [
    """
    CREATE TABLE IF NOT EXISTS bank_attempts (
        id TEXT PRIMARY KEY,
        data TEXT NOT NULL,
        bank_id TEXT, item_id TEXT, session_id TEXT,
        correct INTEGER, mode TEXT, occurred_at TEXT
    )""",
    "CREATE INDEX IF NOT EXISTS idx_ba_item ON bank_attempts(item_id)",
    "CREATE INDEX IF NOT EXISTS idx_ba_sess ON bank_attempts(session_id, occurred_at)",
    "CREATE INDEX IF NOT EXISTS idx_ba_bank ON bank_attempts(bank_id, occurred_at)",
]
```

`data` 字段：`{item_id, bank_id, session_id, user_answer, correct, mode(practice|exam|retry), secs, marked, occurred_at}`

**为什么要独立于 `error_events`**：`error_events`（`db.py:161`）字段是 `kp_id/round/error_tag/is_correct`，服务于「错题归因跨轮次迁移矩阵」，它的语义单位是**知识点**；`bank_attempts` 的语义单位是**题目**，服务于「这道题我做过几次、对了几次」。两者粒度不同，混用会让两张报表都失真。

### 3.3 MD 题库导入格式（与既有**导出**格式对称）

**这是设计的核心原则：导入格式必须先兼容自己的导出格式。** `render/qbank_html.py:279` `export_md()` 的产出格式为：

```markdown
# {title}

## 📋 案例 {case_id}
**案例题干**：{case_stem}
> 本案例 N 道子题

### {id} · {type} · {question}
- A. {opt}
- B. {opt}
**✅ 答案：{answer}**
💡 {analysis}

## 🧩 选项组（B1 共享选项）
- A. {opt}
...
### {id} · {type} · {question}
```

**即「自己导出的 md 必须能原样导回来」**——这是零成本拿到一个正确性判据（往返测试，见 §5.3）。

#### 3.3.1 主格式（推荐，带 frontmatter 的 md）

`【借鉴】` 参考 `nghqqa/tizhou` 的「frontmatter 约定 + 目录即知识库」做法（来源：https://github.com/nghqqa/tizhou/blob/master/docs/question-bank-import.md `【已查证】`）：

```markdown
---
bank: 内科学·呼吸系统
subject: 内科学
chapter: 呼吸系统
source: 医考帮导出
license_note: 用户自备，权利自负
---

### 1. 慢阻肺最主要的病因是
A. 吸烟
B. 感染
C. 空气污染
D. 遗传
**答案**：A
**解析**：吸烟是 COPD 最重要的环境致病因素……

### 2. 下列属于 COPD 诊断必备条件的是
A. ……
**答案**：BDE
```

#### 3.3.2 解析器必须支持的格式矩阵

复用 `library.parse_import_text()` 的能力，同时补强（现解析器对 md 的切块正则是 `library.py:1140-1141`）：

| 格式 | 题干行 | 选项行 | 答案行 | 解析行 | 现状 |
|---|---|---|---|---|---|
| **MedKit md（本方案主格式）** | `### 1. {题干}` 或裸行 | `- A. {文本}` / `A. {文本}` | `**答案**：A` / `【答案】A` / `答案：A` | `**解析**：` / `解析：` / `【解析】` | ❌ **带列表符的选项行不被识别**（实测，见 §5.7）——**一期必修** |
| 无选项标记 md | 裸行 | `A. 甲` | 同上 | 同上 | ✅ |
| json | — | `options: [{label,text}]` | `answer` | `explanation` | ✅ 已兼容官方结构 |
| csv | `题干`/`question`/`stem` | `A`~`F` 列 或 `选项` 列（`\|`/`；` 分隔） | `答案`/`answer` | `解析`/`analysis`/`explanation` | ✅ |
| txt | 题号切块 | 同 md | 同 md | 同 md | ✅ |

`【已查证】` 现解析器答案正则（`library.py:1010-1012`）已支持 `【答案】/答案/答/正确答案` + 多字母 `BD`/`B,D`/`B、D` → 归一大写；解析正则（`library.py:1013`）支持 `【解析】/解析`。

#### 3.3.3 借鉴外部格式的三条具体做法

| 来源 | 借鉴点 | 转化方式 |
|---|---|---|
| **Anki 文本导入** `【已查证】` https://kk7mz.github.io/anki-manual-zh-cn/importing.html | ① **首行定分隔符与字段数**（首行有 `;` 就用 `;`），字段数不同的行**直接忽略**；② `tags:t1 t2` 前置行给整批打标签；③ 重复项策略三选一（更新/忽略/新建）；④ UTF-8 强要求；⑤ 引号包裹可容纳多行字段 | MedKit md 导入**不需要选分隔符**（md 是结构化文本），但应照抄：**① 整批标签（frontmatter `tags:`）；② BOM 剥离（`library.py:1079` 已做 `D-06`）；③ 重复策略三选一**（这是现 `import_site_items` 的「更新」与 `sync_from_paper` 的「跳过」之外的第三选项「新建」，需要用户可选） |

### 3.4 与既有数据的对齐（避免「题库域」变成孤岛）

| 既有概念 | 题库域中的对应 | 对齐方式 |
|---|---|---|
| `mistakes` 一条错题 | 一次判错的 `bank_attempts` + `bank_items` 快照 | 复用 `library.sync_from_paper()`（`library.py:641`），传 `questions` + 补 `user_answer` |
| `knowledge` 知识点掌握度 | 题目的 `subtopic`/`know_tags` → 知识点名 | 复用 `_kp_key()`（`library.py:1153`）：tag 优先 → topic → chapter |
| `review_cards` 复习卡 | 不重复建：刷题判错 → 错题本 → `enqueue_knowledge` 铺卡 | 复用 `rev.enqueue_knowledge()`（`review.py:161`），**不新建第二套调度** |
| `cards` 记忆卡 | 保持独立（记忆卡背的是「知识点」不是「题」） | 不动 |
| 项目产物 `questions_final.json` | F11「从项目导入」→ 复制进 `bank_items` | **复制而非引用**：项目可能被删（`routers/projects.py:272` DELETE），题库不该跟着消失 |

### 5.2 导入去重：三级退化（借鉴 B4）

```
① 严格签名：sha1(subject | chapter | question 全文)         —— 完全同一题
② 宽松签名：sha1(_norm_key(question[:80]))                  —— 题干措辞微改（复用 library._norm_key，library.py:558）
③ 包含检测：新题干的规范化串被已有题干的规范化串包含        —— 题干被加/删前缀
```
命中 ①② 按用户选的策略处理（更新/忽略/新建）；命中 ③ **只提示不自动处理**（`tizhou` 的做法是自动合并，但 MedKit 的红线是机器不替用户拍板）。

### 5.3 必须写的守卫（对照 `gate-falsifiability` 技能）

MedKit 的门禁强度是「每个结构判据都要配元守卫」，题库域新增守卫至少包含：

| 守卫 | 判据 | 证伪方式（不写这一步等于没写守卫） |
|---|---|---|
| 往返一致性 | `export_md(questions)` → `parse_import_text(...)` → 题目集合**逐字段相等** | 注入：改 `export_md` 少输出一行答案 → 必红 |
| 题型推断 | 单字母 ⊆ {A..J} → A1；多字母 → X | 注入：把 X 型答案只留一个字母 → 必红（判 `rc==1`，不是 `rc!=0`） |
| 判分一致性 | 应用内判分结果 == `export_paper_html` 的 JS 判分（黄金值逐题比对） | 用 node 跑一遍 JS 判分逻辑产出黄金值，Python 侧比对 |
| 回流正确性 | 刷题判错 → 错题本条数 +1 且 `user_answer` 在场 | 注入：去掉 `user_answer` 传递 → 必红 |
| 前端分片 | 新片登记进 `tests/test_v15_frontend_split.py:31` `FAMILIES` + `index.html` 恰好一次 + 单文件 ≤800 行 | 注入：把新片插到 `learn.js` 之前且它加载期引用 `learn.js` 的符号 → 必红 |
| 卡片归属 | 新卡片**必须留在对应视图内**（可见性随子视图切换而变） | 判据取「可见性随切换变化」——**不是**「按 id 查得到」（后者对该缺陷恒真，见 MEMORY 教训） |
| 跨层一致性 | `routers/bank.py` 不出现 `cur.execute`/`dbs.tx`；`core/bank.py` 不 import routers | 复用既有跨层用例的模式 |
| 数据纯净 | 题库域不得把题目内容打进安装包 | `pack/check-package.py` 黑名单覆盖（对齐 `borrow-rules.md:65`） |

**特别提醒（来自 MEMORY 的实测教训）**：任何 `except HTTPException: assert 400` 式判据都**区分不了「闸门拦住了」和「协程压根没跑」**（2026-10-02 W12 实测）。刷题端点若有闸门（如「题库不存在」「题目不在题库内」），判据必须钉在**只有真跑进函数体才会置位的观测点**上（MedKit 用 `routers/projects._GATE_PROBE` 模式）。

## 5.7 【实测】R1 真缺陷：md 导入读不回自己的导出格式

原报告把 R1 列为「未实测的风险」。**我实跑了一遍，确认它是必然会踩的缺陷**，因此提前到一期必修项。

### 5.7.1 实测命令与结果

探针脚本 `.workbuddy-ai/tmp/probe_opt.py`，直接调 `medkit.core.library.parse_import_text(text, "md")`：

| 输入形态 | `question` | `options` | `answer` |
|---|---|---|---|
| `A. 吸烟`（无列表符） | `'慢阻肺最主要的病因'` | **`['A. 吸烟', 'B. 感染']`** ✅ | `'A'` |
| `- A. 吸烟`（连字符列表） | `'慢阻肺最主要的病因\n- A. 吸烟\n- B. 感染'` | **`[]`** ❌ | `'A'` |
| `* A. 吸烟`（星号列表） | 同上（选项文本被塞进题干） | **`[]`** ❌ | `'A'` |
| **MedKit 自身 `export_md()` 的输出** | `'### q1 · A1 · 慢阻肺最主要的病因\n- A. 吸烟\n- B. 感染\n**✅ **\n💡 吸烟是主要因素'` | **`[]`** ❌ | `'A'` |

**最后一行是致命的一行**：MedKit 自己 `render/qbank_html.py:279` `export_md()` 生成的就是 `- A. {opt}` 格式（`qbank_html.py:271`：`out.append(f"- {LETTERS[i]}. {_esc_md(opt)}")`）。**即导出 → 导入的往返是坏的**：选项全部丢失、并被当成题干正文，而函数**不报错、不告警**，返回一条看起来「有题干有答案」的记录。用户会导入一批「没有选项的题」。

### 5.7.2 根因（一行）

`medkit/core/library.py:998`：

```python
_OPT_RE = re.compile(r"^[（(]?([A-Ha-h])[)）、.．\s]+(?=\S)")
```

它要求**行首**就是（可选的左括号 +）字母。`- A. 吸烟` 的行首是 `-`，故不命中；随后 `library.py:1046-1048` 的 `elif option_begun and line.strip()` 分支因为 `option_begun` 仍为 `False`，把这一行归进 `q_lines` → 最终进入 `question`。

### 5.7.3 为什么守卫没抓到（**这是一个教科书级的「假绿」样本**）

唯一覆盖 md 导入的用例是 `tests/test_syllabus.py:246` `test_parse_import_md_blocks`：

```python
text = ("1、患儿男 3 岁发热咳嗽 3 天\nA、支原体肺炎\nB、细菌性肺炎\n答案：B\n"
        "2、心电图 QRS 增宽最常见于？\nA、室速\nB、室上速\n答案：A")
```

**它用的是 `A、支原体肺炎`——恰好是没有列表符的形态。** 断言 `len(rows[0]["options"]) == 2` 因此通过。

> 这正是 `gate-falsifiability` 技能里「**只测了会跑通的那个形态**」的典型：用例在场、断言不为零、数字具体，但它测的是**唯一能工作**的分支。md 里最自然的写法（`- A.`）反而没人测。

**证伪对照（把我上面的实测反过来读）**：同一个解析器，输入只差每行开头的 `- `，一个 `options` 长度 2、一个长度 0。这说明**不是环境、不是版本、不是我调用姿势的问题，就是这条正则不吃列表符**。

### 5.7.4 修法与误伤面（已实测）

在 `parse_question_text()` 的逐行循环（`library.py:1041`）里加一步剥前导列表符：

```python
_LIST_MARK_RE = re.compile(r"^\s*(?:[-*+]|\d+[.)])\s+")
...
for line in lines:
    line = _LIST_MARK_RE.sub("", line.strip())   # 新增：剥前导列表符再判选项
    m = _OPT_RE.match(line)
```

**误伤面实测**（`.workbuddy-ai/tmp/probe_fix.py`）——**零误伤**：

| 输入行 | 剥后 | 是否被误判为选项 |
|---|---|---|
| `1. 患者男 3 岁发热` | `患者男 3 岁发热` | ❌ 否 ✅ |
| `- 心电图 QRS 增宽` | `心电图 QRS 增宽` | ❌ 否 ✅ |
| `* 答案应为 B` | `答案应为 B` | ❌ 否 ✅ |
| `A. 甲` / `（A）甲` / `A、甲` | 不变 | ✅ 是（三种既有形态全部保持） |

原因：剥完仍需**命中 `_OPT_RE`** 才计入选项，所以「序号开头的题干行」不会被误吞。

### 5.7.5 必须补的守卫（否则修完还可能回去）

| 守卫 | 判据 | 证伪方式 |
|---|---|---|
| **往返一致性**（新增） | `export_md(questions)` → `parse_import_text(..., "md")` → `options` **逐元素相等**、`answer` 相等 | 注入：把 `_LIST_MARK_RE` 那行删掉 → **必红**（当前实测就是红的） |
| 列表符三形态（参数化） | `- A.` / `* A.` / 无列表符，三种输入产出 `options` 相同 | 注入：只支持一种 → 必红 |
| 既有形态不回归 | `A、支原体肺炎` / `A. 甲` / `（A）甲` 仍命中 | 保留 `test_parse_import_md_blocks` 并**扩充**而非替换 |
| 题干不被吞 | `1. 患者男 3 岁发热` 这类行必须留在 `question` 里 | 注入：把 `_LIST_MARK_RE` 放宽成「剥完不校验」→ 必红 |

**另需一并检查 `_OPT_RE` 之后的一个隐患**（本次未深入）：`library.py:1046-1048` 的「续行归并」在答案行紧邻选项时会把它并进最后一个选项（上表「未修」行已显示 `'B. 感染 答案：A'` 这一串接现象——那是因为答案标记已被 `ans_re` 剥掉。若题干里同时出现未识别的 `答案：` 字面量，会污染选项文本）。修 R1 时应顺手补一条断言。
