## 一、结论先行

**能用，主闭环成立（导入 → 刷题 → 判分 → 回流错题 → 重练 → 归档），且「自己的题」这一侧的粒度

| 严重度 | 条数 | 一句话 |

## 二、P0 问题

### P0-1 真首启：向导盖住模式门，模式门点不动

**现象**：从未完成/跳过新手引导的机器上首次打开，`#wizard_mask`（z-index 200）与 `#modegate`
（z-index 70）**同时出现**。向导遮罩铺满全屏且接收指针事件 ⇒ 模式门的两张卡片**点不动**；
视觉上向导右侧**露出模式门的一截卡片**（像渲染残影）。

**证据**（截图 `01_首启双弹层叠加.png`）：

```
S0 首启叠层：{'wizard': 'flex', 'gate': 'flex', 'wizardZ': '200', 'gateZ': '70', 'hit': 'wgrid'}
```
`hit` 取自 `document.elementFromPoint(模式门卡片中心)` → 命中向导的 `.wgrid` ⇒ 点击被向导吃掉。
点 `#wz_skip` 跳过向导后，模式门才可见（`S0 跳过向导后模式门可见：True`）。

**为什么现有守卫抓不到**：`tests/browser/conftest.py` 预置 `medkit-onboarded=1`，
**所有浏览器用例都跳过向导**；而 `tests/browser/test_mode_gate.py` 只验证模式门自己。
⇒ 两条首启引导**从未被一起验证**。

**影响**：新用户第一屏是两个叠在一起的弹层、其中一个点不动 —— 直接决定「这东西能不能用」的第一印象。
（我作为医学生实测的第一反应：以为界面坏了，去点了右侧露出来那截，没反应。）

**成熟案例**：Anki 的向导走完才进主界面；Quizlet 的 onboarding 是**单条分步卡片流**，
不与其它弹层并存。多弹层叠加是公认的 onboarding anti-pattern。

**建议**：串行化——向导关闭/跳过后再显示模式门（在 `wzDone` 的收尾处调 `modeGateShow()`，
并从 `initTab` 里摘掉无条件显示）。改动约 5 行，不动向导契约。
涉及：`medkit/web/css/wizard.css:2`（z-index 200）、`medkit/web/css/base.css:572`（z-index 70）、
`medkit/web/js/review-desk-review.js:698`（`maybeShowWizard`）、`medkit/web/js/app.js`（`initTab`）。

### P0-2 解析器在「选项先于题干」时产出自相矛盾的结果（B1 共用选项题导入即坏）

**现象**：输入「选项在前、题干在后」这种**合法**结构时，题干取到全文、选项吞掉后续行。

**证据**（最小复现，三例对照）：

| 输入 | `question` | `options` |
|---|---|---|
| `- A. 甲\n- B. 乙\n这道题的题干是什么\n答案：A` | **全文**（含 `答案：A`） | `['A. 甲', 'B. 乙 这道题的题干是什么']` |
| `这道题的题干是什么\n- A. 甲\n- B. 乙\n答案：A` | `这道题的题干是什么` ✓ | `['A. 甲', 'B. 乙']` ✓ |
| `A. 甲\nB. 乙\n这道题的题干是什么\n答案：A` | **全文** | `['A. 甲', 'B. 乙 这道题的题干是什么']` |

**根因**（`medkit/core/library.py:1099-1105`）：一旦 `option_begun` 为真，后续所有非选项行都被
**拼到最后一个选项上**（1099-1101），而题干只能来自选项**之前**的行（1102-1103）；`q_lines` 为空时
fallback 用的是**未剥答案/解析的原文 `text`**（1105），于是「答案：A」也被留在题干里。

**真实影响**（不是构造出来的边角）：医考题库的 **B1 共用选项题**与 **A3/A4 共用题干题**天然是
「材料/选项在前、子题在后」。实测把一份含 B1 的题库导进来：

```
S3 预览行数：5（原文块：A1 + A2 + X + B1组头+4.1+4.2 + A1 = 7 题）
4. {'q': '- A. ST 段抬高型心肌梗死\n- B. 非 ST 段抬高型心肌梗死\n- C. 不稳定型心...',
    'type': 'A1', 'ans': 'A', 'opts': 4}
```
B1 组的 **4.1 / 4.2 两个子题被吞掉**，组头变成一道题、题干是选项列表本身。
`03_题目管理_B1坏题.png` 第 4 行肉眼可见：题干列写着
`- A. ST 段抬高型心肌梗死 - B. 非 ST 段抬高型心肌梗死 - C. 不稳定型心绞痛 - D. 稳定型心绞痛 **4.1** 患...`

**为什么往返测试没抓到**：`tests/test_bank_iq.py` 的往返用例走 `export_md()` 产物，
组头带 `🧩`（`_GROUP_HEAD_RE` 命中）⇒ 走 carry_options 分支，**恰好绕开了这个 bug**。
即「只兼容自己导出的格式」这条原则被验证了，但**第三方写法没有用例**。

**成熟案例**：Anki 文本导入用**列 → 字段映射**（不猜结构）；Quizlet 要求显式分隔符 + 预览；
医考帮类 App 的题库是**结构化字段**（题干/选项/答案/解析各占一列），压根没有「从自由文本猜结构」
这一步。MedKit 走自由文本解析是合理取舍，但**必须对「选项在题干之前」给出定义**。

**建议**：把「选项段」与「题干段」**分段收集**——`option_begun` 后遇到非选项行时，
若题干尚未收集到内容则归题干（并结束选项段），否则才拼到上一选项（保留多行选项兼容）；
`question` 的 fallback 改用 `body`。约 15 行 + 补「第三方写法」参数化用例。

## 三、P1 问题

### P1-3 来源标注错误：题库练习的错题被标成「押题卷」

**证据**（接口实测）：
```
② 题库判错回流后的错题字段：{"source": "paper",
   "source_ref": {"pid": null, "question_id": "qi_1791644130987_0", "sid": null}, ...}
```
`question_id` 是**题库题**的 id（`qi_`），但 `source` 是 `paper` ⇒ 错题本渲染「押题卷」
（`05_错题本_来源标注与分组噪音.png` 可见）。根因：`medkit/core/library.py:662` 在
`sync_from_paper` 里硬编码 `"source": "paper"`；`medkit/web/js/learn-study.js:512` 只认 `paper` 一个值。

**影响**：复盘时误以为「我做过押题卷」，来源筛选与统计失真。
**建议**：`sync_from_paper` 增 `source` 参数（`paper` / `bank`），前端映射表补「题库练习」。

### P1-4 `**解析：**` 残留 `**`

**证据**（判分后解析区实际渲染）：
```
✗ 答错了 | 你的作答：B · 正确答案：A | 解析： |  | ** 吸烟是 COPD 最重要的环境致病因素…
```
`**解析：**` 是中文题库的常见写法，`medkit/core/library.py:1062` 的 `ana_re` 未把 `**` 纳入标记，
取值后也没 `strip(" *")`。医学生看到的是**带脏字符的解析**。
**建议**：正则允许 `\*{0,2}` 前缀并在取值后去星号。

### P1-5 导入向导没有「科目」输入 ⇒ 全链路「未分类」

**证据**：导入时只填了题库名，题库 `subject=""` → 题库行显示「未分类」
（`02_导入预览_确认按钮在预览之前.png`）；回流错题也落进「未分类」，错题本分组头是
`未分类 / 未分章 / 慢阻肺的诊断`（`05_错题本_…png`）。

**影响**：医学生按科目/章节组织复习；科目为空时错题本、掌握度、统计全按「未分类」聚成一坨。
**并且**：第 5 轮刚修的「回流带上题库科目」因此形同虚设 —— 题库自己就没有科目。
**成熟案例**：Anki 导入必选**牌组**（也可用 `#deck:` 文件头指定）；Quizlet 必选/新建 **set**。
**建议**：导入向导加「科目」输入（默认从题库名/文件名猜），事后可在「重命名」里改。

### P1-6 导入预览的信息顺序与可见性

**证据**：`02_导入预览_确认按钮在预览之前.png` —— 「入库到 / 题库名 / 重复题 / 确认入库（5 题）」
排在**逐题预览表之前**，1440×900 下预览表被推到视口下方，**完全看不到**。
向导文案却说「导入前先核对」。
**影响**：核对对象默认不可见 ⇒ 用户容易直接点确认，把解析错的题收进库（与 P0-2 叠加后后果放大）。
**成熟案例**：Anki 2.1.55+ 与 Quizlet 的导入对话框都是「**预览在上、目标与确认在下**」，
预览区固定高度可滚动。
**建议**：把 `.bank-bar`（目标 + 确认）移到表格**之后**；预览表加 `max-height` + `overflow-y:auto`。

### P1-7 窄屏 390px：题目管理表格横向溢出

**证据**：
```
S12 窄屏溢出：scrollWidth=458 innerWidth=390 → 溢出!
S12 溢出元凶：[{'tag':'table','cls':'bank-preview-table','w':373,'right':458},
               {'tag':'td','w':107,'right':458,'txt':'编辑 删除'}, ...]
```
**归属**：`medkit/web/css/base.css:603` 的 `.bank-preview-table{width:100%}` 配
`th{white-space:nowrap}`，而 **★ / 笔记两列是本次改动新加的** ⇒ 我把这个窄屏缺陷引入了。
**建议**：表格外包 `overflow-x:auto` 容器（成熟做法是**表格自己滚**，不是整页滚）。

### P1-8 窄屏 390px：题库行塌成竖排单字 + 模式条文字竖排

**证据**：`04_窄屏390_题库行塌陷.png` —— 题库行右侧出现**逐字竖排**的
「内科学·呼吸与循环 / 未分类」；侧栏顶部「模式 / 未选择」同样竖排。
**归属**：`medkit/web/css/base.css:375-388` 的窄屏规则只隐藏了 `aside.side nav button span`，
而 `.modebar` 是 `nav` 下的**独立 div**、题库行是 `.bank-item{display:flex}` + **6 个按钮**
（按钮数本次从 4 增到 6）⇒ 两者都是本次改动引入。
**建议**：窄屏下 `.bank-item` 改纵向堆叠、按钮折行；`.modebar-lbl` 与 `#mode_name` 隐藏（只留图标）。

## 五、与成熟产品的能力对照

| 能力 | MedKit 现状 | Anki | Quizlet | 医考帮类 | 判断 |

> 医考帮类产品的「解析标注考点出处、考频」取自公开产品介绍与行业测评文章
> （该文自标为商业推广，**仅取其维度口径**，不作为事实权威）。

**最值得补的一条**：解析里给**出处**。医学生信不信一道解析，很大程度取决于「这句话出自哪本教材哪一章」。
MedKit 已有「教材切片」与「讲解产物带 sources」的能力，但**题库的解析里没有出处字段**。

## 六、做得好的地方（不能只挑刺）

1. **模式门文案化解了选择焦虑**：「两种模式共用同一份本地数据，随时可在侧栏顶部切换」+
   「先逛逛（显示全部页签）→」。比多数产品「先注册/先选身份」的硬门友好得多。
2. **判错四件套闭环清楚**：你的作答 / 正确答案 / 解析 / 「已自动加入错题本」——一眼知道下一步去哪。
3. **练习粒度比同类 App 更贴「自己的题」**：全部 / 只练错题 / 只练未做 / 只练收藏；
   错题重练 全部错题 / 只看未掌握。
4. **空态与控件文案质量高于平均**：错题本「只看未掌握（隐藏已归档「已掌握」错题）」有解释性括注；
   搜索框给了具体例子「如：湿啰音 / 前负荷」。
5. **把已知弱点写成功能说明**：「题目管理」卡片直接写「导入的题库常有解析偏差（答案错位、选项切分不对）
   ——在这里直接改，不用重新导入」。诚实，且给了补救路径。
6. **零报错**：19 张截图期间 0 console error / 0 pageerror。
7. **统计口径同源**：每日目标与题库统计取自同一张作答流水，不在前端另记一套。

## 八、整改建议（按性价比排序）

| 序 | 项 | 影响面 | 改动量 | 建议守卫 |
|---|---|---|---|---|
| 1 | **P0-2** 解析器「选项在前」分段收集（fallback 用 `body`） | 导入正确性根基 | 小（~15 行） | 参数化「第三方写法」用例（B1 组头无 `🧩`、选项在前、A3 共用题干） |
| 2 | **P0-1** 向导与模式门串行 | 首启第一印象 | 小（~5 行） | 浏览器用例：**不预置** `medkit-onboarded`，断言两者不同时可见 |
