## 0. 结论先行

### 0.1 一句话判断

**MedKit 已经具备「可信 AI 学习助手」的技术底座，但 AI 还没有真正进入学习主路径：它能回答错题本里的问题，却不能把一次错题变成下一道变式题、下一次复习和下一次可验证的掌握。**

当前不是「AI 功能太少」，而是三件事没有闭环：

1. **题目没有稳定的知识点身份**：本机 497 道题中，`topic` 字段为空 497/497，`item_kc`、`kc_state`、`syllabus_items` 均为 0 行。
2. **解析内容债没有还**：本机导入题库的 `option_rationales`、`source_quote`、`misconceptions`、`difficulty` 覆盖率均为 0/497；网页版为 488/2350 = 20.8%，且 `source_quote` 与 `difficulty` 全库为 0。
3. **助手答完就结束**：没有「同类题/变式题」入口，没有「答完即练」，也没有可观测的迁移效果数据；本机只有 7 次作答、3 个错题文件、0 个项目。

### 0.2 当前水平

| 维度 | 当前判断 | 关键证据 |
|---|---|---|
| 功能完整性 | 学中答疑有，练中、诊断、变式、计划均弱 | 只有 `/api/vault/ask`、`/api/vault/handbook` 两个 LLM 入口；刷题页无 AI 入口 |
| 交互体验 | 聊天基础体验达标，信息呈现未成品 | 真流式、停止、重生成、会话恢复都有；但引用是纯文本路径，不可点、不可跳转 |
| 技术先进性 | 可信引用 + BKT/FSRS 是长板，检索与评测是短板 | 关键词 + jieba 二元组检索，无向量、无重排；无评测集、无遥测 |
| 学习效果转化 | 目前不可证明 | 无前后测、无迁移测、无真实用户数据；本机仅 7 次作答 |

**综合评分：47/100（当前可验证水平）。** 这是「第二梯队起步、可信能力单点领先」的位置，不是「成熟 AI 学习产品」的位置。评分方法与明细见第 8 节。

### 0.3 三个战略判断

1. **不要用「更像 ChatGPT」定义进步。**  
   对医学生真正有价值的是「这题为什么错、下一次换一道题还会不会、什么时候该再复习」。这三件事分别对应诊断、变式、调度，而不是更长的聊天。

2. **现有 AI 的长板是「可信」，不是「全能」。**  
   错题助手强制引用、无依据拒答、工具失败显性、可停止生成——这些约束在公开竞品资料中少见同等严格。下一步应把「可信」变成「可用」，而不是扩写成通用百科。

3. **下一步的收益来自「错题 → 变式 → 复习」的闭环，而不是新增聊天入口。**  
   学习科学证据显示：测验/提取练习的加权效应量约 `g=0.499`，间隔练习约 `d=0.42`，智能导师系统中位效应量约 `d=0.66`。真正抬升成绩的是提取、间隔与反馈，不是「看懂了解释」。

### 0.4 用户新增的两项探索目标

本报告已将以下两项作为正式迭代目标，而不是附带建议：

- **探索目标 A：错点变式训练。** 错题累计到一定程度后，助手基于本地薄弱点规则生成同考点、不同问法的变式题，答完即练、错则回流、对则延迟复测。
- **探索目标 B：错题助手好看好用。** 把「聊天回答」升级为「结论 + 可点依据 + 下一步动作」的学习卡片，并补齐空态、错误态、移动端与无障碍。

## 1. 调研范围、方法与证据边界

### 1.1 范围

本报告的「AI 辅助学习」包含两类能力：

- **LLM 能力**：错题助手、薄弱点复习手册、出题管线、逐选项解析生成。
- **算法型 AI**：BKT 知识追踪、FSRS 间隔重复调度、基于掌握度的优先级排序。

不把「OCR 识别」「网络检索」本身当作 AI 学习能力，只在它们影响学习闭环时提及。

### 1.2 方法

| 证据类型 | 来源 | 等级 | 用途 |
|---|---|---|---|
| 代码与测试 | 本仓 `medkit/`、`tests/`、`docs/features.md` | D（可直接复核） | 现状功能、边界、守卫 |
| 本机数据 | `~/.medkit/library/medkit.db`、`~/.medkit/logs/medkit.log`、错题文件夹 | D（单机样本） | 实际使用与落地效果 |
| 竞品官方资料 | 官方产品页、帮助中心、官方博客、官方白皮书 | A/B | 能力对标 |
| 第三方资料 | 应用商店、行业媒体、研究综述 | C | 补充事实，不作唯一依据 |
| 学习科学 | 同行评议论文与元分析 | A | 效果转化判断 |

### 1.3 边界

- 未购买竞品付费题库做逐题实操；竞品交互结论来自官方页面与公开说明。
- 竞品内部架构不可见；文中「推断」均标注，不作为事实。
- 本机数据是开发机单用户样本，**不能代表真实用户**；本报告把它当作「可复核的落地证据」，不当作市场数据。
- 评分是「有锚点的专家评估」，不是实验室测量；竞品分数标注置信度，误差约 ±5 分。

## 2. 现状盘点：AI 在学习链路里到底做了什么

### 2.1 能力地图

| 能力 | 入口 | 技术实现 | 用户能看到什么 | 当前状态 |
|---|---|---|---|---|
| 错题问答 | `POST /api/vault/ask`（SSE） | JSON 工具协议、最多 5 轮、3 个只读工具、引用校验、无依据拒答 | 逐字流式答复、来源列表、取证工具、存入错题 | 可用；仅覆盖错题本 |
| 薄弱点复习手册 | `POST /api/vault/handbook`（SSE） | 一次性证据（≤30 条错题，每条解析截 400 字），6000 token | 流式 Markdown、可下载 | 可用；空库不调模型 |
| 逐选项解析 | 出题管线 MedGen + 题库渲染 | `option_rationales` / `misconceptions` / `source_quote` / `difficulty` 四字段；批次级完整性门禁；引文逐字核对 | 判分后逐项理由、原文引句、误解标签 | 生成链路可用；导入题库不补齐 |
| 知识点掌握 | `/api/kc/*`（7 个端点） | `item_kc` 映射 + BKT + 经验贝叶斯收缩 + 自评校准 | 掌握度条、校准图、映射确认台 | 代码可用；本机 0 映射、0 状态 |
| 复习排期 | `/api/vault/review/*`、`/api/vault/scheduler` | FSRS（默认）/ SM-2（可切），固定参数、失败当天重来 | 今日复习、记得/模糊/忘了 | 可用；本机 0 复习卡 |
| 出题与质检 | `/api/projects/*`、`/api/trial` | MedGen → 门禁 → MedQC → MedFix → MedReview | 题库/押题卷/手册/Anki | 默认关闭；本机 0 项目 |
| 讲解/提问/苏格拉底 | 无 | v0.15 已整体移除 | 无 | 不存在 |

### 2.2 错题助手：技术实现与边界

**编排方式**：不依赖各服务商的 function-calling，模型输出 JSON 指令，后端执行只读工具，最多 5 轮；轮数用尽再追一轮「只许 final」。这是对多服务商兼容性的务实选择。

**检索方式**：`vault_index.list_items` 把查询用 jieba + CJK 二元组分词，最多 8 个 token，每个 token 对题干、解析、我的理解、我的疑问、答复、主题、章节、科目做 `LIKE` 跨字段 OR，token 之间 AND；最多返回 12 条。没有向量检索、没有重排、没有同义词/别名表。

**可信约束**：

- 引用必须来自索引中真实存在的路径，编造路径会被剔除并告知用户（`_validate_citations`）。
- 没有任何有效引用、也没有调用 `get_topic_stats` 时，答复被强制替换为「没有相关记录」，禁止通识补全。
- 工具失败必须显性写进答复。
- 流式输出可在用户点「停止」时截断 provider 流，不在后台继续烧 token。

**上限**：`MAX_ROUNDS=5`、`MAX_TOKENS=3000`、历史最多 8 轮且每轮截 4000 字、工具结果截 6000 字。手册最多 30 条错题、6000 token、解析截 400 字。

**关键边界**：

- 助手只读错题 vault，**不能**读当前题库题目、教材切片、大纲、掌握度以外的学习数据。
- 手册只做归纳，**没有引用校验**；返回非空 Markdown 就标记 `grounded=true`。
- 检索是词面匹配，缩写/别名（「心衰」→「心力衰竭」）召回不了。
- 没有会话级长期记忆；历史只来自前端 `sessionStorage` 最近 40 条消息。
- 没有成本/延迟记录；无法回答「一次问答花了多少 token、首字多久、引用剔除率多少」。

### 2.3 知识点与复习：底座存在，但没有被激活

**BKT**：四参数 `P_TRANSIT=0.25`、`P_SLIP=0.10`、`P_GUESS=0.20`；人群先验 `0.30`，收缩权重 `2.0`。答对从 0.30 升到 0.783，答错降到 0.091，方向正确。选择 BKT 而不是深度模型，理由是单用户样本量达不到 SAINT/DKT 的训练需求。

**映射**：`item_kc` 以 `syllabus_items.id` 为主键；归一后完全相等才自动确认，字符 bigram Jaccard ≥0.45 只给候选，必须人工确认；LLM 兜底通道尚未实现，显式降级为规则。

**FSRS**：`fsrs==6.3.2`，学习步长 `10 分钟 / 1 天`，`maximum_interval=180`，`desired_retention=0.9`，关闭 fuzzing；连续「记住」的间隔为 `1 → 7 → 32 → 118 → 180 → 180` 天，SM-2 为 `1 → 6 → 15 → 38 → 95 → 238` 天，失败均当天重来。参数是实测标定的，不是库默认值。

**但本机实际状态**：

| 表 | 行数 | 含义 |
|---|---:|---|
| `banks` | 2 | 外科 297 题、耳鼻喉 200 题 |
| `bank_items` | 497 | `topic` 为空 497/497 |
| `item_kc` | 0 | 没有题挂到知识点 |
| `kc_state` | 0 | 没有掌握度状态 |
| `syllabus_items` | 0 | 没有导入大纲 |
| `review_cards` | 0 | 没有复习卡 |
| `bank_attempts` | 7 | 2 对 / 5 错，28.6% 正确率，仅 3 天有作答 |
| `vault_items` | 2（文件夹 3 个 md） | 两条均 `chapter/topic` 为空 |

这说明：**BKT 与 FSRS 是「可运行但未运行」**。用户看到的「今天先学什么」只能回退到 legacy 错题聚合，`readiness` 没有数据时显示未就绪，这是诚实的设计，但也意味着 AI 学习闭环没有真正开始。

### 2.4 逐选项解析：生成端有门禁，导入端是缺口

生成端契约完整：每题要求 `option_rationales` 覆盖全部选项、`misconceptions` 只给错误选项、`source_quote` 逐字摘录、`difficulty` 1–5。门禁分两层：

- **完整性**：批次级 opt-in——本批只要有一题带理由，就要求每题每选项都有；整批都没有则不判，避免旧项目全红。
- **断言级溯源**：`source_quote` 必须在所引切片里逐字核到（归一空白/标点，省略号分段核）；默认 `warn`，`entailment_strict=true` 才 `fail`。

真实覆盖率：

| 对象 | 题量 | 含逐选项理由 | 五项齐全 | `source_quote` / `difficulty` |
|---|---:|---:|---:|---:|
| 本机导入题库 | 497 | 0 | 0 | 0 |
| 网页版内置题库 | 2350 | 488（20.8%） | 386（16.4%） | 0 |

**结论**：生成链路能生产高质量解析，但**没有回填机制**；用户导入的旧题库不会自动获得逐选项解析。网页版 20.8% 的覆盖也不是全量，且最关键的「原文引句」与「难度」全库为 0。

**网页版同源参照**：网页版 `medkit-web-contest` 已实现 AI 流式输出、停止、45s 超时、token 粗估与「依据标注缺失」提示（见 `docs/竞品设计分析与改进方案_2026-10-29.md` §11.1）。它与本地版共享同一产品判断，但两套数据不共享；本报告的技术事实以本地版代码为准。

## 3. 竞品对标

### 3.1 九款产品的 AI 学习能力画像

#### AMBOSS：把 AI 嵌进整个学习生态

2026-02 推出 AI Mode Learning，定位「AI Study Copilot」：基于 AMBOSS 同行评议内容，支持上传讲义、笔记、心电图图片，解释可直接连到文章、Qbank、Anki 卡与进度；不是开放网络问答。官方白皮书称，2026-04 上线的自适应 Qbank 已有 36,000+ 学生使用。  
**对标价值**：最强的「内容图谱 + 练习 + 复习 + 进度」一体化；AI 不孤立存在。

#### UWorld：把 AI 放进题目上下文

UAsk 内嵌在 QBank 与 Medical Library，能识别当前正在看的题/文章，基于 UWorld 自有内容作答；支持追问、类比、总结，答复可转成 Notebook 条目与闪卡。官方页面称 2025 年应用内调查 9.3/10。  
**对标价值**：题目级上下文 + 一键转复习材料，是「练中即时帮助」的标准形态。

#### Osmosis AI：把解释变成主动回忆

基于 Elsevier 内容，提供可点击的文内/教材引用；Tutor Mode 用引导问题而不是直接给答案；可生成闪卡、测验、摘要、表格、口诀，支持暂停视频后按上下文提问；官方称 8M+ 学生使用。  
**对标价值**：引用可核验 + 生成学习材料 + 分步辅导，是「解释 → 主动回忆」的完整链路。

#### 丁香医考：本地化诊断与计划

公开资料称其提供 AI 私教（按进度与目标生成每日计划）、AI 答疑（结合课程讲义、十版教材与考纲）、AI 错因分析（按错误选项定位原因）、AI 学习诊断与数据反馈。题库覆盖 6000+ 真题。  
**对标价值**：中文医学考试场景下，把「错因」与「计划」做成产品，而不是只做问答。

#### 医考帮：内容与解析标准，不是 AI 助手

官方介绍强调「考点还原」「全选项标准解析」、名师视频解析、题库评论与统计、AI 自助组题。公开资料没有同等规模的 AI 导师能力。  
**对标价值**：全选项解析是医学题库的行业底线；AI 不是唯一竞争力。

#### Anki：调度算法标杆，没有 AI 助手

FSRS 已成为 Anki 默认可选算法；基于 DSR（Difficulty、Stability、Retrievability）记忆状态，按 desired retention 调度；官方文档明确「同等保留率下比 SM-2 复习次数更少」。没有 AI 讲解、没有题目内容。  
**对标价值**：调度数学与数据主权；MedKit 的 FSRS 参数标定方向正确，但还没有个性化参数优化。

#### RemNote：笔记、卡片、FSRS 一体

AI 可从 PDF/笔记生成闪卡、测验、摘要；FSRS v6 按个人复习历史优化；官方称 1,000,000+ 学生使用，FSRS 可减少 20%–40% 复习量。  
**对标价值**：内容 → 卡片 → 复习的无缝衔接，是 MedKit「错题 → 变式 → 复习」可借鉴的产品形态。

#### Quizlet：对话式导师 + 大规模内容

Q-Chat 用苏格拉底式提问引导，不直接给答案；AI 可从笔记/PDF 生成学习集；Learn 模式做自适应练习；公开资料称 5 亿级学习者。  
**对标价值**：对话式辅导的易用性与规模化；但内容多为用户生成，医学严谨性不足。

#### Khanmigo：教学法最强，使用率最难

Khanmigo 以「不直接给答案、用引导问题与支架」为核心，支持语音、教师工具、学习记录信号；官方披露自 2023 年以来 1.08 亿次交互、工作日平均 26.9 万次，但**只有约 15% 有权限的学生真正使用**；接入掌握度信号后 next-item correctness 提升 6.1%。NBER 2026 的两年集群随机试验显示，全年效果约 0.06–0.08 个标准差（第三方解读）。  
**对标价值**：AI 教学法有效，但「学生愿不愿意用」是更大的约束；这也是 MedKit 必须把 AI 嵌进主路径而非另开聊天页的原因。

### 3.4 逐维度分析

#### 功能完整性：MedKit 只有「学」的一半

领先产品覆盖「学 → 练 → 诊 → 复 → 测」五段；MedKit 在「学」有错题问答，在「复」有 FSRS，在「诊」有 BKT 但未激活，在「练」与「测」没有 AI。  
最直接的缺口是：**用户在刷题页答错后，没有任何 AI 入口**。UWorld 的 UAsk 就在题目旁；AMBOSS 的 AI Mode 在 Qbank 与文章里；Osmosis 在视频暂停处；MedKit 的助手却在另一个页面，且不知道你刚答错哪题。

#### 交互体验：聊天基础达标，学习动作缺失

MedKit 的流式、停止、重生成、会话恢复、焦点恢复、`aria-live` 处理都优于多数本地工具。问题在「答案之后」：

- 引用是纯文本 `路径#小节`，不可点击、不可跳转、不可复制单条。
- 答复没有「结论 / 依据 / 下一步」结构，长答案像一篇小作文。
- 没有「练 3 道变式」「加入今日复习」「打开原题」这些学习动作。
- 空态只有一句话，没有利用「你有几条错题、几个薄弱点、几条到期」做引导。
- 手册是一段长聊天，不是可折叠、可下载、可加入复习的「产物卡」。

#### 技术先进性：可信约束领先，检索与评测落后

**领先**：引用校验 + 无依据拒答 + 工具失败显性 + 真取消；这在公开竞品资料中少见同等严格。  
**落后**：

- 检索是词面 `LIKE`，没有向量/混合检索/重排；同义表达召回弱。
- 手册没有引用校验，`grounded=true` 只代表「模型返回了非空文本」。
- FSRS 用固定参数，没有按用户复习历史优化，也没有 desired retention / 工作量预测 UI。
- BKT 没有 IRT/DKT 或多知识点关系推理；LLM 映射通道未实现。
- 没有评测集、没有遥测、没有成本/延迟指标；无法证明「回答变好了」。

#### 学习效果转化：目前无法证明

竞品的「效果」至少有使用规模、调查、考试数据或 RCT；MedKit 没有真实用户数据。  
学习科学告诉我们：**解释本身不产生成绩，提取与间隔才产生成绩。** 当前助手停在「解释」，没有进入「提取」。这正是错点变式训练要补的环节。

### 3.5 学习科学证据与启示

| 证据 | 数值 | 对 MedKit 的含义 |
|---|---|---|
| 课堂测验/提取练习元分析（Yang et al., 2020；222 项研究、48,478 名学生） | `g=0.499`（中等效应） | 每道错题后应有一次提取，而不是只看解析 |
| 间隔练习元分析（Donovan & Radosevich；Cepeda 等） | `d≈0.42`；一个月以上保留间隔优势约 15% | FSRS 方向正确，需让用户看见「为什么今天复习」 |
| 智能导师系统元分析（Kulik & Fletcher, 2016；50 项受控评估） | 中位 `d=0.66`；Visible Learning 加权均值 `0.52` | AI 导师有效，但需要个性化与反馈，不是通用聊天 |
| FSRS vs SM-2 | 同等保留率下复习次数更少；RemNote 官方称减少 20%–40% | MedKit 应展示「预计复习量」与「保留率」 |
| Khanmigo 两年 RCT（NBER 35620, 2026） | 全年约 `0.06–0.08 SD`；仅约 15% 有权限学生使用 | 效果存在但有限；**使用率**是 AI 学习产品的第一约束 |

**启示**：MedKit 的下一轮不该追求「更会聊」，而该追求「更会被用」：把 AI 放进刷题结果页、错题列表、复习到期卡，把每次回答变成一个可执行动作。

## 4. 优势、短板与核心差距

### 4.1 四项真实优势

1. **可信引用与拒答**：引用路径必须真实存在，编造剔除；无依据统一拒答；工具失败显性。16 项 Agent/SSE 测试把这几条钉死。公开竞品中，UWorld/AMBOSS 强调「grounded」，但少见「无依据必须说不知道」的同等明确承诺。
2. **真流式与真取消**：SSE 逐字、`AbortController` + 服务端 `threading.Event` 截断 provider 流；不是只停 UI。
3. **本地数据主权**：错题是 Markdown 文件，可同步盘、可手改、可拷走；SQLite 只是可弃索引；API Key 加密；服务只监听本机。
4. **算法与门禁底座**：BKT + FSRS + 题目契约 + 引文核对 + 1418 项测试；这在个人开发产品里属于高工程密度。

### 4.2 六项待补短板

| 短板 | 量化证据 | 影响 |
|---|---|---|
| 知识点身份缺失 | `topic` 空 497/497；`item_kc`/`kc_state`/`syllabus_items` 均 0 | 掌握度、变式、自适应都无法真正运行 |
| 解析内容债 | 本机 0/497；网页版 20.8%；`source_quote`/`difficulty` 0 | 用户看到的多是整题解析，不是逐项教学 |
| 闭环断裂 | 无变式、无后测、刷题页无 AI 入口 | 答完即结束，无法验证迁移 |
| 效果不可测 | 无遥测、无评测集；本机 7 次作答 | 无法证明改进有效，也无法发现退化 |
| 体验未成品 | 引用纯文本、无动作卡、无移动端 | 「能用」但不够「好用、好看」 |
| 技术上限 | 无向量/重排、FSRS 固定参数、无多模态 | 复杂提问召回弱；长期个性化不足 |

### 4.3 五个核心差距

1. **上下文差距**：竞品 AI 知道「你正在看哪道题/哪篇文章」；MedKit 助手只知道「错题本」。
2. **动作差距**：竞品把解释变成题、卡、计划；MedKit 把解释变成一段文字。
3. **内容差距**：竞品有大规模、结构化、逐选项解析的内容；MedKit 依赖用户自备题库，且导入后不补解析。
4. **个性化差距**：竞品有自适应选题与学习者模型；MedKit 有 BKT/FSRS，但没有映射、没有参数优化、没有计划。
5. **证据差距**：竞品有使用规模、调查、RCT；MedKit 没有真实用户数据与效果评测。

### 5.2 P1：错点变式训练（探索目标 A）

详见第 6 节。核心不是「生成更多题」，而是「用本地规则选出最该练的错点，生成同考点不同问法，答完回流」。

### 5.3 P1：错题助手好看好用（探索目标 B）

详见第 7 节。核心不是「换皮」，而是把答案变成学习卡片：结论先行、依据可点、下一步可做。

### 5.4 P2：暂不做，但留接口

- 自适应选题（先让 KC 映射与变式跑起来，再做难度曲线）。
- 多模态问答（图片/心电图上传；AMBOSS 已做，但成本与校验门槛高）。
- 移动端/跨设备同步（当前本地优先是差异化优势，不必为了「像竞品」引入账号体系）。
- 通用聊天/社区/排行榜/模考（明确不做）。

### 5.5 不做的理由

- **通用聊天**：会稀释「只依据你的错题本」的信任边界，且与学习效果无关。
- **社区/排行榜**：需要运营与审核，且小样本下 peer 比较不可信。
- **全真模考/分数预测**：没有足够样本，编分数比不编更糟。
- **云端账号**：破坏本地数据主权；跨设备需求可先用文件夹同步解决。

## 6. 专项方案 A：错点变式训练

### 6.1 定义

「错点变式训练」不是「再刷一道同主题的题」，而是：**围绕一个已经错过的考点，生成 2–3 道问法/情境/干扰项不同的题，验证用户是否真正掌握，而不是记住原题答案。**

它要回答三个问题：

1. 这个错点值不值得练？（本地优先级规则）
2. 练什么样的变式？（同考点、不同问法、难度可控）
3. 练完算不算掌握？（迁移通过，而不是原题复述）

### 6.2 选点规则：直接复用本地 MedKit 口径

不另起一套排序，全部复用现有规则：

| 规则 | 来源 | 用法 |
|---|---|---|
| `score = 0.60×正确率 + 0.30×近期保持 + 0.10×样本置信` | `library.compute_score` | 错题组掌握分 |
| `priority = 0.50×(1-score) + 0.30×min(miss/6,1) + 0.20×近期失败` | `library.compute_priority` | 选点主排序 |
| `priority ≥ 0.3` 才入选 | `gap.plan` | 避免「不薄弱也硬练」 |
| `weight = priority + 0.15×考频 + 0.10×未覆盖` | `gap.plan` | 有真题考频/大纲时加权 |
| 单知识点 ≤3 题 | `gap.KP_QUESTIONS_CAP=3` | 防止一个错点刷 20 题 |
| 连续记住两次即「已掌握」 | vault 复习语义 | 变式通过不直接改「已掌握」，要与原题复习合并判定 |
| 失败当天重来 | FSRS / SM-2 | 变式错题当天进入复习 |
| BKT 优先，legacy 兜底 | `kc_state` / `get_mastery_view` | 有映射用 `p_mastery`，没有用 `compute_score` |

**选点流程**：

1. 从 `vault_index.stats` 取分组（科目/章节/主题），或从 `kc_state` 取 `attempts>0` 的知识点。
2. 过滤：`unlearned>0` 或 `priority≥0.3`，或 `p_mastery<0.65`。
3. 按 `priority` 降序；取前 3–5 个错点；每个错点最多 3 道变式；单次训练最多 9 道。
4. 若 `chapter/topic` 为空：回退 `origin_ref.module`（本机 297/497 有）；再回退题库科目 + 题干关键词聚类；仍无法分组则不生成，明说「这条错题缺少章节信息，先补章节」。
5. 有到期复习卡时优先选到期项，避免「练新不复习」。

### 6.3 变式类型

| 类型 | 改什么 | 不改什么 | 例子 |
|---|---|---|---|
| 干扰项变式 | 换 2–3 个错误选项，保留正确答案与考点 | 题干情境、答案 | 原题考「第 4–7 肋最易骨折」，变式换干扰项为「第 1–3 肋」「第 8–10 肋」组合 |
| 问法变式 | 诊断 → 下一步检查/治疗/机制 | 考点与难度 | 原题问「最可能诊断」，变式问「首选检查」 |
| 情境变式 | 换病例年龄、病程、体征 | 考点 | 原题麻疹，变式换风疹/幼儿急疹做鉴别 |
| 反选变式 | 改成「下列哪项错误」 | 选项集合 | 训练反向提取 |
| 数值/边界变式 | 改数值、单位、阈值 | 考点 | 训练剂量、分级、 cutoff |
| 跨考点鉴别 | 加入一个易混考点做对比 | 主考点 | 「诊断 vs 治疗」「相似病名」 |

**难度控制**：`difficulty` 取原题 ±1，范围 1–5；原题未标注时默认 3；变式必须标注 `variant_of`、`variant_type`、`difficulty`。

### 6.4 生成契约与门禁

复用现有 `QuestionItem` 契约，不另造格式：

```json
{
  "question": "变式题干",
  "options": ["A. …", "B. …", "C. …", "D. …", "E. …"],
  "answer": "B",
  "analysis": "解析",
  "option_rationales": {"A": "…", "B": "…", "C": "…", "D": "…", "E": "…"},
  "misconceptions": {"A": "…", "C": "…"},
  "source_quote": "原题解析/教材原文中的支撑句",
  "difficulty": 3,
  "variant_of": "原错题 id 或 bank item id",
  "variant_type": "option|stem|scenario|negative|numeric|discrimination"
}
```

**门禁**（复用现有 `gates/`）：

1. `options_check`：5 选项、答案键在范围内、无绝对化用语、无重复选项、无长度泄露。
2. `trace_check.check_entailment`：有 `source_quote` 时逐字核对；**原始错题没有教材切片时，明确标注「依据：原题解析」**，不冒充教材原文。
3. `dedupe`：与原题、同批变式的 n-gram Jaccard >0.8 一律拒绝，防止「换皮原题」。
4. 答案分布：同批正确答案不得集中在同一字母；样本 <10 只告警，不阻断。
5. 生成失败/校验失败：**不展示、不静默降级**；提示「这道变式没有通过校验，换一个错点或重试」。

### 6.5 交互流程

1. **入口 1**：错题助手答复底部动作栏「练 3 道变式」。
2. **入口 2**：薄弱项表每一行「变式训练」。
3. **入口 3**：刷题判分结果区「这题错了 → 练变式」。
4. **训练层**：复用现有沉浸式刷题层（点选项即判分、答题卡、键盘、计时），不新建一套 UI。
5. **结果卡**：`2/3 通过`、`迁移通过/未通过`、`下一个到期日`、`再练一组`、`回到错题`。
6. **回流**：变式答错 → 原错题 `miss_count+1`、`status=unlearned`、`due=今天`；变式答对 → 记录 `variant_pass`，不直接改「已掌握」；连续两次变式通过且原题复习通过 → 标记「已掌握」。

### 6.6 数据与掌握语义

- **作答流水**：写入 `bank_attempts`，`mode="variant"`、`session_id="variant:<mistake_id>"`；保持 append-only。
- **变式题存储**：优先生成到临时题库（`bank_items`，`bank_id="variant_<date>"`），不污染用户题库；可一键清理。
- **原错题回流**：只改 front matter 的 `miss_count`、`status`、`due`、`last_tried`，不改题干/解析；文件仍是真身。
- **掌握判定**：`variant_pass` 是「迁移证据」，不是「掌握」；掌握仍由「连续记住两次」与原题复习决定。这样避免「变式蒙对 → 误判已掌握」。

### 6.7 成本与安全

- 单次变式生成：3 个错点 × 3 题 = 9 题；复用 MedGen 的出题成本预估，生成前展示「预计 token / 参考价」。
- 变式题优先使用本地原题解析与教材切片；没有教材切片时只用原题解析，**不联网检索**。
- 不把用户错题原文发送到第三方，除非用户已配置自己的服务商（与现有 BYOK 一致）。
- 生成内容必须过门禁；不过门禁的题不进入训练，不写入题库。

### 6.8 验收指标

| 指标 | 目标 |
|---|---|
| 变式生成成功率（过门禁） | ≥90% |
| 与原题重复率（Jaccard>0.8） | 0% |
| `source_quote` 或「依据：原题解析」标注率 | 100% |
| 从助手答复到开始变式 | ≤2 次点击 |
| 变式作答记录完整率 | 100% |
| 变式答错后当天进入复习 | 100% |
| 7 天延迟后测同考点正确率提升 | 相对基线 +15 个百分点（试点目标，非承诺） |

## 7. 专项方案 B：错题助手好看好用

### 7.1 现状审计

**已经做对的**：

- 聊天是唯一主界面，宽屏两栏，右栏常驻薄弱项/今日复习/错题列表。
- 真流式、停止、重生成、复制、存入错题、会话恢复、贴底才自动滚动、焦点恢复、流式期间关闭 `aria-live`。
- 快捷提问 4 条，空态有基本说明。

**不够好用的**：

| 问题 | 现状 | 影响 |
|---|---|---|
| 引用不可点 | 显示 `路径#小节` 纯文本 | 用户无法一键跳到原错题核对 |
| 答案无结构 | 一段 Markdown 长文 | 不知道「结论是什么、依据在哪、下一步做什么」 |
| 动作缺失 | 只有存入/重生成/复制 | 不能直接练变式、加入复习、打开原题 |
| 气泡过宽 | `max-width:88%`，无阅读宽度上限 | 长文阅读疲劳 |
| 空态太薄 | 一句话 | 没有利用数据做引导 |
| 手册不像产物 | 长聊天 + 下载按钮 | 不能折叠、不能加入复习 |
| 错误态普通 | 红色气泡 + 文案 | 没有「重试/换问法/检查 Key」的分级动作 |
| 移动端未专门设计 | 桌面两栏直接压缩 | 输入框、引用、动作按钮拥挤 |

### 7.2 设计目标

1. **像研友，不像客服**：语气直接、结论先行、不说「希望这对你有帮助」。
2. **像讲义，不像聊天记录**：每条回答是一张「结论 + 依据 + 下一步」的学习卡。
3. **像书桌，不像 AI 面板**：纸、墨、红笔、荧光笔的既有品牌语言，不用紫色渐变、不用发光边框。
4. **一屏一任务**：问、看、练、复习都在同一个错题视图完成，不跳页。

### 7.3 版式与组件

```text
┌─ 错题助手 · 只依据你的错题本 ─────────────── 3 个薄弱点 · 5 条到期 ─┐
│ 正在问：<题干摘要>                          [切换为整个错题本]       │
│                                                                    │
│ ┌─ 结论 ────────────────────────────────────────────────────────┐ │
│ │ 你这一步错在把「热退疹出」记反了：幼儿急疹是热退后出疹，       │ │
│ │ 麻疹是发热期间出疹。                                          │ │
│ ├─ 依据 ────────────────────────────────────────────────────────┤ │
│ │ [1] 解析 · 麻疹前驱期…      [2] 我的理解 · 我以为是…           │ │
│ ├─ 下一步 ──────────────────────────────────────────────────────┤ │
│ │ [练 3 道变式]  [加入今日复习]  [打开这条错题]  [存入错题]       │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ 取证过程 ▸ search_my_mistakes → read_file                          │
│ [输入你的问题…                                        ] [发送]     │
└────────────────────────────────────────────────────────────────────┘
```

**组件规则**：

- **回答卡**：最大宽度 `72ch`，左对齐；结论区用墨色正文，依据区用浅纸色底，下一步区用细分割线。
- **引用 chip**：`[1] 解析 · 麻疹前驱期…`，点击后在右栏打开该错题详情并定位到对应小节；支持复制引用。
- **取证过程**：默认折叠，显示工具链与失败项；不占据主阅读区。
- **动作栏**：最多 4 个主按钮；「练变式」用品牌色，「加入复习」用次级色，「打开错题」用文字按钮。
- **手册卡**：标题 + 目录 + 分节折叠 + 下载 + 加入复习；不再把整本手册塞进一个气泡。
- **空态**：显示「你目前有 N 条错题、M 个薄弱点、K 条今日到期」，给 3 个数据驱动入口：
  - 「我最近哪个章节最弱？」
  - 「这些错题有什么共性？」
  - 「给我 3 道变式题」
- **输入区**：自动增高 1–5 行；发送/停止同键位；`Enter` 发送、`Shift+Enter` 换行；忙碌时禁用发送并显示停止；保留草稿。
- **消息动作**：复制、重新生成、存入错题、打开原题、练变式；错误消息给「重试 / 换问法 / 检查服务商」。
- **移动端**：右栏折叠为底部抽屉；输入框吸底；44px 触控目标；安全区 padding；无横向滚动。

### 7.4 视觉规范

| 元素 | 规范 |
|---|---|
| 字体 | 正文 15–16px，行高 1.75；标题 18–20px；数字等宽 |
| 颜色 | 纸白底、墨黑正文、品牌青绿强调；红笔仅用于「错/警示」；荧光黄仅用于「依据高亮」 |
| 边框 | 1px 细线；卡片圆角 8–12px；不用大阴影、不用发光 |
| 引用 | 书脊式标签：左侧 3px 品牌色竖条 + 路径 + 小节 |
| 动效 | 仅流式光标、发送按钮 pressed、卡片淡入；`prefers-reduced-motion` 关闭 |
| 空态 | 线稿图标 + 数据摘要 + 3 个入口；不画大插画 |
| 暗色 | 纸色反转，保持对比度 AA；红/绿不单独承载语义 |

### 7.5 状态设计

| 状态 | 用户看到 | 可执行动作 |
|---|---|---|
| 未配置 API Key | 「还没有连接服务商，助手不可用」 | 去设置 |
| 首次加载 | 骨架 + 「正在读取错题本」 | 无 |
| 工具取证中 | 「正在查：search_my_mistakes」 | 停止 |
| 流式输出 | 逐字 + 光标 | 停止 |
| 无依据 | 「我的错题库里没有相关记录」+ 说明 | 换问法 / 打开错题列表 |
| 引用被剔除 | 「已剔除无效引用：…」 | 查看有效来源 |
| 模型失败 | 「模型调用失败：…」 | 重试 / 检查服务商 |
| 超时 | 「这次没有在限定时间内返回」 | 重试 / 缩短问题 |
| 空错题库 | 「先录入一条错题，或从练习判错回流」 | 新建错题 / 去刷题 |

### 7.6 可用性与无障碍验收

| 验收项 | 口径 |
|---|---|
| 引用可点 | 100% 有效引用可点击并定位 |
| 从答复到变式 | ≤2 次点击 |
| 移动端 | 390px 无横向溢出；输入框不被键盘遮挡 |
| 触控目标 | ≥44×44px |
| 对比度 | WCAG 2.2 AA |
| 键盘 | Tab 可达所有动作；Esc 关闭详情；Enter 发送 |
| 读屏 | 流式期间不逐字播报；落地后整段播报一次；错误可聚焦 |
| 焦点 | 重绘后焦点回到原动作按钮（现有实现已做，需保持） |
| 空态 | 必须显示真实数据摘要，不能只写「暂无」 |
| 性能 | 流式只重绘当前气泡；Markdown 仅在落地时渲染（现有实现已做，需保持） |

### 7.7 小规模可用性测试

- 对象：5 名正在备考的医学生（至少 2 名使用过错题本）。
- 任务：① 问「我这章为什么老错」；② 点开一条引用核对原文；③ 从答复开始一组变式；④ 把一条错题加入今日复习；⑤ 在 390px 宽度完成一次提问。
- 记录：任务完成率、点击路径、卡点原话、SUS 分数。
- 通过线：任务完成率 ≥90%，引用点击成功率 100%，无阻断性卡点；SUS ≥75。

### 8.3 评分解释

- **47 分不是「产品差」**，而是「AI 学习效果尚未被验证」。工程底座与可信能力是加分项，但四维度等权，效果转化拖低总分。
- **目标分**：P0 完成后约 60–65；P1（变式 + UI）完成后约 72–78；达到 AMBOSS/UWorld 的 80+ 需要内容规模、上下文整合与效果证据，不是一轮迭代能完成。
- 竞品分数是公开资料评估，不是实测；Anki/医考帮的单项满分与综合低分并存，说明「AI 能力」与「学习价值」不是同一件事。

## 附录 D：待确认的产品决策

1. **变式入口优先级**：先做错题助手答复底部，还是先做刷题判分结果区？（建议先做答复底部，改动小、可验证。）
2. **变式题是否入库**：临时题库（可清理）还是永久题库（可复习）？（建议临时题库 + 通过的题可收藏。）
3. **变式失败是否新建错题文件**：只在原错题上累加，还是新建「变式错题」？（建议原错题累加，避免文件膨胀。）
4. **是否允许 AI 生成变式使用原题解析作为唯一依据**：可以，但必须标注「依据：原题解析」，不得冒充教材原文。
5. **UI 2.0 是否保持单页两栏**：建议保持，右栏承担「引用定位 + 薄弱项 + 复习」，不引入第三栏。
