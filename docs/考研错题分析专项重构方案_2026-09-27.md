## 0. 结论先行

**《总纲》要的不是"重构 MedKit"，而是一个新产品的内核。** 二者同属"医学考试学习工具"，
但目标函数不同：

| 维度 | 现状 MedKit | 《总纲》目标 |
|---|---|---|
| 定位 | **生成器**（教材→出题→产物） | **记录器+分析器**（错题→归因→纵向档案） |
| 数据流 | 上游宽（PDF/教材/检索）→ 下游窄 | 上游窄（1 条/题）→ 下游宽（校准/热力图/跨轮次） |
| 核心资产 | 提示词与质检门禁 | **N=1 的元认知数据集**（《总纲》§4.3） |
| 数据规模 | 项目级、可弃（删项目即无痕） | 个人级、**复利增长、不可再生**（§4.3） |
| 摩擦设计 | 越顺滑越好 | **刻意保留摩擦**（§2.4、§3.4） |

**核心判断：不要原地改造 MedKit，而是复用其"数据层 + 调度层 + 渲染层"基建，把"生成链"
整体降级为可选插件，新建一个以错题档案为唯一权威的学习内核。** 依据见 §5.1 方案 A/B/C 对比。

**但有一条《总纲》自己划的红线优先于本方案的全部技术取舍**：§2.1「停手信号——当花在调试工具上的
时间接近花在刷题上的时间时，应立即停手」，§3.4「两周做不出第一版就是范围划大了：MVP 只需要
一个 JSONL 文件、一个 prompt、一个能打聚合表的脚本」，§2.5「第0步：这个周末不写代码，先手工跑
20 道题，认可率≥70% 再动工」。
→ **本方案的正确读法是"能力地图 + 边界条件"，不是"施工排期"。落地应从 §7 的第 0 阶段开始，
在第 0 阶段验收通过前，§4 之后的所有内容都不应开工。**

## 2. 目标架构

### 2.1 分层图（改造后）

```
┌─ 录入层 (Ingest) ────────────────────────────────────────────┐
│  截图OCR · 剪贴板粘贴 · 语音转文字 · JSONL 导入 · Anki 导出导入  │
│  约束：confidence 必须当场填，不提供"补填"接口                  │
└───────────────────────┬──────────────────────────────────────┘
                        ↓  ErrorCard（错题档案，唯一权威）
┌─ 归因层 (Attribution) ───────────────────────────────────────┐
│  error_analysis agent → 归因/考点定位/修正陈述/反事实/回看章节   │
│  红线：正确答案只由用户提供，AI 不判对错（§3.2）                │
│  产出：ai_error_tag（与人工 tag 比对）· counterfactual · fix    │
└───────────────────────┬──────────────────────────────────────┘
                        ↓
┌─ 沉淀层 (Persistence) ───────────────────────────────────────┐
│  错题档案（mistakes v8 扩列）· 反事实卡（cards）· 调度（FSRS）  │
└───────────────────────┬──────────────────────────────────────┘
                        ↓
┌─ 复盘层 (Review/Meta) ───────────────────────────────────────┐
│  校准曲线 · Brier · 标签×科目热力图 · 跨轮次迁移 · 减法清单     │
│  苏格拉底复习（复用 tutor）· 复习队列（复用 review）           │
└───────────────────────┬──────────────────────────────────────┘
                        ↓
┌─ 输出层 (Emit) ──────────────────────────────────────────────┐
│  Markdown 复盘笔记 · APKG · CSV · JSONL 备份（唯一出口格式）   │
└──────────────────────────────────────────────────────────────┘

┌─ 保留插件层（可选，默认不启）───────────────────────────────┐
│  生成链 orchestrator + 5 gates + 7 agents（教材→题→押题卷）   │
└──────────────────────────────────────────────────────────────┘
```

### 2.3 核心数据结构

#### D1 · `ErrorCard`（错题档案，`mistakes` 表 v8 扩列）

现有 20 字段保留，**新增 8 个可空列**（SQLite 冗余列 + `data` JSON 双写，遵循 ADR-001）：

| 字段 | 类型 | 空值语义 | 落哪一列 | 出处 |
|---|---|---|---|---|
| `confidence` | int 1-5 | `NULL` = 未填（**此状态不可看答案**） | `confidence INTEGER` | §3.1 |
| `my_reasoning` | str ≤120字 | `""` = 未填 | 仅 `data` | §3.1 |
| `my_answer` | str | 复用现 `user_answer` | 现有列 | §3.1 |
| `error_tag` | str 枚举6 | `""` = 未归因 | `error_tag TEXT` | §3.1 |
| `ai_error_tag` | str 枚举6 | `""` = 未跑分析 | `ai_error_tag TEXT` | §3.2 |
| `tag_match` | int 0/1 | 派生列（人工 vs AI 是否一致） | `tag_match INTEGER` | §3.2 |
| `counterfactual` | str | `""` = 无 | 仅 `data` | §3.2 |
| `fix` | str ≤25字 | `""` = 未写 | 仅 `data` | §3.1 |
| `round` | str | `""` = 未标轮次 | `round TEXT` | §3.3 |
| `kp_id` | str | 由 `kpid.py` 派生 | `kp_id TEXT` | §3.3 |
| `knowledge_ref` | str | `""` = 无出处 | 仅 `data` | §3.1 |
| `verified` | bool | 默认 `False` | 仅 `data` | §3.1 |
| `source_tier` | str T0-T3 | `""` = 未标 | 仅 `data` | §2.3 |

**JSONL 兼容**：《总纲》§3.1 的 JSONL schema 与上表一一对应，`error_ingest.import_jsonl()`
直接映射，`options` 由 dict 转 list（现 MedKit 是 list）——**这是唯一的格式转换点**。

#### D2 · `KpAlias`（知识点 ID 对齐，新表 `kp_alias`）

```
id TEXT PRIMARY KEY            -- kp_id
data TEXT NOT NULL
subject TEXT, chapter TEXT, topic TEXT
canonical TEXT                 -- 归一后的规范名
created_at TEXT
```

用途：同一考点在三轮里的不同表述（"心输出量"/"心排出量"/"CO"）归一到同一个 `kp_id`。
**入库时先查别名表，命中则复用 ID；未命中则新建并登记。**

#### D3 · `ErrorEvent`（纵向追踪，新表 `error_events`，append-only）

```
id TEXT PRIMARY KEY
data TEXT NOT NULL
kp_id TEXT, round TEXT, error_tag TEXT, is_correct INTEGER, occurred_at TEXT
```

与 `mistakes` 的关系：`mistakes` 是**当前快照**（可编辑），`error_events` 是**不可变流水**
（每轮每次作答一条）。跨轮次迁移矩阵从流水算，不从快照算——**因为快照会被用户改，
流水不会**（这是保证 §3.3「三轮对齐」可信的前提）。

#### D4 · `CalibrationBucket` / `MetaStats`（纯计算，不落表）

```python
# core/metacog.py — 全部纯函数，无 IO，便于注入式测试
def calibration(cards, *, field="confidence", n_bins=5) -> list[Bucket]
def brier(cards) -> float                    # mean((conf/5 - is_correct)²)
def m_ratio(cards) -> float                  # 元认知效率
def migration_matrix(events, kp_ids) -> Matrix  # 跨轮次 tag 迁移
def jol_bias(cards) -> float                 # 学习判断偏差
```

**取舍依据**：不落表是因为这些指标随查询口径变化（全量/近一月/单科），落表就要处理缓存失效；
错题量级在万级以下，实时算的成本可忽略（对比 `library.py` 实测：SQL 轨单条写入 0.3ms）。

### 2.4 前端加载顺序契约（硬约束）

`test_v15_frontend_split.py` 规定：单文件 ≤800 行 / `index.html` 中每族恰好一次且族内有序 /
**加载期不得跨片前向引用**（经典脚本无 ESM，函数提升只在同片生效）。

新增 3 片，**必须插在正确位置**：

```
<script src="/assets/js/app.js"></script>          ← 基础
<script src="/assets/js/md.js"></script>
...（现有复习台族）...
<script src="/assets/js/review-meta.js"></script>       ← 新增①：录入台/复盘台（可用 app.js 的 fetch 封装）
<script src="/assets/js/review-meta-stats.js"></script>  ← 新增②：校准曲线/热力图（仅被①的事件调用）
<script src="/assets/js/review-meta-io.js"></script>     ← 新增③：JSONL/Anki 导入导出
```

**纪律**：加载期（顶层）只允许定义函数与常量；所有跨片调用必须发生在事件回调里。
**若某函数在加载期被调用，它必须与调用方同片或更早片**——这是本项目历史上踩过的坑。

## 3. 五条核心流程重设计

### 3.1 错题录入（《总纲》§3.1）

```
[截图/粘贴/语音]
      ↓
① 题干落地（OCR 或直接粘贴）——可延后
② 【当场必填】confidence 1-5  ← 闸门：不填无法进入下一步，且无补填接口
③ 【当场必填】my_answer + my_reasoning(≤120字，语音可转写)
      ↓  ← 此处状态 = "locked"，前端禁用"看答案"按钮
④ 用户输入 correct（红线：AI 不给正确答案）
⑤ 事后可补：error_tag（6 选 1）、fix(≤25字)、knowledge_ref
      ↓
⑥ 落库 → 触发 error_events 一条 → 可选触发归因层
```

**注入式验收点**（可证伪）：
- `test_meta_gate.py`：构造 `confidence=None` 的 card，断言 `can_reveal_answer()` 返回 `False`；
  **并断言 API 层不存在"补填 confidence"的端点**（扫路由表，命中即红）。
- `test_meta_40s.py`：计时埋点，从录入开始到落库 >40s 时前端给警示（软提示，不阻断）。

**取舍**：§2.4「刻意保持难用」→ 这里**故意不做批量快速录入的快捷键自动填充**。摩擦是产品特性。

### 3.2 题目解析（《总纲》§3.2）

```
ErrorCard (locked/complete)
      ↓
attribution.py 组装 prompt（error_analysis.md）
      ↓  LLM（复用 core/llm.py + 现有 Key 配置）
ErrorAnalysis 契约校验（schema.py，失败重发1次→None 走人工）
      ↓
落回：ai_error_tag · counterfactual · fix(若用户未写) · 建议回看章节
      ↓
比对：tag_match = (error_tag == ai_error_tag)   ← 不一致 = 最高价值样本
      ↓
counterfactual 非空 → cards.py 生成检验卡（source="counterfactual"）→ FSRS 调度
```

**红线守卫**：`error_analysis.md` 的 prompt 必须含"正确答案由用户提供"约束；
`test_prompt_contracts.py` 增加断言——prompt 中**不得出现"请判断正确答案"类指令**（剥注释后扫）。

**取舍**：AI 只做"解释与定位"，不做"判对错"。这牺牲了"自动判分"的便利（竞品都有），
换来的是归因可信度——《总纲》§4.4 明确指出这正是商业产品不敢做的空位。

### 3.3 知识点归类（《总纲》§2.3、§3.3）

```
录入时：subject + chapter + topic
      ↓
kpid.resolve(subject, chapter, topic)
      ↓  ① 查 kp_alias 精确命中 → 复用 kp_id
      ↓  ② 归一后命中（去空格/别名/中英同义）→ 复用
      ↓  ③ 未命中 → 新建 kp_id = sha1(subject|chapter|canonical)[:16]，登记别名
      ↓
每轮录入都带 round（早鸟轮/跟课轮/强化轮/冲刺轮）
      ↓
error_events 累积 → migration_matrix() 算三轮迁移
```

**判据**（§3.3）：若某 kp_id 三轮 tag 相同 → 修补动作无效，前端标红提示"换方法"；
若 tag 发生迁移（机制混淆→记忆偏差）→ 上一轮修对了方向，正常。

**取舍**：不做自动语义聚类（不用 embedding 自动归并考点）。
理由：§2.4「绝不把机构讲义整批灌进向量库」，且自动归并一旦出错会**污染纵向档案**（不可逆损失）。
人工确认别名表的成本远低于错归的代价。

### 3.4 错题复习（《总纲》§3.2 苏格拉底模式 + §5.1 闪卡）

```
① 常规间隔重复：复用 core/review.py + scheduler.py(FSRS)
   来源扩展：mistakes（错题本体）· cards（反事实题）· knowledge（知识点）

② 苏格拉底复习（新增）：复习同一题时不直接给解析
   先问：「你现在认为正确选项是哪个，为什么？」
   → 用户答 → tutor 判断是否真懂 → 才给解析
   复用 core/tutor.py 现有提问机制，新增 socratic_review.md 提示词

③ 反事实检验：counterfactual 卡按 FSRS 调度，答对才算真懂
```

**取舍**：苏格拉底模式**不设为默认**。理由：它把单题复习时间拉长 3-5 倍，
在"刷题量"优先的阶段（早鸟轮）是负收益；应在强化轮/冲刺轮对**高价值题**
（`tag_match=0` 或 `confidence=5 但做错`）自动启用。**这是分阶段策略，不是全局开关。**

### 3.5 统计分析（《总纲》§3.3，四条指标 + 减法清单）

| 指标 | 输入 | 算法 | 干预动作 | 输出 |
|---|---|---|---|---|
| 校准曲线 | confidence × is_correct | 按 conf 分 5 桶算正确率 | conf=5 正确率<90% → 强制写 my_reasoning | 折线 + 表 |
| Brier 分数 | 同上 | `mean((conf/5 - correct)²)` | 月度追踪趋势 | 单值 + 趋势 |
| 标签×科目热力图 | error_tag × subject | 5×6 矩阵计数/占比 | 发现"生化全记忆偏差/生理全机制混淆" | 热力图 |
| 跨轮次迁移 | kp_id × round × tag | 迁移矩阵 | 同 tag 三轮不变 → 标红换方法 | 矩阵 + 警示 |
| 减法清单 | 章节题数 × 正确率 × 频次 | 加权排序取末位 | 标"本周不排" | 清单 |

**复用点**：热力图的 subject 维度已有 `library.get_mastery_view()`；
减法清单的"频次"数据来自现有 `realexam_freq` 表（**这是生成链留给新内核的最有价值资产**）。

## 5. 方案对比与取舍依据

### 5.1 三条路线

| | **A·原地改造** | **B·新建内核复用基建**（本方案推荐） | **C·完全重写** |
|---|---|---|---|
| 做法 | 在现有 MedKit 上加元认知层 | 复用 db/scheduler/render/llm，新建错题内核，生成链降为插件 | 弃 MedKit，从零写 |
| 复用率 | 100% | ~65%（数据层+调度层+渲染层+LLM 层） | 0% |
| 现有测试 | 全部要改（因为动了主入口） | **大部分零改动**（新增路由 + 可空字段） | 全部作废 |
| 风险 | **生成链与新内核耦合**，改一处双向震荡 | 边界清晰，可回滚到 v0.10.5 | 重复踩 MedKit 已填的坑（双轨存储/加载顺序/沙箱守卫） |
| 周期 | 中 | 中 | 长 |
| 与《总纲》§2.1 一致性 | 差（生成链仍是主入口，注意力被拖走） | **好**（入口即错题，生成链退居二线） | 好 |
| 与 §2.4「做成管道不做平台」 | 中 | **好** | 好 |

**推荐 B，依据三条**：

1. **复用率高且边界天然清晰**。《总纲》§2.4 要的"输入端兼容 PDF/截图/Anki/JSONL / 输出端
   markdown/APKG/CSV"—— MedKit 的 `core/llm.py`（Key 配置）、`core/review.py`+`scheduler.py`
   （FSRS）、`render/apkg.py`（APKG 导出）、`core/fsutil.py`（原子写）**已经全部具备**。
   从零写 C 路线等于重造这四块。
2. **回归风险可控**。§4.3 的接口策略（只新增、字段全可空）保证现有 ~95 个测试文件
   中绝大多数无需改动 → 可以用"现存测试全绿 + 新测试覆盖新功能"作为验收判据。
3. **A 路线的致命问题**：`orchestrator.py` 1533 行是 MedKit 的主动脉，一旦让新内核
   从它内部长出来，两边会争抢 `main.py` 启动路径与 `config.json`。**B 路线通过"降级主入口"
   一刀切开**，代价只是侧栏顺序调整。

### 5.2 逐项取舍依据表

| 决策点 | 选择 | 放弃的方案 | 依据 |
|---|---|---|---|
| confidence 是否可补填 | **否** | 可补填（体验好） | §3.4 硬约束："不许事后补"，摩擦保证数据真实性 |
| 归因是否让 AI 判对错 | **否** | AI 自动判分 | §3.2 红线；且这是竞品不敢做的差异点（§4.4） |
| 知识点归类 | **人工确认别名表** | embedding 自动聚类 | §2.4 禁灌讲义入向量库；错归会污染不可逆档案 |
| 苏格拉底模式 | **高价值题才默启** | 全局默认 | 时间成本 3-5×，早鸟轮是负收益 |
| 统计是否落表 | **实时算** | 物化视图 | 数据量万级，落表引入缓存失效复杂度 |
| 纵向追踪用快照还是流水 | **流水（error_events）** | 复用 mistakes 快照 | 快照可被用户编辑 → 迁移矩阵失真 |
| 生成链 | **降级不删除** | 删除 | §2.1 停手信号；删除需重算前端家族顺序，风险>收益 |
| JSONL 出口 | **作为唯一备份格式** | 只用 SQLite | §2.4 输出端通用格式；且用户数据不可再生（§4.3）需可携带 |
| 网络检索 | **默认关闭** | 保持默认开 | §2.4 离线优先（医院/图书馆网络） |
