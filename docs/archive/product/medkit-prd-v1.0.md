## 2. 项目背景与目标

### 2.1 项目背景

MedKit 是一款面向医学生的本地化 AI 题库生成工具。用户可上传自备教材 PDF 和教师重点，通过 AI 自动生成题库、押题卷、复习手册和 Anki 卡片包。当前版本（v0.8.0）已具备完整的五阶段出题管线（MedGen → 门禁 → MedQC → MedFix → MedReview）、学习中心（错题本/掌握度诊断/复习计划/大纲覆盖/真题考频/薄弱组卷）、多服务商 AI 接入等能力。

### 2.2 核心问题

经过用户使用反馈和自查，当前产品存在以下核心问题：

- **按钮过多，功能堆砌**：首页平铺了「导入题库」、「设置」、「统计」、「练习模式」等大量入口，用户打开后不知从何下手，认知负荷高。
- **功能复杂，学习成本高**：出题管线的五阶段配置（题型配比/Bloom层级/难度旋钮等）对普通医学生过于复杂，新手引导不足以消化。
- **缺乏场景化设计**：未针对「期末考试」和「考研」两个核心场景做差异化设计，所有用户面对相同的界面和流程。
- **刷题体验不佳**：刷题界面交互方式不够沉浸，缺乏卡片式翻转、即时反馈、滑动操作等现代学习产品的交互设计。

### 2.3 产品目标

核心目标：将 MedKit 从「功能堆砌的工具」转型为「医学生期末/考研的高效刷题利器」。

| 目标 | 说明 |
|---|---|
| 做减法 | 简化首页和导航，减少按钮数量，让用户「打开就能用」 |
| 场景化 | 针对「期末突击」和「考研冲刺」两种场景提供差异化体验 |
| 沉浸式刷题 | 借鉴 Anki、医考帮、墨墨背单词等成熟产品的设计 |
| 降低认知负荷 | 默认配置智能化，高级选项折叠隐藏 |

## 3. 用户画像与场景

### 3.1 用户画像

| 维度 | 期末复习型用户 | 考研备考型用户 |
|---|---|---|
| 使用场景 | 考试前1-2周集中复习 | 考前6-12个月持续备考 |
| 核心需求 | 快速过重点、刷真题、查漏补缺 | 系统记忆、反复复习、追踪进度 |
| 时间特点 | 时间紧迫，功利性强 | 时间相对充裕但需长期坚持 |
| 功能偏好 | 速刷模式、重点提炼、错题本 | 艾宾浩斯复习、真题标记、掌握度分析 |
| 技术能力 | 一般，希望简单易用 | 较高，可接受一定配置 |

### 3.2 核心使用场景

**场景一：期末突击**
1. 用户上传教材 PDF + 老师给的复习重点
2. 选择「期末速通」预设配置
3. 一键生成题库和押题卷
4. 进入速刷模式，像刷抖音一样上下滑刷题
5. 做错的题自动进入错题本
6. 考前最后一天只看错题和背诵清单

**场景二：考研系统备考**
1. 选择「考研西综强化」预设配置
2. 上传教材和历年真题
3. 系统按艾宾浩斯记忆曲线推送每日复习任务
4. 每天打开 App 直接看到「今日待复习 XX 题」
5. 刷题时点击翻转看答案和解析
6. 每周查看掌握度报告和薄弱点清单
7. 考前用薄弱点组卷功能针对性刷题

| Notion | 标签化组织；块级编辑；简洁的视觉风格 | 标签化 + 简洁视觉 |

## 5. 产品定位

MedKit 是一款面向医学生的 AI 驱动本地化刷题工具，以「少即是多」为设计理念，针对期末复习和考研备考两大场景，提供沉浸式刷题体验。

核心设计原则：

| 原则 | 说明 |
|---|---|
| 少即是多 | 首页只保留「今天该做什么」，按钮藏起来，题目亮出来 |
| 场景先行 | 期末和考研两种模式，默认配置自动适配 |
| 无脑工具 | 打开就能刷，不需要思考「该点哪个按钮」 |
| 本地优先 | 所有数据保存在本机，隐私安全 |

## 6. 功能规划

### 6.1 首页重构（仪表盘）

目标：解决「按钮太多」的核心问题，让用户打开 App 就知道该做什么。

| 元素 | 说明 | 优先级 |
|---|---|---|
| 今日待复习数 | 根据 SM-2/FSRS 算法计算今日需复习的题目数 | P0 |
| 今日新题数 | 今日可学习的新题目数 | P0 |
| 倒计时 | 距离考试/考研的天数（用户可设置） | P1 |
| 主按钮 | 一个巨大的「开始学习」按钮，点击进入刷题 | P0 |
| 快捷入口 | 底部小字链接：错题本 / 查看 / 设置 | P2 |

交互说明：
- 首页仅展示以上信息，不展示任何功能按钮
- 「开始学习」按钮为页面视觉焦点（大尺寸、强调色）
- 点击后根据用户设置自动进入「今日复习」或「新题学习」

### 6.2 导航栏精简

目标：将复杂功能收纳到层级化导航中。建议底部导航栏（4 个 Tab）：

| Tab | 名称 | 内容 |
|---|---|---|
| 1 | 学习 | 刷题界面（核心） |
| 2 | 题库 | 科目选择、题目列表、搜索筛选 |
| 3 | 统计 | 记忆曲线、掌握度分析、考试模拟成绩 |
| 4 | 我的 | 设置、数据导入导出、主题切换 |

各 Tab 详情：

- **Tab 1 - 学习**：默认展示「今日任务」卡片（待复习 + 新题）；点击「开始学习」进入刷题界面；刷题过程中可侧滑查看题目详情/解析
- **Tab 2 - 题库**：按科目/章节组织题目；支持关键词搜索、题型过滤、Bloom 层级过滤；支持按掌握程度筛选（已掌握/未掌握/模糊）
- **Tab 3 - 统计**：记忆曲线图（复习趋势）；各科目掌握度百分比；考试模拟成绩历史（最近 10 次）；薄弱知识点清单
- **Tab 4 - 我的**：AI 服务商配置；素材库管理；数据导入导出；主题切换；版本更新检查

### 6.3 场景化功能

#### 6.3.1 期末速通模式

触发方式：首页选择「期末模式」或预设配置中选择「期末速通」

| 功能 | 说明 | 优先级 |
|---|---|---|
| 速刷模式 | 全屏卡片式刷题，上滑下一题，左滑标记「不认识」，右滑标记「认识」 | P0 |
| 重点提炼 | 从复习手册中提取高频考点，生成「考前必看清单」 | P1 |
| 只看错题 | 一键过滤只显示错题和收藏题 | P0 |
| 限时模考 | 模拟考试时间，计时答题，交卷后自动判分 | P1 |
| 倒计时提醒 | 首页显示距离考试的倒计时 | P2 |

#### 6.3.2 考研冲刺模式

触发方式：首页选择「考研模式」或预设配置中选择「考研西综强化」

| 功能 | 说明 | 优先级 |
|---|---|---|
| 真题标记 | 每道题标记年份（如「2023年西医综合真题」），真题优先推送 | P0 |
| 艾宾浩斯复习 | 基于 SM-2/FSRS 算法自动推送复习任务 | P0 |
| 每日任务量 | 设定每日新题+复习目标，系统自动安排 | P0 |
| 掌握度追踪 | 按知识点/章节追踪掌握程度，可视化展示 | P0 |
| 薄弱点组卷 | 根据薄弱知识点自动生成专项练习题 | P1 |
| 考频分析 | 基于自备真题的考频统计，高频率考点优先 | P1 |

### 6.4 刷题交互优化

目标：借鉴 Anki 和医考帮的设计，打造沉浸式刷题体验。

#### 6.4.1 卡片翻转设计

| 交互 | 说明 |
|---|---|
| 正面 | 显示题目（题干），底部显示选项（选择题） |
| 翻转 | 点击卡片翻转，显示答案+详细解析 |
| 解析折叠 | 解析默认展开，可折叠收起 |
| 关键词高亮 | 解析中的关键词（如「首选药」、「金标准」）加粗标红 |

#### 6.4.2 底部操作按钮

刷题界面底部仅保留 3 个按钮：

| 按钮 | 颜色 | 效果 |
|---|---|---|
| 忘记/错误 | 红色 | 加入复习池，明天再考 |
| 模糊/不确定 | 黄色 | 加入复习池，10分钟后重考 |
| 掌握/简单 | 绿色 | 根据算法安排下次复习时间 |

#### 6.4.3 即时反馈

| 场景 | 反馈方式 |
|---|---|
| 答错 | 震动反馈 + 红色提示 + 自动进入复习队列 |
| 答对 | 绿色提示 + 平滑动画 |
| 切换题目 | 平滑过渡动画 |

### 6.5 保留但折叠的高级功能

以下功能不删除，但收纳到「我的 > 高级设置」中，避免干扰核心体验：

| 功能 | 说明 |
|---|---|
| 出题管线配置 | 题型配比、Bloom 层级、难度旋钮等详细配置 |
| 提示词编辑器 | 查看和编辑内置提示词 |
| 素材库管理 | 素材会话的创建、合并、导入导出 |
| 数据管理 | JSON/SQLite 导入导出、备份恢复 |
| 网络检索设置 | 搜索后端配置、URL 过滤规则 |

## 7. 视觉设计规范

### 7.1 设计原则

- 大量留白：不要填满页面，给内容呼吸空间
- 颜色克制：不超过 3 种主色（白底、黑字、一种强调色如青绿色）
- 字体清晰：使用易读的无衬线字体
- 层级分明：通过字号递减 + 字重 + 颜色建立清晰的信息层级

### 7.2 配色方案

| 元素 | 颜色 | 色值 |
|---|---|---|
| 背景 | 白色 | #FFFFFF |
| 正文 | 深灰 | #2E3440 |
| 强调色 | 青绿 | #2A6B5A |
| 错误 | 红色 | #E15759 |
| 警告 | 黄色 | #EDC948 |
| 成功 | 绿色 | #59A14F |
| 辅助文字 | 中灰 | #6B7280 |

### 7.3 字体规范

| 元素 | 中文字体 | 字号 | 字重 |
|---|---|---|---|

### 8.2 用户操作流程

**流程一：首次使用**
打开 App → 3 步欢迎向导（软件介绍→API Key 配置→开始使用）→ 首页展示「开始学习」按钮 → 点击「开始学习」→ 进入题库选择科目 → 选择科目 → 开始刷题

**流程二：日常刷题**
打开 App → 首页看到「今日待复习 200 题」→ 点击「开始学习」→ 卡片式刷题 → 翻转看答案 → 选择掌握程度 → 全部完成 → 返回首页

**流程三：期末突击**
打开 App → 切换到「期末模式」→ 上传教材+重点 → 选择「期末速通」预设 → 一键生成题库 → 进入速刷模式 → 快速过题 → 只看错题 → 查漏补缺

## 10. 风险评估

| 风险 | 描述 | 应对策略 |
|---|---|---|
| 功能裁剪争议 | 用户可能依赖被折叠的复杂功能 | 保留高级设置入口（折叠在「我的」中），不彻底删除 |
| 技术债务 | 现有代码架构可能不支持新的交互模式 | 评估是否需要前端框架重构，必要时分阶段迁移 |
| 用户习惯 | 老用户可能不习惯新的导航方式 | 提供「经典模式」切换选项，逐步引导 |
| 开发资源 | 单人开发，功能量大 | 严格按优先级排期，先做 P0 功能 |
| AI 依赖 | 刷题体验依赖 AI 响应速度 | 优化缓存策略，本地预处理 |
