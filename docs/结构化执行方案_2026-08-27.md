## 0. 执行原则（先立规矩）

1. **零后端不变**：所有新增能力仍走「本机存储 + 用户 BYOK LLM」，不引入账号/云端。
2. **成本护栏不变**：凡生成式 LLM 调用，前端先出成本预估 toast、后端按次记账（复用 `/api/cost/estimate` + `usage.context`）；聚合/判定/调度一律本地零 LLM。
3. **不携带旧产物质料不变**：真题、教材图、大纲皆「用户自备、本机存储」；真题防照抄硬约束（`agents/medgen.py` v0.5.2 注释）继续生效。
4. **可回滚**：每个 WP 独立 feature flag（**新建** `core/state.py` FLAG + 前端 feature 常量——学习中心先例为 sessionStorage 视图记忆而非 flag，属全新机制），出问题即关。
5. **先 SPIKE 后落地**：任何新依赖/新技术底座先做 1 天以内的可行性验证（见 S0），通过才进主线。
6. **数据永远可退**：任何 schema 变更前自动备份 `~/.medkit/`（复用 `library.heal_encoding` 的 `pre-heal-*.bak` 模式）。

## 3. S1 · v0.8.0 考试锚定（WP-01 ~ WP-04）

### WP-01 大纲覆盖度引擎

**用户价值**：回答「这章 40 个考点，我出了几题/掌握了几项/还差什么」，这是 306 备考的第一刚需；同时给组卷和备考指数提供锚。

**成熟案例对标**：
- NCLEX-RN Test Plan（公开蓝图，按类别给 % 权重）→ 大纲条目带「权重列」，覆盖度报表按「考点权重 × 掌握缺口」排序；
- USMLE content outline / 306 大纲（[新东方 306 大纲](https://mtoutiao.xdf.cn/kaoyan/202511/15003976.html)）→ 考试锚定的公开事实来源；
- 医考帮类 App 的「考点章节树」→ 前端交互形态（章 → 条目 → 状态打勾）。

**数据模型**（`core/syllabus.py` + `~/.medkit/library/syllabus.json` 或 SQLite 表 `syllabus_items`）：

```
{syllabus_id, exam: "考研306-2026", subject, chapter, item, weight: 1.0,
  source: "paste"|"parser"|"mineur", status: "pending"|"covered"|"mastered", topics: [kp_id…]}
```

**范式（两种输入，人工确认门）**：
- ① 粘贴文本/条目（首版主力，SPIKE K3 不达标时的保底）；
- ② PDF 走既有 MinerU → md → LLM 抽取条目（`chat_json` + schema 校验，复用 D3），预览确认后入库。

**API**（`routers/syllabus.py`，挂 `/api/syllabus/*`）：
- `POST /api/syllabus/parse`（文本/文件 → 条目草稿，预览用，一次 LLM）
- `PUT /api/syllabus/confirm`（用户确认 → 落库；条目可改可删）
- `GET /api/syllabus`（按 exam/subject 分组树）
- `GET /api/library/coverage?pid=&subject=` → `{chapter, items_total, items_covered, items_uncovered[], mastery:{weak,shaky,…}}`（本地 join，零 LLM）
- `GET /api/library/coverage/report` → 全部未覆盖条目清单（导出 md，充当「考前清单」）

**接入出题**：`agents/medgen.py` 增加 `syllabus_text` 注入（≤800 字，与 teacher 同通道）；`prompts/medgen.md` 要求 `subtopic` 尽量对齐大纲条目短语；`gates/trace_check.py` 增加「无法对齐任何一条且切片无此内容 → soft flag 进人工复核清单」（不自动剔除，D3 兜底语义）。

**任务分解**：T1 data/迁移表；T2 parse+confirm 路由与 schema；T3 coverage 本地聚合（现 library 数据 join）；T4 medgen 注入 + 校验；T5 前端「考试锚定」视图（挂在学习中心概览下新增子区或第 6 个 tab：「大纲覆盖」：树 + 打勾 + 未覆盖清单 + 一键生成缺章题）；T6 导出 md。

**验收**：粘贴 306 呼吸系统大纲 → 出 20 题 → 覆盖报表与人工核对一致；掌握覆盖随学习中心实时更新；成本：parse 一次 LLM 调用，其余零 LLM。

**风险/回退**：大纲条目与 subtopic 对齐不稳 → 报表提供「手动关联」（条目↔错题/知识点手选）；flag 关闭即回退为无大纲模式。

### WP-02 真题考点频次分析（把「自备真题」升级为量化器）

**用户价值**：真题高频考点 = 押题权重；当前只做 prompt 内「高频考点优先」口头约束，学生看不到「哪 20 个考点被考过 5 次」。

**成熟案例对标**：
- 医考帮/蓝基因的「真题分章 + 考点频次」是题库 App 标配；本项目定位差异 = 「**自动**从自备真题提取频次 + 驱动个性化出题」；
- wttwins/wrong-notebook：AI 打标 + 人工确认 → 结构化（参考其「预览-确认」交互）。

**数据模型**（`~/.medkit/library/realexams.json` 或 SQLite 表）：

```
{exam_year, chapter, topic, freq, type: "A1|A2|B1|X", first_seen, source: "自备真题",
  confirmed: bool   // 人工确认门
}
```

**流程**：
1. `POST /api/library/realexams/analyze`（`core/realexams.py`）：自备真题全文 → 一次 LLM（`chat_json` + schema `RealexamItem[]`）→ 返回 **频次草稿**（按原文出现次数计，LLM 只做考点归一 → 本地计数，防 LLM 计数幻觉）；
2. 人工确认页：表格改错/合并 → `POST /confirm` 落库；**未确认数据不进入任何权重**（红线）；
3. 权重接入：
   - `core/library.py compute_priority` 增加 `+ w_freq * (1 - norm_freq)`（默认 `w_freq=0.15`，可调）；
   - 出题配额（`core/orchestrator.py` 切片配额公式）：「教师重点词频」与「真题考频」并列，新增旋钮 `真题考频权重 0~30%`（复用 KNOB 通道，默认 0 保持现状兼容）;
4. 可视化：`GET /api/library/realexams/freq?subject=` → 章节×频次热力表 + 导出 md（仅展示频次与条目，**不展示真题原文**）。

**任务分解**：T1 抽取 + schema；T2 人工确认 UI（复用审核台表格模式）；T3 权重接入（priority + orchestration 旋钮）；T4 热力表 + 导出。

**验收**：导入 5 年真题 → 频次表与人工统计误差 ≤20%（确认后即修正）；`考研西综强化` 预设出题时高频章节题量上浮且默认旋钮为 0（显式开启才生效）。

**风险/回退**：LLM 归一偏差 → 确认门 + 频次本地计数兜底；防照抄红线不变（仅展示频次，不展示原文）。

### WP-03 缺陷驱动智能组卷（「一键刷我的薄弱点」）

**用户价值**：从「推荐列表」到「今天练什么」的一键闭环——考研最高效节奏是「薄弱 → 针对性重练 → 回流」。

**成熟案例对标**：
- AMBOSS Adaptive Question Sessions（薄弱主题 → 自适应出题队列）；
- 项目自身 `gap_killer` 预设（错题重练二轮）+ `recommend()`（`core/library.py`）——把已有件串起来，**不新建生成引擎**。

**API**：`POST /api/library/gap-paper` → `{subject, question_count=50, use_syllabus=true}`
1. 本地配题：`recommend()` 取 top-N 知识点 → 题量 ∝ `priority × (大纲未覆盖权重)`（依赖 WP-01），单知识点 ≤3 题；
2. 复用既有课题创建 + 管线：内部调用 `routers/projects.py` 创建临时课题（标记 `scope: "gap"`），沿用断点/取消/成本预估全链路；
3. 产物自动绑定：卷面标注「本次针对：薄弱点清单」；判错后既有 `sync-paper` 自动回流（零新代码，闭环转起来）。

**任务分解**：T1 gap-paper 配题算法（纯本地，单测覆盖）；T2 复用课题创建通道（含 scope 标记与 meta 记录）；T3 前端「概览 → 一键刷薄弱」入口 + 成本 toast；T4 回流闭环确认（浏览器测试）。

**验收**：3 次点击完成「薄弱点 → 卷 → 判错 → 回流错题本」；生成前成本预估可见；重复点击不产生重复课题（幂等去重）。

**任务分解**：T1 slice image 字段 + 素材清单 UI 附图上传；T2 medgen 图题干规则 + image_ref 校验；T3 渲染器 img/table + 打印；T4 错题拍图（已有 OCR）产物完善（图随题入错题本）；T5 打包/体积验证（K4）。

**验收**：传教材插图 → 出 1 道引用该图的题 → 题库/押题卷/复习手册 HTML 显示正常、打印正常；表格题以 table 呈现；无图项目零回归（字段可选）。

## 4. S2 · v0.9.0 学习闭环深化（WP-05 ~ WP-08）

### WP-05 记忆卡工厂 + FSRS

**用户价值**：学生背的医学卡是数值卡/口诀卡/鉴别表卡，不是刷题卡；把讲解产物与复习手册「变成可背的卡」。

**成熟案例对标**：
- Anki + [FSRS（open-spaced-repetition/fsrs）](https://github.com/open-spaced-repetition/fsrs)（默认调度，含 fsrs-optimizer 调参）；[FSRS vs SM-2 指南](https://memoforge.app/blog/fsrs-vs-sm2-anki-algorithm-guide-2025/)；
- [Anki 医学教育系统评价](https://link-hkg.springer.com/content/pdf/10.1007/s40670-026-02643-5.pdf)（正效果 + 学习理论一致性）。

**数据模型**（SQLite 表 `cards`，关联既有 `review_cards`）：`card_id, kp_id, kind: value|mnemonic|contrast|concept, front, back, source: "explain"|"handbook", created_at`

**流程**：
1. `POST /api/library/explains/{id}/cards`（`core/cards.py` + `agents/medcards.py`）：讲解四段（结论/机制/鉴别/锚点）→ 3~6 张卡（一次 LLM，schema 校验，人工可编辑）；复习手册五层（考点速记/易混淆/数值速查/背诵清单）同法生成；
2. 卡入队：`review_queue` 按 `kp_id` 关联（既有 grade → `record_review` 回写掌握度链路**零改动**）；
3. **Scheduler 协议**：`core/scheduler.py`（`schedule(card, quality, now) -> next_due/ease/interval`）；实现 A：py-fsrs（默认）；实现 B：SM-2（legacy 可切，保证老卡不废）；迁移函数幂等（K2）；
4. Anki 导出扩展：`render/apkg.py` 支持「刷题卡包 / 记忆卡包 / 混合」，标签加 `card_kind`（`render/apkg.py` 既有稳定哈希命名不动）。

**任务分解**：T1 schema + cards 表；T2 生成 agent + 人工编辑 UI；T3 Scheduler 协议 + fsrs + 迁移；T4 apkg 扩展。

**验收**：一篇讲解 → 3 张卡 → 入队 → 今日可答 → quality 回写掌握度；FSRS/SM-2 切换后队列不丢、可回滚；freezegun 冻结时钟单测全绿。

**风险/回退**：卡质量不稳 → 人工编辑 + 单卡删除；FSRS 数值异常 → 保留 SM-2 实现一键切回。

### WP-06 临床技能：病史采集模拟 + 病例分析批改

**用户价值**：执医技能第一站 + 考研复试面试；对话式 LLM 恰擅长，且复用 tutor 引擎成本极低。

**成熟案例对标**：
- [atultiwari/medkit-app（语音优先 AI 病人模拟器）](https://github.com/atultiwari/medkit-app)——形态参考（对话式问诊 + 评分）；
- [KI-gestützte Patientensimulation（德国医学教育虚拟问诊）](https://thieme-connect.com/products/ejournals/abstract/10.1055/s-0045-1810662)；
- 项目自身 `core/tutor.py` 会话状态机（加 `kind: "history"` 即可复用）。

**设计**（`core/tutor.py` 扩展 + `agents/medclin.py` + 新 prompt `medclin.md`）：
- **病史采集**：AI 扮演患者（依据切片主诉模板应答，严格「不主动给齐信息、不引导性提问回应」）；学生问诊结束 → `POST /api/library/clin/score` → 评分卡：`{dim: [问诊要素覆盖/鉴别追问/术语/效率], score, max, note}[]` + 漏点清单（LLM 判分 + 本地规则兜底：需覆盖 ≥N 个要素，要素表用户可编辑，默认对齐诊断学教材）；
- **病例分析**：输入病例摘要（可复用 A3 案例素材）→ 学生输出「诊断+依据+鉴别+检查+治疗」→ AI 红笔批改（按得分点计分，输出「漏点/过度诊疗」）；
- 产物：`clinical_runs.json`（SQLite 表），可回看/重练；前端学习中心第 6 子视图「临床技能」；成本预估前置（每轮/每次批改按次记账）。

**任务分解**：T1 tutor kind 扩展 + 会话隔离；T2 medclin prompt + 评分 schema；T3 本地要素兜底规则；T4 前端对话流 + 评分卡展示；T5 病例分析批改。

**验收**：一个问诊会话完整跑通出评分卡；批改能识别「漏了过敏性休克抢救」类扣分点；断网时走本地要素检查不崩。

**风险/回退**：患者应答越界（替学生说答案）→ prompt 硬约束 + 评分卡「患者合规性」维度；判分过严/过松 → rubric 明确 + 记录分分布可调阈值（沿用 `medtutor.py` 的 -1 不计分兜底模式）。

### WP-07 统计洞察（从正确率升级为学习分析）

**用户价值**：学生要三个数——「哪个系统最弱」「总错在哪类错因」「我大概什么段位」。

**成熟案例对标**：
- AMBOSS Knowledge Profile（主题级熟练度 → 驱动自适应）；
- flutter_learning_analytics（掌握度/遗忘曲线/热力日历）+ MCAT dashboard（逐科正确率/错题加权）——视觉形态。

**设计**（`core/insights.py`，全部本地聚合，零 LLM）：
1. **系统/器官聚合**：章节名规范化映射（内科→呼吸/循环/消化…），提供规则表 + 用户手动归并（`chapter_alias.json`）；
2. **错因分析**：`error_reason` 聚合 → 「40% 概念混淆、30% 数值记忆」+ 行动建议（混淆→讲解鉴别；数值→铺数值卡）；
3. **易混对挖掘**：同 `kp_id` 下错误选项分布 top → `{正确项, 误选项, 次数}` → 一键「生成易混辨析卡」（接 WP-05）或「生成 B1/X 对比题」（接 WP-03）；
4. **备考指数**：`y = f(大纲覆盖度, 薄弱集中度, 近期正确率趋势, 距考试天数)`（依赖 WP-01/02），0~100 + 可解释拆解 + 每日历史 → 趋势线。

**API**：`GET /api/library/insights?subject=`；前端「概览」升级为洞察卡组（重灾区/错因/易混对/备考指数）。

**任务分解**：T1 章节别名 + 聚合查询；T2 错因分布；T3 易混对挖掘；T4 备考指数 + 历史；T5 前端洞察卡组。

**验收**：5 分钟内看懂「重灾区+错因+该做什么」；易混对与人工抽样一致率 ≥60%；指数每日更新可解释。

### WP-08 每日学习计划与阶段规划（对抗「记忆量大 + 实习冲突」）

**用户价值**：医学生最缺「今天该干什么」的确定性；短时高频 + 计划性是复习科学的落点。

**成熟案例对标**：
- 间隔重复/交错练习系统评价（Radiology Education SR、Health Competency Exams SR）；
- 习惯打卡类产品的「今日清单」交互（一屏完成 + 连续天数）。

**设计**（`core/plan.py`，零 LLM）：
1. `GET /api/library/plan/today` → 到期卡 N + 建议错题 M + 薄弱讲解 1 + 智能组卷 1（可选）；打勾写 `plan_log.json`（SQLite 表），周报 + 连续打卡；
2. 阶段模板（复用 presets 结构）：基础（教材+大纲全扫）/强化（真题+薄弱）/冲刺（模拟+押题）；每阶段默认日配额；考前 30 天自动收紧（复习量 +1 档、错题优先）；
3. 交错默认：智能组卷默认跨章节交错（interleaving），提供「同章集中/全科交错」开关；
4. 前端：「概览 → 今日」卡片一键开始（手机局域网模式下单页极简——与 WP-11 衔接）。

**任务分解**：T1 plan 聚合 + 模板；T2 plan_log + 打卡周报；T3 交错/集中开关进组卷；T4 前端今日卡。

**验收**：今日清单与「到期卡+薄弱点」一致；连续 7 天打卡出周报；考前 30 天强度自动上调并有提示。
