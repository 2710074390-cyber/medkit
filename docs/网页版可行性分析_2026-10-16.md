# MedKit 网页版可行性分析（2026-10-16）

> 口径说明：本文的「网页版」指**托管多用户的线上版**（区别于现在的本机回环单用户版）。
> 所有端点数字为 2026-10-16 用 `.buildenv/Scripts/python.exe` 内省 `app.routes` 实测
> （129 条 API 路由；记忆中的「110」为旧口径，已过期）。
> 结论先行：**做题闭环 100% 可复现，全量功能约 75% 端点可复现，阻断项是「无用户体系」而非业务代码。**

## 四、阻断性改造点（必做，按工作量排序）

1. **用户体系（零基础）**——全仓无任何登录/会话概念。需新建：注册/登录/会话中间件/用户表。约 500-800 行。
2. **模块级单用户路径常量**——`CONFIG_DIR`（`core/config.py:27`）、`DB_PATH`（`core/db.py:31`）、`vault_dir`/`projects_dir`（`core/config.py:91-92`）全是模块级常量，全仓到处派生。
   **好消息**：测试已证明整体换根可行（`monkeypatch.setattr(cfg,"CONFIG_DIR",tmp)` + `setattr(dbs,"LIBRARY_DIR"/"DB_PATH",...)`，浏览器层由 `tests/browser/server_launcher.py` 重定向）——改造手法是把「模块常量求值」改为「按请求上下文解析」，**每用户一个 SQLite 库即可，无需改 schema 加 user_id**。
3. **回环 Host 守卫中间件**（`main.py:188-221`）——拒绝一切非 127.0.0.1 的 Host，是托管版第一道 403 墙。移除并替换为认证中间件。
4. **DPAPI 密钥**（`core/config.py:126-218`）——绑定 Windows 用户账户；服务端集中存储需换方案。BYOK 语义可保留。
5. **桌面专属 API**——`webbrowser.open`（`main.py:125`）、`os.startfile`（`routers/data.py:185`）、icacls 检查（`core/config.py:64`）、msvcrt 单实例锁（`run_medkit.py:52-71`）、端口探测 4880-4889：全部移除。
6. **pid 全局命名空间**（`routers/_common.py:38` `_safe_pid`）——多用户下项目 ID 会撞车，需加用户前缀；`state.py` 全局 `RUNNING/RUN_THREADS/OCR_JOBS` 线程表同理（v1 不带工坊则此项不急）。
7. **前端小改 ~5 处**——登录/登出页、「打开数据目录」按钮、「检查更新」角标、vault「选择文件夹」按钮（改导出语义）、出题工坊开关已由 localStorage 默认关（零改动）。

## 五、推荐 v1 范围（我的判断）

**带（95-97 端点，覆盖完整做题产品）**：登录 + bank 21 + vault 10 + library 29 + syllabus 12 + parse/sessions 6 + prompts 3 + presets 3 + data 导出 3 + health。

**不带（服务端 flag 关，30 端点）**：出题工坊全链（projects 18、trial/cost、OCR 4、检索 2、gap-paper、import-image、syllabus LLM 2、vault ask）。理由：
- LLM Key 归属与成本是产品决策不是工程问题，不该堵在 v1 上线前；
- `require_flag` 机制已支持服务端整组下线，将来放开是配置动作；
- 前端入口已默认隐藏，v1 用户根本看不到。

**前端改动面**：做题族与学习中心组 3,151 行零改动；总改动 ≈ 登录页 + 5 处小改。

**多租户策略**：每用户一个 SQLite 库（`~/.medkit/users/<uid>/` 整体换根），不加 user_id 列——所有路径派生自 `CONFIG_DIR` 一处，一个解析点切换即可。

## 六、风险与决策点

| 项 | 说明 |
|---|---|
| **AGPL-3.0** | LICENSE 第 1 行确认。托管版即「网络交互」——AGPL 要求向通过网络使用的用户提供源码。你是作者可自行决定授权策略，但公开发布前需明确这一点 |
| **数据隐私** | vault 现有卖点「文件是真身、可手改、可丢进坚果云」在托管版变成「服务端 markdown + 导出下载」——对外宣传口径要改 |
| **已有在线资产** | med-review-site（押题卷 HTML，`render/qbank_html.py` 1,160 行）已支持在线答题判分——网页版上线后导出仍可用，两者并存不冲突 |
| **响应式** | 前端已过 768/390 响应式三引擎测试（`test_responsive`）——手机浏览器做题无额外工作量 |
| **并发** | 管线是线程模型（`state.py` 全局表）；v1 不带工坊则做题链路无并发问题（SQLite WAL 已覆盖并发读） |
