# MedKit 奥卡姆精简 · 重构设计方案

> **审查时间**：2026-10-13 ｜ **基线**：`8921c21`（v0.14.0）
> **方法**：奥卡姆剃刀——「如无必要，勿增实体」。凡是**普通用户不会用、或用了也说不清价值**的功能，一律列为移除候选。
> **证据口径**：本方案所有结论来自① 本机真实数据库行数（`~/.medkit/library/medkit.db`，只读查询）② 代码行数实测（`wc -l`）③ 端点枚举（`grep @router`）④ 既有评估文档（`docs/生成链剥离为插件_评估_D2_2026-10-01.md`、`docs/体验质检_医学生视角_2026-10-10.md`）。**不含「读代码推测」。**

> **落地状态（2026-10-13 更新）**：**P1「关灯」+ P2「删除错题归因域」+ P4「生成链降级为可选插件」已实施**
> —— 首启模式门 + 3 步向导已移除、「练习」并入「刷题」（6 → 5 个一级页签）、「开始」页改为刷题向落地页；
> EP-01 归因全域（15 个后端文件 + 3 个前端片 + 30 个端点）已删除；出题工坊默认关闭，
> 开关在「我的 → 出题工坊」，`#bank` 直达被拒。
> **P3（考试锚定 / 网络检索）改为「随插件隐藏」而非删除**：`core/orchestrator.py`（生成链）
> 依赖 `syllabus` / `webexams` / `websearch` 做「大纲锚定注入 / 网络检索 / 真题考频」，
> 而生成链按 D-1 保留为插件——删它们要动 1562 行的生成链核心，收益与风险不成比例。
> 真身：单元 1184 / 浏览器层 55 / 总 1239（浏览器层 chromium 全绿；ruff / mypy(77) / eslint 全绿）。

## 0. 结论先行（五句话）

1. **真实数据只证明了一件事**：本机 `~/.medkit/` 里唯一有内容的域是**题库刷题**（导入 220 题 / 1 个题库）；`projects/` 空、`sessions/` 空、`cards`=0、`review_cards`=0、`syllabus_items`=0、`tutor_sessions`=0、`error_events`=0、`kp_alias`=0、`realexam_freq`=0。
2. **近 10 个 git 提交，9 个在改「题库导入 / 刷题 / 重解析」**——用户自己的迭代方向，已经用脚投票选出了核心。
3. **MedKit 现在是一个壳里塞了两个产品**：①「教材 → LLM 出题」的**生成链**（教师/进阶向）；②「导入自己的题 → 刷 → 复盘」的**刷题工具**（学生/普通向）。两者的代码、UI、心智模型互不相干。
4. **剃刀结论**：把产品收敛为 **3 个页签的「本地刷题 + 错题复盘」工具**；生成链降级为**可选的高级插件**（默认关闭）；EP-01 错题归因、大纲覆盖、真题考频、薄弱组卷、网络检索、提示词编辑等**整域移除**。预计可删 **≈12,200 行 Python（约 51%）+ ≈6,000 行前端（约 72%）**。
5. **一个必须由你拍板的岔路**（§9）：生成链是「降级隐藏」还是「彻底删除」。这是产品决策，不是工程决策——D2 文档已明确此点。

## 2. 核心价值识别：两个产品被塞进一个壳

把全部功能按「**谁用、解决什么、真实数据**」三列重新归类，会立刻浮现两条互不相干的脉络：

### 脉络 A · 生成链（教师 / 进阶向）
> 「我有教材和教师重点，让 AI 帮我出一套全新的题。」

- 需要：API Key + 充值 + 上传教材 PDF + 理解 Bloom 层级 / 题型配比 / 门禁规则 / 提示词
- 真实数据：**0 个课题**
- 代码：约 **7,517 行 Python + 2,362 行前端**（D2 文档实测口径）
- 用户心智：**「工坊」——生产工具，重配置**

### 脉络 B · 刷题工具（学生 / 普通向）
> 「我手上有一份题库，想刷、想看解析、想把错题攒起来复盘。」

- 需要：一份 md/txt/csv 题库文件（或从出题项目导入）
- 真实数据：**220 题在库**（唯一有数据的域）
- 代码：`bank.py`(590) + `bank_iq.py`(412) + `routers/bank.py`(429) + `bank*.js`(1,381) ≈ **2,800 行**
- 用户心智：**「刷题 App」——消费工具，轻上手**

**核心矛盾**：两者被 6 个页签 + 双模式 + 两道首启门强行编织在一起，导致**两边都变复杂**——学生要先过「模式门」再找「刷题」，教师要在「学习中心」里忍受一堆与出题无关的错题统计。这正是奥卡姆要剃掉的「不必要的实体」。

## 3. 剃刀决策表

> 分级：**🟢 保留**（核心闭环）· **🟡 降级**（默认隐藏，设置里可开）· **🔴 移除**（整域删除）

### 3.1 题库刷题域（🟢 全部保留 —— 这就是产品本身）

| 功能 | 决策 | 理由 |
|---|---|---|
| 导入题库（md/txt/json/csv + 预览 + 去重） | 🟢 | 核心入口，唯一有真实数据的能力 |
| 粘贴文本导入 | 🟢 | 零门槛入口，保留 |
| 沉浸式刷题（点选即判 / 答题卡 / 背题 / 键盘） | 🟢 | 核心动作，v0.13.0 刚重做，体验质检评价「比同类 App 粒度更细」 |
| 题目管理（编辑 / 收藏 / 笔记 / 手动加题） | 🟢 | 导入偏差的必要补救（质检已把它写成功能说明） |
| 错题重练 + 判对归档 | 🟢 | 核心闭环的收口 |
| 每日目标 + 今日进度 | 🟢 | 轻量激励，成本极低 |
| 导出为交互押题卷 HTML | 🟢 | 「带走」能力，复用成熟渲染器 |
| 重新解析 | 🟢 | v0.14.0 刚做，解决「已入库数据不会自动变干净」 |

### 3.2 错题本（🟢 保留，但**瘦身**）

| 功能 | 决策 | 理由 |
|---|---|---|
| 错题列表 + 科目/章节分组 | 🟢 | 复盘核心 |
| 错题 → 重练 直达 | 🟢 | 与题库刷题同源判分 |
| 错题批量导入/导出（json/csv/md/txt） | 🟢 | 数据可携带，是本地工具的底线 |
| 拍照/图片导入错题 | 🟡 降级 | 真实需求但实现重（vision 476 行 + OCR 兜底）；先保留 `library` 的轻量 `import-image`，砍掉 EP-01 的完整视觉管线 |
| LLM 讲解产物（explain） | 🟡 降级 | 有用但非核心；收进「错题详情」的一个按钮，不再占独立页签 |

### 3.3 EP-01 错题归因（🔴 整域移除）

| 功能 | 决策 | 理由 |
|---|---|---|
| 五阶段管线（intake→…→analyze） | 🔴 | 0 使用；`error_events`=0 |

| 知识点 ID 对齐（kpid + 别名表） | 🔴 | 0 使用；只为迁移矩阵服务，矩阵本身已移除 |

## 4. 精简后的产品形态

### 4.1 信息架构：从 6 页签 → 3 页签

```
【现在】                              【精简后】
侧栏                                 侧栏
├─ 模式（错题/生成）  ← 首启模式门     ├─ 刷题      ← 导入 + 开始 + 今日进度
├─ 开始   （生成链仪表盘）             ├─ 错题本    ← 列表 + 重练 + 复盘
├─ 练习   （导入题库）                 └─ 设置      ← 服务商 / 数据 / 关于
├─ 刷题   （选择题刷题）
├─ 题库   （出题工坊）        ← 生成链
├─ 学习中心（6 视图）         ← 混合
└─ 我的   （服务商/提示词/数据）
   + 首启向导（3 步）
   + 20+ 子视图
```

### 4.2 普通用户的完整旅程（3 步走完）

```
第 1 步 · 导入
  打开软件 → 落在「刷题」页 → 点「导入题库文件」
  → 选自己那份 md/csv → 看到逐题预览（题干/选项/答案/题型）
  → 确认入库                              （无模式门、无向导、无 API Key）

第 2 步 · 刷题
  选择题库 + 范围（全部/未做/错题/收藏）→「开始刷题」
  → 点选项即判分 → 看解析 → 答题卡跳题 → 下一题
  → 判错的题自动进错题本（页面顶部一条提示）

第 3 步 · 复盘
  切到「错题本」→ 按科目/章节分组看 → 点「→ 重练」
  → 判对即归档「已掌握」→ 需要深挖时点「问 AI / 看讲解」
```

**全程零配置、零付费、零 LLM 即可走完主闭环**——这正是它现在唯一被验证的能力。

### 4.3 「设置」页里还剩什么

- 服务商与 API Key（**默认折叠**，只有点「生成题库」「问 AI」时才提示配置）
- 数据：备份 / 恢复 / 打开数据目录 / 清空
- 外观：主题
- 关于：版本 / 检查更新 / 反馈 / 在线站点 / **「启用出题工坊（高级）」开关**

### 4.4 界面语言的变化

| 概念 | 现在 | 精简后 |

## 8. 反方论证：我为什么可能错

诚实列出本方案的薄弱点，供你权衡：

1. **样本单一**：真实数据只有 1 台机器、1 个用户（就是你自己）、220 题。若目标是「给别的医学生用」，他们可能恰恰需要生成链（没有现成题库的人）。→ **这是我建议生成链「降级」而非「删除」的核心原因**。
2. **EP-01 是项目最具原创性的部分**：校准曲线 / Brier / 迁移矩阵 / 减法清单——学术上是亮点，开源上是差异化。删除它等于放弃「科研型学习工具」的定位。→ 若你珍视这一定位，可把 EP-01 也做成「高级插件」，而非删除。
3. **生成链是项目身份**：README 第一行就是「授人以渔：自备教材 + 教师重点 → 生成全新题库」。删除它等于重写产品定位与 AGPL 开源动机。→ 这也是 D2 文档判定「剥离是产品决策」的原因。
4. **移除 ≠ 更易上手**：若移除后剩下的功能仍然藏在复杂 UI 里，普通用户照样困惑。→ 所以 P1（关灯 + 合并页签）比 P2–P4 更关键。
5. **数据不代表意图**：你可能只是**没时间**用生成链，而非**不需要**它。→ 需要你确认。
