## 0. 方案选择点（先拍板，避免返工）

以下 8 个点是本计划的分叉点。每处给出**唯一推荐方案**与理由，不并列罗列。

| # | 选择点 | 推荐方案 | 理由（被否方案为何不选） |
|---|---|---|---|
| **D1** | 知识追踪模型 | **BKT（4 参数 HMM）+ 经验贝叶斯收缩**，纯函数实现 | 公开 benchmark 上 BKT AUC 0.71–0.76、SAINT 0.82–0.85，但样本量决定选型：单用户本地永远到不了 SAINT 所需的 10M 交互。深度模型还要拖入 numpy/torch 依赖与模型漂移问题。BKT 纯函数 → 可用黄金值钉死，符合本仓「凡改动必有能证伪守卫」的规矩。**否掉 DKT/AKT**：为 0.05 量级 AUC 付出依赖与运维代价不划算。 |
| **D2** | 题目标定 | **p 值 + 点二列区分度 + 经验贝叶斯收缩到 0.6**，不用 IRT/2PL | IRT 2PL 要求每题 300–500 份作答才可稳定估计参数，单用户本地不可能达到；强行上 IRT 会得到一堆噪声参数。p 值/区分度在小样本下可收缩到有意义的先验，且**直接可解释**（「这题你做对 30%」）。**否掉 IRT**：门槛与场景不匹配。 |
| **D3** | FSRS 接入方式 | **直接用已声明的 `fsrs==6.3.2` 依赖**（`requirements.txt` 第 14 行已 pin），自己写 DSR 公式 | 依赖**已经在** requirements.txt 里（当初随 `core/cards.py` 一起被删，实现没了但依赖还在）。重新接线 = **零新增依赖**。自己实现 DSR 会重造 FSRS 且拿不到社区持续调优的 21 个参数。**否掉自研**。 |
| **D4** | 题→知识点映射 | **三段式**：规则精确匹配（自动确认）→ 规则模糊匹配（进待确认）→ LLM 兜底（进待确认）；**全部待确认项必须人工点确认** | 与仓库既有「人工确认门」同构（`core/realexams.py` 的 `confirmed` 门、`core/syllabus.py` 的 `confirm` 门）。纯 LLM 映射不可核、纯规则映射召回低。**否掉「全自动」**：映射错了会让掌握度归错知识点，比不映射更糟。 |
| **D5** | KC 级作答历史的存储 | **不建新表**：`bank_attempts` ⋈ `item_kc` 可随时 JOIN 重建；只维护 `kc_state` 读模型 | 仓库核心原则是「一个真相来源」。另建 `attempt_kc` 会让「同一份作答」有两个存储点，一旦漂移无法察觉。`kc_state` 是**可重建的读模型**（删表 → 从 JOIN 重放即可），与 vault 的「SQLite 只是可弃索引」一致。**否掉新表**。 |
| **D6** | 蕴含级溯源是否强制依赖 LLM | **可选降级**：有 Key 走 LLM judge，无 Key 走关键词覆盖率启发式；两者都判定「不支持」时统一进人工复核清单，**绝不阻断出题** | MedKit 是 BYOK，**没有 Key 是常态**。若强制 LLM，无 Key 用户会失去出题能力。强制阻断也会把「模型抖动」变成「出题失败」。**否掉强制依赖**。 |
| **D7** | 新 UI 的落点 | **映射确认台 → 设置 › 进阶功能**（与「大纲管理」并列）；**知识点状态/校准 → 学习中心新增子视图** | 映射是**一次性配置/运维任务**，不是学习任务，放学习中心会挤占主界面并稀释「错题助手是唯一主界面」的既有决策；大纲管理已经在进阶功能区，映射台与它同源。知识点状态是**学习视图**，该放学习中心。**否掉「都塞学习中心」**。 |
| **D8** | 置信度采集时机 | **判分前内联一行**（5 个 radio + 「跳过」），默认折叠 | 弹窗会打断刷题节奏；不采集则永远拿不到校准曲线。内联一行 + 可跳过是唯一既能拿到数据又不烦人的形态。**否掉「判分后补选」**：那时用户已知对错，自评已被污染，校准曲线失真。 |

### 1.3 根因归纳

R1/R2/R3 同源：**这个仓有「数据」但没有「数据的模型」**。
`bank_attempts`（全量流水）、`syllabus_items`（稳定主键）、`mistakes`（错题原文 + 学生自述）三样原料都齐了，
但它们之间没有连接，也没有一个「人 × 知识点」的状态表。学习者模型缺位 ⇒ 掌握度只能是启发式加权，
排期只能是逐题 SM-2，教学只能是检索式问答。

**本计划的核心就是补上这一层。**

#### 3.2.1 纯函数（全部可用黄金值钉死）

```python
# --- 文本归一（映射与去重的共同基础） ---
def norm_text(s: str) -> str:
    """归一到可比较形式：去空白与常见标点、转小写、全角→半角。"""

# --- 规则匹配 ---
def rule_candidates(topic: str, kc_pool: list[dict]) -> list[dict]:
    """按 topic 在知识点池里找候选。

    返回 [{"kc_id","item","chapter","subject","score","match_type"}]，
    match_type ∈ {"exact", "fuzzy"}，按 score 降序。
    exact：归一后完全相等（score=1.0）
    fuzzy：字符 bigram Jaccard ≥ 0.45（score = Jaccard）
    """

# --- BKT ---
def bkt_update(p_mastery: float, correct: bool,
               p_transit: float = 0.25, p_slip: float = 0.10,
               p_guess: float = 0.20) -> float:
    """一次作答后的掌握概率（Corbett & Anderson 四参数 HMM，标准写法）。

    L0 = (1-p) * (guess if correct else slip)
    L1 = p     * ((1-guess) if correct else (1-slip))
    post = L1 / (L0 + L1)
    return post + (1 - post) * p_transit
    """

def shrink(p: float, n: int, p_prior: float, k: float = 3.0) -> float:
    """经验贝叶斯收缩：把 n 次观测的后验按权重 k 拉回人群先验。

    p = (n * p + k * p_prior) / (n + k)
    n=0 → p_prior（冷启动回退先验，不返回 0）
    """

def apply_attempt(state: dict | None, correct: bool,
                  p_prior: float = 0.30) -> dict:
    """把一次作答应用到 kc_state 记录，返回**新的** state dict（纯函数，不改入参）。

    流程：BKT 更新 → 收缩 → attempts/correct 累加 → 置信度累加（可选）
    """

# --- 校准 ---
def calibration_curve(pairs: list[tuple[int, bool]],
                      buckets: list[int] = (1, 2, 3, 4, 5)) -> dict:
    """输入 [(自评置信度 1..5, 是否答对)]，输出 {"n","brier","buckets":[...]}。"""

# --- 题目统计 ---
def item_stats(attempts: list[dict], items: list[dict]) -> dict[str, dict]:
    """每题的 p 值 / 区分度 / 作答数 / 置信区间（小样本收缩到 0.6）。"""
```

**为什么 BKT 后还要收缩**：BKT 的 `p_mastery` 在只答过 1 题时方差极大（答对 → 0.87，答错 → 0.19）。
直接展示会让用户看到「我这一个考点掌握度 87%，另一个 19%」这种噪声。收缩用 `k=3`（先验等效 3 次观测），
n 增大后自动失效（n=20 时先验只占 13%）。

**p 先验取 0.30 的理由**：医学执业资格考试的常见通过率区间，单知识点首次接触的正确率大致在 0.3 上下。
这是一个**可调常量**（`core/kc.py` 顶部 `PRIOR_P_MASTERY = 0.30`），并在 §7.1 的评测里做敏感性检查。

**影响范围**：新文件 + `core/library.py`（改为从 `kc_state` 读掌握度，保留旧 `knowledge` 表作为兼容源）。

**如何验证**：
- 新增 `tests/test_kc_bkt.py`：
  - `test_bkt_update_monotonic`：同一参数下连续答对 ⇒ 概率单调不降；答错 ⇒ 下降
  - `test_bkt_known_values`：手工算出的 3 组黄金值（如 p=0.3, correct=True, transit=.25, slip=.1, guess=.2 ⇒ 0.6449…，精确到 4 位小数）
  - `test_shrink_cold_start_returns_prior`：`shrink(0.9, 0, 0.3) == 0.3`
  - `test_shrink_converges_to_posterior`：`shrink(0.9, 1000, 0.3) ≈ 0.9`
  - `test_apply_attempt_is_pure`：入参 dict 在调用后**未被修改**（用 `copy.deepcopy` 比对）

**文件**：`core/schema.py`（`QuestionItem`）、`medkit/prompts/medgen.md`、渲染层

#### 3.7.1 契约字段

在 `QuestionItem` 新增（**全部带默认值，旧产物不受影响**）：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `option_rationales` | `dict[str, str]` | `{}` | 选项字母 → 该选项为什么对/错。**键必须落在 `options` 的字母集合内** |

| `source_quote` | `str` | `""` | 支撑正确答案的教材原文那一句 |

4. `misconceptions` 不得包含正确答案的字母（正确项不是误解）。

> **注意 `extra="forbid"`**：`QuestionItem` 是 `extra="forbid"`，新增字段后**旧的 LLM 输出（不含这些字段）仍然合法**
> （因为有默认值）。但**新的 LLM 输出若含未知键会失败** ⇒ 必须在 `prompts/medgen.md` 同步要求输出这四个字段，

```python
def check_entailment(questions: list[dict], slice_texts: dict[str, str],
                      judge=None) -> dict:
    """断言级溯源校验。

    judge: 可调用对象 judge(claim: str, evidence: str) -> bool
```

**流程**：
1. 从 `analysis` 里抽取断言（按句号/分号切句，过滤掉引用标注本身）。

4. 不支持 ⇒ `F3`；证据缺失 ⇒ `F4`。

**实施中发现并修掉的三个真问题**（都不是计划里预想的）

1. **fsrs 库默认值不能照搬**。实测：学习步长默认以**秒**为单位；`maximum_interval=36500`
   会把连击 6 次「记住」的间隔排成 8/66/397/1875/7265/23933 天；`enable_fuzzing=True`

   `learning_steps=(10 分钟, 1 天)` / `relearning_steps=(10 分钟,)` / `maximum_interval=180` /
   `desired_retention=0.9` / **关 fuzzing**。标定对照：SM-2 `1→6→15→38→95→238` 天，
   FSRS `1→7→32→118→180→180` 天；失败后两者都**当天**重来。

2. **「记住」映射到 Easy 是错的**。fsrs 的 Easy 会让新卡**直接毕业**（initial_stability=8.2956
   ⇒ 首次「记住」就排到 8 天后），而 SM-2 的首次「记住」只排 1 天——体感上像「白复习了」。
   ⇒ 映射改为 `≤1 Again / 2 Hard / 3~4 Good / 5 Easy`，「记住」落在 Good 上（首次 +1 天）。

3. **vault 的三个复习按钮传错了档位（前端 off-by-one）**。原为 **5/3/1**，
   而后端 `GRADE_PASS=3` 判「quality ≥ 3 记作记住」⇒ **「模糊」被算成了「记住」**：
   连点两次模糊，这道错题就被判「已掌握」并从错题本默认视图里隐藏。
   CHANGELOG「决策 3」定的映射本就是 **忘=0 · 糊=2 · 记=4**。
   ⇒ 前端改为 4/2/0，并加**前后端一致性守卫**（`test_frontend_review_buttons_*`，

**实施中修正的三处**

1. **`dbs.tx()` 不可重入**：它是 `BEGIN IMMEDIATE`，在别人的写事务里再开一个会抛
   `cannot start a transaction within a transaction`。⇒ 状态写入拆成 `put_state_in(cur, …)` /
   `apply_attempt_in(cur, …)`（接受外部游标），事务边界留给**唯一**的编排点。
   **这也解释了为什么编排不能放 routers**：本仓 U-09 守卫禁止路由层出现 `dbs.tx(`，
   所以「同事务」只能在 core 里做——计划里写的「routers 层编排」按仓库现行分层改到了 core。
2. **回流时 `source_ref` 被覆盖**：`library.sync_from_paper` 原来无条件写入
   `{pid, question_id, sid}`，把题库回流塞的 `bank_id` / `item_id` **抹掉了** ⇒
   错题重练永远找不到原题、掌握度归不到知识点（「练了不算」）。已改为**合并**：
   标准三键优先，调用方自带键保留（`_merge_source_ref`）。
3. **冷启动先验不能当 0**：测试辅助函数原先「无状态行 ⇒ 0.0」，导致第一次答错显示
   `0 → 0.23`（看起来「不降反升」）。真实含义是「冷启动先验 0.30 → 0.23」——**下降**。
   ⇒ 判据取先验，而不是 0（这条已写进用例注释，避免下一个人重踩）。

**可证伪性（实测过，不是纸面）**

- **原子性**：把 `record_attempt_with_kc` 改回「先 `record_attempt` 再
  `apply_attempt_for_item`」两次独立写 ⇒ `test_grade_and_attempt_are_atomic` 立刻红

**实施中撞出来的两处（都不是计划里预想的）**

1. **入库白名单会静默吞字段**：`core/bank_iq.normalize_item` 是**白名单式**的（显式列字段），
   契约与提示词都改了，但题落库时四个字段被丢掉——**任何测试都不会红**，用户看到的是
   「模型明明输出了逐选项理由，界面上没有」。已补齐并加注入验证（删三行 ⇒ `/reveal` 立刻 `KeyError`）。
   ⇒ **凡是白名单式搬运，必须配一条「端到端读得到」的用例**，否则「字段加了」只是纸面。
2. **省略号切分把单个 `…` 漏掉了**：初版 `[…\.]{2,}` 要求两个以上，而中文引文常只写一个 `…`，
   于是「分段核对」形同虚设（整句当一段）。已改为 `…+|\.{2,}|；|;`——**ASCII 至少两个点**
   （否则会误切小数点），中文一个就够。

**两处刻意的取舍（写进代码注释与 CHANGELOG，避免后来者「顺手收紧」）**

- **理由完整性 = 批次级 opt-in**：整批都没有该字段 ⇒ 不判。理由：历史项目重跑不能全红；
  而一旦本批出现理由，就意味着这批来自新提示词，此时缺项就是真缺陷。
- **引文核不到默认 `warn` 而非 `fail`**：默认 fail 会把一次 50 题的批次剔到空题库。
  配置 `entailment_strict=true` 才升级为 fail。这是「可选升级不得变成破坏性变更」的同一条原则。

### 6.2 `tests/test_dangling_refs.py`（新增守卫，R3 根治）

**判据**：全仓 `.py` 文件的**注释与 docstring** 中出现的反引号包裹路径，若不以 `medkit/`、`tests/`、`docs/`、`pack/` 开头则跳过；若以这些开头，则解析为仓库相对路径并检查存在性；**不存在 ⇒ 红**。

**豁免登记**：`_PATH_EXEMPT` 同款机制，每条必须写明理由（如「ADR-004 描述的是决策时的文件名」）。

> **为什么必须新增**：本计划发现的 `core/bank.py:22` 悬空引用**已经存在了 3 个月**且没让任何测试变红。
> 删模块时 grep 注释是**人工纪律**，不可靠；要有机器守卫。

## 7. 验收

### 7.1 离线回放验证（**每个阶段出口都要跑**）

用历史 `bank_attempts` 重放，验证模型行为：

```
输入：任意用户历史的 bank_attempts + item_kc 映射
断言：
  ① 只做对 → p_mastery 单调上升，且 n=1 时 ≈ shrink(0.9, 1, 0.3) = (1×0.9 + 3×0.3)/4 = 0.45
  ② 只做错 → p_mastery 单调下降
  ③ 混合 → 终值落在 [0.1, 0.9]
  ④ 重放两次结果完全一致（确定性）
```

### 7.2 指标目标（上线后 4 周观察）

| 指标 | 目标 | 采集 |
|---|---|---|
| 题目映射覆盖率（≥1 条 confirmed） | ≥ 80% | `GET /api/kc/overview` |
| 映射准确率（人工抽检 100 条） | ≥ 90% | 抽检 |
| 置信度采集率 | ≥ 60% 的作答带 confidence | SQL 统计 |
| 校准 Brier | ≤ 0.25 | `GET /api/kc/calibration` |
| 到期卡数（同保持率下） | 相对 SM-2 下降 ≥ 20% | 前后对比 |
| 坏题识别（p<0.2 或区分度<0） | 检出率 ≥ 90%（对照人工判定 50 题） | 抽检 |

### 7.3 手工验收清单（发版前逐条走）

1. 导入一份 30 题的题库 → 「进阶功能 › 知识点映射」→ 回填（先 dry_run）→ 正式回填 → 人工确认 5 条 → 刷新后确认仍在
2. 刷 10 题（5 对 5 错）→ 打开「学习中心 › 知识点」→ 相关考点掌握度有变化 → 判错的那题出现在「错题本」
3. 判分前出现置信度行 → 选 4 → 判分 → 「知识点」页校准曲线上出现该点
4. 「今日复习」条目标注显示 `FSRS` → 评分「记得」→ due 前移 → 切回 SM-2（配置）→ 数据不丢
5. 一道带 `option_rationales` 的题判错 → 解析区逐选项显示理由与误解
6. 出题工坊跑一批 → 人工复核清单里出现 `F3`（若有断言不被支持）→ 正常
7. 不配 API Key → 回填（llm）→ 自动降级为 rule 并在 notes 说明 → 不报错
8. 关闭 `features.kc` → `/api/kc/state` 返回 404 → 前端入口隐藏 → 其余功能不受影响
9. 迁移回滚演练：升到 11 → 回滚到 10 → `bank_attempts` 数据完好
10. 390px 窄屏：知识点表格不横向溢出、映射台可操作

**铁律**：
1. 字段名**全小写 + 下划线**，后端 JSON 与前端 JS **完全同名**，前端不做任何重命名映射。
2. 新增字段一律**可选**；前端按「存在才渲染」处理。
3. 新增端点一律走 `{"ok": true, ...}` 信封。
4. 新增错误码必须在 `core/error_codes.py` 登记。
5. 本文件 §3.4 / §3.5 是**冻结契约**；阶段 5 之后改字段名必须同步改前端 + `tests/test_frontend_kc_contract.py`。
