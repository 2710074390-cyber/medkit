## 1. 管线的目标与适用场景

### 1.1 目标

把一道「考生自己记下的错题」变成**可纵向追踪的元认知档案**——记录的不只是"我选错了"，
而是"我**为什么**选错、当时**有多确信**、这个错因**跨轮次怎么演变**"。

依据《总纲》§4.3：真正的护城河不是功能，而是那份**带信心值、原始推理链和三轮演化轨迹的
个人错误档案**。本管线就是生产这份档案的产线。

### 1.2 适用场景

| 适用 | 说明 |
|---|---|
| 医学考研（西综 306）按轮次刷题 | 早鸟轮/跟课轮/强化轮/冲刺轮，跨轮次复用同一批考点 |
| 需要有"自我认知偏差"的证据 | 校准曲线、人工 vs AI 归因不一致 |
| 离线环境（医院/图书馆） | `attribute` 阶段可跳过，全程零 LLM 调用 |

### 1.3 **不适用**场景（重要，避免误用）

- **试卷自动批改**——红线：**正确答案必须由考生提供**（《总纲》§3.2）。本管线不判断答案对错。
- **一次性题海记录**——没有跨轮次复用价值，用 `/api/library/*` 的错题本即可。
- **把机构讲义灌进知识库**——《总纲》§2.4 明确禁止。本管线的检索面只有错题与笔记。

## 2. 整体架构与各阶段数据流转

```
输入（截图OCR / 粘贴 / JSONL / 直接录入）
   │
   ├─ P1 intake ────────── normalize_card()
   │     · options dict→list（唯一格式转换点）
   │     · error_tag 校验（自造标签清空）
   │     · confidence 归一（非法→None，不取默认值）
   │     └─→ 闸门判定：缺 confidence/my_reasoning ⇒ gate_ok=False
   │              ↓（闸门不过：可入库，但禁止进入 P3）
   ├─ P2 kp_align ──────── align_kp() → kpid.resolve()
   │     · canonical 命中别名表 → 复用 kp_id
   │     · 未命中 → 生成 kp_id + 登记别名（幂等）
   │              ↓
   ├─ P3 attribute ─────── attribute_one() → agents.error_analysis
   │     · 闸门前置：未过闸门**直接不调 LLM**
   │     · 产出 ai_error_tag / fix / counterfactual
   │     · apply_analysis() 派生 tag_match（人工 vs AI 是否一致）
   │              ↓
   ├─ P4 persist ───────── persist()
   │     · 无 id → add_mistake 建卡；有 id → 只更新元认知字段
   │     · error_events.append（append-only 流水，幂等）
   │              ↓
   └─ P5 analyze ───────── analyze() → metacog 纯函数
         · 校准曲线 + Brier + JOL 偏差
         · 标签×科目热力图
         · 跨轮次迁移矩阵
         · 人工/AI 归因一致率
         · 减法清单
```

### 2.1 每个阶段的输入/输出契约

| 阶段 | 输入 | 输出 | 失败行为 |
|---|---|---|---|
| P1 `intake` | 任意 dict | `{card, gate_ok, missing}` | 不抛异常；非法值归一为"未填" |
| P2 `kp_align` | card | `kp_id: str` | 异常吞掉 → `""`（记 `errors.record`） |
| P3 `attribute` | card + LLM client | `{ok, analysis, error}` | **fail-soft**：记录 + 返回 error，不抛 |
| P4 `persist` | card | `{saved, event_id, warnings}` | 流水失败不回滚快照 |
| P5 `analyze` | cards + events | 五组统计 | 无数据返回零值结构（不抛） |

### 2.2 阶段可跳过（设计要点）

`run(stages=(...))` 支持子集。三种典型用法：

```python
# 离线补录：完全不碰 LLM
run({...}, stages=("intake", "kp_align", "persist"))

# 只出统计（采集板首屏）
run({}, stages=("analyze",))

# 只跑归因（对已有错题补 AI 分析）
run({"id": mid, **rec}, stages=("attribute", "persist"))
```

**为什么必须可跳过**：P3 是唯一有外部依赖的阶段。若不能跳过，断网环境下整条管线不可用
（违反《总纲》§2.4「离线优先」）。

### 2.3 图像输入：P0 之前的「图片 → 结构化字段」

P1 只吃结构化 dict，而考生的错题往往只有一张截图。故在 P0（输入端）之前加一段
`core/vision.py`，产出直接喂 `normalize_card()`：

```
图片 bytes ─┬─ ① 原生视觉模型（model_gen 带视觉标记）──→ ErrorImageExtract 契约 ─┐
            └─ ② MinerU OCR ──→ Markdown ──→ parse_question_text（本地零 LLM）──┤
                                                                                ↓
                                                            errorpipe.normalize_card()
```

**为什么优先 ①**：一次调用同时完成"认字"与"分字段"，且模型理解版式
（题干/选项/答案各在哪一块、考生勾了哪个选项）——OCR 出来的是一段纯文本，
还得靠正则猜边界。

**为什么 ② 是真正的兜底**：它**不需要模型支持视觉**，且 `parse_question_text`
是纯本地规则（零 LLM），所以断网也能用（MinerU agent 模式免 Token）。

**判据方向**：`looks_like_vision()` 是**正面**判据——模型名命中已知视觉标记才算支持，
认不出即判"不支持"→ 走 OCR。这个方向是刻意选的：反了会让用户拿到一个 400 报错
却不知道该换模型还是该配 OCR；现在最坏只是多走一次 OCR，且 `prefer="vision"`
允许用户**强制**覆盖自动判定（未知但实际支持的模型没有被堵死）。

**红线在这一段的落点**：`ErrorImageExtract` **有** `answer` 字段，但语义与
`ErrorAnalysis` 完全不同——它是**用户图片里的原样转录**（用户拍的讲义/APP 截图本来就把答案印在上面），
属于**用户提供的数据**，不是模型产出的结论。把这个区别变成机械可查的性质靠两个布尔：
`answer_from_image` / `user_answer_from_image`。`vision.sanitize()` 丢弃所有
**没有出处声明**的 `answer` / `user_answer`——所以"模型编一个答案写进 `mistakes.answer`"
在数据层就断掉了（守卫 `test_extract_answer_requires_provenance` 用注入证明它会红）。

**闸门不放宽**：`confidence` / `my_reasoning` **不在** `ErrorImageExtract` 契约里
（模型没有代填通道），只能作为请求参数传入；前端在两项填好前禁用「开始识别」按钮。
理由是图片里通常就印着答案，"先识别再让用户补自评"等于允许事后补填。

**流式**：`iter_extract()` 是编排的**唯一实现**，非流式 `extract()` 就是它的消费者
（`extract()` 的返回 == 流式最后一个 `result` 事件，守卫
`test_extract_matches_stream_result` 把这条不变量钉住）。SSE 端点在识别阶段推
`delta`（模型原始输出增量，让 5~20 秒的等待可感知），在流水线阶段推 `stage`
（复用 `errorpipe.run` 的 `progress` 回调，用 `queue.Queue` 从 worker 线程桥接出来）。

**入口只有一个**：错题本视图原有的「拍题(图片 OCR)」（只调 MinerU、回填文本框、
不过闸门）的**前端实现已删除**，按钮改为 `miFocus()` 引导到本卡片——
同一视图放两个「拍题」按钮会让能力口径与闸门口径分裂，用户无从知道该点哪个。
后端 `POST /api/library/mistakes/import-image` 保留（仍是合法的"只要 OCR 文本" API）。
浏览器用例 `test_only_one_image_entry_in_mistakes_view` 按「视图内图片文件输入框数量 == 1」钉住。

**两条录入路径（默认两步）**：

```
                     ┌── 默认：识别 → 校对 → 入库 ─────────────────────────────┐
图片 ─ POST image/extract/stream（SSE，只识别、不落库）→ 可编辑字段 → 用户核对/修改
      └→ POST intake/stream（SSE，已确认字段 → P1→P4）
                     └── 勾选「识别后直接入库」：POST intake/image（识别完直接落库）
```

为什么默认两步：OCR 认错字是常态（纸质讲义照片尤甚），而 `confidence` / `my_reasoning`
**不可补填**——错字连同闸门数据一起落库后，事后要改只能删了重录，
等于让用户重新回忆当时的确信程度（那份回忆已经不可靠了）。
两条路径**共用** `_payload_from_fields` / `_stages_for` / `_run_pipeline_stream` / `_done_frame`，
故闸门语义、`correct` 派生、阶段事件完全一致；
守卫 `test_both_intake_paths_produce_the_same_card` 把这条不变量钉住（两份编排必然漂移）。

用户在核对界面里**手填**答案时把 `answer_from_image` 置真——语义上它变成"用户提供的答案"，
而《总纲》§3.2 的红线正是「正确答案必须由考生提供」，故这比"图里读到的"**更强**。

## 3. 核心模块与职责划分

| 模块 | 行数 | 职责 | 依赖方向 |
|---|---|---|---|
| `core/errorpipe.py` | ~470 | **编排**五阶段；闸门语义；fail-soft | → db / library / kpid / metacog / error_events |
| `core/kpid.py` | ~200 | kp_id 对齐 + 别名表 CRUD + 合并 | → db |
| `core/metacog.py` | ~330 | **纯函数**统计（无 IO） | 无（只吃 list[dict]） |
| `core/error_events.py` | ~120 | append-only 流水 | → db |
| `core/vision.py` | ~330 | **图像 → 结构化字段**（原生视觉优先 / OCR 兜底；能力判定 + 降级 + 红线清洗） | → schema / llm / mineru / library |
| `core/schema.py`（扩） | +70 | `ErrorAnalysis` 契约 | → pydantic |
| `agents/error_analysis.py` | ~85 | LLM 归因（不写库） | → schema / llm |
| `medkit/prompts/error_analysis.md` | — | 归因提示词（含红线约束） | — |
| `routers/errors.py` | ~300 | `/api/errors/*`（15 端点） | → core（**不碰 SQL**） |

### 3.1 分层纪律

`routers → core → db/llm`（项目铁律）。`routers/errors.py` 中**不出现** `cur.execute` /
`dbs.tx` / SQL 字面量——全部经 core 域函数。这是它可以被 `TestClient` 直接测的前提。

### 3.2 `metacog` 为什么全纯函数

四个统计指标都随查询口径变化（全量/近一月/单科）。落表就要处理缓存失效；
错题量级在万级以下，实时算成本可忽略（对比 `library.add_mistake` 实测 SQL 轨 0.3ms）。
纯函数还带来一个实际好处：**可以被任意样本集喂数据做单测，不需要构造数据库**——
本管线的 20 项统计测试全部零 IO。

## 4. 与现有代码的衔接与复用策略

### 4.1 复用清单（不重造轮子）

| 复用的既有资产 | 用在哪 | 为什么复用 |
|---|---|---|
| `db.put_row` / `tx` / `find_row` / `list_rows` | 全部落库 | 已解决 JSON↔SQL 无损往返、WAL、`BEGIN IMMEDIATE` 串行化 |
| `db.migrate()` + `_V*_UP/DOWN` 模式 | v8 迁移 | 已解决「升级前自动备份 + 幂等 + 版本单调」 |
| `library._store()` 事务适配器 | P4 写元认知字段 | 拿到行级增量写（`upsert_rows`），避免整表替换 |
| `library.add_mistake` | P4 建卡 | 顺带派生知识点掌握度（`_touch_knowledge_in`） |
| `library._backfill_json_once` | 双轨切换 | V-10 防线：JSON 轨数据在切轨时自动补导 |
| `agents.load_prompt` | 提示词加载 | 支持 `~/.medkit/prompts/` 影子副本（可玩性 3A） |
| `schema.validate_or_repair` 家族 | 契约校验 | ADR-003：校验失败→带错重发→人工复核 |
| `errors.record` | 全阶段留痕 | 统一的错误台账（诊断页可见） |
| `realexam_freq` 表 | 减法清单频次 | 生成链留给本管线**最有价值的资产** |

### 4.2 新表一律 `dbs.migrate()`，不回落 JSON

对齐 **ADR-006**（JSON/SQLite 双轨退役方向）。`kpid` / `error_events` 在首次调用时即建库，
**不**提供 JSON 回落分支。这与既有 5 个领域模块的 `_store_is_sql()` 双分支不同——
那些是历史包袱，新模块不该再复制。

### 4.3 双轨切换的数据可见性（实测验证）

```
新装 → add_mistake（JSON 轨，写 mistakes.json）
     → 跑 kp_align（kpid 首次调用 → migrate 建库）
     → 库域改判 SQL 轨 → _backfill_json_once 自动补导 → 旧数据**仍可见**
```

这条路径有专门用例 `test_json_to_sql_track_flip_keeps_record_visible` 钉住。
（历史上这里出过 P0：「新装→用错题本→点一次大纲管理→错题全空」，V-10 才修好。）

## 6. 异常处理、性能与兼容性

### 6.1 异常处理（fail-soft + 绝不静默）

| 故障 | 行为 | 为什么不抛 |
|---|---|---|
| LLM 归因失败 | 记 `errors.record` + `warnings` | 错题本体已保存，少个 AI 标签不该丢记录 |
| kp_id 生成失败 | 返回 `""` + 记异常 | kp 是纵向追踪的加分项，不是录入的必要条件 |
| 流水追加失败 | 不回滚快照 + `warnings` | 宁可少一条统计，不可丢一条错题 |
| 进度回调抛异常 | 吞掉 | 进度是观测，不是契约 |
| 单条批量导入失败 | 记错误继续下一条 | 不因一条脏数据废掉整批 |

**关键区分**：返回结构里 `warnings` 非空 = 跑了但有降级；`stages[x].skipped=True` = 没跑。
调用方**能区分「没跑」与「跑了但失败」**——这是《总纲》不变量在工程上的落地。

### 6.2 性能

| 操作 | 实现 | 实测 |
|---|---|---|
| 单条录入（P1+P2+P4） | 2 次事务（建卡 + 流水） | 毫秒级 |
| 元认知字段更新 | `upsert_rows` 行级增量 | 避免 `replace_all` 的 O(表内行数) |
| 统计（P5） | 全量读 + 纯函数 | 万级以下可忽略；不做物化视图 |
| 单条只读 | `get_mistake` 定向单行 | 命中主键，不整表解析 |

### 6.3 兼容性

- **v8 迁移全部可空/空串** → 历史错题、旧前端行为不变。
- **v8 幂等**（`PRAGMA table_info` 先探测）→ 测试模拟旧库不抛 `duplicate column`。
- **路由全新增** → 既有 17 个路由文件签名未动，`/api/library/*` 完全不变。
- **`add_mistake`/`update_mistake` 是扩展而非改签名** → 既有调用方不受影响。
- **`_M_TABLE` 加列** → 列只作 WHERE 过滤，权威数据仍在 `data` JSON（ADR-001），读侧无损。

## 7. 实现过程中发现并修掉的真实缺陷（留档）

> 这一节记录**实现时踩到的坑**，因为每个坑都对应一类"不报错的功能失效"。

### 7.1 `add_mistake` 静默丢弃新字段

`library.add_mistake` 的 `record` 是**固定形状的白名单字典**——任何未列出的键被静默丢弃。
表现：录入端点返回 200，但库里的 `confidence` / `my_reasoning` / `error_tag` **全是 None**。
这是最危险的一类 bug：**没有异常、没有日志、功能看起来正常**。

修法：`_META_FIELD_DEFAULTS` 集中声明 + `_coerce_meta` 类型归一，并在注释中写明
「新增元认知字段必须同时改本表与 `routers.MistakeBody`」。

### 7.2 `options` 的 `list(dict)` 静默丢文本

`list({"A": "增加"})` → `["A"]`，**选项文字全丢且不报错**。
此前不可达（`MistakeBody` 声明 `list[str]`，pydantic 先拒掉 dict），
但本管线直接从 core 调用，且《总纲》§3.1 的 JSONL schema 里 `options` **正是 dict**
→ 一旦走通就是静默数据损坏。

修法：抽 `_norm_options()` 收口，dict/list/None/标量四种输入各有单测。

### 7.3 `confidence=2.5` 被 `int()` 截断成 2

`int(2.5) == 2` → 一个"看起来填了其实没填"的自评通过了闸门，
并把 `conf/5` 的校准曲线算成 0.4 —— 一个不存在的自评档位。
同时 `True`（bool 是 int 子类）也会被当成 `1`。

修法：显式拒绝小数与 bool。由测试 `test_intake_confidence_out_of_range_treated_as_missing` 逼出。

### 7.4 `subtract_plan` 的 cut 退化为 0

`int(len(rows) * 0.25)` 在 `len(rows)=2` 时得 `int(0.5) = 0` → **减法清单恒为空**，
功能看起来"没反应"。修法：改 `math.ceil`，保证只要有章节就至少给一条建议。

### 7.7 `_freq_map` 用 `hasattr` 探测能力 → 静默返回空（第 4 类"不报错的功能失效"）

`routers/errors.py::_freq_map()` 原本这样写：

```python
rows = realexams.list_freq() if hasattr(realexams, "list_freq") else []
```

但 `realexams` 的公开函数叫 **`freq_view()`**，`list_freq` **从不存在** →
`hasattr` 恒为 `False` → **永远返回 `[]`** → `_freq_map()` 返回 `{}`。

后果：减法清单的 `freq_missing` **永远是 `True`**，一张正确性 × 真题频次的
"建议别看"表退化成"只按题量×正确率"。用户视角是「真题考频明明导进去了，
减法清单却一点没变」——**这正是《总纲》§3.5 说的"生成链留给新内核最有价值资产"白导**。

**为什么这类 bug 特别值得记**：`hasattr` 探测把"函数名写错"这个**编译期就能发现的错误**
（IDE/静态检查会标红）变成了**运行期静默降级**。它同时满足了：
① 不抛异常；② 不写日志；③ 功能"看起来在跑"（列表有内容，只是缺了频次维度）。
与 §7.1（字段静默丢弃）、§7.2（选项静默丢文本）是同一种病。

**修法**（两条同时做才算修完）：
1. **直接调用确实存在的函数**——`realexams.freq_view()`，它本身就按章节聚合好了，
   连"要不要自己 group by"这个判断都省掉；
2. **异常改走 `errs.swallow`**——万一 `freq_view()` 内部真出错，留痕而不是静默吞
   （项目对 `except Exception: pass` 零容忍，由 `test_u15_silent_pass_converged` 逐文件扫码）。

**守卫（3 条，分工明确）**：

| 守卫 | 层次 | 抓什么 |
|---|---|---|
| `test_router_freq_map_reads_confirmed_realexam_freq` | 端到端 | confirm 频次后 `_freq_map()` 非空、且 `subtract()["freq_missing"] is False` |
| `test_freq_map_does_not_probe_nonexistent_helpers` | 源码级 | 函数体内不得再出现 `hasattr` 探测（**先剥注释再扫**） |
| `test_freq_view_really_exists` | 契约级 | 钉住上游 `realexams.freq_view` 存在且返回 `chapters`，防止「守卫和实现一起漂」 |

**反向验证**：把修复后的块重新注入为 `hasattr` 探测版 → 前两条守卫**同时变红**
（`assert 'hasattr' not in ...` + `应读出已确认章节频次，实际 {}`），证明守卫绑的是行为而非文本。

**我在这条守卫上踩的坑（本文件 §7.5 之后第三次同类错误）**：
源码级守卫第一版直接扫原始源码，结果**命中了我自己写的解释性注释**（注释里当然会出现
`hasattr` 这个词）→ 代码是对的、守卫却红了。
这与 §7.5、以及 2026-09-27 产物下载守卫那次是**同一个根因**：
**"扫源码"类守卫必须先剥注释（含 docstring）再扫，且还要把字符串字面量抹掉**，
否则"注释里写了目标串"既会造成假绿（删代码留注释）也会造成假红（注释解释原因）。
已抽 `_strip_comments()` 统一处理，并在 `test_freq_map_guard_actually_catches_hasattr_probe`
里补了守卫自身的反向验证。

**第二个坑：备份必须打在注入之前。**
第一次还原失败，是因为我先注入、后 `cp` 备份 → 备份里存的是**注入后的字节**，
SHA256 "校验通过"反而制造了"已还原"的假象（文件其实还是坏的）。
第二次用「注入前备份 + 还原后逐字节比对 SHA256」才真正回到干净态
（`901cf49c…`，且 CRLF 计数为 0，未被 `core.autocrlf` 改脏）。
**教训：反向验证的备份必须发生在注入之前；还原判据是「与注入前字节相等」，不是「命令返回 0」。**

### 7.8 红线②在自由文本上的"最后一百米"（阶段 3 真发现的漏洞）

写苏格拉底复习时我按惯例设了两道防线：提示词明文禁止给答案 + 契约无 `answer` 字段。
**两道都设了，但泄漏测试照样红。**

原因：`gap`（差距说明）与 `next_question`（下一问）**是自由文本**。
契约能挡住"多出来的字段"，挡不住"把答案写进合法字段里"。
测试里模拟模型"嘴瓢"（`gap: "答案就是 <真答案>"`）→ 返回值原样透传给学生。

**修法：出口机械剥离**（`routers/errors.py::_strip_answer_echo`）。
判据用归一化后的子串匹配（去空白 + 大小写无关），故意**不做**"智能判断"——
宁可误伤（把一段无害文本整段替掉），不可放过：误伤只是这一轮提示质量下降，
放过则是"学生自己想到答案"这个前提被污染，而那是整条管线存在的理由。

三个刻意的取舍：
1. **单字符答案（"A"）不剥离** —— 它在任何中文文本里都可能偶然出现，误伤率接近 100%。
   这类答案交给提示词与契约防守，机械层不介入（`test_socratic_answer_redaction_ignores_single_char_answer` 钉住这个边界）。
2. **`next_question` 被剥离后不能留空** —— 否则下一轮学生会看到空白问题；
   改为换一个不含答案的追问。
3. **剥离必须留痕** —— 返回 `redacted=True` 且 `errs.record("socratic.answer_echo", ...)`；
   前者让用户知道"这次反馈被拦了"，后者是提示词迭代的依据（"模型多常违反红线"）。

**守卫（4 条，含一条反向验证）**：

| 守卫 | 抓什么 |
|---|---|
| `test_socratic_never_leaks_answer_in_answer_path` | 端到端：模型输出含答案 → 返回值里**不出现**该串 |
| `test_socratic_answer_redaction_actually_strips` | 函数本体：直击 + 加空格/改大小写绕行都能命中 |
| `test_socratic_answer_redaction_ignores_single_char_answer` | 边界：单字符答案**不**被误伤 |
| `test_answer_redaction_guard_actually_catches_the_defect` | **反向验证**：注入恒等剥离 → 泄漏用例必须红 |

最后一条尤其重要：它证明的是"守卫真的绑住了行为"。
若没有它，`test_socratic_never_leaks_answer_in_answer_path` 可能是**假绿**
（比如泄漏根本没走到剥离函数，而是被别处提前拦掉了——那样这个守卫就测不到剥离）。

### 7.10 我再次把动态值拼进内联事件 JS（RV1 复犯）
