## 三、盲区结论

**该盲区未被现有防线完整覆盖；缺口集中在「活 SQLite 文件」这一环。**

已成立的防线（经本轮验证）：
- 升级前对 JSON 活数据确实做 `.pre-db-*.bak` 备份（A2）；
- `import_from_json` 以 id 幂等，重复导入不丢不重（B3）；
- `data`/`.bak` 列损坏被 `list_rows` 安全降级、不产空壳记录（E1）；
- 从 `.pre-db-import-*.bak` 可手工恢复且数据完整（E3）；
- 清空前强制全量自动备份、备份失败则中止清空（`data.py:201-205`）；
- 测试侧 conftest 家目录哨兵机制健全（24 项离线测试全绿且不污染真实家目录）。

缺口（按风险排序）：
1. **回滚点本身不完整**（W1-01/02）：迁移前 DB 备份不是一致性快照，WAL 未 checkpoint、无 backup API、无可读校验——ADR-005 承诺的「可一键回退」在有未合并 WAL 时打折（R5 真实事故已出现 3.2MB 待回放 WAL）。
2. **备份失败不阻断升级**（W1-03）：连备份都没做成仍继续不可逆迁移。
3. **「清空全部数据」在运行中对权威 SQLite 存储实际不生效**（W1-04）：db 文件被锁删不掉，API 却报成功，重启后数据回生；叠加 exports/sessions/logs 残留（W1-05），删除权不完整。
4. **备份覆盖面不全**（W1-06/08）：核心备份漏 sessions、漏 .bak 回滚点。
5. **工程性弱点**：rename-in-transaction（W1-07）、会话写非原子（W1-09）、无产品化 restore（W1-10）。

**严重程度计数**：S0=0，S1=0，S2=7（W1-01/02/03/04/05/06/07），S3=3（W1-08/09/10）。
**总体判断**：本盲区不涉及 Key/隐私外泄或付费额度（无 S0/S1），属**数据可靠性与删除权完整性**问题；最该优先修的是 W1-01/03（让回滚点真实可用）与 W1-04（让「清空」不谎报成功）。
