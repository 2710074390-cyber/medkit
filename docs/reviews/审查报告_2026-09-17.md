## 三、攻击链串联分析（跨层链 × 阻断点 × 可绕过窗口）

### 链 A：localStorage 投毒 → 产物页 XSS → 同源 API 滥用（M1-02 + M1-03）

```
本机恶意进程 / 早期 XSS / file:// Firefox 跨文件共享
  → 写 127.0.0.1:4880 同源 localStorage（KEY+'-his' / KEY+'-retry'）
  → 用户打开押题卷（经 /api/projects/{pid}/files/{name} 预览，origin=127.0.0.1:4880）
  → showHistory() innerHTML 拼未转义 score/total（qbank_html.py:755-756）
     或 retryWrong() 把 q.media 原样 innerHTML（:876-880 + render() :671/:688）
  → 同源脚本执行 → 任意调用本地 API（同源 fetch 不受 Origin 守卫约束）
  → 读全部项目/产物、DELETE 项目、POST /api/llm/test 小额烧 Key、清空数据
```

- **现有防线**：① Host 白名单 + Origin 校验（`main.py:128-143`）；② 产物全量转义（题干/选项/解析均 esc）。
- **阻断点**：localStorage 写权限——**跨站恶意网页无法写 127.0.0.1:4880 的 localStorage**（同源隔离），
  故该链**不能从远程网页直接发起**；触发器限定为本机进程 / 已有的同源脚本执行 / file:// 跨文件共享。
- **可绕过窗口**：若产物 HTML 以 `file://` 双击打开，API 调用时 Origin=`null` 不在白名单 → POST 被拦，
  影响退化为 file:// 源内；**但经回环服务器预览时（同源），XSS 即等于完整 API 控制权**。
- **结论**：非远程可稳定利用，按 S2 防御纵深处理；修复（强转数字 / 删 media 字段 / 结构白名单）成本低，建议尽快。

### 链 B：恶意网页跨站 GET → 静默外呼 / 覆盖缓存文件（M2-02）

```
受害者访问恶意网页 → <img src="http://127.0.0.1:4880/api/update/check">
  或 <img src=".../api/library/cards/export/apkg">
  → Host=127.0.0.1 过白名单；GET 不查 Origin（main.py:139 仅对非 GET 查 Origin）
  → ① 服务端静默外呼 api.github.com（泄露本机出网指纹）
     ② 覆盖 ~/.medkit/exports/MedKit记忆卡_*.apkg 缓存文件
```

- **阻断点**：无——该 GET 端点当前**确实可被跨站 `<img>` 触发**。
- **限制**：**不烧 LLM Key**（所有烧钱端点均为 POST+JSON，POST 被 Origin 拦）；
  **不能读响应体**（同源策略）；不能删项目（DELETE 是 POST/带 Origin）。
- **可绕过窗口**：无需绕过，当前成立；但后果仅为外呼与覆盖缓存，非窃密/烧钱。
- **结论**：S2 纵深加固；修复=两个带副作用 GET 改 POST 或加 Origin 校验。

### 链 C：检索素材注入 → 出题内容污染 → 弱 QC → 错误医学内容流出（M3-09 × M3-01 × M3-02）

```
开启网络检索 → Round3 检出与教材冲突素材（conflict=True）
  → digest_for_prompt 仍整体注入 MedGen（orchestrator.py:606），仅靠【勿用答案】标签（M3-09）
  → LLM 忽略标签，以矛盾素材为依据出题/定答案
  → MedQC 复核：若该批 LLM 超时/限流 → 异常降级 PASS_WITH_FIXES，整批跳过事实校验（M3-01）
     或：生成模型把错误剂量写得"看似合理"，同模型质检判 warn 不 fail（M3-02）
  → 错误医学数值题进入产物，学生备考学错
```

- **阻断点**：① 渲染侧转义**已成立**（路1 复核：LLM 内容经 esc/mdRender/sanitize，注入渲染不出 XSS）；
  ② MedFix 不接收 web 素材（medfix.py:37-48）；③ 真题考频不展示原文。
- **可绕过窗口**：**"勿用答案"仅 prompt 层自觉，无程序化剔除**；冲突素材仍全量进 MedGen system。
  叠加 M3-01（一次故障即跳过整批事实校验）与 M3-02（同模型自评无数值锚点），事实防线可被两端同时绕开。
- **结论**：这是本轮**后果最重**的一条内容信任链。渲染安全兜得住，**内容正确性兜不住**。

### 链 D：上传解析 → 本机 DoS（M2-04）；路径穿越已被阻断

```
上传恶意/畸形 DOCX（高压缩比 zip bomb）或超长本地 PDF
  → _parse_bytes 仅按扩展名白名单放行（_common.py:128-159），无魔数校验
  → python-docx 不解压炸弹 / _extract_pdf 无页数上限
  → 内存/CPU 耗尽（本机 DoS）
```

- **阻断点**：**路径穿越已被双守卫封死**（`_safe_pid` 白名单 + `project_file` 后缀白名单 + 内部文件黑名单，
  路2/路4 独立复核成立）；跨站上传被 Origin+JSON 拦；上传者即本机用户。
- **可绕过窗口**：仅本机 DoS；无越权读 ~/.medkit、无任意文件写。
- **结论**：S3（威胁面有限，上传者即本机用户）；建议补 zip 解压率校验 + 本地 PDF 页数上限。

### 链 E：数据生命周期不彻底（M4-01 × M4-02 × M4-03）

```
用户点「清空全部数据」→ 仅 rmtree library/ + projects/（data.py:33）
  → exports/（含完整题干/答案/掌握度的科目删除备份 + 备份 zip 内含 config.json 密文 Key）
     + sessions/ + logs/ 全部残留（M4-01）
另：一键备份 zip 不含 sessions/（M4-02）→ 换机恢复后切片丢失、需重新付费 OCR
另：迁移前 DB 备份只拷 medkit.db 主文件、未随附 -wal（M4-03）→ 回滚点非一致性快照
```

- **阻断点**：无——UI 承诺"清空全部数据"与实际残留面不符。
- **后果**：PIPL 第47条删除权落实不完整；换机/送修/同步盘场景下完整学习数据仍明文可读。
- **结论**：S2（数据卫生/合规，非外部攻击）。

### 链 F：供应链审计失明 → 带病依赖进产物 → 不可校验（M5-02 × M5-01 × M5-07）

```
CI 用 pip-audit 审 requirements.txt（>= 浮动约束，解析到最新 starlette）
  但实际打包装 requirements.lock（钉 starlette==1.2.1，< CVE-2026-54283 修复线 1.3.1）
  → 审计图 ≠ 产物图，1.2.1 漏洞在审计里"不存在"，审计绿 ≠ 产物干净（M5-02/M5-01）
  → 且产物由维护者本机 build.bat 手建、无 CI 打包 job、无签名、无 sha256 清单（M5-07）
  → 用户除"GitHub over HTTPS"外无法校验二进制完整性
```

- **阻断点**：M5-01 的 DoS 跨站利用被 Host/Origin 守卫阻断（仅本地已具权进程可 DoS）。
- **可绕过窗口**：审计假绿；构建机环境污染（M5-04：dist/_internal 含 8 个 lock/notices 未声明包，
  含 LGPL chardet）可随产物分发而无人察觉。
- **结论**：S2（供应链加固不足，非已确认投毒）。

### 链 G：脱敏旁路（SEC-REDACT 三子项）

  经 test msg / run.log / diagnostics 三处之一泄漏。属纵深缺口。
