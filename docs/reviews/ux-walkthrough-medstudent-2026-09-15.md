# MedKit 考前医学生视角 · 全链路体验走查报告

> **视角**：临床医学本科在读、距离期末考试约 2 周、手上有老师划的重点和自己的教材 PDF。
> **范围**：注册/接入 → 素材 → 建课 → 生成 → 审核 → 产物 → 刷题 → 学习中心 → 复习计划 → 数据设置，全链路逐环节实操。
> **方法**：真机起服务 + 浏览器逐屏实操（Playwright，桌面 1440×900 + 窄屏 390×844）+ 产物页真答真判 + 关键疑点回到源码取 `file:line` 证据。走查脚本与截图见 `.workbuddy-ai/uxwalk/`、`docs/reviews/ux-walkthrough-shots/`。
> **版本**：v0.10.1（HEAD 工作区）。**本轮未修改任何产品代码**。
> **成本披露**：为在零成本下跑通真实管线，走查时向 `agents.get_client` 注入了一个本地"假 LLM"（内容为真实医学考点）。但「试出一题」端点绕过了该接缝（`routers/pipeline.py:134` 直连 `LLMClient`），实际发生了 **2 次真实 DeepSeek 调用**（均 200 OK，估 ≤¥0.05），在此说明。
> **数据副作用**：走查在 `~/.medkit` 留下 1 个测试项目（19 题）与 12 条错题等；已提前全量备份至 `~/.medkit-backup-uxwalkthrough-20260915-110918`。

## 0. 结论速览

### 0.1 一个前提澄清：这个产品没有"注册/登录"

走查第一件事就是找注册入口——**不存在**。MedKit 是本地 BYOK 桌面应用：没有账号、没有云端同步、没有登录态。考生视角的"注册登录"实际对应两件事：

1. **软件安装 + 首启向导**（3 步欢迎向导）；
2. **"注册"发生在别人家**——去 DeepSeek 官网注册、充值、创建 API Key，再回来粘贴保存。

这个设计对"考前 2 周、只想快点出题"的场景是**加分项**（省去账号/验证/找回密码），但它把整个首次门槛压在了一个考生不熟悉的概念上：**API Key**。向导文案已经做得很努力（"相当于你和 AI 服务商之间的**充值卡**"），但"充值 ¥10""API Keys 页创建""粘贴保存"这三步仍然需要用户离开软件、完成一次站外注册流程。**这是全链路最长的一段"外部等待"，也是首次流失风险最高的地方。**

### 0.3 值得肯定的地方（回归底线）

- 首启向导 3 步、文案贴考生（"充值卡"类比、"稍后配置不影响了解软件"、两条开始路径）。
- 错误 Key 反馈友好且**可操作**：实测 401 → 「连接失败：API Key 无效或未授权——请检查 Key 是否正确、是否已充值/开通」。
- 解析预览给**字数 / 切片数 / token 估算**，并给体检提示（"未检测到章节标题…建议使用带章节标题的教材版本"）。
- **成本预估前置**（实测 ≈6.1 万 token · 约 ¥0.26，且明示"参考价，以官网为准"）。
- **门禁是真的在工作**：实测抓到 R7「选项长度过短（2 字，疑似残片）：腺癌」与 DUP「与 Q005 题干高度相似（Jaccard 1.00）」，自动触发 MedFix 两轮，修复轮次用尽后**把 fail 题剔除并写入《人工复核清单.md》**——不强行渲染，这一点做得很硬。
- 长任务体验：50 条子步骤事件流（门禁四类 × 轮次）、百分比、日志着色、断点续跑。
- 押题卷作答闭环完整：计时、答题卡、判分（含用时）、错题回顾、只练错题、成绩留存（上次/最佳）、打印。
- 复习手册：字号三档、目录、阅读进度。
- 讲解（SSE 流式，实测 2.4s 完成）与苏格拉底提问（完整一轮：判 2/3 + 差距分析 + 追问）都能用，且提问确实"不直接给答案"。
- **390px 窄屏五个页签横向溢出均为 0px**（开始/题库/学习中心/刷题/我的），无文字截断、无按钮挤压。

## 1. 安装与首启（"注册登录"的对应环节）

**我做了什么**：用一个干净的用户目录模拟全新安装，打开软件 → 向导第 1 步 → 第 2 步 → "稍后配置" → 第 3 步 → 用我自己的教材开始。

**体验感受**

第 1 步讲清了"是什么、钱怎么算、数据在哪"，四张能力卡（题库/押题卷/复习手册/学习中心）一目了然，底部还补了一句 Anki。第 2 步把"API Key"翻译成"充值卡"，并直接给出四家服务商的「官网注册 ↗」跳转，这是全链路最聪明的一处文案。第 3 步只给两条路："载入示例立即体验" / "用我自己的教材开始"——符合考前用户"别让我选太多"的心理。

**困惑点**

- 第 1 步的四张卡是 3+1 排布（第 4 张单独换行），视觉上像"少了一张"，收尾不干净。
- "跳过引导，我自己探索 →" 是灰色小字，对比度低（截图 `s1-01-wizard-step1.png`），对"已经烦了、只想快点开始"的考生来说，这个最该被看见的逃生口反而最弱。
- 向导结束后落在「题库」页，但页面顶部**没有"你现在该做什么"的单一指引**，而是一个包含 8 组参数、5 个上传框、7 个按钮的长表单（见 §3）。

**优化建议**

1. 第 1 步四张卡改 2×2 网格，视觉收口。
2. "跳过引导"提高对比度（至少 `--dim` 上一档），并给键盘可达焦点。
3. 向导结束落点加一条**一次性引导条**（"① 先传教材 + 老师重点 → ② 点『解析并预览』 → ③ 想先看效果就点『试出一题』"），并在用户完成首次解析后自动消失。
4. 向导第 2 步补一句成本锚点："一套 20 题的题量约 ¥0.3，充值 ¥10 足够跑完整个期末"。现在的"¥1~5/套"是 100 题口径，对只想先试 20 题的考生偏吓人。

## 2. 连接服务商（"注册"落地环节）

**我做了什么**：进「我的 → 连接服务商」，看四家预置服务商 + 自定义端点；故意粘贴一个无效 Key 点「测试连接」；再查看 API Key 存档管理。

**体验感受**

服务商卡片信息量克制但够用（国内直连、是否自带联网搜索、"模型与能力以官方最新为准"）。Key 存档区把"多服务商各自存档、切换免重填"讲明白了，还带掩码回显 `sk-8***e71a`，这是对"我有好几个 Key"的真实场景的体贴。错误 Key 的反馈**超出预期**：不是 `401 Unauthorized`，而是可操作的中文提示。

**困惑点**

- 测试连接用了约 20 秒才返回（截图 `s1-06-invalid-key-test.png` 中仍显示"正在连接…"），期间按钮只变文案、没有进度感，用户容易连点。
- 「获取模型列表」与「手动输入…」并排，但没说清什么时候需要手动输入；对不懂模型名的考生是纯噪声。
- 页面很长（连接服务商 + OCR + 网络检索 + 提示词 + 门禁速览），副标题承诺的"数据管理"并不存在（见 B3）。

**优化建议**

1. 「测试连接」加**转圈 + 已耗时秒数**，并明确"最长 30 秒"；按钮在请求中禁用。
2. 「获取模型列表」成功后给出**一句人话结论**："已自动选择 deepseek-v4-flash（最新、最便宜），不用管"；「手动输入…」折叠进"高级"。
3. 把 OCR / 网络检索从"我的"里拆出为独立子页签（或折叠默认收起），让"我的"首屏只留连接服务商。

## 3. 素材上传与解析

**我做了什么**：上传教材（txt，含 2 个章节标题）+ 教师重点（8 条提纲）→ 点「解析并预览」。

**体验感受**

这是我认为**做得最好的一环**。解析结果不是冷冰冰的"成功"，而是：

```
教材（必填）
内科学_呼吸系统.txt · 1213 字 · 2 切片 · 估算输入 ≈ 0.1 万 token
教师重点（必填）
教师重点_呼吸系统.txt · 216 字 · 1 切片 · 估算输入 ≈ 0.0 万 token
未检测到章节标题（第X章 / 一、 / 1.1 / ##），将按全文整体切片；建议使用带章节标题的教材版本…
内容较短（疑似节选），出题素材不足时建议补充完整章节
```

字数、切片数、token 三个数让人对"我要花多少钱、会出多少题"有预期；两条体检提示直接告诉我**怎么改教材会更好**。下方的"就绪清单"进一步汇总（教材 ✓ / 教师重点 ✓ / 真题 — / 补充资料 —）并给出总成本预估。上传区还支持拖拽、可移除、有"素材要求与建议"折叠说明。这是成熟产品才有的细节。

**困惑点**

- 上传区一共 4 个框（教材/教师重点/自备真题/补充资料），对"考前只想快点出题"的考生，两个"可选"框视觉权重与必填框相同，制造了"我是不是漏了什么"的焦虑。
- 解析后切片**默认全部展开**，教材一多会撑很长，把下面的按钮推得很远。

**优化建议**

1. 「自备真题」「补充资料」默认折叠为一行链接（"有历年真题？点这里增强考点权重 →"），需要时再展开。
2. 解析结果区默认只展开前 2 条切片，其余折叠；解析完成后**自动滚动到按钮区**（解析并预览 / 试出一题 / 创建课题）。

## 4. 参数配置与「试出一题」

**我做了什么**：填科目「呼吸系统疾病」、目标考试「期末」、目标题数 20；把题型配比调成 A1 50 / A2 20 / B1 20 / X 10；看 Bloom 配比；然后点「试出一题」。

**体验感受**

配比区有可视化色块 + 合计校验（"合计 100% ✓"）+ 一键重置，比纯数字输入友好。Bloom 四档带解释（"考研/执医可提高『应用』占比"），预设里有「期末速通 / 考研西综强化 / 执医冲刺 / 查漏歼灭 / 教研自命题」——**这五个预设名本身就是对备考场景的准确理解**，是很好的设计。

「试出一题」是这个产品的杀手锏：不建项目、不跑管线、30 秒内给一道真题，还附门禁体检结果（我这次抽到的是"关于 CURB-65 评分，下列哪项不属于其评分内容？"，下方标注 `[R2] 选项长度失衡（8 vs 4，>1.5x）`）。对"我先看看这软件靠不靠谱"的考生，这一屏决定了要不要继续。

**困惑点**

- **「试出一题」的位置很尴尬**：它排在「解析并预览」之后、与「创建课题 →」同一行，但**必须先解析完素材才可用**。考生最想"先看效果"的那一刻（还没传任何文件时），这个按钮点了没有反馈路径（向导里那个"载入示例"入口在向导关掉后就找不到了）。
- 试出题的等待期只有一句"试生成中（首次约 30~60 秒）"，没有进度条/取消按钮，30~60 秒的静默等待对考生偏长。
- 配比区下方那句"X 型受命题硬约束「≤ 章节题量 10%」（超出将被压低）"很重要——它解释了**为什么我设了 20% 却可能拿不到 20%**——但它是灰色小字，容易错过。

**优化建议**

1. 「试出一题」在没有素材时**也应可用**：直接用内置示例切片（或在按钮上注明"需先解析素材，或点这里用示例体验"），把"载入示例体验"从向导里搬到这里常驻。
2. 试出题加进度指示（"正在检索切片 → 正在出题 → 正在过门禁"三步）与「取消」。
3. 把"X 型被硬约束压低"这条改成**橙色提示条**，并在设 X > 10% 时即时反馈（"当前设置 20%，实际会被压到约 10%"）。

## 5. 建课与配额分配

**我做了什么**：点「创建课题 →」，看项目详情里的配额分配。

**体验感受**

创建后立刻给出**分章配额**，而且解释了依据：

```
各章节配额（教师重点词频加权）：
第一章 慢性阻塞性肺疾病与支…：8题
第二章 肺炎、肺结核与呼吸衰…：12题
```

"教师重点词频加权"这个设计我认为是产品的核心竞争力：**把"老师划的重点"变成出题权重**，比任何"考频数据库"都更贴考生真实处境。第二章拿到更多题，正是因为我的教师重点里第二章相关的词命中更多——逻辑自洽，用户能理解。

**困惑点**

- 配额表里章节名被截断成"…"，看不到全称，鼠标悬停也无 title。
- 从"创建课题"到"开始生成"之间**没有成本确认弹窗**（就绪清单里有预估，但创建动作本身没再确认一次），与"生成前展示成本预估"的承诺略有落差。

**优化建议**

1. 章节名加 `title` 悬停全文；或允许换行显示两行。
2. 「开始生成」前弹一次轻量确认：`目标 20 题 · 预计 ≈6.1 万 token · 约 ¥0.26（参考价）· 开始生成？`，带"不再提示"选项。

## 6. 生成管线（进度 / 子步骤 / 日志）

**我做了什么**：点「开始生成」，全程观察 stepper、子步骤面板与日志，直到"已完成"。

**体验感受**

长任务体验是这个产品相对同类最突出的部分。实测：

- 顶部 9 段 stepper：网络检索 → 出题 → 门禁① → 质检 → 修复 → 汇总 → 复习 → 产物 → 完成；
- 子步骤事件流累计 **50 条**，把门禁拆成四类并标出轮次（"选项校验 · 第 2 轮"、"Bloom 校验 · 第 1 轮"、"溯源回查"、"查重"），每条带时间戳；
- 日志实时着色，能读到"切片 S001（第一章…）出题 8 题"、"门禁① fails=1 dup=2 → MedFix 修复第 1 轮"、"门禁① 修复轮次用尽，1 道 fail 已剔除并转人工复核"、"最终题库 19 题"。

**"门禁 + 修复 + 剔除转人工"这条链路是整个产品最专业的地方**：它不是"让模型直接吐题"，而是"出题 → 机器质检 → 定向修复 → 兜底剔除"。实测确实抓到了真实缺陷（选项"腺癌"只有 2 字、两道题题干 Jaccard 1.00 完全重复），并把超限题剔除、写进《人工复核清单.md》。对考生而言，这意味着"我拿到的题至少过了一遍机器审查"。

**困惑点（本环节问题最集中）**

1. **网络检索必然失败，但界面显示"已开启"**（A4）。就绪清单写"网络检索已开启"，实跑却是 3 条 `[deepseek_tool] 检索失败：未配置 DeepSeek API Key`，最后写进人工复核清单。**考生会以为检索生效了**，实际上既没拿到素材、也没意识到要做什么。这是"看起来在工作、实际什么都没做"的静默失败，比直接报错更伤信任。
2. **重复题照样进产物**（A5）。日志明明白白写了"与 Q005 题干高度相似（n-gram Jaccard 1.00 ≥ 0.8），建议改写题干或更换考点"，MedFix 修了两轮没修好，然后……这两道题**原样进了最终题库和押题卷**。考生视角：我刷押题卷时会遇到两道一模一样的题，白做一遍。
3. "网络检索"这一段**没有取消入口**：日志提示"首次约 1~3 分钟"，若后端不可达，用户只能干等。

**优化建议**

1. **修 A4**：`orchestrator.py` 的检索 Key 解析对齐 `routers/search.py:70` 与 `library.py:468` 的回退口径（内置后端复用服务商 Key）。若确实无法回退，则**在生成前就明确拦截**："网络检索已开启，但未检测到可用 Key → 本次将跳过检索（继续生成 / 去配置）"，而不是跑完 3 轮再写进复核清单。
2. **修 A5**：dup 类问题的处置口径应与 fail 一致——要么**剔除并计入人工复核清单**（产物计数同步），要么在产物页对该题打「⚠ 疑似重复」标记。现状"警告了但不处置"等于没拦。
3. 「网络检索」阶段加**取消按钮**；若 3 轮全失败，在进度面板直接给一条**可点击的**黄色提示条（"检索失败，点这里去配置"），而不是只写日志。
4. 完成后的"阶段：已完成"旁边，建议直接给一句**人话总结**："20 题目标 → 产出 19 题（1 题未过门禁已剔除，2 题疑似重复请注意）"。

## 7. 逐题审核台

**我做了什么**：进「逐题审核」，看题目卡片（题干/5 选项/答案/解析/溯源），试搜索与筛选。

**体验感受**

审核台的信息密度刚好：每题一张卡，左上角 chip 化 meta（`Q001 / A1 / 记忆 / COPD 诊断标准`），下面是题干、5 个选项、`✓ 答案：A · 解析…【源:切片S001】`。操作齐备：✓ 保留 / ✗ 剔除 / 编辑 / 重掷 / 复制，顶部有"保留 19 / 共 19 题"实时计数、题型/Bloom/年份筛选、批量保留/剔除、保存并重渲染。**每题都带 `【源:切片SXXX】` 溯源**，这点对医学备考很关键——考生能知道这题的出处。

**困惑点**

- 顶部筛选区只有"全部题型 / 全部层级 / 全部年份"三个下拉 + 批量按钮，**没有搜索框**（我用 `#rv_search` 找不到元素而超时）。19 题尚可，100 题时定位某道题只能靠滚动。
- "单题重掷（约 30 秒，消耗一次调用）"的提示很好，但重掷按钮没有任何成本/次数确认，连点会连扣。

**优化建议**

1. 审核台补**关键词搜索框**（题干/考点），与题库页的搜索能力对齐。
2. 「单题重掷」首次点击弹一次"本次将消耗一次模型调用（约 ¥0.01~0.05），继续？"，提供"本次会话不再提示"。

## 8. 产物（题库 / 押题卷 / 复习手册 / Anki）

**我做了什么**：逐一点开四类产物，在题库页测试筛选/搜索/Bloom 过滤，在押题卷页真答真判。

**体验感受**

产物区卡片化（图标 + 中文名网格），四类产物齐全：题库 MD/HTML、押题卷 HTML、复习手册 MD/HTML、Anki `.txt` + `.apkg`，另有 `questions_final.json`、`追溯日志.md`、`人工复核清单.md`。还提供「预览 Anki 卡样」和「Anki 导入指引」——导出前先看卡面，这个细节很贴心。

押题卷的作答闭环完整且顺手：顶部"共 19 题 · 作答自动保存 · 🖨 打印"，右侧答题卡 1~19（已答计数实时更新），底部"提交判分"，判分后给"得分 5/19（26 分）· 用时 0:03 + 错题回顾 + 只练错题 → + 同步错题到错题本 + 重新作答"，并且**判分后锁定作答防误改**。二次打开还显示"📈 上次 5/19（26 分）· 最佳 5/19（26 分）"——成绩留存对考前自测很有价值。

复习手册带 A−/A＋/默认 三档字号 + 目录 + 阅读进度，正文是"考点速记表 / 易混淆点辨析 / 临床思维路径 / 数值速查 / 背诵清单"五段式——**这五段正好是医学生考前复习的真实动作顺序**，结构设计到位。

**困惑点（本节问题最集中）**

1. **题库页「重置」按钮显示为 `null`**（A3）。筛选区最后那个按钮上写的是英文字面量 `null`，考生完全不知道它是"清除全部筛选"（DOM 实测 `#qreset.textContent === 'null'`，见截图 `s4-06-qbank-top.png`）。这是**学生一眼就会看到**的低级缺陷。
2. **头部题数与筛选计数不一致**（B1）：头部"共 19 题"，筛选栏计数 `A1·9 + A2·5 + B1·1 + X·2 = 17`，搜索后提示"显示 5 / 17 题"。原因是 B1 组题（3 道子题共享选项）在列表里按 1 张卡计。考生会怀疑"是不是丢了 2 题"。
3. **重复题在押题卷里同时出现**（A5）：Q006 与 Q016 是同一道题（"女，28 岁，接触花粉后突发喘息…首选的治疗是？"），押题卷里排在第 5 和第 14 位。刷到第二遍时那种"这题我刚做过"的困惑，会直接削弱押题卷的可信度。
4. 「全部年份」下拉只有一个选项（因为我的题没有真题年份标注）——**空筛选器不该出现**，占位且让人以为有内容。
5. 押题卷页顶部有一行灰色小字"ⓘ 练习自测用：答案内嵌于本页源码…请勿用于正式考试"——诚实，但位置在标题下方，容易被当噪声忽略。

**优化建议**

1. **修 A3**：`setCounts()` 改为只遍历带 `data-t` 的按钮（或给 `#qreset` 加 `data-label="重置"`）。同时加一条**产物页渲染冒烟断言**（断言 `#qreset.textContent === '重置'`），防回归。
2. **修 B1**：头部改为"共 19 题（17 张卡，其中 B1 组 1 组含 3 题）"；或让筛选计数按子题计（B1 组按 3 计）。
3. **修 A5**（同 §6 建议 2），并在产物页对疑似重复题加可见标记。
4. 「全部年份」无数据时**隐藏该下拉**（而不是留一个空选择器）。
5. 押题卷的"练习自测用"提示改为**判分后**在结果区显示一次（此时最相关），顶部只留一个 `ⓘ` 图标。

## 9. 刷题与复习计划（SM-2 / 记忆卡）

**我做了什么**：进「刷题」看科目卡 → 点「铺卡（薄弱点全部入队）」→ 看复习卡 → 试翻卡与三键自评；再到「学习中心 → 讲解产物」找记忆卡入口。

**体验感受**

刷题页结构清楚：科目卡片（每科显示今日到期/总卡/错题/掌握率，点卡片过滤）→ 复习计划（SM-2）→ 卡片式复习区。卡片交互说明也写得很直白："先在脑中回忆 → 点卡翻面看提示 → 底部红黄绿三键自评（快捷键 1/2/3）"，并解释了 SM-2 的作用（"越顺面越宽、做错会缩短重来"）。复习卡本身还有"📖 展开提示（教材原文 · 不消耗 AI）"——**从卡片直接回到教材原文且不花钱**，这个设计对考前冲刺非常实用。

**困惑点（本环节是两个 P0）**

1. **「铺卡（薄弱点全部入队）」点了没反应**（A1）。实测点完仍是"0 今日到期 / 0 总卡片 / 0 新卡"，控制台报 `405 Method Not Allowed`。根因：前端 `learn.js:2205` 用 GET 调了后端只注册 POST 的路由（`library.py:936`）。我用 API 直接 POST 同一路径，**立刻入队 11 张卡**，界面随即正常显示 11 张新卡——证明功能本身是好的，只是**批量入口的按钮彻底坏了**。（单条"铺卡"走的是另一个正确路径，所以是"每条点一次能用、批量一键不行"。）
2. **记忆卡功能整体看不到**（A2）。讲解产物展开后的按钮只有 `→ 提问练习 / ↻ 重新生成 / 复制 / 删除`，**没有「🧠 生成记忆卡」**；刷题页的"🧠 医学记忆卡"面板也是空的。根因：`learn.js:1468/2226` 判断 `window.FEATURES`，但 `app.js:10` 用的是 `const FEATURES`，`const` 不会挂到 `window` 上——浏览器实测 `typeof window.FEATURES === 'undefined'`，而 `FEATURES.cards === true`（开关本来是开的）。于是这个 v0.8.1 的功能（记忆卡 + Anki 卡片包）**在界面上完全无法触达**。

**优化建议**

1. **修 A1**：`learn.js:2205` 补 `{ method: "POST" }`。建议同时加一条**前后端方法一致性检查**（我全仓扫描 123 处前端调用，只有这 1 处不匹配——很适合做成 CI 断言或单测）。
2. **修 A2**：`learn.js:1468/2226` 的 `window.FEATURES` 改为 `FEATURES`（或在 `app.js` 里显式 `window.FEATURES = FEATURES`）。建议对 `FEATURES` 的 5 个开关各写一条"入口存在性"测试，防止"开关是开的但按钮不渲染"这类静默失效。
3. 「铺卡」这类批量操作加**明确的成功/失败反馈**（现在成功后只弹一个 toast，失败时 toast 一闪而过）。建议：成功后把按钮临时变为"已入队 11 张 ✓"。
4. 复习计划区在"0 卡"时给**两条并列入口**（"铺卡（薄弱点全部入队）" + "只铺最弱的 3 个点"），减少一次铺 11 张带来的压力感。

## 10. 学习中心（概览 / 错题本 / 讲解 / 提问 / 大纲）

**我做了什么**：在押题卷里故意答错 → 判分 → 回学习中心看概览、错题本、讲解、提问、大纲管理五个视图；完整跑通一轮"生成讲解"与一轮"苏格拉底提问"。

**体验感受**

**这是产品的第二增长曲线，也是我认为最贴合"考前"场景的部分。** 判分后错题自动回流（实测一次回流 12 条），概览立刻反映：错题沉淀 12 → 薄弱点诊断 15 个知识点 / 14 薄弱 → 掌握率 7% → "近期活动"时间线（"入库错题 · 哮喘急性发作 · 呼吸系统疾病"）→ 最弱章节（"呼吸系统疾病·S002 · 7 点 · 7 错"）→ 薄弱点清单（每条带"优先 60"、以及 `讲解 / 提问 / 铺卡` 三个直达动作）→ "⚡ 一键刷薄弱组卷"（按薄弱点配题，单知识点 ≤3 题）。

讲解产物实测：选中"哮喘急性发作" → 生成讲解 → SSE 流式，2.4 秒出完"结论先行 / 机制解析 / 鉴别要点 / 记忆锚点"四段，并标注"纯教材 / 0 来源"，还提供"📄 查看教材切片原文（不消耗 AI）"。

苏格拉底提问实测完整一轮：第一问"请你说说：为什么 COPD 患者会出现呼气性呼吸困难，而吸气相对不受限？" → 我作答 → "本轮得分 2/3 —— 方向对（气道阻力增加），但漏掉了肺泡弹性回缩力下降这一关键机制…" + 追问。**判分有理有据、追问顺着我的漏洞走、不给答案**，符合它自称的"苏格拉底法"。

**困惑点**

1. **错因恒为「推理断链」**（B2）。12 条回流错题的错因标签**全是"推理断链"**，因为我全是乱选答错的，显然不都是推理问题。根因：`core/library.py:353` 在缺字段时默认 `"reasoning"`，而押题卷 sync 不传 `error_reason`。这个字段看起来像"AI 诊断了你的错因"，实际是常量，会误导考生对自身薄弱环节的判断。
2. 讲解产物的**"生成记忆卡"入口不可见**（A2，见 §9），导致"讲解 → 记忆卡 → Anki"这条本应闭环的路径断开。
3. 同一知识点重复生成讲解会累积多条同名记录（B4），没有"已存在，是否覆盖"的提示。
4. 概览顶部有"⚠ 检测到 3 条历史记录存在编码损坏（显示为 ????）· 一键修复（先备份）"——**产品能发现并修复脏数据是加分**，但脏数据仍出现在所有科目下拉里（`???`、`???????`），且被计入"15 个知识点 / 掌握率 7%"的统计口径。考生会困惑"这 ??? 是什么科"。
5. 大纲管理页信息量偏大：教师重点 8 条 + 官方 306 种子（中医学 102 / 内科学 282 / 外科学 358 条目…）+ 真题考频热力表挤在一屏，对"考前 2 周"的用户，这个页面更像给教研用的。

**优化建议**

1. **修 B2**：押题卷 sync 时带上可推断的错因（至少区分"未作答 / 选错"），或后端缺省值改为 `"unknown"` 并在 UI 显示"未标注"而不是伪造一个"推理断链"。
2. **修 A2**，把"讲解 → 🧠 生成记忆卡 → Anki 导出"这条链显式化（讲解卡上直接给两个按钮："生成记忆卡"、"导出 Anki"）。
3. 生成讲解前检查同知识点是否已有产物，给"已存在（9-15 11:31），覆盖 / 新建 / 取消"三选。
4. **脏数据隔离**：一键修复后，未修复/已标记损坏的记录应从科目下拉与掌握率统计中**排除**（或集中放到"⚠ 待处理"分组），不要让 `???` 参与"掌握率"分母。
5. 大纲管理按使用频率分层：默认只显示"教师重点"标准（这已经是默认），把"官方 306 种子 / 真题考频"收进"进阶"折叠区。

## 11. 开始页与考试计划

**我做了什么**：看开始页四张统计卡 + 考试计划 + 最近项目；点「＋ 添加考试」。

**体验感受**

开始页是"今天该干什么"的答案页：今日待复习 / 新卡待学 / 已完成 / 掌握率 四个数，加一句引导（"先清掉今日到期，再去「题库」生成新题"），下面是考试计划与最近项目。**"考试计划支持多场：期末 / 考研 / 执业"** 直接对应医学生的真实处境（期末、考研、执医可以同时存在）。考试计划为空时给的是"还没有考试计划：可添加期末 / 考研 / 执业 / 规培等多场日期"——文案准确。

**困惑点**

- 考试计划**没有和任何东西联动**：填了考试日期后，不会影响出题优先级、不会影响复习计划排期、也不会在生成时提示"距考试还有 X 天"。它目前只是一个记录。对"考前 2 周"的用户，"还剩几天"应该贯穿整个产品。
- 四个统计卡与学习中心概览的数字重复（掌握率、今日待复习），两处口径一致但重复展示。

**优化建议**

1. 让考试计划真正驱动行为：① 在开始页显示"距《内科学》期末还有 12 天"；② 生成时按剩余天数推荐题量/难度（"距考试 12 天 → 建议一次 50 题覆盖 2 章"）；③ 复习计划按考试日期倒排（考前 3 天自动只排"高频 + 薄弱"）。
2. 开始页四卡改为"今天要做的 1 件事 + 3 个进度"，避免与学习中心重复堆数字。

## 12. 数据、设置与反馈

**我做了什么**：翻「我的」全页、找数据管理入口、看反馈与更新检查、验证窄屏。

**体验感受**

- **更新检查**：启动静默检查 GitHub Releases（实测有请求），仅提醒不打扰，行为克制得当。

- **窄屏 390px**：开始 / 题库 / 学习中心 / 刷题 / 我的 五个页签横向溢出均为 **0px**，侧栏收缩为图标态，无截断、无挤压。

**困惑点**

1. **承诺的「数据管理」不存在**（B3）。副标题写"服务商 / 提示词 / **数据管理**——配置一次，平时不用管"，但「我的」只有两节：连接服务商、提示词与规则。而真正的数据操作散落在四处：删除项目（题库→项目详情）、删除错题/导出 JSON/MD（学习中心→错题本）、删除科目（刷题→科目管理）、乱码一键修复（学习中心→概览横幅）。考生想"把数据备份一下/清一下"时，无处下手。
2. 数据存放位置（`~/.medkit/`）只在向导里提过一次，之后在界面上找不到"我的数据在哪、占多大、怎么带走"。

**优化建议**

1. **补上「数据管理」区**（或把副标题改掉）：一个地方集中提供——① 数据目录路径 + 一键打开；② 一键备份（导出 zip）；③ 各科目/项目占用统计；④ 导入/恢复；⑤ 清空全部（二次确认 + 自动备份）。现有的分散入口保留为快捷方式，但要有统一归属。
2. 在数据管理区显示"本机数据：项目 1 · 错题 12 · 讲解 2 · 复习卡 11 · 占用 xx MB"，让"我的东西在哪、有多少"一目了然。
