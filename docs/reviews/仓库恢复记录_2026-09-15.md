### 6.1 过程中新增发现（重要）

1. ⚠️ **git 自动维护会破坏恢复**：提交 A 时 git 自动触发 `geometric-repack`，因缺失对象失败  
   （`fatal: bad tree object 072ddf6… / error: failed to perform geometric repack`）。  
   若该 repack 成功，悬空对象即被清除。**已立即关闭**：
   ```bash
   git config gc.auto 0
   git config maintenance.auto false
   git config gc.autoDetach false
   ```
   → 在 `r5-batch0-1` 与 `.git/lost-found/` 异地归档完成前，**不要恢复这三项**。
2. **`refs/remotes/origin/*` 随 `.git` 损坏一并丢失**：`git fetch` 报「new branch」但跟踪引用未落盘  
   （疑与并发会话竞争引用写锁有关）；已用 `update-ref` + 直接写 `.git/refs/remotes/origin/master`  
   恢复，`git status -sb` 现为 `## master...origin/master`（无 ahead/behind，即完全对齐）。
3. **另一并发会话也在做恢复**：本次发现其创建的 `refs/recovered/r5-batch1 → eb7855a`，  
   与本记录独立得出同一结论（`eb7855a` 是唯一完整的 R5 提交）。两条恢复线同时操作同一 `.git`  
   是本次多处引用异常的成因，**必须收敛为单线操作**。
4. `r5-batch0-1` **不能推送**：其祖先 `8f98d44` 的根树缺失，推送会因缺少必要对象而失败；  
   它仅作本地保全引用（远端已有重建后的等价内容，见提交 A）。
