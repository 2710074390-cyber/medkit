## 2. P0 —— 立即修（默认主路径的并发双扣费）

### R4-01 SSE 流式讲解/提问「在飞去重」在响应返回即释放 → 双击/双标签并发双扣费、tutor 双会话
- **位置**：`routers/library.py:456-466`（`_explain_guard`）、`:648-658`（`_tutor_start_guard`）——去重 `begin/end` 挂在 **FastAPI yield-依赖** 上；消费端流式端点 `explain_stream`（`:519-576`）、`tutor_start_stream`（`:691-744`）。
- **机制（已复核）**：FastAPI/Starlette 对返回 `StreamingResponse` 的路由，yield-依赖的 `finally` 在**路由返回 Response 对象时**即执行，而非 SSE 生成器 `gen()` 流完。即生成真正在后台跑时，`_ACTIVE` 里的 key 已被 `dedupe.end()` 清掉 → 连点/双标签并发提交不再被 409 拦截。tutor 侧 `:705` 还会开第二个 session。
- **用户影响**：流式已是前端默认主路径（CHANGELOG PR-7「优先流式」）。双击生成按钮/双标签 = 两份 LLM 扣费；tutor 侧产生两个问题会话。
- **最小修法**：把 `begin` 移进 `gen()` 在 `yield meta` 前、`end` 在 `done/canceled/error` 后（绑定流生命周期）；或流式端点沿用 `try_acquire` 信号量、锁的生命周期改为「生成器 finally」释放。
- **测试**：并发两个同 key `explain/stream` 请求，断言第二个 `409`；tutor 同 key 并发断言仅 `added=1` 个 session。
- **借鉴**：流式请求的并发控制必须绑定「流关闭」而非「响应对象返回」。参考 OpenAI/Anthropic 流式 API 的请求去重语义与 Starlette `StreamingResponse` 生命周期边界；去重锁的持有期 ≡ 资源消耗期，才不出现「锁放了、活还在烧」窗口。

## 3. P1 —— 本轮修（链路断点）

### 3.1 SSE 讲解/提问三条链（默认主路径，集中爆点）
- **R4-02 流式无「停止」能力 + 服务端 `canceled` 分支是死代码**（A-R4-A-01 + F-F04 合并）
  - file:line：前端无 `AbortController`（`learn.js:571-590` `consumeSSE`；`expGenerate` `1429-1475`；`tutorStart` `1738-1776`）；服务端流式端点建 client 未传取消事件（`library.py:533-536`/`705-709` → `get_client(cancel=None)`，`agents/__init__.py:37-41`），故 `library.py:544`/`:717` 的 `if ev.get("canceled")` **永远为假**。
  - 用户影响：生成一旦下发只能等它跑完。跑偏/过长/误触无法中止，白白烧 token；切走主 view 后流仍向隐藏的 `#exp_live/#tu_live` 写入并在完成时静默落库（用户以为已离开，实际产物已沉淀）；关浏览器/断网触发 GeneratorExit 但 provider 侧连接不一定被中断。
  - 最小修法：`AbortController` + 「停止」按钮；`showLearnView/showTab` 切换时对在途生成 abort；服务端为两流式端点创建可 `set()` 的 cancel 事件并在 `StreamingResponse` 断开时下发。
  - 测试：中途断流，断言 provider 连接关闭、usage 不再增长。
  - 借鉴：SSE 双侧取消是流式交互标配（Duolingo / Notion AI 生成均有「停止」按钮）；终止信号需贯穿「前端 → 传输 → provider」全链路。
- **R4-03 断流自动回退非流式 → 重复整题生成 / token 双花**（A-R4-A-02）
  - file:line：`learn.js:1459-1474`（expGenerate catch）、`:1762-1774`（tutorStart catch）——SSE 已流出的 token 作废后，外层 catch 直接再调非流式 `/explain` 或 `/tutor/start`，同一知识点烧两遍且第二次覆盖产物。
  - 最小修法：断流终止（非 header 校验失败）时**不再自动回退**，toast「流式中断，本次未生成，请重试」并复位按钮；仅当服务端明确不支持 SSE（content-type 非 event-stream）才走非流式。
  - 测试：测试桩发射部分 delta 后中断响应流，断言只出错误提示、不再请求第二遍端点。
  - 借鉴：一次性生成不要「失败即整题重试」，否则叠加网络不确定场景双倍计费——参考 AWS/Azure 的「失败给可重试提示、用户决定重试」原则。
- **R4-04 tutor_start_stream 客户端断连残留空会话**（B-R4-B-03）
  - file:line：`library.py:705` 流式前 `start_session`，生成器仅 `canceled`/异常/空内容时 `delete_session`（`:718/725/730`）；**客户端断连≠`canceled` 事件**，Starlette 停止拉取后空会话残留（状态待答）。
  - 用户影响：与 D-04「第一问失败回滚会话」承诺断裂；空会话干扰掌握度/会话统计。
  - 最小修法：对未落定会话加 TTL/心跳兜底清理，或建会话与 `seed_first` 间保持「未落定」态、断连时由兜底任务回收。
  - 借鉴：短期资源要有兜底 GC（参考即时通信/短时任务的心跳+过期回收），回滚语义需覆盖「客户端异常断开」而非仅「显式取消」。

## 7. 行业优秀工程借鉴点（borrow-rules 风格）

| 发现 | 对齐的业内优秀实践 | 借鉴要点（可落库） |
|---|---|---|
| R4-01 流式去重过早释放 | OpenAI/Anthropic 流式 SDK 的请求去重；Starlette `StreamingResponse` 生命周期 | **锁的持有期必须 ≡ 资源消耗期**。流式请求的并发控制绑定「流关闭/生成器 finally」，而非响应对象返回或依赖 teardown。 |
| R4-02/03 流式无取消/断流回退双烧 | Duolingo、Notion AI 的「停止生成」按钮；AWS「失败给可重试提示」 | 终止信号贯穿「前端→传输→provider」全链路；一次性生成**失败不自动整题重试**，交给用户决定，避免网络抖动叠加双倍计费。 |
| R4-04 断连空会话残留 | 即时通讯/短时任务的心跳 + 过期 GC | 回滚语义需覆盖「客户端异常断开」而非仅「显式取消」；未落定资源要有 TTL 兜底回收。 |
| R4-05 付费 LLM 输出死胡同 | GitHub Copilot / Jira「草稿→提交」两段式 | 高成本 LLM 输出必须是 actionable——有「确认落库」出口，否则等于烧钱买预览；产物出口缺失即成本流失。 |
| R4-06/07 上传无上限 / config 并发覆盖 | AWS S3 size-limit + 配额；对象存储原子写 | 写前校验 Content-Length 与配额；原子写用唯一 tmp + 重试（复用仓库自身 `fsutil.write_json_atomic`）。 |
| R4-09 子步骤终态缺失 | Kubernetes Jobs / CI 构建状态机 | 每个 in-flight 状态必须有 `done/failed/cancelled` 至少一个出口，杜绝永久「running」。 |
| R4-10 僵尸线程 | Go `context` 取消 / 线程池任务隔离 | 超时（ttl timeout）不等同于任务停止；放弃后要对共享写做快照/隔离，且控制独立 ctx 的计费。 |
| R4-12 静默截断配额 | Google API-error / fail-fast 契约 | 入参超界应 fail-fast（400）并明示，而非静默 clamp 让用户按错误值决策。 |
| R4-14/15 损坏输入 500 / 异常串回显 | OWASP 安全错误处理 / 输入类型校验 | 对外读入强制 `isinstance`；错误响应只回归一化提示，不回显端点/细节。 |
| R4-16 未分类重复计数 | 分析口径「每实体只归一类」 | 统计口径需满足分区互斥，未分类实体不应同时计入多科目。 |
| R4-20 考前提醒死数据 | 功能「宣称 vs 实现」一致性（anti-fake-feature） | 界面能力选项必须有对应触发逻辑；无触发则去能力化措辞，避免误导。 |
| R4-21/22 批处理全选/竞态 | Google Drive / 邮箱批量操作 | 「全选可见≠全选全部」需明示数量；所有批量写操作在途必须禁用+进度反馈。 |

> 上述借鉴点与仓库既有 `docs/engineering/borrow-rules.md` 风格一致，建议在批次落地时择要沉淀为长期规则，避免同类问题复发。
