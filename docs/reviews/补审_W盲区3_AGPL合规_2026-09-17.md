## 1. AGPL §13 条款摘要与适用分析

### 1.1 条款原文要点（仓库内 `LICENSE`）

> **§13 Remote Network Interaction（`LICENSE:540-551`）**：
> "…if you **modify the Program**, your modified version must **prominently offer all users interacting with it remotely through a computer network** (if your version supports such interaction) an opportunity to receive the **Corresponding Source** of your version by providing access to the Corresponding Source **from a network server at no charge**, through some standard or customary means of facilitating copying of software."

配套条款：
- **Corresponding Source 定义**（`LICENSE:122-139`）：目标码的对应源 = 用于修改与调试该作品的全部源码、接口定义文件、控制编译与安装的脚本。
- **§5(a)/(b) 修改声明**（`LICENSE:202-208`）：再分发基于本程序的修改版，须显著标注「已修改」及相关日期，并显著声明以本许可发布。
- **§5(d) Appropriate Legal Notices**（`LICENSE:218-221`）：有交互用户界面的作品须展示适当法律声明（但原程序界面本身未展示者可豁免）。

### 1.2 触发要件拆解与本仓适用判定

| §13 要件 | 桌面版（本仓库产物） | 公网站点 med-review-site |
|---|---|---|
| ① 基于 Program 的修改版 | 是（本程序本身，AGPL-3.0） | **无法从本仓库确认**（站点代码不在本仓） |
| ② 通过计算机网络供用户远程交互 | **否**——`run_medkit.py:112` `uvicorn.run(app, host="127.0.0.1", ...)` 仅绑回环；`medkit/main.py:137-138` Host 守卫拒绝非 `127.0.0.1/localhost/::1` | 是——`https://med-review-site.pages.dev` 为公网 Cloudflare Pages 站，任何浏览器用户远程交互（外部事实，本仓仅见 URL 声明） |
| ③ 须向远端用户提供对应源（网络服务器、免费、显著提供） | 不适用（要件②不成立） | **若要件①成立则触发**；本仓无站点源码提供途径的任何声明 |

**分析结论**：
- 桌面版自身**不触发 §13**——ADR-007 的「不提供面向公众的网络化服务，触发风险低」（`docs/adr/ADR-007-license-agpl.md:16`；`THIRD_PARTY_NOTICES.md:16`）对桌面版**成立**。
- 但该论证**外推不到同源站**：med-review-site 恰是「通过计算机网络让用户远程交互」的服务，是否触发 §13 **完全取决于要件①**——站点是否分发/运行了 Program 的修改版（派生代码）。这一点无法从本仓库证实或证伪，是本盲区的核心未决项。

## 4. 合规结论

**结论：无法确认（conditional —— 桌面侧已验证合规；站点侧本仓无法证实或证伪，当前口径下为「未闭合」而非「已违规」）。**

理由：
1. **桌面版自身合规**：§13 对桌面版不触发（仅绑回环，`run_medkit.py:112`），其自身 §4/§6 源码与许可证提供义务履行到位（LICENSE 全文随包、公开 GitHub 仓、Releases 跳转链）——这一部分**合规**。
2. **站点侧义务是否成立不可判定**：med-review-site 是公网服务，天然满足 §13「远程网络交互」要件，唯一未决变量是「站点是否分发 Program 修改版」。本仓文档从未正面回答，且「同源同规格」（README:24-25）与「同源项目」（borrow-rules:59）两种表述**保留了两种相反解释**：
   - 解释 A（同源=产物数据格式）：站点为独立静态前端，与本程序仅 JSON schema 互通（WP-11，`library.py:456-494`）→ §13 不触发，当前文档仅需一句澄清即可闭环；
   - 解释 B（同源=代码派生）：站点复用了 AGPL 的 `medkit/web`/`render` 代码 → §13 强制要求站点显著提供 Corresponding Source + §5 修改声明，而本仓文档零披露 → 实际状态将为 **S1 级不合规**。
3. 在产品侧书面定版之前，不能判「合规」（存在解释 B 成立的未排除风险），也不能判「不合规」（无任何仓库内证据证明站点复用了 AGPL 代码）。

## 6. 盲区结论

- **现有防线覆盖度**：本盲区**已被前序审查识别并标记**（M5-13 / S2-25 / 总报告 §六覆盖矩阵），属于「已知缺口待外部澄清」，而非无人发现的盲区；本次补审把该缺口从「跨仓无法核验」细化为**可定位的 6 个文档级发现**（W3-01~W3-06），并确认桌面版自身 §13 基线干净（W3-07）。
- **剩余缺口**：不在本仓库内，无法在本审查模式下关闭——① 产品侧对「同源」语义的书面定版；② 对线上 med-review-site 实际页面的外部核验（是否有许可证页、源码链接、修改声明）。这两项移交产品/法务，不属本仓只读审查职责。
- **严重程度判定**：**S2（中）**。无 S0/S1 实锤；但因「同源同规格」表述把一个**本可一句话澄清的合规边界**长期置于两义并存状态，且同一作者经营的公网 AGPL 服务若无源码提供，风险会随站点用户增长线性放大——应在下一版文档修订时随 R1~R3 一次性闭环。
