## WP-2 出题进度条修复（#2）· 规模 M · ✅ 已完成（PR-2）

### 现状锚点
- `medkit/core/orchestrator.py`：`_set_progress(proj_dir, stage, done, total, detail)` 写 `progress.json`（stage/done/total/pct/detail/updated）。
- `medkit/web/js/review-desk.js`：`renderStepper(stage, progress)` 仅在 `progress.pct > 0` 时显示进度条；`STEPS` 数组含 websearch/generating/gate1/qc/fixing/review/rendering。
- 门禁只按“轮次”上报（`round_i-1 / FIX_ROUNDS_GATE+1`），缺少 check 粒度 → 前端看起来从门禁①开始空。

### 方案要点
- 进度模型升级为 `{stage, done, total, pct, detail, sub, sub_done, sub_total, updated}`；`sub*` 为可选子进度。
- 统一阶段常量 `PIPELINE_STAGES = ["websearch","generating","gate1","qc","fixing","review","rendering","done"]` 放 `core/orchestrator.py`（`_common.STAGE_LABELS` 同步）。
- 前端 `renderStepper` 当 `pct===0` 且 stage 非 done 时显示“准备中…”；`sub` 存在时展示“子任务 k/n：label”。

### 细化任务
- [ ] 2.1 `_set_progress(..., sub="", sub_done=0, sub_total=0)` 扩展签名（向后兼容默认值）。
- [ ] 2.2 出题阶段：并发切片完成一处后 `_set_progress(..., "generating", done, total, "切片 k/n")`（已存在，补 sub）。
- [ ] 2.3 门禁①：把 4 类检查（options/bloom/trace/dup）逐一上报：`sub="选项校验"`、`sub_done=i`、`sub_total=4`；修复轮之间也上报。
- [ ] 2.4 QC：按批次上报 `sub="质检批次 k/n"`；修复阶段上报 `sub="修复 12/30"`；汇总/渲染各报 `sub="已写入 xx"`。
- [ ] 2.5 `review-desk.js` `renderStepper`：空 pct 显示“进行中”，sub 渲染为一行小字。
- [ ] 2.6 `GET /api/projects/{pid}/status` 透传 `progress` 全字段（已透传则补新字段）。

### 测试与验收
- `tests/test_orchestrator_progress.py`：mock LLM，断言每个阶段 progress.json 有非空 pct 与 sub。
- 浏览器用例：门禁①出现“选项校验 1/4 → 4/4”子步骤。
- 验收：全程无空进度；百分比单调；取消续跑后进度不为 0。

## WP-3 门禁 subagent 分步可视化（#14）· 规模 M~L · ✅ 已完成（PR-3）

### 现状锚点
- 门禁/质检/修复是 `for round_i` + 长函数，日志只进 `run.log`，前端无子步骤流。
- DSH 可借鉴点：子任务事件 + 状态视图 + 超时重试；**不引入进程级 agent**。

### 数据与交互方案
- 新文件 `{project}/substeps.jsonl`，每行：`{"stage","step","label","status","detail","ts"}`；status ∈ pending/running/done/failed/retry。
- `orchestrator.py` 提供 `_substep(base, stage, step, label, status, detail="")` 短函数；项目 meta 不膨胀。
- 前端 `review-desk.js` 增加“子步骤面板”`#pd_substeps`，与 stepper 并列；按 stage 过滤最近 50 条。
- 超时：`_run_substep(name, fn, ttl=60, retries=2)` 包装每个门禁 check/QC 批次；超时标 failed + 重试；仍败 → 写人工复核清单并继续（不中断管线）。

### 细化任务

- [x] 3.2 门禁4类检查、QC 每批、MedFix 每条 issue 都调 `_substep()`。
- [x] 3.3 `_run_substep` 超时/重试包装；retry 事件写 `substeps.jsonl`。
- [x] 3.4 `GET /api/projects/{pid}/status` 返回 `substeps`（最近 50 条）。
- [x] 3.5 前端子步骤 UI：当前运行高亮、失败红标、重试提示、可展开详情。
- [x] 3.6 在 `docs/engineering/borrow-rules.md` 记录 DSH 借鉴点（事件流/子任务视图/重试）。

### 测试与验收

- 浏览器用例：mock 慢 LLM 显示“正在 第1轮选项校验，超时重试 1/2”。
