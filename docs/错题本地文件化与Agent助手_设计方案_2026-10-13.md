## 1. 需求拆成四件事

| # | 需求 | 性质 | 是否已有零件 |
|---|---|---|---|
| 1 | 错题记录在**本地文件夹** | 存储反转 | 部分（`bank_sources` 存原文 + reparse 模式） |
| 2 | MedKit 内 **Agent** 读这些错题 | 检索 + 编排 | 部分（`db.find_row` 全文检索、`llm` 客户端、`agents/` 六件套） |
| 3 | 分析**薄弱项** | 纯本地计算 | ✅ **已有**：`library.compute_state/score/priority` |
| 4 | 用户写自己的理解与疑问，Agent 结合两者答复 | grounded Q&A | 部分（`tutor` / `explain` 域还在） |

## 2. 成熟案例对照（调研结论）

| 案例 | 借什么 | 对本方案的落点 |
|---|---|---|
| **Obsidian + Dataview** | vault = 一堆 markdown；front matter 即数据；视图是对文件的**查询**而非另一份存储 | 薄弱项分析 = 对 front matter 的查询，**不建第二份真相** |
| **Anki（牌组 + FSRS）** | 卡片是独立可迁移单元；调度器与内容解耦；生态靠 AnkiConnect 开放接口 | 错题文件 = 可迁移单元；SM-2 复习状态与内容分离，导出即通用格式 |
| **NotebookLM** | answers **只能来自用户给的源**，且逐句带引用 | Agent 答复必须引用到**具体文件 + 具体段落**；引用不到就说不知道 |
| **Ink & Switch「local-first 七理念」** | 「你的数据就是你的数据」「无转圈即本地优先」「网络是可选的」「 longevity：数据寿命超过软件」 | 文件放用户自己会同步的目录；关闭 API Key 全部功能仍可用（降级到纯本地） |
| **Obsidian Copilot / Smart Connections（+ Ollama）** | vault-grounded assistant；可全本地（LM Studio / Qwen） | Agent 是**增强层**，不是前提；BYOK 或本机 Ollama 两条路 |
| **LlamaIndex / LangChain Agentic RAG** | 把「检索」做成 agent 可调用的 tool，而非固定管道 | `search_my_mistakes()` / `get_topic_stats()` / `read_file()` 做成 3 个工具，编排交给模型 |

**一句话**：这不是「AI 错题本」，而是「**一个你自己的 markdown 仓库 + 一个只能引用这个仓库的助手**」。
后者是否开机，不影响前者的价值。

## 3. 架构：四层，单向依赖

```text
┌─────────────────────────────────────────────────────────────┐
│ L4  助手层  agents/mistake_agent.py   可缺席（无 Key 也完好可用）│
│     工具：search / stats / read_file / ask → 答复必须带引用      │
├─────────────────────────────────────────────────────────────┤
│ L3  推断层  core/vault_index.py::stats  零 LLM，纯计算          │
│     薄弱项 = 对 front matter 的聚合（已有 compute_* 可复用）      │
├─────────────────────────────────────────────────────────────┤
│ L2  索引层  medkit.db 里的 mistakes_vault 视图                  │
│     可从 L1 全量重建；删掉它不丢任何数据                          │
├─────────────────────────────────────────────────────────────┤
│ L1  文件层  <你的文件夹>/**/*.md      ← 唯一真身                 │
│     用户可用任何编辑器改；改完索引重建即生效                       │
└─────────────────────────────────────────────────────────────┘
```

**单向依赖是硬约束**：L1 不知道 L2/L3/L4 的存在。因此
「卸掉 Agent」「清空数据库」「换一台机器只拷文件夹」三者都不会让资产失效。

## 4. 为什么这次不会重蹈 EP-01 的覆辙

EP-01（错题归因）昨天被整域删除，理由是**实测证据**：`error_events` = 0 行、
`kp_alias` = 0 行，且录入要求每题填「把握程度 + 当时的想法」——普通用户第一题就被劝退。
本方案逐条对上这四个死因：

| EP-01 的死因 | 本方案的对策 |
|---|---|
| 数据存在数据库里，用户看不见、改不了、拷不走 | 数据是**用户自己目录里的 markdown**；不装 MedKit 也能读 |
| 录入有闸门（缺字段不许归因） | **所有字段可空**。只写题干也能入库，Agent 照样能就着一张卷面回答问题 |
| 归因/校准/热力图没人看 | 第一屏只给一件事：**你哪个章节错得最多、最近错得最多**（`compute_priority` 已有） |
| 需要 API Key 才能体现价值 | 价值分两层：**L1–L3 完全离线**；Agent 只是 L4 增强。没 Key 时 App 依然是个好用的错题库 |
| 元认知四张统计卡（架构炫技） | 砍到一张表。要更多统计，让用户在仓库里自己用编辑器查 |

> **判断标准（可证伪）**：如果一个用户从今天起只用「写文件 + 看薄弱项表」、
> 从不点 Agent，他三个月后是否仍觉得这东西有用？
> **答案是** ⇒ 值得做。**答案否** ⇒ 说明又做成了 EP-01。

## 5. L1 文件层：一个错题一个文件

### 5.1 目录（用户自己会同步的地方）

```text
<你选的文件夹>/                    默认 ~/文档/MedKit错题本/，设置里可改
├── mistakes/                      一道错题一个 .md
│   ├── 2026/10/                   按年/月归档，避免单目录过万文件
│   │   ├── 2026-10-13-copdl-病因.md
│   │   └── 2026-10-13-心衰-首选检查.md
├── notes/                         自己的知识笔记（可选，Agent 也会检索）
│   └── copd.md
├── attachments/                    题目原图（引用而非内联）
├── README.md                      首次生成，说明格式与"随便改"约定
└── .medkit-vault.json             格式版本 + 文件夹 GUID（用于识别"这是我的仓库"）
```

**为什么按 `年/月` 分目录**：单目录 1 万个文件会让 Windows 资源管理器与部分同步工具退化；
按月归档后目录规模恒定，且天然带时间线。

**为什么放「文档」而不是 `~/.medkit/`**：`~/.medkit` 是应用私有目录，用户不会同步它；
而「本地文件夹」的隐含诉求是**这东西归我、我能备份/同步/拷走**。

### 5.2 文件格式（front matter 管查询，正文管阅读）

```markdown
---
id: mk-20261013-8f3a
subject: 内科学
chapter: 呼吸系统
topic: 慢阻肺
tags: [copd, 病因]
status: unlearned          # unlearned | learned | archived
created: 2026-10-13T21:12:04+08:00
source: bank               # bank | manual | ocr | paper | paste
---

# 慢阻肺最主要的病因是

- A. 吸烟
- B. 感染
- C. 粉尘
- D. 过敏

**答案**：A

## 解析

吸烟是 COPD 最重要的环境致病因素……

## 我的理解

我当时选了 B，把"感染致急性加重"当成了"患病病因"。
现在分清：感染是**加重**诱因，不是**患病**危险因素。

## 我的疑问

- 稳定期还会用抗菌药吗？指南怎么说的？
- "环境致病因素"和"危险因素"是同一回事吗？

## Agent 的答复

> 依据你的疑问第 2 条：两者在你库里出现过不同表述……
> 引用：本题 `## 解析`、`notes/copd.md#稳定期`
> 未证实：抗菌药部分我的库里没有依据，建议查证 GOLD 指南版本
```

### 5.3 五条硬约定

1. **字段可空**——subject/chapter/答案/我的理解/我的疑问全可不填，不填就是空串，不做校验拦截。
2. **正文人可读优先**——宁可少一个结构化字段，也不把正文变成模板填空题。
3. **Agent 答复也是文件的一部分**——它写进 `## Agent 的答复`，可折叠、可整段删掉、可手改。
   删掉不影响任何功能（它只是文本）。
4. **手改即时生效**——用户在 VS Code / Typora / 手机 Markdown 编辑器里改完，
   索引重建（§6）后 App 立刻跟着变。
5. **格式版本化**——`.medkit-vault.json` 记 `format_version`；格式演化时旧文件仍可读，
   索引层负责兜底，**不回写用户文件**。

## 6. L2 索引层：把主从关系倒过来

### 6.1 现状与目标

| | 现在 | 目标 |
|---|---|---|
| 真身 | `medkit.db` 的 `mistakes` 表 | **`<vault>/mistakes/**/*.md`** |
| JSON 双轨 | `library.json`（遗留兼容） | 退役（ADR-006 条件③already 满足路径已演练） |
| SQLite | 真身 | **可弃索引**（`vault_files` + `mistakes_vault` 视图） |
| 删库后果 | **数据全丢** | **0 丢失**，全量重建 |

### 6.2 新增库域存储必须走 `_sql_ready()`

（仓内既有硬约束：`library._sql_ready()`，双轨退役路径已在
`docs/双轨退役_迁移演练_D6_2026-10-01.md` 演练过。）索引表：

```sql
CREATE TABLE IF NOT EXISTS vault_files (
    path       TEXT PRIMARY KEY,   -- 相对 vault 根的 posix 路径
    mtime      REAL NOT NULL,      -- 用于增量重建
    size       INTEGER NOT NULL,
    sha1       TEXT NOT NULL,      -- 内容寻址：内容没变就不重解析
    fmt_ver    INTEGER NOT NULL DEFAULT 1
);
-- mistakes_vault = 视图/派生表：由 vault_files 解析 front matter + 正文得到
-- （subject/chapter/topic/tags/status/created + 题干/答案/解析三段的起止行号）
```

### 6.3 重建算法（三态，可断言）

```
全量扫描 vault_files（mtime+size+sha1 三级比对）
  ├─ 新文件            → 解析 → 插入
  ├─ sha1 变           → 重新解析 → 更新   ← 用户手改走这条
  ├─ mtime 变但 sha1 同 → 只更新 mtime（touch 不重解析）
  └─ path 消失         → 从索引删除（**不动文件**）
```

**关键不变量（可写成守卫）**：
- `DELETE FROM vault_files` 后全量重建，得到的结果与重建前**逐行相等**（幂等）。
- 重建过程**只读 vault**，任何失败都不得写/删用户文件。

### 6.4 为什么这不违反「双轨退役条件」

ADR-006 的退役条件③是「新写入已有唯一真身且可回退」。此处**文件即真身**、
SQLite 是缓存，属于同一思路的延伸而非倒退：我们消掉了一条轨（JSON），
把另一条轨（SQLite）降级为索引。**净复杂度下降。**

## 7. L3 推断层：薄弱项（零 LLM，已有零件）

仓里 `medkit/core/library.py` 已有三个纯函数，**直接复用，不重写**：

| 函数 | 行 | 用途 |
|---|---:|---|
| `compute_state(score)` | 342 | 薄弱/不稳/扎实/已掌握 四态 |
| `compute_score(correct,total,last_tried)` | 350 | 0–100 掌握分（含时间衰减） |
| `compute_priority(score,miss_count,last_tried)` | 367 | 该先学哪个 |

在此之上只需一层极薄聚合（`vault_index.stats()`，实际约 40 行）：

```text
薄弱项表 = GROUP BY subject, chapter, topic
           聚合（错题数 / 未掌握数 / 反复错次数 / 最近一次时间）
           → compute_priority 排序 → 取前 N
```

**为什么敢只给一张表**：EP-01 给了校准曲线、Brier 分数、热力图、迁移矩阵、减法清单五张卡，
实测 0 使用。一张「按优先级排序的薄弱章节表」就够了——
它直接回答「我现在该回头学什么」，而且不需要任何模型。

**离线可用性**：这一层不 import `llm`、不 import `agents`。可在 CI 无网络环境完整测试。

## 8. L4 助手层：Agent 只能引用你的仓库

### 8.1 工具集（ Agentic RAG 的最小形态）

```text
search_my_mistakes(query, subject?) → [{path, 题号, 题干, 命中字段, 片段}]
get_topic_stats(subject?)           → 薄弱项表（= L3 的同一份结果）
read_file(path, section?)           → 文件原文（或指定小节）
ask_agent(question, scope?)         → 主入口：自行决定调哪些工具后作答
```

**检索实现分档**（按用户机器能力自动选，不强制）：
1. **关键词 + 章节过滤**（默认，零依赖，复用 `db.find_row()` 的 SQL 思路）；
2. **jieba 二元组**（仓内已依赖 jieba，`db.py` 在用）；
3. **本地 embedding + Ollama**（可选，检测到 Ollama 才启用；不可用则静默回落到 1）。

> 刻意**不做**服务商 embedding API：那会把整个仓库内容外传，
> 与「文件在本地、归用户」的出发点冲突。

### 8.2 答复的四条硬约束（可证伪）

1. **必须带引用**：每个结论后面跟 `[来源: <相对路径>#<小节>]`。检索不到依据的句子不许下结论。
2. **不知道就说不知道**：工具返回与问题无关时，答复必须是「我的错题库里没有相关记录」，
   **禁止**用通识补全（这是 NotebookLM 的关键性质，也是它可信的原因）。
3. **可以读用户的「我的理解/我的疑问」**，并把用户原话纳入上下文——
   答复要**回应他自己的那个具体误解**，而不是泛泛讲知识点。
4. **静默失败 = 失败**：任何工具抛错，答复里要写明哪个工具失败了，而不是给一份"看起来完整"的答案。

### 8.3 写入策略

- 答复**默认只读**，显示在对话区；
- 用户点「存进这个错题」才写入该文件的 `## Agent 的答复`（追加，不覆盖手写内容）。
- 这样避免 Agent 每次调用都把用户文件改一遍（内容寻址失效 + 用户的 diff 噪音）。

### 8.4 提示词

新增一个提示词文件 `mistake_agent.md`（放进提示词目录，与既有六个提示词同规制），
走已有的 `render_prompt` + 占位符校验 + 影子副本机制。
必须有 `### Prompts` 小节进 CHANGELOG、同步 `tests/fixtures/llm_cases/`（NX-06 既有约定）。

| **R2 薄弱项表** | `vault_index.stats()` + 学习中心「本地错题」子视图一张表 | 即刻获得：**先学什么**，零 LLM | 1 天 |
| **R3 Agent 只读问答** | 工具集 + grounded 答复 + 对话 UI | 有 Key 才增强；没 Key 不受影响 | 2 天 |
| **R4 应答沉淀** | 「存进这个错题」写回 `## Agent 的答复` | 答复成为资产的一部分 | 0.5 天 |
| **R5 可选增强** | 本地 embedding / Ollama 检索、批量导题、Git 提交助手 | 有需求再做 | 视需要 |

**每期结束都可停**：R1 之后它就是 Anki 式的本地错题库；R2 之后它告诉你先学什么；
R3/R4 才引入模型。这与「先剥后建」的收敛方向一致。

## 11. 风险与红线

| 风险 | 对策 |
|---|---|
| 手改文件导致 front matter 解析失败 | 解析失败**单独记一条告警**（列出路径与原因），**不阻塞**其它文件；App 不自动"修复"用户文件 |
| 单目录文件过多 | 按年/月归档（§5.1） |
| 用户把 vault 放进同步盘，锁冲突 | 所有写操作**先写临时文件再原子 rename**（仓内已有 `write_json_atomic` 范式） |
| Agent 引用不存在的文件 | 引用用**索引里的 path**，不用模型自己编的路径；答复后校验文件仍存在 |
| Agent 泄露答案（想看题时被剧透） | 检索结果默认**不含 `**答案**` 行与 `## 解析`**，需显式开"看解析" |
| 用户担心隐私 | 默认工具 1/2 全本地；embedding 只走 Ollama；BYOK 提示与既有口径一致 |
| 又一次做成没人用的重功能 | §4 的可证伪判断标准 + 分阶段可停 |

## 12. 守卫（按仓内 gate-falsifiability 约定）

1. **索引幂等**：删索引 → 全量重建 → 与重建前**逐行相等**（含 sha1/mtime/size）。
2. **重建只读**：monkeypatch 文件系统写函数为抛错，跑全量重建，断言零调用。
3. **手改生效**：改一个文件的 `topic`，重建后该错题的薄弱项分组真的变了。
4. **引用真实性**：Agent 答复里的每个 `[来源: path#section]`，该 path 必须在索引里、section 必须存在
   （注入"模型编造路径"必须红）。
5. **无依据必须说不知道**：检索结果与问题无关时，答复必须含「库里没有相关记录」
   （用空库跑，断言不含任何知识点陈述）。
6. **可空即所得**：只写题干、其余全空，仍能入库、能被检索、能进薄弱项表（分母如实计入）。
7. **零 LLM 可测**：`vault_index.py` 不得 import `llm` / `agents`（AST 判据，不是注释声明）。
