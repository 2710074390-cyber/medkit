# MedKit 审查报告：对照医学教育特点与医学生·考研需求的结构化改进建议

> 日期：2026-08-27 · 类型：需求侧产品审查（非代码审查）
> 依据：① 项目全量盘点（README / 设计文档 v0.5~v0.7 / core+agents+prompts+routers+render / 前端 index.html / 174 项 pytest）
> ② 公开调研（医学教育研究、学习科学证据、中国医学考研/执医场景、竞品功能），来源见文末链接。

---

## 0. 结论概要（TL;DR）

MedKit 在**「本地化出题工坊 + 学习闭环」**这个定位上已相当成熟：五阶段出题管线、四道门禁、溯源防幻觉、成本护栏、错题本→掌握度→讲解→提问→SM-2 复习的完整循环，工程上甚至有 174 项测试与数据卫生自愈能力。**基本盘没有问题，不需要重构。**

真正与「医学生 + 考研需求」之间的差距集中在 **4 个结构性空白**：

| # | 空白 | 一句话 | 优先级 |
|---|---|---|---|
| A | **考试锚定层缺失** | 有「自备真题」但只做风格校准，无「大纲→覆盖度」「真题→考频」的量化锚定 | P0 |
| B | **医学图像/影像/图表能力为零** | 教材图、心电图、X光/CT、病理图、辅检表既不能入题也不能渲染 | P0 |
| C | **学习闭环缺「计划性」与「统计洞察」** | 无每日计划/阶段规划；掌握度是扁平知识点，无系统/器官聚合、错因分布、备考指数 | P1 |
| D | **临床技能形态缺失** | 只有客观题；病史采集/病例分析（执医技能、面试）这类医学特有训练完全空白 | P1 |

其余为生态层（手机碎片场景、CSV/Excel、教师端、数据备份）与质量层（数值题版本锚定、难度实测回传、IRT 长线）的 P2 建议。

**推荐路线：v0.8 = 考试锚定（A+B）→ v0.9 = 闭环深化（C+D）→ v1.0 = 生态与信度。**

## 1. 审查方法与需求框架

把「医学教育特点 → 需求」映射到三层框架，作为逐条建议的判据：

```
① 学习科学层  记忆（间隔重复/生成效应/检索练习）· 理解（机制/鉴别）· 临床推理（病例/渐进披露）
② 中国医教场景层  5+3 一体化 · 大三~大五备考期与实习冲突 · 期末 · 考研 306 · 执医（技能+笔试）
③ 考试工程层  大纲 → 考点 → 题源(真题/教材) → 题型结构 → 难度/信度 → 覆盖度与预测
```

项目现状对照（✓ 已实现 / △ 部分 / ✗ 缺失）：

## 2. 为什么这些空白恰好是「医学生需求」——依据

1. **54 万级考生的考研赛道上，真题与大纲就是复习的锚**：306 西综题型为 A1/A2/A3/A4/B1/X（与 MedKit 题型结构完全同构），命题趋势是病例题占比上升、强调机制与鉴别；学生端几乎所有刷题产品（医考帮/蓝基因等）的核心卖点都是**真题分章练习 + 考点频次 + 押题**。MedKit 定位「新题生成」必须回答「新题覆盖了哪些考点、与真题高频点是否对齐」，否则学生无法判断这套新题值不值得练。
2. **医学是强视觉学科**：心电图、X线/CT、病理切片、解剖图、辅检表格是教材与考试体量的 30% 以上；无图能力等于把内科/影像/儿科/病理的题库全部降级为「纯文字题」，且丢掉了医学训练的核心——视觉模式识别。
3. **医学生备考的经典矛盾是「记忆量大 + 时间被实习切碎」**：间隔重复、检索练习、交错练习在医学教育中有系统性证据；每日学习计划与「只学最该学的」推荐是刚需，而不是高级特性。
4. **执医技能与考研复试**（病史采集、病例分析、问诊模拟）是学生绕不开的第二战场，对话式大模型恰好适合做「虚拟标准化病人」，而 MedKit 已有 tutor 引擎可低成本复用。
5. **AI 在医学教育中的主要风险是事实性错误与指南时效**（多项综述一致指出 accuracy/reliability 是挑战）；MedKit 已用「教材为准 + 溯源 + 冲突入人工复核」应对，但「数值题锚定教材版本/页码」应再前移一步。

## 3. 结构化改进建议

### P0-1 大纲覆盖度引擎（考试锚定的第一块砖）

**需求依据**：306 大纲由国家医学考试中心每年发布、条目公开；学生与机构（医考帮等）都按「大纲考点 → 刷题覆盖 → 打勾」组织复习。项目现状：大纲只能当「补充资料」或一条检索词，无法回答「这章 40 个考点我出了几题/掌握了几项」。

**现状差距**：无大纲数据结构、无覆盖度报表、出题配额只按切片+教师重点词频。

**建议**：
1. 新增素材角色 `role: "syllabus"`（大纲文本/粘贴的条目清单，纯文本即可——不追求自动解析 PDF 表格，首版人工粘贴由用户粘贴节选，如「第一章…考点1、考点2…」）。
2. 新增 `core/syllabus.py`：大纲条目 → `{条目, 所属章节, 状态}`；生成时 LLM 把题目 `subtopic` 对齐到大纲条目（复用现有问答式 JSON 输出，非新增调型）。
3. 三个报表（均本地聚合、零 LLM）：
   - **出题覆盖度**：`GET /api/library/coverage?pid=` → 每章「大纲条目数 / 已出题数 / 未覆盖条目列表」；
   - **掌握覆盖度**：`GET /api/library/coverage/learn` → 大纲条目 ↔ 知识点掌握度并集，标出「没学过/薄弱/已掌握」；
   - **超纲清单**：题目 `subtopic` 匹配不到大纲条目 → 人工复核清单提示（保守显示，不自动删）。
4. 出题时 `syllabus_text` 注入 system（与教师重点同通道，控制成本），提示词要求「优先覆盖未出题的大纲条目」。

**验收**：粘贴 306 大纲某章节 → 出 20 题 → 覆盖度报表显示遗漏条目且与人工核对一致；掌握覆盖度随学习中心数据实时更新。

---

### P0-2 真题考点频次分析（把「自备真题」从校准升级为量化器）

**需求依据**：真题高频考点 = 押题权重。项目已有 `role: "exam"` 自备真题（防照抄硬约束做得很规范），但只用于 prompt 内「高频考点优先」的口头约束，**没有结构化输出**，学生看不到「哪 20 个考点被考过 5 次以上」。

**现状差距**：`agents/medgen.py` EXAM_CHAR_LIMIT=4000 截断注入；无考频数据。

**建议**：
1. 新增批处理分析（**本地 LLM 抽取 + 人工确认**，一次调用）：`POST /api/library/realexams/analyze` — 自备真题文本 → `[{考点, 频次, 年份, 题型, 章节}]`，落盘 `realexams.json`，支持增删改（用户可纠正抽取错误）。
2. 考频进入两个权重：
   - **推荐权重**：`core/library.py compute_priority` 增加 `+w*(1 - 考频归一化)` 项（考频高的薄弱点优先），参数可调，默认 0.15；
   - **出题配额**：切片配额公式（`core/orchestrator.py`）中把「教师重点词频」与「真题考频」并列加权，滑杆 `真题考频权重 0~30%`（沿用现有旋钮通道）。
3. 可视化：「考点频次热力表」（章节 × 频次），供学生看「哪些章是重灾区」，也天然成为押题卷组卷依据。
4. **合规红线保持**：一切分析仅在本机、展示频次不展示原文；防照抄约束（`medgen.py` v0.5.2 注）继续生效。

**验收**：导入 5 年真题文本 → 频次表与人工统计误差 ≤20%（人工确认后修正）；「考研西综强化」预设出题时高频考点章节题量上浮。

---

### P0-3 缺陷驱动智能组卷（「一键刷我的薄弱点」）

**需求依据**：医学考研公认最高效的复习节奏是「错题/薄弱 → 针对性重练 → 再检验」。项目已有 `gap_killer` 预设（错题重练二轮），但**需要手动配题**，且不与学习中心掌握度联动。

**现状差距**：`presets.py` gap_killer 是静态配比；推荐列表与出题管线之间没有一键通道。

**建议**：
1. `POST /api/library/gap-paper` → 输入 `{subject, 题量, 覆盖率}` → 取 recommend() 前 N 个知识点 → 自动创建临时课题并复用既有管线（`/api/projects` + `pipeline` 流程），返回课题 id。
2. 题量分配规则（本地）：`知识点题量 ∝ priority × 大纲权重`（结合 P0-1/2），同一知识点 ≤3 题防重复轰炸。
3. 产物与学习中心双向：该卷判错 → 继续 sync-paper 回流错题本（闭环自动转起来）；卷面标注「本次针对薄弱点：…」。
4. 首屏入口：「概览 → 建议今天刷 X 题薄弱点 → 生成」（复用成本预估 toast）。

**验收**：3 次点击完成「薄弱点 → 专属练习卷 → 判错 → 回流错题本」；生成前有成本预估。

---

### P0-4 医学图像/影像/图表能力（结构性补齐）

**需求依据**：医学教育强视觉（心电图/影像/病理/解剖/辅检表）；执医与考研病例题普遍带图。当前管线文字-only，等于放弃一半医学可能。

**现状差距**：素材解析（`core/extract.py` 图片走 OCR）+ 错题拍题 OCR 已有，但**输出只有文本**——图片不会成为题干的组成部分，渲染器（`render/qbank_html.py`/`review_html.py`）无 `<img>`，打印亦无图。

**建议（首版最小闭环）**：
1. **素材图入题**：项目素材清单支持图片附件「作为图片素材」（用户自备教材插图/图谱，保持不内置原则）；`slices.json` 增加 `image: {path, caption, source_page}` 字段；切片过滤时保留图片字段。
2. **出题引用**：`prompts/medgen.md` 增加「图题干」（题干=病例+「如图」+表格/图片描述），LLM 输出 `image_ref: "fig_1"`；门禁校验 image_ref 在注入切片内存在（`gates/trace_check` 扩展）。
3. **渲染**：题库/押题卷/复习手册渲染器支持 `img`（本地相对路径 → 打包产物时复制到产物目录，或转 base64 内嵌保证可打印/可移动）；打印样式加 `max-width` 与分页保护。
4. **图表题**：新增题干形式 `data_table`（辅检表格：血常规/生化/血气），prompt 生成 Markdown 表格题干，渲染为真实 <table>——这比图片成本低、又是考试高频。
5. **长线（P2）**：接入 `deepseek-v4-flash-vision` 等视觉模型（README 已支持该模型名）做「图 → 结构化描述」，用于照片型教材页；首版不做，避免范围膨胀。

**验收**：传一张教材插图的切片 → 生成的 1 道题题干引用该图 → 押题卷/题库 HTML 中图正常显示、打印正常；表格题以 table 呈现。

### P1-5 记忆卡工厂 + FSRS（把讲解/复习手册变成可背的卡）

**需求依据**：Anki 用于医学教育效果好且有系统评价支持；学生背的医学卡主要是**数值卡/口诀卡/鉴别表卡**，而不是「题干+选项」的刷题卡。当前 Anki 导出（`render/apkg.py`）只有刷题卡，且调度是 SM-2（Anki 主推 FSRS）。

**现状差距**：`prompts/medreview.md` 的分层手册（考点速记/易混淆/数值速查/背诵清单）与 `explains.json`（四段讲解）都是自然语言，未转成卡。

**建议**：
1. 新增 `MedCard` 生成：`POST /api/library/explains/{id}/cards` —— 讲解产物四段（结论/机制/鉴别/锚点）→ 3~6 张卡（正面=问题/挖空/对比表，反面=答案，`card_kind: value|mnemonic|contrast|concept`），一次 LLM 调用 + 人工可编辑；复习手册五层同步生成。
2. 卡对接复习队列：卡批量入 `review_queue.json`（复用 M5），卡与知识点通过 `kp_id` 关联（判分回写掌握度链路已有）。
3. **FSRS 升级**：引入 `fsrs`/py-fsrs（轻依赖），保留 SM-2 作为降级开关；对比标准：间隔序列更平滑、记忆积压更少。若引入成本高，先做「SM-2 → 参数即 FSRS 子集」的接口抽象（`Scheduler` 协议），FSRS 作为实现之一。
4. Anki 导出扩展：支持选择「刷题卡包 / 记忆卡包 / 混合」，`apkg` 标签增加 `card_kind`。

**验收**：一篇讲解产物 → 3 张卡 → 入队 → 今日到期可答 → quality 回写掌握度；FSRS 开关切换后队列不丢数据（迁移函数幂等）。

### P1-6 临床技能场景：病史采集模拟 + 病例分析（差异化强需求）

**需求依据**：执医技能第一站（病史采集/病例分析）与考研复试面试是医学生刚需；对话式 LLM 做「虚拟标准化病人」非常成熟，且 MedKit 已有 Socratic tutor 引擎（`core/tutor.py`）可复用。

**建议**：
1. **病史采集演练**（复用 tutor 会话机制，新增 `kind: "history"`）：AI 扮演患者，按主诉/现病史/既往史/过敏史/家族史逐轮回答；学生问诊 → 结束 → **结构化评分卡**（覆盖问诊要素、是否追问鉴别点、引导性提问扣分），LLM 判分 + 本地规则兜底（如「至少问到 X 个要素」）。
2. **病例分析小作文**：给一份病例摘要（A3 素材可复用），学生写出诊断+依据+鉴别+检查+治疗 → AI 按红笔批改（按条计分，输出「得分点/漏点」），产物存 `clinical_runs.json`。
3. 场景入口：学习中心新增子视图「临床技能」（第 6 个 tab）或并入「提问学习」的扩展；成本预估前置沿用。
4. 长线（P2）：体格检查/操作流程的卡片化 + 技能评分表模板（用户可导入本校 OSCE 评分表）。

**验收**：一个问诊会话完整跑通并出评分卡；病例分析批改能认出「漏了过敏性休克抢救步骤」这类扣分点；无 LLM 时走本地要素检查兜底。

### P1-7 学习统计洞察（从「正确率」升级为「学习分析」）

**需求依据**：学生最想要的三个数——「我哪些**系统**最弱」「我总错在哪类**错因**」「以我的水平**大概什么段位**」。医学知识天然按器官/系统组织，扁平知识点列表不够。

**现状差距**：`dashboard.py` 仅科目维度；错因只有枚举字段无聚合；无「易混淆对象」挖掘（学生错得最多的干扰项及其正确选项就是最该背的鉴别点）。

**建议**：
1. **系统/章节聚合**：`knowledge.json` 已有 chapter；新增聚合视图 `GET /api/library/insights` —— 按章节/系统（内科→呼吸/循环/消化…需章节命名规范化，提供映射规则+人工编辑）输出掌握度分布与趋势 sparkline（`history` 已有时间轴）。
2. **错因分析**：按 `error_reason` 聚合，输出「你的错题 40% 是概念混淆、30% 是数值记忆」+ 对应行动建议（混淆→讲解鉴别；数值→铺数值卡）。
3. **易混淆对挖掘**：同知识点下错误选项分布 → 输出 top 易混淆对（`A 误选为 B`）→ 用户一键生成「易混辨析卡」（接 P1-5）或直接生成一道 B1/X 对比题（接 P0-3）。
4. **备考指数**（考试锚定的量化出口，依赖 P0-1/2 数据）：`备考指数 = f(大纲覆盖度, 薄弱点集中度, 近期正确率趋势, 距离考试天数)`，0~100 分，附「可解释因素拆解」；每周自动补一条历史，形成趋势。

**验收**：洞察页 5 分钟内可看懂「重灾区 + 错因 + 该做什么」；易混淆对与人工分析抽样一致率 ≥60%。

---

### P1-8 每日学习计划与阶段规划（对抗「记忆量大 + 实习冲突」）

**需求依据**：医学考研普遍提前 1~2 年启动、与实习并行，最缺的是「每天该干什么」的确定性；间隔重复与交错练习的证据也指向「计划性 + 短时高频」。

**现状差距**：只有 SM-2 到期队列（今天该答哪些卡），没有「今日清单」聚合、没有阶段规划。

**建议**：
1. **今日清单**（零 LLM 聚合）：`GET /api/library/plan/today` → 「到期复习卡 N 张 + 建议错题重练 M 题 + 薄弱点讲解 1 篇 + 智能组卷 1 套（可选）」；完成打勾记录 `plan_log.json`，形成打卡与周统计（连续学习天数激励）。
2. **阶段模板**：内置「基础（教材+大纲全扫）/强化（真题+薄弱）/冲刺（模拟+押题）」三模板（复用 presets 结构），每阶段配默认每日配额；模板可叠加「考试倒计时」自动收紧（考前 30 天每天复习量+1，错题优先）。
3. **交错练习默认策略**：生成卷默认跨章节交错（interleaving，证据见文末），提供「同章集中/全科交错」开关（默认交错，对齐记忆科学）。
4. 移动端降级（P2 相关联）：今日清单做「单页极简」输出，手机浏览器（局域网模式开启时）可在一屏内完成打卡。

**验收**：首页「今日」卡片可一键开始；连续 7 天打卡有周报；考前 30 天计划强度自动上调并有提示。

### P2-9 数据可携带（整库备份/迁移/分享）

1. 学习库 ZIP 导出/导入（`~/.medkit/library/` 全量 + 项目目录可选），覆盖换电脑、防丢失——学生数据是最贵的资产。
2. 错题本 CSV/Excel 导入模板（与外部刷题 App 导出的常见列对齐：题干/选项/答案/解析/科目/章节/标签），替换现在的纯 JSON。
3. 预设/大纲/评分表的跨机分享格式统一为 JSON（已有预设导出，扩展到大纲与评分表）。

### P2-10 教师端轻量视图

1. 教研命题（已有 `teaching_bank` 预设）→ 「导出答案卷 + 学生答题卡」（HTML 打印）；学生答题卡输入 → 统计报表（正确率/知识点分布）。
2. 班级场景留白：不建号不建群，**文件级流转**（教师导出题包 JSON → 学生导入生成项目 → 学生导出答题结果 → 教师导入分析），符合零后端架构，也规避隐私合规。

### P2-11 局域网/手机碎片模式（可选开关）

`main.py` 现仅回环；增加 `--lan` 启动参数 + 首次提示（安全警告：任何局域网内设备可消耗你的 API 额度；建议仅家庭场景）+ 简单访问令牌。碎片时间刷卡是高频场景，但成本与安全要明示。

### P2-12 教学质量与信度（长线）

1. **数值题版本锚定**：教材元数据增加版次/年份；数值类答案在分析中强制标注「（教材第九版 P123）」，产物页脚注统一「数值以你上传教材版本为准」。
2. **题目难度实测回传**：押题卷判分结果匿名回写题目级 `p 值`（正确率）、`区分度`（高阶/低阶分组差）——教师命题模式的价值标尺；题目 `difficulty` 字段从「生成时声明」升级为「实测校准」。
3. **IRT 自适应（stretch 已有）**：题量足够后用 2PL 选择下一题难度；保持现有「本地规则优先」取向，仅在标准组件（`routers/review.py` 或新 `routers/adapt.py`）内实现。

## 5. 优先级路线图

| 版本 | 内容 | 里程碑验收 |
|---|---|---|
| **v0.8 考试锚定** | P0-1 大纲覆盖 · P0-2 真题考频 · P0-3 薄弱组卷 · P0-4 图像/表格题 | 贴 306 大纲出题得覆盖报表；真题频次校准出题；图/表题可渲染可打印；pytest 全绿 |
| **v0.9 闭环深化** | P1-5 记忆卡+FSRS · P1-6 临床技能 · P1-7 洞察 · P1-8 每日计划 | 讲解→记忆卡→复习队列全通；病史采集评分卡可用；备考指数上线 |
| **v1.0 生态与信度** | P2-9~12 | 整库备份/CSV；教师题包流转；局域网模式；难度实测回传 |

**取舍说明**：
- 大纲解析不做自动 PDF 结构识别（成本高、306 大纲文本易得），首版「粘贴条目 + 人工确认」。
- 图像首版只做「图片附件引用 + 渲染」最小闭环，视觉模型做图→结构化描述放长线。
- FSRS 视依赖引入成本，允许只做 Scheduler 抽象 + SM-2 优化（先解决「卡片由讲解生成」这一更关键的缺口）。
- 教师端坚持文件级流转，不引入账号体系（与零后端、本地数据原则一致）。
