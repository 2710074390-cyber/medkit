## 0. 结论摘要

0.10.0 不是单纯的“修 bug”，而是一次以 **“体验正确性 → 管线可观测性 → 产品方向重构 → 工程规范”** 为顺序的迭代。核心主线有四条：

1. **学习闭环体验修复**：多场考试倒计时、科目切换/删除、错题本批量与分类、红点来源可感知。
2. **生成管线可观测**：进度条从“门禁①开始为空/卡住”修复，借鉴 DSH 的 **subagent 分步可视化**。
3. **产品方向重构**：取消“大纲覆盖”，改为“大纲管理”，明确 **官方 306 = 补充、教师重点 = 主要依据**，并支持 AI 结构化大纲（不丢信息）。
4. **信任与工程基线**：纯净安装包（不带学科/题目/测试数据）、网络检索修复 + 可信来源、数据互通导入、抄/借鉴优秀工程的**书面规则**。

## 2. 主题分组

### A. 开始页与规划（#1）
- 多场考试（期末/考研/执业/规培等）独立倒计时。
- 参考：成熟规划类应用（Notion/日历/番茄钟）的“事件列表 + 最近优先 + 提醒”。

### B. 刷题 / 学习中心（#3、#4、#5、#8）
- 科目：可见、可点击、可删除（含关联数据处置策略）。
- 错题本：分组、折叠、批量选择、批量删除/归档/导出。
- 红点：来源具名、可跳转、无待办不显示。

### C. 生成管线（#2、#14）
- 进度：阶段 + 子步骤双粒度；门禁①起不空档。
- 卡点：超时/停滞可诊断；借鉴 DSH subagent 的**分步任务树/事件流**观感（本地 Python 实现，不引入进程级 agent）。

### D. 实时性与沉浸感（#9、#11、#12）
- 讲解/提问 → 流式（SSE）交互；出题 → 实时子步骤日志。
- 简化入口与链路；参考优秀 AI 学习/题库产品的“一句提问→持续对话→沉淀复习卡”。

### E. 网络检索（#6、#7）
- 后端连通修复；项目生成真正接入检索；可信来源白名单。

### F. 大纲体系（#13）
- 取消“覆盖”心智 → “管理”。
- 官方 306：补充大纲（结构性、广覆盖）；教师重点：主要偏向（权威、个性化）。
- AI 结构化大纲：原文 + 结构化双份存储，不丢信息可校验。

### G. 视觉（#10）
- 产物与页面从“纯文本”走向“富文本/卡片/高亮/图表化”；保持零 CDN。

### H. 打包与数据（#4、#16、#18）
- 安装包纯净；外部站点数据可导入；本地数据可导出备份（为删除科目/批量删除提供安全网）。

### I. 工程规范（#15、#17）
- “借鉴优秀工程”落地为规则：先调研、记录来源、最小改动、附带测试/CHANGELOG。

## 4. 目标 / 非目标

### 目标
- 0.10.0 可交付：安装包纯净、学习闭环顺手、生成全程可见、网络检索可用、大纲体系符合新定位。
- 每一项都有明确验收与回归测试（单元 / API / 浏览器用例）。
- 新增功能默认**最小改动**：优先复用现有端点、状态机与本地库。

### 非目标（本期不承诺）
- 不转移动端范式（沿用桌面侧栏 + 一屏一任务）。
- 不引入外部重量级依赖（保持零 CDN、PyInstaller onedir 构建不显著膨胀）。
- 不做多用户/云同步；学习数据仍以本机 `~/.medkit/` 为准。
- 不把 DSH 的进程级 subagent 机制直接照搬进 MedKit（目标是借鉴其分步呈现与编排思想）。

## 6. 风险与开放问题

1. **移除 306 种子 / 示例素材**会破坏 `ensure_seed` 与“载入示例”入口，需先定义替代路径（官网下载/用户导入/示例仅开发保留）。
2. **网络检索**依赖服务商能力，无 Key/无网环境必须优雅降级；可信来源白名单要避免“地域/版权”争议。
3. **AI 结构化大纲不丢信息**较难，必须采用“原文 + 结构化”双存储，并用条数/文本散列做可逆校验；失败时保留原文。
4. **删除科目/批量删除**不可逆，应先提供导出备份或软删除/回收站，避免误删学习数据。
5. **流式交互**改动讲解/提问的后端契约与前端视图，需保证旧产物兼容（`grounded`、无 JSON 契约输出等）。
6. **外部站点导入**依赖 med-review-site 导出格式，需要先与站点侧约定 schema；无约定时先用通用 JSON/CSV 兜底。
