## 1. 目标

面向医学生个人备考，扩展出题工坊与错题详情，使其形成：

`原错题 → 有意义变式题 → 知识点速记卡 → 复习与掌握追踪`

同时修复同一账号多设备登录后学习数据不完整、被覆盖或未上传的问题。

## 2. 已确认的产品决策

- 变式题素材：当前错题 + 同考点题目 + 相邻知识点。
- 变式题生成：错题完成后推荐，用户确认后才调用模型。
- 变式题默认生成 3 道，单个错题硬上限 5 道；有效题不足时不强行补齐。
- 变式题和速记卡均归属于原错题。
- 生成内容可查看、练习、删除；第一阶段不直接编辑正文。
- 第一阶段速记卡为知识点速记卡，进入复习调度。
- 书架分为「内置题库」与「生成内容」，两组均可折叠展开。
- API Key、主题和设备级操作偏好不进入账号同步。

## 3. 变式题设计

### 3.1 产物字段

每道变式题必须具备稳定 `artifact_id`，并保存：

- `artifact_type=variant_question`
- `source_mistake_id`
- `generation_batch_id`
- `variation_type`
- `source_kc_ids`
- `source_refs`
- `novelty_note`
- `created_at`、`updated_at`、`deleted_at`
- 标准题目字段、逐选项解析、误解标签、难度和原文引句
- `dedupe` 指纹字段

### 3.2 有意义变化

至少改变一个实质维度：病例情境、提问角度、认知层级、干扰项逻辑或相邻知识点综合。允许的变化类型包括病例迁移、诊断依据、下一步处理、鉴别对比、机制解释和前置知识补强。

禁止仅替换年龄、数字、病名、单位、选项顺序或病例名称；禁止只改变表面变量却保留相同问法与错误认知。

### 3.3 去重与上限

生成候选统一经过：题目契约、答案一致性、出处核验、选项质量、精确指纹、结构指纹、语义相似度和变式意义检查。

- 精确重复：题干/选项/答案相同。
- 结构重复：仅变量替换或选项换序。
- 语义重复：考点、正确结论、问法和误解高度相同。
- 同一 `variation_type` 对同一原错题最多保留 1 道。
- 历史已生成和已删除产物均参与去重，删除不释放历史指纹。
- 目标 3，道具硬上限 5；不足则返回实际有效数量与原因。

### 3.4 复习行为

变式题作答进入统一作答流水。判错回流原错题并更新原错题复习状态；判对只记录迁移证据，不直接把原错题标记为已掌握。变式题必须能从书架和原错题详情进入练习。

## 4. 速记卡设计

每个原错题最多关联一张当前有效速记卡，字段包括：

- `artifact_type=quick_note`
- `source_mistake_id`
- 核心结论、高频考点、易错点、鉴别要点、记忆锚点
- 一条可核验教材依据
- 1–3 个主动回忆问题
- `created_at`、`updated_at`、`deleted_at`
- FSRS/复习状态

速记卡可查看、开始复习、删除；删除时同步删除其复习卡，不影响原错题和变式题。

## 5. 书架

书架分为两个一级可折叠分组：

### 内置题库

包含应用内置题库和同步获得的固定来源题库。只读，不允许删除。

### 生成内容

包含生成题库、变式题集合和知识点速记卡。每项显示类型、来源错题、生成时间、数量、复习进度和操作入口；支持查看、练习/复习和删除。

折叠状态写入账号级 UI 偏好，使同一账号在设备间保持一致；不影响内容数据。

## 6. 跨设备同步修复

### 6.1 当前问题

现有网页版使用 `localStorage` 快照上传到每用户 SQLite 的单个 `user_state` JSON。问题包括：

1. 同步白名单漏掉实际学习键和后续生成产物键。
2. `PUT /api/state` 用整份快照覆盖，设备并发学习会互相覆盖。
3. 1.5 秒延迟上传在页面关闭、锁屏或断网时可能丢失。
4. 没有统一删除标记，旧设备上传会让删除内容复活。
5. 登录后只在特定时机拉取，设备长时间打开时无法及时得到其他设备更新。

### 6.2 同步协议

服务端保留账号状态、单调递增 `revision` 和更新时间。客户端上传：

- `base_revision`
- 本次变化的键/实体
- 客户端生成的 `change_id`
- 客户端时间

服务端按实体类型合并；revision 冲突不直接覆盖，而是返回合并后的最新状态和新 revision。客户端落地合并结果后再刷新页面数据。

### 6.3 合并规则

- 作答流水：`id + ts` 去重并集，保留最近 8000 条。
- 错题和生成产物：按稳定 ID 合并，按 `updated_at` 选择最新字段；删除使用 `deleted_at` tombstone。
- 收藏/笔记：按实体 ID 和更新时间合并。
- 考试计划：按计划 ID 合并，删除保留 tombstone。
- 每日统计：按日期合并，计数不因旧快照回退。
- 用户题库：按题库稳定 ID与题目稳定 ID合并。
- 复习状态：按卡片/实体 ID和更新时间合并。
- 进行中试卷：按会话 ID取更新时间较新的版本。
- 设备偏好、BYOK、主题不上传。

### 6.4 客户端可靠性

- 建立集中式同步键/实体注册表；新增学习数据必须登记后才可写入。
- 保留待同步变更，网络失败时不清除。
- `visibilitychange`/`pagehide` 时触发立即同步；普通场景仍使用防抖批量同步。
- 登录后立即拉取并合并；前台定期检查 revision，发现更新自动拉取。
- 同步状态明确显示“已同步 / 等待同步 / 同步失败”，不静默假成功。

### 6.5 隐私边界

服务端只保存学习数据和用户明确选择同步的账号级偏好；API Key、模型配置、主题和设备级行为不上传。同步接口继续执行账号隔离、大小限制和同源写保护。

## 7. 错误处理

- 模型生成失败：不创建半成品，保留原错题，返回可重试状态。
- 所有候选被去重或门禁剔除：返回有效数量、剔除原因摘要和下一步建议。
- 达到 5 道上限：不再调用模型，直接提示上限。
- 同步 401：保留本机未同步数据，要求重新登录。
- 同步冲突：服务端合并后返回结果，不覆盖本机未上传变更。
- 同步超限：拒绝本次变更并保留待同步队列，提示清理数据。
- 删除失败：不从本机移除，明确提示重试。

## 8. 测试要求

### 变式题与产物

- 精确、结构、语义重复均被拦截。
- 变量替换题不得作为有效变式。
- 同一问法类型最多一题；总数最多 5，道具不足不凑数。
- 生成内容与原错题关联稳定。
- 删除变式题/速记卡的级联复习状态正确。
- 判错回流原错题，判对只记迁移证据。
- 书架两组折叠、展开、刷新和空态正确。

### 同步

- 所有账号学习键都进入快照注册表，BYOK/主题不进入。
- 两个客户端同账号登录后共享状态。
- 两个设备并发新增作答、错题、笔记、生成产物时不互相覆盖。
- 删除在旧设备上传时不会复活。
- 网络失败、页面离开和重新登录后数据最终可恢复。
- revision 冲突合并、大小限制、401 和不同账号隔离均有测试。
- 浏览器测试覆盖桌面和 390px 移动视口。
