## 已有能力（不重复建设）

以下在网页版里已经实现，经代码核对确认：

- 题库卡片一点即开始、高级选项收进 `<details>`（`app.js:683-690`、`index.html:191-217`）。

**Files:** `js/app.js`（聊天回答渲染，`app.js:1369-1375` 附近）

## 2026-10-30 线上双端 UX 优化计划（本轮待实施）

### 1. 计划目标

在不改变现有题库、错题、复习和账号同步数据契约的前提下，降低 MedKit 在电脑与手机上的理解成本，使用户能更快完成以下核心任务：

1. 登录或试用后明确知道数据是否同步、下一步做什么。
2. 从首页直接进入唯一优先任务。
3. 在刷题页快速选择题库并开始练习，不被管理功能打断。
4. 在手机上进入独立、稳定、可连续操作的答题状态。

6. 在题库页集中完成导入、同步、生成和管理。

本轮只做前端信息架构、布局、交互和状态表达优化；不增加社交、排行榜、连续打卡、宠物化激励、题目稳定 ID 迁移或新的 AI 生成链路。

### 3. 目标信息架构

#### 3.1 今天

今天页只回答“现在最应该做什么”。根据状态只突出一个主按钮：

- 首次使用：`选择题库，开始刷题`
- 存在未完成会话：`接着做上次练习`
- 存在到期复习：`开始今日复习`
- 今日任务已完成：`查看薄弱知识点`

其余统计、考试、近期活动和薄弱点保留为次级卡片或折叠区，不与主行动并列竞争。

#### 3.2 刷题

刷题页只负责“选择练什么并开始”，固定顺序为：

```text
继续上次练习 → 今日复习 → 快捷练习 → 最近使用 → 全部题库 → 更多选项
```

导入、同步、重命名、排序、启停、生成内容管理不在刷题主流程中展示，改由题库页承载；刷题页保留低干扰的“导入题库”入口作为空状态兜底。

#### 3.3 错题

错题页固定顺序为：

```text
今日复习 → 薄弱知识点 → 按科目练错题 → 全部错题 → 错题助手
```

空状态时先说明错题如何产生，并提供“去刷题”入口；没有错题数据时不把聊天输入框作为第一视觉焦点。

#### 3.4 题库

题库页成为唯一的资源管理中心：

```text
内置题库 → 生成内容 → 导入 / 同步 → 题库管理 → 出题工坊
```

内置题库和生成内容继续支持折叠；题库卡片的“开始练习”只跳转到刷题会话，不在题库页复制另一套练习配置。

#### 3.5 设置

设置分组调整为：

```text
账号与同步
数据与备份
答题偏好
外观
AI 服务（Key + 模型）
危险操作
```

### 6. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 答题全屏化破坏断点恢复 | 先保留现有会话字段，只改变展示层和进入 / 退出时机；补刷新、退出、恢复测试 |
| 题库折叠导致用户找不到题目 | 保留搜索、科目摘要数量和“全部题库”入口；首次展开状态不覆盖业务数据 |
| 错题助手降级后用户认为 AI 被删除 | 明确标注“错题助手”，置于复习之后并保留快捷入口 |
| Toast 调整造成重要反馈消失 | 账号创建、同步错误、导入结果使用页面内状态；Toast 只处理短反馈 |
| 桌面与手机出现两套行为 | 任务顺序和数据状态保持一致，仅改变布局和操作承载方式 |
| 前端文件继续膨胀 | 不新增大文件；优先复用现有函数和 CSS 令牌；继续遵守单文件不超过 800 行约束 |
