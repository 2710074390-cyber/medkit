## 0. 先厘清「分区」的三种语义（重要）

逐字检索全仓「分区」，代码里**没有名为「分区」的模块/表/字段**。它实际落在三个正交层面——三个都建议强化，但**改法完全不同**，混在一起谈会失焦：

| 语义 | 承载物 | 现状 | 本次重点 |
|---|---|---|---|
| **A. 教材分区** | `slice`（`{sid,title,text,source,page}`）+ 角色 `role` | 启发式切分，平面、只读 | ⭐ 主战场 |
| **B. 大纲分区** | `syllabus_items`（subject→chapter→item 两级） | 独立一条线，未与切片挂接 | ⭐ 次战场 |
| **C. 题库分区** | `subject` 单层精确匹配（「分区互斥」R4-16） | 靠字符串串比，别名不归并 | 小改 |

证据：`core/slice.py:1-3`（教材分区定义）、`core/syllabus.py:3-4`（大纲两级）、`core/cards.py:152`（「R4-16：分区互斥」= 题库分区）、`docs/AGENT_HANDOFF.md:12`（别名边界）。

## 1. 当前设计现状与不足

### 1.1 分区（教材切片层）

**现状（机制）**

- **唯一创建点**：`slice_text(blocks, max_chars=MAX_CHARS)` — `core/slice.py:27`。边界判定 = **标题启发式 + 定长兜底**：`CHAPTER_PATTERNS`（6 条正则，`slice.py:10-17`）匹配「第X章/Chapter N/一、/1.1/附录/##」；超长按段落拆（`slice.py:55`）；**无标题则全文定长切**（`slice.py:63-69`，兜底分支）。
- **角色分区**：`role ∈ {textbook, teacher, exam, extra}`（+`image`）—— 前端 `review-desk-materials.js:104` `ROLE_LABEL`；后端 `routers/projects.py:353`。四个独立 drop zone，互不混。
- **配额分配**：`quota.allocate(slices, teacher_text, target)` — `core/quota.py:40`。按 `字数 × (1 + 2.0×min(命中/20,1))` 加权 + 最大余额法（`quota.py:43-59`）。
- **存储**：**无 SQL 表**。项目级 `slices.json`（`routers/projects.py:120`）+ `meta.json.quota`；跨项目素材走 `~/.medkit/sessions/{id}.json`（`core/sessions.py:56-61`）。有 `slices_fts` FTS5 虚表（`db.py:55`）但仅 `syllabus_items` 建了 chapter/kind 索引（`db.py:77-79`）。
- **消费**：`orchestrator.py:1170` `slice_by_sid = {s["sid"]: s for s in textbook_slices}` —— **平面字典**；`_stage_generate` 按 quota 遍历出题（`orchestrator.py:1015-1017`）。
- **一致性重编号**：多教材会话合并按 `sid` 重编号防覆盖（`projects.py:109-114`）。

**不足（逐条带证）**

1. **分区是纯启发式，无「分区正确性」闸门**。`_is_chapter` 只做 `p.match(line)`（`slice.py:23-24`）——**顶格才算章节**；PDF 里常见的「第X章」缩进/加符号即漏判，静默降级为「全文定长切」。且**降级不报错**，仅前端 warning（`_common.py:140-142`）。
2. **单层、无父子层级**。切片只有一层 `{sid,title,text}`（`slice.py:51-53`），无 chapter 父节点；大纲虽两级（`schema.py:299-332`）但**与切片无任何外键/映射**——教材分区和大纲分区是两条平行线。
3. **无切片编辑/合并/拆分 API**。`slices.json` 只在创建（`projects.py:120`）与图片资产增删（`projects.py:414,480`）时写入；**没有 rename/merge/split/edit 端点**。改切片只能重建项目（`routers/pipeline.py:35`「如需重跑请删除后重建」）。
4. **没有跨分区关联**。切片间零 link，`slice_by_sid` 是平面字典（`orchestrator.py:1170`）——无法表达「本章前置是上一章」这类知识依赖。
5. **分区归属靠字符串精确匹配**。题库分区 R4-16 用 `c.get("subject")==subject`（`cards.py:153`），别名/前缀不归并（与 `errsearch` 缩写边界同源，见 §3.4）。
6. **硬编码不可配**：`MAX_CHARS=4000`/`MAX_TITLE=40`（`slice.py:19-20`）、6 条写死正则（`slice.py:10-17`）、`BOOST=2.0`（`quota.py:13`）、`TEACHER_TEXT_LIMIT=4000`（`quota.py:14`，超长重点后段直接不参与锚定）。
7. **无「分区质量」可观测面**：前端只展示 `quota` 各切片题数（`review-desk-project.js:293`），没有切片长度分布/标题缺失率/切片数异常等体检。全仓 `core/` **零 TODO/FIXME**（问题以 R-x 工单化，不在代码里）。

### 1.2 错题管线（EP-01）

**现状（机制）**

- **五阶段** `STAGES=("intake","kp_align","attribute","persist","analyze")` — `errorpipe.py:78`；可任意跳过（P3 是唯一外部依赖，跳过即零 LLM，`errorpipe.py:418`）。
- **闸门** `GATE_REQUIRED=("confidence","my_reasoning")` — `errorpipe.py:81`；缺任一 ⇒ 可入库但**禁止归因**；`_coerce_confidence` 显式拒绝 bool/小数/越界（`:153-174`，非法视为未填、不取默认）；**补填端点被明确禁止**（`routers/errors.py:11-13` + `EditBody` 不含这两字段 `:90-96` + 源码级守卫 `test_no_confidence_backfill_endpoint`）。
- **知识点对齐** `align_kp`（`errorpipe.py:185`）→ `kpid.resolve` 确定性派生 `kp_id`（canonical = `subject|chapter|topic` 归一，`kpid.py:103,133`）；`kp_alias` 表（`db.py:178`）做别名桥。
- **持久化**：`mistakes` 表（`db.py:44`，v8 增 `confidence/error_tag/ai_error_tag/tag_match/round/kp_id` `db.py:171-176`，**列仅作 WHERE 过滤，权威在 `data` JSON** ADR-001）+ `error_events` append-only 流水（`db.py:185`）。
- **掌握度**：**非 BKT**，加权线性—— `score = 0.60×correct_rate + 0.30×(0.4+0.6×recency_kept) + 0.10×confidence`（`library.py:350-364`）；状态阈值 `mastered 0.95 / solid 0.80 / shaky 0.60 / weak`（`library.py:116`）；`priority = 0.50×(1-score) + 0.30×miss_density + 0.20×recent_miss`（`library.py:367-374`）。
- **复习**：**两套调度并存** —— `DEFAULT_SCHED="fsrs"`（`scheduler.py:25`，`SCHEDS=("fsrs","sm2")`）+ 经典 SM-2（`review.py:34-38`：`INIT_EASE 2.5 / MIN_EASE 1.3 / FIRST 1d / SECOND 6d`，`next_intervals` `:95-102`）。
- **复盘层** `metacog.py`（**全纯函数，不落表不缓存**，`:12-15`）：校准曲线 + Brier + JOL 偏差（`:79`）、标签×科目热力图（`:154`）、跨轮次迁移矩阵（`:239`）、人工/AI 一致率（`:302`）、减法清单（`:327`）。**错因只有固定 6 类** `ERROR_TAGS`（`metacog.py:30-37`，「第一轮只留 6 个，绝不扩张」）。

**不足（逐条带证）**

1. **完全没有「卡点/困惑」信号**。全库无 friction 字段；`metacog` 只有 confidence 校准（`metacog.py:79`），没有「卡在哪一步」。`where_uncertain` 只是 AI 结果的 `ai_uncertain`（`errorpipe.py:245-246`），**非用户自报**，也无独立列。
2. **掌握度粒度太粗**。`compute_score` 是**知识点级**（`library.py:350`）；`_kp_key = chapter·topic` 或 `chapter`（`library.py:1160-1164`）。**没有 lookatstudy 那样的「一课 2–7 个知识组件（KC）」层**——无法做「课时掌握度 = 最弱概念」或「⚡弱项优先出题」。
3. **错因粒度被锁死 6 类**（`metacog.py:30`）。这本身是**有意的产品决策**，但导致：无法表达「同一知识点的不同错误子型」，迁移矩阵只能在 6 个大类间跳。
4. **弱点可视化只到 `subject×error_tag`**（`metacog.py:154`）——没有概念图/知识点级热力。
5. **陈旧错题无 prune/merge**。`kpid.merge_into` 只合并**别名**，且**不改已存 `mistakes.kp_id`**（`kpid.py:204-208`）；无按时间的错题清理。
6. **跨次重传去重不可靠**。去重键 `sha1(subject|chapter|question)` 只在 `sync_from_paper`/判分回流用（`library.py:563-576`）；**errorpipe/apkg 导入无跨次去重**（`routers/errors.py:295-325` 逐条 `_ingest_items`）⇒ 重传重复入库。
7. **硬编码阈值无配置面**：`OVERCONFIDENCE_CEILING=0.90`（`metacog.py:47`）、`MIN_BUCKET_N=3`（`:50`）、`bottom_ratio=0.25`（`:328`）、`MAX_NOTES=5000`（`apkg_import.py:50`）、`STUCK_ROUNDS`（`routers/errors.py:700`）。
8. **复盘层「不落表不缓存」是把双刃剑**：万级以下实时算便宜（`:12-15` 论证成立），但**没有历史趋势**——无法回答「我的过度自信这个月比上月好了吗」。

## 2. 可借鉴的功能点与设计思路（lookatstudy）

lookatstudy 的数据模型（`state.json`）里与我们**直接对口**的三组字段：

```jsonc
// C:\Users\38063\.dsh\lookatstudy-plugin\state.json
"courses": [],                      // 课程树（可折叠章节头带完成/总数）
"memoryGlobal": null,               // 学习者记忆三槽位：全局风格
"memoryPatterns": {},               // 单课程模式
"frictionGlobal": [],               // ← 卡点/摩擦信号（静默记录）
"proposals": [],                    // 掌握度提案 propose→apply（等学习者表态才生效）
"lessonSessions": {}, "lessonThreads": {},
"xp": {"total":0,"todayKey":"","todayXp":0},
"streak": {"currentStreak":0,"longestStreak":0,"freezeCount":2},   // 连击 + 冻结卡
"profile": {"style":{"start","interaction","feedback","pacing"}, "motiveStage", ...},
```

| # | lookatstudy 的做法 | 我们对口的现状 | 可借鉴点 |
|---|---|---|---|
| **L1** | **KC 层**：每课提炼 2–7 个概念，逐概念跑 BKT，**课时掌握度 = 最弱概念**，⚡弱项优先测验（README「知识组件（KC）」条） | 掌握度是知识点级、无 KC 层（`library.py:350,1160`） | ⭐⭐ 引入 KC 层 |
| **L2** | **friction/卡点静默记录** `study_report_friction`，显示为 ⚡😣 弱点 | 完全无（§1.2-1） | ⭐⭐ 卡点信号 |
| **L3** | **掌握度提案 propose→apply**：≥85% + 费曼讲解 → 提议提前毕业，**等明确表态才生效** | 掌握度纯自动改状态（`library.py:1160-1214`） | ⭐ 把「跳级/毕业」变成需确认的提案 |
| **L4** | **门控解锁**：章节/课时带锁定态，≥50% 提前解锁下一课；≥90% 毕业并排首次 SM-2 | quota 只分题数，无门控（`quota.py:40`） | ⭐ 分区「解锁/毕业」规则 |

| **L6** | **概念图** `study_map`：本课知识组件排成 draw.io 风格图，**弱项（<70%）琥珀色标出**（内置 ELK 布局，无外部服务） | 无（热力图只到 subject×error_tag，`metacog.py:154`） | ⭐⭐ 知识点级弱点图 |
| **L7** | **康奈尔笔记三区**（线索/笔记/总结），选区→笔记锚点 + 「回到原文」定位 | 无笔记层 | ⭐ 错题笔记锚定 |
| **L8** | **产物卡片沉淀进黑板**：`study_generate_quiz`/`study_pose_guess`/`study_compare_table`/`study_draw_diagram` 各以卡片渲染并沉淀 | 出题产物是文件（押题卷/题库 HTML） | ⭐ 对比表/图自动沉淀为错题产物 |
| **L9** | **吸附「学习者记忆」三槽位**（全局风格 / 单课程模式 / 单课缺口），读-合并-写 | 无学习者画像 | ⭐ 记忆槽位驱动归因/出题风格 |
| **L10** | **软删除 trash** 回收站 | 错题删除无回收站 | ⭐ 删除可反悔 |
| **L11** | **全状态单轮询** `/lookatstudy/api/state` 3s（README「宿主拥有循环，面板拥有 UI」） | 前端各视图各自拉取 | ⭐ 分区/掌握度统一状态面 |

**一句话取舍**：lookatstudy 是「**引导式学习闭环**」（门控推进 + 掌握度驱动 + 提案确认 + 卡点感知 + 记忆槽位），MedKit 是「**证据档案工厂**」（归因 + 校准 + 迁移矩阵 + 减法清单）。**它多的是「学习者状态机」，我们多的是「错误元认知」**——最有价值的借鉴是把它的**KC/卡点/门控**接进我们的**归因/掌握度/分区**，而不是照搬它的游戏化。

## 3. 具体改进方向（含预期收益 / 潜在取舍）

按「先补观测 → 再补结构 → 最后上模型」排序。**P0 = 低风险高收益**，值得先做。

### P0-A「分区体检」闸门（教材分区）

- **做法**：新增只读函数 `slice_audit(slices, blocks)`，产出：切片数、长度分布（p50/p95/max）、**标题缺失率**（`title` 落到「全文」或 `blk_title` 的比例）、超长切割占比、疑似同章重复标题。落成 `GET /api/projects/{pid}/slices/audit`，前端在素材区显示徽标。
- **收益**：把 §1.1-1 那个「静默降级」变成**可见信号**——用户在出题前就知道分区质量，而不是等产物跑偏。
- **取舍**：多一个端点 + README 端点计数要同步（`docs` 守卫 `test_docs_coverage.py`）。纯只读，零风险。
- **验证**：造一份「全部无章节标题」的 md → 断言 `title_missing_rate == 1.0` 且 `fallback=="fixed_length"`；造一份正常 md → 断言 `title_missing_rate < 0.2`。**注入反向验证**：把 `_is_chapter` 改成 `return False` → 体检必须红。

### P0-B「切片编辑/合并/拆分」端点（教材分区）

- **做法**：补三个写端点 —— `PATCH /slices/{sid}`（改 title/text）、`POST /slices/merge`（相邻两块合）、`POST /slices/{sid}/split`（按偏移拆）。全部走现有 per-pid RLock（`projects.py:35-40`）+ 先备份 `slices.json`。
- **收益**：解决 §1.1-3 的「改切片只能重建项目」——这是**当前最硬的功能缺口**，直接影响出题准确性（用户看到切歪了却只能重来）。
- **取舍**：**破坏性**。必须：① 改写前 `cp slices.json` 备份并报路径；② 已出题的 slice 被改动 ⇒ 产物与切片漂移，需在响应里标 `affected_artifacts`；③ 合并/拆分要处理 `sid` 重编号与 `quota` 重算的一致性。
- **验证**：合并两块 → 断言 `len(slices)` 减 1 且 `sum(chars)` 不变；拆分 → 断言文本拼接后与原块**逐字节相等**；改动已用切片 → 断言响应含 `affected_artifacts` 非空。**必须做「注入即红」**：把备份步骤注释掉 → 断言崩（防再次丢档）。

### P0-C「分区树 UI + 状态角标」（教材分区，借鉴 L5）

- **做法**：前端 `review-desk-materials.js` 的四个 drop zone 之上，加一棵**可折叠的分区树**（按 `role` → 按章节 title 聚合），每行带：切片数、字数、配额题数、长度超阈警示。状态角标沿用 lookatstudy 五态语义（锁定/可学/进行中/已完成）。
- **收益**：把 §1.1-7 的「无观测面」变成日常可见；用户能**按章聚焦**而非面对一个扁平列表。
- **取舍**：前端是经典脚本、加载顺序即契约（MEMORY 二）——**新卡片必须留在 `.learnview` 内部**，且新增 JS 片要同步 `test_v15_frontend_split.py` 的 `FAMILIES` 与 `index.html`。守卫判据要取**「可见性随子视图切换而变」**，不是「按 id 查得到」（后者对该缺陷恒真）。
- **验证**：注入「把树移到 `.learnview` 外」→ 前端分域守卫必须红。

### P1-A「卡点信号」（错题管线，借鉴 L2）⭐ 最值得做

- **做法**：新增 **可选** 字段 `friction`（枚举：`困惑/阻塞/沮丧/时间不够`，可多选）在 `normalize_card` 里归一（`errorpipe.py:94`），**不进门禁**（它是自报信号，不是归因前提）。持久化到 `error_events`（已有 append-only 结构，加列/加 JSON key）。P5 新增统计 `friction_by_kp()`，前端在错题卡上显示 ⚡😣 角标。
- **收益**：补上 §1.2-1 的**最大空缺**。卡点与 confidence 是正交的两条轴：一个说「我多确信」，一个说「我卡在哪」——二者交叉能区分「自信但卡」和「不自信但不卡」，这是 lookatstudy 证明有效、而我们**完全缺失**的信号。
- **取舍**：**录入成本增加**（多一个可选项）。必须**默认不填也能入库**，且**不进门禁**——否则违反「闸门字段必须当场填」的既有红线精神（闸门是 `confidence`+`my_reasoning`，不能扩张，`errorpipe.py:81`）。
- **验证**：录一条带 `friction=["阻塞"]` → 断言入库且 `error_events` 有该值；录一条不填 → 断言 `gate_ok` 不受影响。**关键**：断言「friction 未填不阻塞 P3」——这才是「不扩张门禁」的证明。

### P1-B「KC 知识组件层」（错题管线，借鉴 L1）⭐⭐ 收益最大

- **做法**：在 `kp_id`（现在 = `subject|chapter|topic`）**之下**加一层 `kc`（知识点下的 2–7 个概念）。最小实现：`knowledge` 表加 `parent_kp_id` 列（迁移 v9），或新增 `kcs` 表 `(kc_id, kp_id, name, mastery)`；掌握度算法对每个 kc 跑 `compute_score`，**kp 掌握度 = 最弱 kc**（对齐 lookatstudy 口径）。
- **收益**：直接补上 §1.2-2。这是**从「知识点级」到「概念级」的粒度跃迁**：现在的「内科学·心衰」是一个点，之后是「心衰 下的 收缩力/前负荷/后负荷/神经内分泌」四个概念——**弱点定位从"哪个病"精确到"哪个机制"**，且能让 `quota.allocate` 按 ⚡弱项加权出题（对齐 L4）。
- **取舍**：**最大的一次改动**。① 迁移成本：已有 `mistakes`/`knowledge`/`error_events` 三表都要挂 kc；② `metacog` 的迁移矩阵/热力图现有口径以 `kp_id` 为键，要决定是否下移到 kc；③ 概念从哪来——**必须用户/AI 产出**，不能凭空。建议**分两步**：先加列但置空（零破坏），再只在**新录入**的错题上填 kc。
- **验证**：① 迁移幂等（跑两次 schema 一致）；② 断言「kc 全空时 kp 掌握度 == 旧算法结果」（**等价改写必绿**）；③ 断言「某 kp 下某 kc 从 0.9 掉到 0.3 → kp 掌握度同步掉到 ≤0.3」（最弱概念口径生效）。

### P1-C「概念图 / 弱点可视化」（错题管线 + 前端，借鉴 L6）

- **做法**：`GET /api/errors/kp-graph?subject=…` 返回 `{nodes:[{kp_id,mastery,weak}], edges:[{from,to,kind:"前置/包含"}]}`；前端用**离线**布局（lookatstudy 用内置 ELK，无外部服务——我们必须同样零 CDN，MEMORY 架构条）。弱项（mastery < 阈值）琥珀色。
- **收益**：补 §1.2-4。把 `metacog.heatmap`（`metacog.py:154`）的「科目×错因」二维热力图，升级为**知识点一维 + 掌握度着色的图**，痛点从「哪科弱」精确到「哪块知识弱、它连着谁」。
- **取舍**：① 依赖 P1-B 的 kc 层（否则只有 kp 节点，图很稀疏）；② 前端零 CDN 是硬约束——**不能引 mermaid 的 CDN**，需自绘 SVG 或内联布局；③ 阈值（<70%）要可配，别写死。
- **验证**：断言「弱项节点的 `weak==true` 且色值 == 琥珀」；断言「图数据不出仓」（节点全部来自 `/api/errors/*`，不包含教材正文——对齐《总纲》§2.4 的检索面红线，`errsearch.py:31-44`）。

### P2-A「掌握度提案」（错题管线，借鉴 L3）

- **做法**：掌握度跨越阈值（如 0.90）时**不自动改状态**，而是生成 `proposal`（存 `proposals.json`，对齐 lookatstudy 的 `proposals`），前端弹「你已掌握 X，是否标记毕业？」，用户确认才 `apply`。
- **收益**：解决 §1.2 中「掌握度纯自动」的隐患——**防止算法误判直接篡改用户的复习计划**。lookatstudy 的「只有明确决定才生效」是经过验证的人机边界。
- **取舍**：增加一次交互；`proposals` 要处理过期/失效（用户不响应怎么办 → 保留 pending，不静默应用）。
- **验证**：断言「越阈后状态**未**自动改」（**削真行为必红**：把自动 apply 加回去 → 用例必须红）；断言「apply 后才改」。

### P2-B「跨次去重 + 回收站 + 陈旧 prune」（错题管线，借鉴 L10）

- **做法**：① 给 errorpipe/apkg 导入接上已有的 `sha1(subject|chapter|question)` 去重键（`library.py:563-576`），重传返回 `duplicates` 计数而非重复入库；② 删除走 `trash`（软删，可反悔）；③ 提供 `prune`（按「N 轮未复现 + 掌握度 solid」筛陈旧错题，**默认 dry-run**）。
- **收益**：补 §1.2-5、1.2-6。重传是企业/多设备场景的必然，目前会**静默涨库**。
- **取舍**：**破坏性**（prune/删除）。必须遵守 `pack/` 脚本既有不变量（MEMORY：① 默认 dry-run，判据 = **目录逐字节未变**；② 移走用 `rename` 不删；③ 绝不覆盖活文件；④ 不可信数据拒；⑤ 备份在写之前）。
- **验证**：重传同一批 → 断言 `len(mistakes)` 不变且 `duplicates>0`；prune dry-run → 断言 `slices/mistakes` 文件**逐字节未变**（不是只看 rc）。

### P2-C「复盘历史快照」（错题管线）

- **做法**：把 `metacog` 的五组统计**定期落一份快照**（如按轮次/按周，存 `metacog_snapshots.json`），前端画趋势线。
- **收益**：补 §1.2-8。现在「不落表」是对的（避免缓存失效，`metacog.py:12-15`），但**趋势问不出来**。
- **取舍**：引入「快照与真身漂移」这一新失效模式（MEMORY 里 `errsearch` 明确拒绝 FTS 就是这个理由）——**必须快照带口径版本 + 生成时间**，且前端明确标「历史快照 vs 实时」，绝不混算。
- **验证**：断言「快照口径版本变更后，旧快照不被用于新口径曲线」；断言「实时值 == 快照重算值」（口径未变时）。

## 4. 落地关键约束

1. **前端经典脚本、加载顺序即契约**（MEMORY 二）。新增分区树/概念图卡片：**必须留在 `.learnview` 内部**；新增 JS 片必须同步 `test_v15_frontend_split.py` 的 `FAMILIES` + `index.html`；加载期调用的函数不能跨片前向引用。
2. **零 CDN 硬约束**。概念图**不能引 mermaid CDN**（lookatstudy 可以，我们不行）——必须自绘 SVG / 内联布局。
3. **分层单向 `routers → core → db/llm`**。新端点不得在 router 里直接 `cur.execute`；`core` 不得 import `routers`。上帝函数阈值 400 行（`metacog.py` 379 行已接近，加功能要拆）。
4. **门禁不得扩张**。`confidence`+`my_reasoning` 是红线（`errorpipe.py:81`），**friction/KC 一律不得进门禁**，否则违反「补填端点被禁止」的既有设计。
5. **双轨存储**：库域（mistakes/knowledge）**新增存储路径必须走 `library._sql_ready()`**（MEMORY 二）。P1-B 的 kc 表要同时支持 JSON 轨，否则纯净版用户崩。
6. **破坏性操作五不变量**（`pack/` 脚本范式）：默认 dry-run、`rename` 不删、不覆盖活文件、拒不可信数据、备份在写之前。
7. **改动会连带中招的守卫**（必须先读再改）：`test_docs_coverage.py`（README 端点计数 / EP-01 双断言）、`test_readme_test_count_is_not_stale`（测试数 ±5%）、`test_ci_gate_parity.py`（CI 步骤对齐）、`test_errorpipe.py`（`test_no_confidence_backfill_endpoint`）。
8. **schema 迁移要幂等**（P1-B 上 v9）：先跑两次断言 schema 一致，再验证旧数据可读。

## 5. 建议的推进顺序

| 批次 | 内容 | 风险 | 依赖 |
|---|---|---|---|
| **1** | P0-A 分区体检 + P0-C 分区树 UI | 低（只读） | 无 |
| **2** | P1-A 卡点信号 | 低（可选字段，不进门禁） | 无 |
| **3** | P0-B 切片编辑/合并/拆分 | 中（破坏性，需备份） | 批次 1 的体检做前后对照 |
| **4** | P2-B 去重 + 回收站 + prune | 中（破坏性） | 无 |
| **5** | P1-B KC 层（v9 迁移） | 高（最大改动） | 批次 2 的 friction 可作 KC 弱点的旁证 |
| **6** | P1-C 概念图 + P2-A 提案 + P2-C 快照 | 中 | 批次 5 |

**先做 1、2 的理由**：都是**只增不改**、零破坏，且立刻给用户可见价值（分区质量可见化 + 卡点信号），同时为后面的大改（KC 层）积累真实数据——没有真实数据，KC 层的概念划分只能靠猜。

## 6. 一句话总纲

**分区的问题在「结构太浅」**（单层启发式、无编辑、无层级、无观测）；**错题管线的问题在「信号太薄」**（无卡点、掌握度粒度粗、无概念层、无历史）。lookatstudy 的 KC 层 + 卡点 + 门控 + 提案，正好补我们的「浅」与「薄」；但它的游戏化（XP/连击/宠物/朗读）与我们的「证据档案」定位不符，**明确不借鉴**。
