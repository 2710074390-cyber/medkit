## 0. 先把话说明白

### 0.1 与既有方案的关系

仓库里已有 `docs/前端设计重构方案_2026-10-20.html`，其 **S1–S4 已全部落地**：`tokens.css` 语义令牌、字号 16→5 档、圆角 7→4 档、z-index 语义阶梯、暗色抬底、亮色"底灰卡白"、5 页签 IA 收敛、Ctrl+K 命令面板、骨架屏、空态统一。

**所以本报告不是重做设计，而是"落地后复审"**：视觉与令牌层已经过关，问题集中在令牌**没有覆盖到的层**——语义结构、键盘与焦点、间距与组件抽象、请求与渲染效率。

### 0.2 结论先行

**一句话**：这套前端已经是"一位有品味的工程师手工打磨过的作品"，但它的**可访问性语义层基本是空的**，而**组件抽象层被内联样式替代了**。前者让键盘/读屏用户走不通核心闭环，后者让后续每一次改动都在复制粘贴里加债。

六个维度的现状与判断：

| 维度 | 评分 | 判断 |
|---|---|---|
| 页面结构与组件划分 | 5.5 / 10 | IA 清晰（今天/刷题/错题/题库/设置），但**组件抽象缺失**：布局靠内联 flex，文件按行数而非职责切分 |
| 交互与视觉一致性 | 7.0 / 10 | 令牌系统是本项目最强的一层（OKLCH 语义层 + 双主题 + 对比度达标）；但按钮族尚未收敛，**首屏 CTA 是浏览器原生按钮** |
| 响应式适配 | 6.0 / 10 | 覆盖到 390px 且无横向滚动（实测过的），但双栏断点定在 1360px，主流笔记本拿不到；窄屏侧栏固定 60px |
| **可访问性** | **3.5 / 10** | **色彩对比已达标，但语义 / 键盘 / 焦点三层几乎空缺**：刷题选项不可键盘操作、对话框无焦点陷阱、55 个 label 只有 8 个关联控件 |

| 可维护性 | 6.0 / 10 | **守卫体系罕见地强**（域耦合/800 行/CSS 令牌/无孤儿类），但 402 个全局声明 + 152 处内联 handler + 加载顺序即契约 |

**三个 P0**（会阻断核心闭环或属 WCAG A 级违规）：

1. **「题目笔记」弹窗参数错位 → 笔记功能完全不可用**（真 bug，刷题主路径上）
2. **刷题选项是 `<div onclick>`，键盘与读屏都点不了**（"点选项即判分"是产品的心脏）
3. **三个对话框都没有焦点陷阱、没有可访问名称、关闭不归还焦点**（`aria-modal="true"` 是空承诺）

### 0.3 已达标、**不要动**的部分

改动前请先明确这些是资产，不是负债：

## 1. 页面结构与组件划分

### A1 · HTML 单文件承载 5 个页签 + 2 个全局浮层

**位置**：`index.html`（783 行，52 KB）
**现状**：5 个 `.panel` 全部常驻 DOM，靠 `.panel.show{display:block}` 切换；设置页 8 张卡 + 题库页 3 张卡在首屏就被解析。
**影响**：首屏解析与内存占用偏高（隐藏面板的 DOM 也建出来了）；单文件内 5 个页面的结构无边界，`index.html` 成为多人改动的冲突热点。
**优先级**：P2
**建议**：用原生 `<template id="tpl-settings">` 承载设置页（当前最大的隐藏块），首次进入该页签时注入一次。不引入构建、不改 CSS 类名、不影响 `test_css_no_orphans`。

### A2 · 文件按「行数」而非「职责」切分，命名与 IA 已脱节

**位置**：`medkit/web/js/`
**现状**（实测函数归属）：

| 函数 | 实际所在文件 | 文件名义职责 |
|---|---|---|
| `sylLoad` / `rexAnalyze` / `gapPaper` / `enterMistakes` | `learn.js` | "学习中心"（该视图已不存在） |
| 建课表单 / 素材上传 / OCR 进度 | `review-desk-materials.js` | "审核台" |
| 项目列表 / 项目详情 | `review-desk-project.js` | "审核台" |

`learn.js` 实为"大纲 + 真题 + 薄弱组卷 + 错题入口"的杂物间；`review-desk-*` 四片里只有 `review-desk-review.js` 是真正的审核台。根因是 `test_v15_frontend_split.py` 的「单文件 ≤800 行」判据——为了达标而切片，而非为了内聚而分域。
**影响**：新人无法由文件名定位代码；改「大纲管理」时会打开一个叫"learn"却装着设置页逻辑的文件。判据达成了，内聚没达成。
**优先级**：P2
**建议**：按域重命名为 `settings-syllabus.js` / `settings-realexams.js` / `bank-create.js` / `projects-list.js` / `projects-detail.js`；同时把判据从"单文件 ≤800 行"升级为"**单域 ≤N 行 + 跨片引用必须在文件头显式登记**"（登记制在本仓已有先例，见域耦合守卫）。

### A3 · 402 个顶层声明共享一个全局作用域，加载顺序即隐式契约

**位置**：`index.html:759-781`（14 个 `<script src>`）、各 JS 文件顶层
**现状**：实测顶层 `function/const/let` 声明 **402 个**，全部落在同一个全局作用域；`index.html` 的注释自己写明"⚠️ 加载顺序即隐式契约"，`eslint.config.js` 甚至要扫目录把"别人的顶层声明"注入成 globals 才能让 `no-undef` 工作。
**影响**：任何一次调序静默失败（`ReferenceError` 只在运行时炸）；名字冲突只能靠人肉避让；`eslint` 的跨文件 globals 注入随文件数增长而变慢变脆。
**优先级**：P1（架构级，但可渐进）
**建议**：不引入打包器的前提下，用 **命名空间对象收口**：每个域导出一个 `window.MK.learn = {...}`，跨域只经 `MK` 调用。先只对**新增代码**生效，旧代码用 `// TODO(MK)` 标记，避免一次性大 diff。

### A4 · 152 处内联事件属性，HTML 与 JS 双向耦合

**位置**：`index.html` 与各 JS 模板字符串
**现状**：`onclick="..."` / `onchange="..."` 等共 **152 处**（含 JS 模板内生成的）。为让内联处理器能调到函数，代码里不得不在文件尾写 `window.xxx = xxx` 显式挂载。
**影响**：CSP 永远无法收紧到 `script-src 'self'`；重命名函数时 IDE 无法安全重构；HTML 与 JS 的依赖关系不可静态分析。
**优先级**：P2
**建议**：本仓已有事件委托先例（`app.js:297` 的全局外链守卫），照此模式扩为统一 `data-action` 分发：`document.addEventListener("click", e => { const a = e.target.closest("[data-action]"); ... })`。同样**只对新代码强制**，旧代码逐步迁移。

## 2. 交互与视觉一致性

### B1 · 首屏 CTA 是浏览器原生按钮（`.ob-btn` 只有一条 margin 规则）

**位置**：`css/base.css:583`、`js/app.js:565`、`js/app.js:570`
**现状**：

```css
.ob-btn{margin-top:8px}   /* 这就是全部样式 */
```

`<button class="ob-btn">去导入</button>` 因此落回 UA 默认样式：**系统字体（不继承 "Segoe UI / Microsoft YaHei"）、原生灰边框、默认内边距与字号**。
**影响**：这是新用户第一次打开「今天」页（`projCount === 0`）看到的**唯一两个行动按钮**，却是全站唯一没有设计过的按钮。第一印象直接掉档。
**优先级**：P1（低成本、高曝光）
**修复**：改用现成家族 `<button class="act">`（主）/`<button class="act gray">`（次），或补齐 `.ob-btn` 的完整外观并复用 `.act` 的交互态。

### B2 · `.inlineBtn` 的默认语义是"危险"，中性动作必须额外加 `.blue`

**位置**：`css/base.css:210-213`
**现状**：`.inlineBtn:hover{border-color:var(--bad);color:var(--bad)}` —— 默认 hover 变**红**；只有 `.inlineBtn.blue:hover` 才是主色。
**影响**：命名与语义反转。任何人新增一个中性按钮（如"选择文件"忘了加 `blue`）就会得到一个"看起来要删东西"的按钮。当前 `.inlineBtn` 的实际使用者恰好都是破坏性动作（清空/删除），**这是巧合而非契约**。
**优先级**：P2
**建议**：反转默认——`.inlineBtn` 中性、`.inlineBtn.danger` 破坏性；一次性把 4 处破坏性调用改类名。

### B3 · 按钮族仍有 9 种，缺三态契约

**位置**：`css/base.css` 全域
**现状**：`.act` / `.act.gray` / `.act.danger` / `.inlineBtn` / `.inlineBtn.blue` / `.mini-btn` / `.mini-btn.danger` / `.themeBtn` / `.rst` / `.ob-btn`（无样式）/ `.chat-chip` / `.css-pill` / `.chip`。
只有 `.act` 有 `:hover` `:disabled`；`.mini-btn`、`.inlineBtn`、`.rst` 均无 `:active`、无 `:disabled`。
**影响**：禁用态只能靠 `disabled` 属性碰运气（`.mini-btn:disabled` 无样式 → 视觉上看不出禁用）；按下无反馈。
**优先级**：P2
**建议**：收敛为 3 档（主 / 次 / 静默）× 5 态（默认·悬停·按下·聚焦·禁用），其余作为修饰符。这是纯 CSS 改动，风险低。

### B4 · 最高危操作用了最不可控的原生 `confirm()`

**位置**：`js/app.js:384`（清空全部数据）、`js/review-desk-review.js:12`（未保存离开）
**现状**：全站自定义了 `confirmModal`（统一的语气、危险色、ESC 取消回调），但"清空全部学习数据与项目"这个**不可逆操作**却走了原生 `confirm()`。
**影响**：样式不可控、阻塞主线程、无法本地化按钮文案（"确定/取消"而非"清空/取消"），且与前一句"请输入「清空全部数据」"的双重确认在视觉上完全脱节——第一道闸门是定制的，第二道是浏览器的。
**优先级**：P1
**建议**：改为 `confirmModal`，`okLabel` 用"确认清空"，`danger=true`；`review-desk-review.js` 的离开守卫同理（该处若需同步返回布尔值，可保留原生但补注释说明原因）。

### B5 · 可见性全靠 `style.display` 硬切换

**位置**：全站
**现状**：`.style.display` 操作 **93 处**；`index.html` 里 `style="display:none"` **28 处**。
**影响**："这个元素默认可见还是隐藏"散落在 HTML 属性、JS 赋值、CSS 规则三处；调试时无法从 CSS 判断初始态；`display:""` 依赖浏览器默认值（`div`→block，`span`→inline），换成 flex 容器时行为会变。
**优先级**：P2
**建议**：统一为 `hidden` 属性 + `[hidden]{display:none!important}`，JS 侧改 `el.hidden = true/false`。纯机械替换，可由守卫测试防回归。

### B6 · 间距没有令牌，全靠内联样式（视觉一致性的真正根因）

**位置**：`css/tokens.css`（**无 `--space-*`**）、`index.html`、各 JS 模板
**现状**（实测）：

- JS 模板内联 `style=` **176 处**，HTML 内联 **123 处**
- `margin-top:8px` 出现 **33 次**、`margin-top:6px` 12 次、`margin-bottom:8px` 13 次、`margin-top:12px` 10 次

**优先级**：P1（这是"一致性"的根因，且不修则每个新功能都在加剧）

4. 内联样式**只允许**用在"一次性定位"（如 `left:${cum}%`），不允许表达间距。

### B7 · 标题层级：区块标题与卡片标题同为 `h2`

## 4. 可访问性（本报告最重的一节）

> 说明：**色彩对比这块已经做对了**（`tokens.css` 里每个色值都标了实测比值，亮色从 1.00:1 修到卡片浮起、控件边框 3.77:1）。下面的问题**全部是语义、键盘、焦点**，与配色无关。

### D1 ·【P0】刷题选项是 `<div onclick>`，键盘与读屏都操作不了

**位置**：`js/bank-drill.js:362-366`
**现状**：

```js
<div class="bank-opt" id="bopt_${i}" onclick="bankDrillPick(${i})">
  <span class="bank-opt-k">${_BANK_LETTERS[i]}</span>
  <span>${esc(o)}</span>
</div>
```

无 `tabindex`、无 `role="radio"`/`role="checkbox"`、无 `aria-checked`；容器 `#bank_opts` 无 `radiogroup`。`bank-drill.js` 全文 **0 个 aria 属性**。
**影响**：这是产品的心脏交互（"点选项即判分"）。
- 纯键盘用户：只能靠 `A–Z / 1–9` 全局快捷键选中（`bank-drill.js:139-141`），而**这个快捷键在界面上没有任何提示**——侧栏快捷键有 `title`，选项快捷键没有。Tab 键**根本落不到选项上**。
- 读屏用户：听到的是 5 段无角色、无状态、无分组的静态文本，判分后 `.right/.wrong` 只改边框颜色，**完全静默**。
- WCAG 违规：2.1.1 键盘（A）、4.1.2 名称角色值（A）、1.3.1 信息与关系（A）。

**优先级**：**P0**（核心闭环对某类用户完全不可用）
**建议**（视觉零变化）：
1. `.bank-opt` 由 `div` 改 `<button type="button" role="radio" aria-checked="false">`，容器 `role="radiogroup" aria-labelledby="题干id"`；
2. 键盘：Tab 进入组 → `↑↓` 或 `A–E` 移动 → `Space/Enter` 选中；保留现有全局快捷键作为加速器；
3. 判分后在选项上加 `aria-describedby` 指向"✓ 正确答案 / ✗ 你的选择"的隐藏文本；
4. `## 步骤` 拆成两批：先做语义化 + Tab 可达（1 小时内可验收），再做 roving tabindex。

### D2 ·【P0】三个对话框都没有焦点陷阱、没有可访问名称、关闭不归还焦点

**位置**：`index.html:748-757`（`#modal_mask`）、`index.html:738-745`（`#palette_mask`）、`index.html:719-735`（`#bank_drill_card`）
**现状**（全站 grep 实测）：

- `inert` / `focusTrap` / `focus-trap`：**0 处**
- `aria-labelledby`：**0 处** —— 三个 `role="dialog" aria-modal="true"` 全部**没有可访问名称**
- `confirmModal` 打开时只 `$("md_ok").focus()`（`app.js:102`），关闭时**不把焦点还给触发按钮**

**影响**：
- `aria-modal="true"` 是一个承诺："模态之外的内容不可交互"。承诺没兑现——按 Tab 会直接跑到背后的页签和表单上，读屏用户不知道自己在对话框里还是在页面上。
- 对话框被读屏念作 "dialog"，然后**没有名字**，用户不知道该确认什么。
- 关闭后焦点回到 `<body>`，键盘用户需要从页面顶部重新 Tab 一遍才能回到原来的位置。
- WCAG 违规：2.4.3 焦点顺序（A）、4.1.2（A）、2.1.2 无键盘陷阱（A，反向风险）。

**优先级**：**P0**（贯穿全站的每一次确认/删除/反馈）
**建议**：
1. `confirmModal` / `askModal` 内给 `#modal_mask .modal` 加 `aria-labelledby="md_title"`（标题已在 DOM 里，只差一个属性）；
2. 打开时记录 `document.activeElement`，关闭时 `focus()` 回去；
3. 加焦点陷阱：监听 `keydown`，`Tab` 到最后一个可聚焦元素时回卷到第一个（本仓 `paletteKey` 已有"Tab 不逃出面板"的雏形，`palette.js:112-114`，可提取为公共函数）；
4. 遮罩打开时给 `main` / `aside.side` 加 `inert`（现代浏览器原生支持，零 JS 库）；
5. `#bank_drill_card` 同理——它甚至没有"打开时把焦点移进去"这一步（`_bankDrillOpen()` 只改 `display`）。

### D3 ·【A 级】主 tablist 只做了一半的 ARIA tabs 模式

**位置**：`index.html:45-51`、`js/app.js:460-465`
**现状**：`<div role="tablist">` + 5 个 `role="tab"` + `aria-controls`，但：
- 对应的 `.panel` **没有** `role="tabpanel"`、没有 `aria-labelledby`（`#tab-start` 等 5 个面板全是裸 `<section>`）
- 5 个 tab **全部在 Tab 序里**（APG 要求 roving tabindex：只有当前 tab `tabindex="0"`，其余 `-1`）
- `←/→` 方向键不切换页签（APG 要求）
- 同时设置 `aria-current="page"` —— **`role="tab"` 上不该有 `aria-current`**，两者语义冲突

**影响**：读屏用户听到 5 个"选项卡"，按 Tab 要连按 5 次才能离开导航区；方向键无效（与所有主流实现的肌肉记忆相反）；面板没有与 tab 关联，切换后读屏不知道内容区变了。
**优先级**：P1
**建议**：二选一，**推荐后者**——
- 补齐 APG tabs（roving tabindex + 方向键 + tabpanel + 去 `aria-current` + 切换后 `focus()` 到面板标题）；
- 或**降级语义**：改回 `<nav aria-label="主导航">` + `<a href="#start">`，用 `aria-current="page"` 表达当前位置。页签本质是路由，"导航链接"比"选项卡"更准确，且**零键盘实现成本**。

### D4 ·【A 级】55 个 `<label>`，只有 8 个与控件关联

**位置**：`index.html`
**现状**：`<label>` 55 个；带 `for=` 7 个；包裹控件 1 个 ⇒ **≥47 个标签与输入框无关联**。典型：

```html
<div><label>接口地址 base_url</label><input type="text" id="base_url" ...></div>
```

`<label>` 是 input 的**兄弟**，既无 `for` 也无包裹关系。
**影响**：读屏用户进入"设置 → 连接服务商"时，听到的是「编辑框」×4、「组合框」×2，**没有任何名称**。placeholder 会在输入后被清空，也不能替代标签。这是整站表单最普遍的 A 级违规。
**优先级**：P1（数量大但机械可修，可脚本批量 + 人工抽检）
**建议**：统一改为 `<label for="base_url">` 包裹式或 `for=` 关联；`id` 已存在，改动是纯属性级。**注意**：`index.html:97`/`197` 那两个用 `<label style="…height:1px…">.</label>` 做基线对齐的占位必须一起删掉（改成 `align-items:flex-end`）。

### D5 ·【A 级】`textarea` 没被纳入 `:focus-visible` 规则

**位置**：`css/base.css:206`
**现状**：

```css
button:focus-visible,summary:focus-visible,a:focus-visible,input:focus-visible,select:focus-visible{outline:2px solid var(--accent)}
```

**少了 `textarea`**。textarea 只有 `:focus{border-color:var(--accent)}`（`base.css:73`）——1px 边框变色。
**影响**：错题助手的聊天输入框（全站最高频输入）、题库粘贴导入、附加生成要求——这些位置键盘用户很难看出焦点在哪。WCAG 2.4.11 / 2.4.13。
**优先级**：P1（一个选择器，最高性价比）
**建议**：把 `textarea` 加进该规则；顺带补 `[contenteditable]:focus-visible`。

### D6 ·【A 级】判分结果区没有 `aria-live`

**位置**：`js/bank-drill.js:498-513`（`#bank_result`）
**现状**：全站仅 3 处 `aria-live`（`#toasts`、`#vault_chat`、OCR 区）。`#bank_result`（判对/判错 / 你的作答 / 正确答案 / 解析）**没有**。
**影响**：读屏用户点完选项后，页面视觉上出现了完整判分与解析，但**语音上什么也没发生**——他们不知道对了还是错了。
**优先级**：P1
**建议**：`#bank_result` 加 `role="status" aria-live="polite"`；同时给选项的 `.right/.wrong` 补 `aria-label`（"正确答案" / "你的错误选择"），让状态不只靠颜色传达（这也修了 1.4.1 仅靠颜色）。

### D7 ·【A 级】`.segbar` 的 `role="img"` 把它里面的 slider 全部吞掉

**位置**：`index.html:452`/`462`（`role="img"`）、`js/review-desk.js:440-442`（`role="slider"` + 完整 aria 值）
**现状**：配比条容器 `role="img"` 且带动态 `aria-label`；**内部**却渲染了 `tabindex="0" role="slider" aria-valuenow/min/max` 的拖拽把手。
**影响**：ARIA 规范中 `img` 是 **leaf role**——其所有后代在无障碍树中被视为 presentational。所以那三个精心写的 `role="slider"` + `aria-label="拖动调整 A1 与 A2 的配比（方向键 ±5%）"` + `aria-valuenow` **全部失效**，读屏用户看不到任何可调的滑块。（键盘 `←/→` 逻辑本身是通的，`review-desk.js:549-555`，只是 AT 发现不了。）
**优先级**：P1
**建议**：去掉 `.segbar` 的 `role="img"`，改为 `role="group" aria-label="题型配比"`；`aria-label` 的"合计 X%"移到可见的 `.ratioSum`（`index.html:450` 已有），不要在拖拽时高频改 `aria-label`。

### D8 · 聊天区的 `aria-live` 会刷屏，且整列重绘会丢焦点

**位置**：`index.html:623`（`aria-live="polite"`）、`js/learn-vault-chat.js:145-172`
**现状**：
- 流式期间 `_vaultChatPaint()` 每帧（`requestAnimationFrame`）替换气泡的 `innerHTML`，而容器 `aria-live="polite"` ⇒ 读屏每帧都有新内容要播报。
- `result` 事件到达时 `vaultChatRender()` **整列重建** `innerHTML`。

**影响**：① 读屏用户会听到持续被打断的碎片，永远听不完一句完整回答；② 如果用户此刻正 Tab 在「存入错题」按钮上，结果一到，**焦点丢失到 `<body>`**（DOM 节点被替换），键盘操作链路断掉。
**优先级**：P1
**建议**：
1. 流式期间把容器设为 `aria-live="off"`，`result` 落地时改回 `polite` 并只播报一次摘要（"回答完成，共 N 字，3 条来源"）；
2. 局部更新用"只改文本节点的 `textContent`"，`result` 阶段才做完整重绘；
3. 重绘前记录 `document.activeElement` 的 `data-i`，重绘后恢复焦点。

### D9 · 无 `document.title` 更新，SPA 切页对读屏与浏览器历史都不可见

**位置**：`js/app.js:445-493`（`showTab`）
**现状**：全站 `document.title` 出现 **0 次**；`<title>` 恒为"MedKit · 医学题库工坊"。
**影响**：切页签时①读屏不会播报页面变化（WCAG 2.4.2 页面标题）；②多标签页用户无法从标签栏区分；③浏览器前进/后退的历史条目全同名。
**优先级**：P1（三行代码）
**建议**：`showTab` 末尾 `document.title = \`${页签名} · MedKit\``；切换后把焦点移到 `.ptitle`（加 `tabindex="-1"`），让读屏播报新页面标题。

### D10 · 标题层级压平（同 B7）

见 §2 B7。可访问性影响：读屏的"按标题导航"功能失效。

### D11 · 点击目标偏小

**位置**：`css/base.css:504-508`（`.mini-btn`）、`:655-657`（`.dc-cell`）、`:140-141`（`.rst`）
**现状**（按 `padding + font-size × line-height` 估算）：`.mini-btn` ≈ **30×26px**；`.dc-cell` 最小 30px；`.rst`（"重置"）≈ **20px 高**。
**影响**：`.rst` 低于 WCAG 2.5.8（AA，24px）下限；`.mini-btn` 在触屏上误触率高（题库列表一行 3 个 mini-btn 相邻）。
**优先级**：P2
**建议**：`.mini-btn` 提到 `min-height:32px`（桌面）/`40px`（`pointer:coarse`）；`.rst` 提到 24px；`.dc-cell` 最小 36px。

### D12 · `role="button"` 的 `<span>` 没有键盘处理

**位置**：`index.html:74`
**现状**：`<span class="v" id="side_ver" title="检查更新" role="button" tabindex="0">v—</span>` —— 可聚焦，但**无 `keydown` 处理**，按 Enter/Space 无反应。
**影响**：键盘用户 Tab 到这里，看到焦点环，按下却没反应。（鼠标可点。）
**优先级**：P1（一行）
**建议**：改为 `<button class="v" type="button">`（顺带解决 role 与元素语义不一致）。

### D13 · 无 `<noscript>`

**位置**：`index.html`
**影响**：脚本整体加载失败（如 PyInstaller 打包路径错误）时，页面停在骨架屏，用户只看到"加载中…"永远不动。
**优先级**：P3
**建议**：`<noscript>` 一句："MedKit 需要 JavaScript 才能运行，请检查浏览器设置。"

## 5. 性能与加载体验

### E1 · 首屏 14 个阻塞脚本 + 3 个阻塞样式

**位置**：`index.html:8-10`（3 个 CSS）、`759-781`（14 个 `<script src>`）
**现状**：HTML 52 KB + CSS 67 KB + JS **338 KB**（合计 457 KB），**全部未压缩、无 gzip、无 `defer`/`async`/`module`**（实测：14 个 script 标签，0 个带 defer）。CSS 在 `<head>` 同步加载 ⇒ 阻塞首绘。
**影响**：本地 `127.0.0.1` 下网络耗时可忽略，但 457 KB 的**解析+编译**发生在主线程；PyInstaller 冷启动 + 浏览器首绘叠加时，从双击到可交互存在可感知窗口。重复访问有 ETag/Last-Modified 304（FastAPI `StaticFiles` 默认行为），不构成问题。
**优先级**：P2
**建议**（按性价比排序，**均不破坏零构建**）：
1. 14 个 script 加 `defer`（零风险，仅改变执行时机到 DOM 解析后；因脚本已在 body 末尾，实际行为不变，但允许并行下载）；
2. 按页签懒加载：`bank` / `review-desk` 族只在工坊开启时注入（当前是"隐藏了 UI，脚本照加载"——`showTab` 里已有 `genEnabled()` 判断，可复用）；
3. 若要压缩，只在打包阶段（`pack/build.bat`）加一步 terser，源码仓库仍保持可读 —— 这是**唯一需要你拍板**的性能项（见 §7 决策 1）。

### E2 · 打开「今天」触发 8 个请求，`dashboard` 被完全相同地拉 3 次

**位置**：`js/app.js:475-479`、`js/learn-study.js:100-116`、`:157-164`
**现状**：一次 `showTab("start")` 依次调用三个函数：

| 调用 | 请求 |
|---|---|
| `loadStart()` | `/api/library/dashboard`、`/api/projects` |
| `loadDashboard()` | `/api/library/subjects`、`/api/library/dashboard?subject=` |
| `loadLibrary()` | `invalidateLearnCache()` → `loadOverview()`：`/api/library/subjects`、`/api/library/dashboard?subject=`、`/api/library/mastery`、`/api/library/recommend` |

⇒ **`/api/library/dashboard` ×3**、`/api/library/subjects` ×2、合计 **8 个请求**。
更矛盾的是 `loadLibrary()` 第一行 `invalidateLearnCache()`（`learn-study.js:158`，注释："学习中心刷新 = 全量刷新"）**主动把 30s 缓存废掉**，而它紧接着调用的 `loadOverview()` 又依赖 `cachedSubjects()` —— 缓存机制被自己的刷新入口抵消。
**影响**：每次切回「今天」都重复拉全量统计；后端 `dashboard` 要聚合掌握度/闭环/近期活动，是本服务最重的只读端点之一，3 倍开销直接落在每次切页。
**优先级**：P1
**建议**：
1. **单源化**：让 `loadStart` 只负责"今日待办 + 考试计划"，dashboard 数据**只由 `loadOverview` 拉一次**，通过一个 `renderFromDashboard(d)` 分发给右栏；`loadDashboard()` 合并进 `loadOverview()`（两者差一个 subject 参数）。
2. `invalidateLearnCache()` 只保留给"用户明确点了刷新"和"写操作后"，不要在切页时无条件调用。
3. 给 `loadOverview` 加请求序号（`vaultLoad` 已用该模式，见 `learn-vault.js`），防止快速切页时旧响应覆盖新内容。

### E3 · 聊天流式是 O(n²)：每帧重新解析整段 Markdown

**位置**：`js/learn-vault-chat.js:97`、`:157-172`
**现状**：`_vaultChatPaint()` 每帧调用 `_vaultBodyHTML(m)` → `mdRender(m.text)`，而 `m.text` 是**累计的全文**（上限 8000 字）。一个 4000 字的回答 ≈ 每帧解析 4000 字 × 约 500 帧 ⇒ 200 万字符的处理量。
**影响**：长回答时主线程持续繁忙，输入框打字/滚动都会卡；低配笔记本上可感知。
**优先级**：P2
**建议**：流式期间**不渲染 Markdown**，只把新增字符 `textContent +=` 追加（或渲染纯文本 + 末尾光标）；`result` 落地时一次性 `mdRender`。用户感知上反而更"逐字"，且开销从 O(n²) 降到 O(n)。

### E4 · 加载态覆盖不均（同 B8）

见 §2 B8。性能视角的补充：`#dash_loop` 在 `renderDashboard` 里被**两次赋值** `innerHTML`（`learn-study.js:137` 和 `:148` 的 `+=`），第二次会把第一次的 DOM 整体重新解析一遍。

### E5 · 无请求去重/取消（除聊天 SSE）

**位置**：全站 `api()`
**现状**：`api()`（`app.js:70-86`）无 `AbortController`、无超时、无并发去重。快速在「今天 ↔ 错题」之间来回切，会叠加多份在途请求。
**影响**：旧请求晚到会覆盖新渲染（竞态）；无超时时，若后端卡住，用户只能等浏览器默认超时。
**优先级**：P2
**建议**：`api()` 接 `signal`；给"列表型"调用加请求序号守卫（`vaultLoad` 已有实现可复用）；只读端点加 15s 超时。

### E6 · `<img>` 无懒加载

**位置**：`js/review-desk-project.js:360`
**现状**：全站唯一一处 `<img>`（项目图片素材），无 `loading="lazy"`、无 `decoding="async"`、无固定宽高比。
**影响**：上传多张教材图时一次性解码；无尺寸预留 ⇒ 加载完成时布局跳动（CLS）。
**优先级**：P3
**建议**：补 `loading="lazy" decoding="async"` + CSS `aspect-ratio`，容器给 `min-height`。

### F8 · 无类型、无 JSDoc

## 9. 需要你拍板的 5 个决策

1. **是否允许打包阶段压缩？** `pack/build.bat` 加一步 terser 可让 338 KB → ~110 KB，但违反"零构建"。仓库源码仍可读，仅产物压缩。**我倾向"允许，仅打包阶段"**。
2. **导航语义降级还是补齐？** 推荐把 `role="tab"` 改回 `nav + a[aria-current]`（零键盘成本、语义更准），而不是补 APG tabs。需要你确认不介意去掉"选项卡"的读屏播报。
3. **窄屏是否改底部导航？** 这是外壳结构改动（涉及 `showTab` 激活态、浏览器用例、390px 截图回归）。收益是内容区 +60px。**我倾向改**。
4. **文件重命名接受多大 diff？** `A2` 会同时改 `index.html` 的 14 行 script 顺序、`eslint.config.js` 的目录扫描、`test_v15_frontend_split.py` 的分片清单。可以一次性做完，也可以只改新增文件。
5. **a11y 守卫的存量豁免策略？** 47 个 label + 152 处内联 handler 无法一天清零。建议**登记制 + 只减不增**（与 `test_assertion_audit` / `test_skip_audit` 同款机制，你已有成熟范式）。
