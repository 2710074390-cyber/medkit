## 二、类别一：间隔重复 / 记忆算法生态

### 项目 1：Anki（SM-2 调度机制 + 卡牌状态机）

- **链接**：https://faqs.ankiweb.net/what-spaced-repetition-algorithm ；手册 https://docs.ankiweb.net/deck-options.html
- **技术栈**：桌面端 Rust（`rslib`）+ Python 后端；调度代码位于 `rslib/src/scheduler/states`（官方 FAQ 明确给出路径）。

**核心机制（官方文档明确写明）：**

1. **卡牌状态机（4 态）**：
   - `New`（新卡）→ `Learning`（初学中）→ `Review`（毕业复习卡）→ 失败后进入 `Relearning`（重学）。
   - 初学/重学阶段走一组固定步长（默认 1m, 10m），按 Again / Hard / Good / Easy 四键推进；Good 走完最后一步即「毕业」为 Review 卡，Easy 立即毕业。
   - 官方明确：新卡阶段的反复失败**不影响** ease factor（避免 SM-2 原生的 "low interval hell"）。

2. **SM-2 调度规则（Anki 改编版）**：
   - 毕业卡获得 ease factor，起始 2.5。
   - `Again`：进入重学，ease -20%，当前间隔 × new interval（出重学后生效）。
   - `Hard`：ease -15%，间隔 ×1.2。
   - `Good`：间隔 × 当前 ease，ease 不变。
   - `Easy`：间隔 × ease × easy_bonus，ease +15%。
   - 所有新间隔（除 Again）至少比前一间隔多 1 天；ease 不低于 130%。

3. **Anki 对 SM-2 的三处偏离**（官方 FAQ 原文）：
   - 初始学习步长用户完全可控（SM-2 硬编码 1 天→6 天）；
   - 只设 1 个失败键而非 SM-2 的 3 个（失败占比小，靠正面反馈调 ease 足够）；
   - 逾期复习仍记住的卡，下次间隔会被「补加」（late review boost）。

**可借鉴点（对 Cherry Studio 方案）**：
- 卡牌状态机是「错题本」最容易复现的骨架：每道错题就是一张卡，字段记录 `state`（new/learning/review/relearn）、`interval_days`、`ease`、`last_review_date`。
- 不需要真的装 Anki，用一张 Markdown/JSON 表就能实现等价状态机——每次 Agent 启动时扫表，把 `today >= next_review_date` 的题推给你重做。

**来源**：
- https://faqs.ankiweb.net/what-spaced-repetition-algorithm
- https://docs.ankiweb.net/deck-options.html

### 项目 2：fsrs4anki / fsrs-rs（FSRS 双变量记忆模型）

- **链接**：
  - 记忆模型技术文档（DeepWiki 精读）：https://deepwiki.com/open-spaced-repetition/fsrs4anki/5.1-memory-model
  - Rust 实现（crates.io）：https://crates.io/crates/fsrs （仓库 `github.com/open-spaced-repetition/fsrs-rs`）
  - OpenSpacedRepetition 组织主页：https://open-spaced-repetition.github.io/
  - 多语言实现清单：https://open-spaced-repetition.github.io/awesome-fsrs/
- **技术栈**：fsrs4anki = Python（优化器 notebook `fsrs4anki_optimizer.ipynb`）+ JavaScript（运行时调度器 `fsrs4anki_scheduler.js`）；fsrs-rs = Rust（含 Optimizer + Scheduler），已被 Anki 23.10 原生集成。

**核心机制（DeepWiki 与官方 FAQ 明确写明）：**

1. **三变量记忆状态（DSR 模型）**——每张卡独立持有：
   - **Retrievability R**：当前时刻成功回忆的概率（0~1），随时间衰减。
   - **Stability S**：R 从 100% 降到 90% 所需天数（记忆强度/半衰期）。成功复习↑，失败↓，越易的卡涨得越快。
   - **Difficulty D**：该卡对你的固有难度（1~10），反映「复习一次能把 S 提高多少」，比 S 更稳定。
   - 官方 FAQ 原话：「R 每天变化，D 和 S 只在复习后变化」。

2. **遗忘曲线与间隔反推**：
   - FSRS-4：`r = e^(-t/s)`；下一次间隔 `t = s · ln(requestRetention) / ln(0.9)`。
   - FSRS-4.5 改用幂律遗忘曲线 `P(recall) = (1 + factor·t/s)^decay`（DeepWiki srs-benchmark 页明确）。
   - 调度目标：让下次复习日的预期 R ≈ 你设定的 desired retention（默认 0.9）。

3. **参数拟合（与 SM-2 的本质区别之一）**：
   - 模型有 19 个权重 `w0~w18`（v4.5 为 17 个），**不手工调**。
   - 优化器扫描你全部历史复习记录，找出「如果当初用这组参数，最能预测真实回忆成败」的那组参数。
   - 官方 FAQ 原话：「users should not tweak the parameters manually… choose an appropriate value of desired retention」。

4. **理论出处**：Ye, J., Su, J., & Cao, Y. (2022). *A Stochastic Shortest Path Algorithm for Optimizing Spaced Repetition Scheduling*. KDD '22, 4381–4390. doi:10.1145/3534678.3539081（多个第三方页面一致引用此论文，LessWrong 上有作者本人写的 FSRS 演进史 https://www.lesswrong.com/posts/G7fpGCi8r7nCKXsQk ）。

**可借鉴点**：
- FSRS 的 R(t) 本身就是「掌握度估计」——你不需要另造一套掌握度指标，`R = e^(-天数/S)` 就是当前这道题你还记得多少的概率。
- Cherry Studio 方案里，每道错题只需存两个数：`S（天）` 和 `D（1-10）`。答对就按规则增大 S、微调 D；答错就大幅降 S、升 D。下次复习日 = 解出 `e^(-t/S) = 0.9` 的 t。这是不写代码也能手算/让 Agent 算的。

**来源**：
- https://deepwiki.com/open-spaced-repetition/fsrs4anki/5.1-memory-model
- https://faqs.ankiweb.net/what-spaced-repetition-algorithm
- https://crates.io/crates/fsrs
- https://open-spaced-repetition.github.io/awesome-fsrs/

### 项目 3：anki-connect（FooSoft）

- **链接**：GitHub 仓库已迁移至 `https://git.sr.ht/~foosoft/anki-connect`，历史镜像见 https://github.com/FooSoft/anki-connect ；端口 8765。
- **技术栈**：Python（Anki 插件），对外暴露 HTTP/JSON API。

**核心机制（文档明确写明）：**
- 在本机 `http://localhost:8765` 开一个 HTTP 服务，请求体固定三段：`{"action": "<动作名>", "version": 6, "params": {...}}`，响应 `{"result": ..., "error": null}`。
- 常用 action：`deckNames`、`createDeck`、`addNotes`（批量加卡）、`findNotes`、`updateNoteFields`、`answerCards`、`sync`。
- 本质：把 Anki 的内部 Python API 包成 HTTP，让外部脚本/AI 不用打开 Anki UI 就能读写牌库。

**可借鉴点**：
- 这是「Agent → 闪卡软件」的标准桥接范式。Cherry Studio 的 Skills 如果将来要对接真实闪卡 App，就是这个模式：Agent 产出结构化 JSON → HTTP POST 到本地服务 → App 落库。
- 即使你不用 Anki，这个「Agent 输出标准化 JSON schema → 落库」的思路直接可搬到 Cherry Studio：Skill 规定输出字段（题干/答案/标签/S/D/下次复习日），Agent 每次按 schema 输出，追加到你的错题 Markdown 表。

**来源**：
- http://bytemeta.vip/repo/FooSoft/anki-connect （README 镜像，含 version/addNotes 示例）
- https://zatoima.github.io/en/anki-connect-google-cloud-tts-auto-generate/ （addNotes 实战示例）

### 项目 4：genanki（kerrickstaley）

- **链接**：https://github.com/kerrickstaley/genanki ；README 全文 https://raw.githubusercontent.com/kerrickstaley/genanki/refs/heads/main/README.md
- **技术栈**：纯 Python 3 库，离线生成 `.apkg` 文件。

**核心机制（README 明确写明）：**
- 四层概念：`Model`（定义字段和正反模板，如 Question/Answer）→ `Note`（一条事实）→ `Deck`（一摞卡）→ `Package.write_to_file('output.apkg')`。
- **GUID 去重**：每条 Note 有唯一 `guid`，默认是字段值的哈希；同一 GUID 重新导入会**覆盖**旧卡。README 明确：这是「反复改卡面、重新生成 deck、增量导入」的关键。
- 支持 media（音频/图片）、Cloze 挖空模型、自定义 CSS。

**可借鉴点**：
- genanki 示范了「不依赖运行中的 Anki，纯离线造卡包」的路线。Cherry Studio 方案对应物：Agent 把错题写成一个结构化 Markdown/CSV 文件，你定期导入任意闪卡 App。
- **GUID 思想必须抄**：给每道错题一个稳定 ID（如 `西综-病理-肺炎-001`），这样你改解析、改标签后重新生成时不会产生重复题。

**来源**：
- https://raw.githubusercontent.com/kerrickstaley/genanki/refs/heads/main/README.md

### 项目 5：AnkiBrain / AnkiChatGPT

- **链接**：https://ankiweb.net/shared/info/1915225457
- **技术栈**：Anki 插件，对接 OpenAI/其他 LLM API。

**核心机制（插件页面明确写明）：**
- **知识抽取式制卡**：导入你自己的笔记、PPT、PDF、讲义、教材、论文，AI「以你的文档为 source material」自动生成 Basic 或 Cloze 卡，可送进新牌组或已有牌组并打标签。
- **防幻觉约束**：页面强调「Note/document importing and a temperature of zero ensures that the language model adheres strictly to the source material」——即 **temperature=0 + 强制引用源材料**，避免 LLM 编教材里没有的内容。
- 支持在 Anki 内直接和 AI 对话澄清概念，再把答案一键转成卡。

**可借鉴点（对西综考生极其关键）**：
- 西综最忌 AI 瞎编病名/药理机制。AnkiBrain 的教训直接可用：**给 Agent 的 System Prompt 里写死「只能基于知识库中的教材原文作答，不得引入知识库外的医学知识；不确定就说不知道」，并把 temperature 调到 0**。
- 流程：知识库灌《贺银成》/教材 PDF → Agent 读完一章 → 按固定 schema 输出「考点→题干→答案→解析→所属系统章节标签」。

**来源**：
- https://ankiweb.net/shared/info/1915225457

### 项目 6：AnkiAIUtils（thiswillbeyourgithub）

- **链接**：https://github.com/thiswillbeyourgithub/AnkiAIUtils （AGPL-3.0，Python；软件介绍镜像 https://softono.com/software/ankiaiutils ）
- **技术栈**：Python，对接 OpenAI（GPT + DALL-E）。

**核心机制（软件介绍明确写明）：**
- 定位不是「从零生卡」，而是**对已有卡片做二次增强**，尤其针对「你反复 struggle 的卡」：
  - `Explainer`：解释你为什么答错、补知识缺口。
  - `Reformulator`：卡面措辞不清时改写（LLM 被训练成会保留已经合格的卡面，不瞎改）。
  - `Mnemonics Helper`：生成记忆术。
  - `Illustrator`：DALL-E 生成助记图。
- 项目自述面向「medical school and beyond」——医学学生场景。

**可借鉴点**：
- 这是「错题生成」里**变式生成 + 错后补强**的成熟范式：答错一道题，Agent 不只把原题收进错题本，还自动做三件事——① 解释错在哪（Explainer）；② 把拗口的考点改写成更好记的表述（Reformulator）；③ 给一个助记联想（Mnemonics）。
- Cherry Studio Skill 可直接照抄这个工具清单：一个「错题后处理 Skill」，输入是错题+你的作答，输出是解析+改写+助记。

**来源**：
- https://softono.com/software/ankiaiutils
- https://olud.ai/project/thiswillbeyourgithub-ankiaiutils.html （确认 AGPL-3.0、Python、面向医学）

### 项目 7：anki-llm（Raine Virta）

- **链接**：https://crates.io/crates/anki-llm
- **技术栈**：Rust CLI/TUI，对接 OpenAI 兼容 API。

**核心机制（crates.io README 明确写明）：**
- 命令行批量生成/清洗 Anki 卡，支持 `--temperature`（0.0~2.0，越低输出越一致）。
- 生成后进入**交互式 checklist**（方向键+空格多选），由人确认哪些卡真正导入——AI 先出候选，人最后把关。

- temperature 参数理念：制卡任务用低 temperature（0~0.3），助记/改写任务可用稍高。

### 项目 8：DeepStudent（开源 AI 原生学习 Agent）

- **链接**：V2EX 发布帖 https://global.v2ex.co/t/1194966 ；SiliconFlow 官方案例 https://docs.siliconflow.cn/cn/usercases/use-siliconcloud-in-deepstudent

- **AI 错题分析**：用 LLM 深度分析错题，找出知识薄弱点，给个性化学习建议。
- **智能错题管理**：错题自动按「知识点 / 难度 / 时间」三个维度分类。
- **多题统一回顾**：支持一次喂多道错题给 AI，**发现共性错误模式**，生成综合学习报告。
- **ChatAnki 智能制卡**：对话里自然语言触发（如「把这篇文档做成卡片」），AI 批量生成卡片，3D 翻转预览，确认后一键同步 Anki。
- 还集成知识导图、题库练习、作文批改等技能，全部挂在「技能系统」上。

**可借鉴点（这是和你 Cherry Studio 方案最像的一个）**：
- DeepStudent 本身就是「Agent + 技能系统 + 本地数据 + Anki 桥」，和你要做的事同构。它证明了这条路可行。
- **「多题统一回顾找共性错误模式」= 元认知分析的核心**：不要一道题一道题看，定期让 Agent 把最近 N 道错题聚在一起，输出「你最近反复在『心律失常鉴别』上错，根源是『房室传导阻滞分度』没掌握」。这就是知识图谱/薄弱环节诊断的最简实现。
- 错题三维分类（知识点/难度/时间）直接抄作错题表的列。

### 项目 9：MistakeLab（错因认知分类学 + SM-2）—— 闭源，机制借鉴

- **链接**：https://devotellix.github.io/apps/mistakelab/
- **技术栈**：iOS 原生，VisionKit OCR。**如实说明：这是 App Store 商业 App，未开源**，但其错因分类设计是错题本类里最清晰的，故作为「机制模式」而非「可复现代码」收录。

**核心机制（官网明确写明）：**
- **On-Device OCR**：10 秒拍屏/拍书，VisionKit 自动提取题目文本，图片本地存。
- **Cognitive Taxonomy（错因五分类）**：每题必须归到一个根因——
  1. Content Gap（知识缺口：理论没学过）
  2. Careless Mistake（粗心：分心失误）
  3. Misread Prompt（读错题：漏关键词）
  4. Concept Trap / Logic Trap（概念陷阱：被逻辑干扰项带偏）
  5. Time Pressure（时间压力：赶速度慌了）
  - 每类配心理学定义 + 例题 + 诊断建议。
- **SM-2 间隔重测**：错了不马上重测（避免「虚假熟练」），按科学间隔排进 Today's SRS Queue。
- **Mastery Percentage 仪表盘**：掌握度百分比 + 周变化 + 活跃错题数 + 今日待测数。

**可借鉴点**：
- **错因五分类是「错因归类」最成熟的模板**。Cherry Studio 方案里，每道错题让 Agent（或你自己）打一个错因标签 ∈ {知识缺口, 粗心, 读错题, 概念陷阱, 时间压力}。统计一段时间后，你会知道自己主要丢分是「不会」还是「会但粗心」——这两者的对策完全不同（前者补知识，后者练读题节奏）。
- 「Mastery Percentage + 周变化」= 元认知仪表盘的最简形态：`已掌握题数 / 总错题数`，每周对比。

**来源**：
- https://devotellix.github.io/apps/mistakelab/

## 五、专题：FSRS 与 SM-2 的本质区别（按硬要求讲透）

| 维度 | SM-2（Anki 老调度器） | FSRS（Anki 23.10 起内置 / fsrs4anki / fsrs-rs） |
|------|----------------------|--------------------------------------------------|
| **记忆变量个数** | **单变量**：每张卡只有一个 ease factor（起始 2.5），间隔 = 前间隔 × ease。无独立的「难度」维度。 | **双变量（+一个时变量）**：Stability S（记忆强度，天）+ Difficulty D（卡片固有难度，1~10）+ Retrievability R（当前回忆概率，随时间变）。 |
| **间隔怎么算** | 规则式：Good→间隔×ease；Again→重学并降 ease；Hard/Easy 各乘固定系数。常数写死。 | 公式式：先由遗忘曲线 `r=e^(-t/s)`（v4）或幂律（v4.5）反推，令下次复习日的预期 R = desired retention（默认 0.9），解出间隔 `t = s·ln(0.9)/ln(0.9)`。 |
| **参数从哪来** | **人工设定的固定常数**（ease 2.5、-20%、+15%、×1.2 等），全局一张表。 | **从你自己的历史复习数据里机器学习拟合**（19 个权重 w0~w18），优化器找「最能预测你真实回忆成败」的那组参数；每个用户参数不同。 |
| **优化目标** | 无显式目标函数，凭经验调间隔。 | 显式优化：在**达到目标保留率（如 90%）的前提下，最小化总复习次数**——建模为随机最短路径问题（KDD 2022 论文标题即 *A Stochastic Shortest Path Algorithm for Optimizing Spaced Repetition Scheduling*）。 |
| **对「逾期复习」的处理** | Anki 版已加 late-review boost，但仍是启发式。 | 官方 FAQ 明确：FSRS 对「隔了几周/几个月回来复习」的排程明显更好，因为 D/S 是连续估计的。 |
| **用户要调什么** | 要调一堆 deck option（learning steps、new interval、easy bonus…）。 | 官方原话：用户只需设一个 desired retention，其余参数别手动碰。 |

**一句话总结**：SM-2 是「一套固定乘法规则 + 一个全局乘数」，FSRS 是「一张你个人记忆的数学模型（S 和 D）+ 从你错题历史里拟合出来的参数 + 一个保留率目标反推间隔」。FSRS 把「这道题你大概还记得多少」变成了一个可计算的概率 R(t)——这恰好就是元认知分析要的「掌握度」。

**来源**：
- https://faqs.ankiweb.net/what-spaced-repetition-algorithm （Anki 官方对 DSR 三变量、desired retention、ML 拟合的原话）
- https://deepwiki.com/open-spaced-repetition/fsrs4anki/5.1-memory-model （遗忘曲线、间隔公式、w0~w18 参数、优化器/调度器分工）
- https://www.lesswrong.com/posts/G7fpGCi8r7nCKXsQk （作者 Jarrett Ye 本人写的 FSRS 演进史）

## 六、归纳：三大功能在开源世界最成熟的机制模式

### 模式 A：错题生成 = 「知识抽取 + 变式生成 + 防幻觉约束 + 人工闸门」

- **知识抽取**：把教材/讲义/PDF 喂给 LLM，以源材料为唯一依据抽考点（AnkiBrain、DeepStudent ChatAnki）。
- **变式生成**：一个考点产出 Basic（问答）/ Cloze（挖空）/ MCQ（选择）多种题型（AnkiBrain、anki-llm）。
- **防幻觉约束**：temperature=0 + Prompt 写死「只依据知识库原文，不得外引」（AnkiBrain 明确写 temperature=0）。
- **人工闸门**：AI 出候选清单，人确认后才入库（anki-llm 的交互式 checklist；DeepStudent 的 3D 预览确认）。
- **错后补强**：答错的题再触发 Explainer（解析）+ Reformulator（改写）+ Mnemonics（助记）（AnkiAIUtils）。
- **支撑项目**：AnkiBrain、anki-llm、AnkiAIUtils、DeepStudent、genanki（结构化输出格式）。

### 模式 B：错题管理（间隔重复调度）= 「卡牌状态机 + 双变量记忆模型 + 保留率目标反推」

- **状态机**：New → Learning → Review → Relearn，四键评分驱动转移（Anki）。
- **双变量**：每道错题记录 Stability S（天）和 Difficulty D（1~10），答对增 S/微调 D，答错降 S/升 D（FSRS）。
- **掌握度即 R(t)**：`R = e^(-距今天数/S)`，R<0.9 就该重做（FSRS）。
- **间隔反推**：下次复习日 = 解 `e^(-t/S)=0.9` 得 t（FSRS 公式）。
- **轻量替代**：不做参数拟合，直接用 FSRS 默认 w 参数 + desired retention=0.9，对考研强度足够（本报告推断：FSRS 默认参数本身就是在大规模真实数据上拟合的通用模型，个人冷启动期不必先优化）。
- **支撑项目**：Anki（SM-2 状态机）、fsrs4anki / fsrs-rs（DSR 模型与间隔公式）、MistakeLab（SM-2 错题重测）。

### 模式 C：元认知分析 = 「作答历史统计推断 + 错因归类学 + 跨题共性聚类」

- **掌握度估计**：不主观判断「会/不会」，用 R(t) 概率量化（FSRS 的 Retrievability 就是掌握度）；或 MistakeLab 的 Mastery Percentage = 已掌握/总数。
- **错因归类**：每题强制打一个根因标签，模板直接抄 MistakeLab 五类（知识缺口/粗心/读错题/概念陷阱/时间压力）。
- **薄弱环节诊断**：把最近 N 道错题聚在一起做共性分析，从「这道题错」追溯到「背后哪个知识点没掌握」（DeepStudent 多题统一回顾）。
- **知识图谱**：最轻量的实现不是真画图，而是给每题打「系统→章节→考点」三级标签，统计哪个标签下错题密度最高（DeepStudent 的知识点分类；本报告推断：Cherry Studio 知识库的文件夹结构本身就是知识图谱）。
- **支撑项目**：FSRS（R(t) 掌握度）、MistakeLab（错因五分类 + Mastery 仪表盘）、DeepStudent（多题共性聚类 + 知识点三维分类）、AnkiAIUtils Explainer（错后补缺口）。

## 七、对「Cherry Studio Agent + 知识库 + Skills」方案的落地启示

> 以下为**本报告基于上述机制的推断与建议**，非任何项目文档原文。

1. **知识库 = 你的 RAG 源**：把西综教材/贺银成 PDF 灌进 Cherry Studio 知识库，作为错题生成的唯一依据（学 AnkiBrain 的 temperature=0、只依据原文）。
2. **错题表 = 你的数据库**：用一个 Markdown 或 CSV 文件存所有错题，字段建议：
   `ID | 题干 | 答案 | 解析 | 系统→章节→考点标签 | 错因类别 | S(天) | D(1-10) | 上次复习日 | 下次复习日 | 状态`
3. **Skill 1（生成）**：触发「把这页书/这道错题做成卡片」→ Agent 按 schema 输出 → 你确认 → 追加进错题表。
4. **Skill 2（调度）**：每次打开对话，Agent 先读错题表，挑出 `今天 >= 下次复习日` 的题（即 R<0.9）推给你重做；你答完后 Agent 更新 S、D 和下次复习日（按 FSRS 简化公式手算）。
5. **Skill 3（元认知周报）**：每周让 Agent 把本周错题聚在一起，输出三件事——① 错因分布（五类各占多少）；② 错题密度最高的 3 个考点；③ 一句「你主要丢分是不会还是粗心」。
6. **GUID 思想**：每题一个稳定 ID（如 `xs-path-肺炎-001`），改解析重生成时不产生重复题（学 genanki）。
