# AI 辅助学习的行业标杆与 MedKit 改进方案

> 调研时间：2026-10-27　|　对象：MedKit v0.20.0（本地优先 · 医学题库工坊）
> 方法：公开产品文档 + 同行评议文献 + 独立技术拆解 + 本仓代码静态审计（结论标行号）
> 证据分级：**强** = RCT / 系统综述　**中** = 官方技术文档 / 公开 benchmark　**弱** = 厂商宣称 / 二手报道

---

## 0. 结论先行

**MedKit 缺的不是模型能力，是中间那一层。**

它今天是一个很好的「生成器 + 刷题器」：能把教材变成题、能把题刷成错题、能把错题变成可检索的 markdown。
但行业头部已经走到「学习者状态 + 教学策略引擎 + 可验证内容」——三者构成闭环，模型只是执行器。

MedKit 有四处结构性断点，全部可在代码里指认：

| # | 断点 | 代码位置 | 后果 |
|---|---|---|---|
| **A** | **作答流水没进学习者模型**——`bank_attempts` 是全量流水，但掌握度只由**错题**聚合 | `core/bank.py:22`（设计说明原文）；`library.py:1353 _touch_knowledge_in`（只在错题入库/更新时被调）；`library.py:350 compute_score` | 模型里的「正确」不是「答对」，是「**错题后来被攻下了**」；答对 50 题掌握度不动 |
| **B** | **题目没有稳定的知识点身份**——`subtopic` 是自由字符串，`syllabus_items.id` 是稳定 id，两者之间没有 join | `schema.py:62 QuestionItem`（无 `kc_id`）；`db.py:219` `bank_items`（`topic TEXT`）；`db.py:69` `syllabus_items`（有 id） | 做不了知识追踪、跨题库聚合、前置知识追溯；同一个考点在不同题库里是三个不同的字符串 |
| **C** | **错题之后是「问答」，不是「教学」**——Agent 只读检索 + 引用 + 拒答，没有诊断策略、支架梯度、fading | `medkit/prompts/mistake_agent.md:25-36`（四条硬规矩）；`agents/mistake_agent.py`（3 个只读工具，≤5 轮） | 它回答你的问题，但不改变你的状态；这是 2023 年的 RAG 形态，不是 2026 年的 tutor 形态 |
| **G** | **悬空依赖：排期域的委托目标已被删除**——`bank.py` 把「何时该复习」委托给「既有的知识点级调度（review / cards）」，而这两个域在 v0.15 精简中已删；ADR-004 决策的 FSRS 实现随 `core/scheduler.py` 一起消失 | `core/bank.py:22`；`CHANGELOG.md:316`；`docs/adr/ADR-004-fsrs-scheduler.md`（状态仍为「已接受」）；`core/vault_index.py:415-446` | 线上唯一的排期是**逐值复制过来的 SM-2**（注释自称「本域唯一实现」）；**FSRS 从未接到线上路径**；README 目录树里的「scheduler(FSRS·SM-2)」与实现不符 |

另有三个次要但真实的缺口：

| # | 缺口 | 位置 | 说明 |
|---|---|---|---|
| **D** | 溯源是**字符串对齐**，不是语义蕴含 | `gates/trace_check.py:14 _align_hit`（整串命中，否则**前 2 字**命中即过） | 引用对了切片、内容说错了，门禁照样放行 |
| **E** | 解析是**一整块文本**，没有逐选项理由 / 误解标签 / 原文引句 / 难度标定 | `schema.py:62` 只有 `analysis` 单字段 | 与 UWorld / AMBOSS 的核心体验差距不在题，在**解析的教育密度** |
| **F** | 排期是 **SM-2 + 每题一卡**，不是 FSRS + 每知识点一卡 | `core/vault_index.py:415-446`（`ease/interval/reps/lapses`） | 同一考点的 5 道错题 = 5 张卡，重复复习；SM-2 比 FSRS 多约 20–30% 复习量 |

**一句话路线**：先补 A/B（数据层，2–3 周，零新模型），再补 C（策略层，4–6 周），最后补 E/F 与临床推理（差异化，6–10 周）。

## 1. 行业全景：五种范式，五条护城河

市面上的「AI 辅助学习」不是一类东西。按**它究竟在哪一层建立壁垒**，可以分成五种范式。这个分类比按「学科/年龄段」分更有解释力，因为每一种范式对应一种不同的工程重心。

### 范式 A · 约束式导师（pedagogical constraint）

**代表**：Khanmigo、ChatGPT Study Mode、Gemini Guided Learning（LearnLM）

**怎么实现的**

- **Khanmigo**：底层是 GPT-4 一类的通用模型，护城河在**编排**而不在模型。请求先被分类（要答案 / 要提示 / 闲聊 / 越界），再检索 Khan Academy 的课程与练习图谱拿到「你正在学哪一课」，然后走一条苏格拉底链（反问 → 提示 → 分步引导），最后过一层响应过滤。三道约束叠加：system prompt + orchestration + 输出审计。所以它能做到「同一道题，学生要答案时给的是下一步问题」。
- **ChatGPT Study Mode**：与教师、学习科学家共同撰写的**自定义 system instructions**，明确五个行为目标——激发主动参与、调节认知负荷、发展元认知与自省、培养好奇心、给具体可执行的反馈。配套动作是「先问你已知什么 / 卡在哪 / 下一步想怎么做」，再分层解释，再用开放题检查理解。它不是新模型，是**行为层**。
- **LearnLM / Guided Learning**：把这套东西做成训练目标。Google 的做法叫「教学法指令跟随」（pedagogical instruction following）——训练与评测样本里带 system-level 的教学法属性描述，模型学会**按指令切换教学角色**（tutor / coach / TA）。五条学习科学原则：主动学习、认知负荷管理、适应学习者、激发好奇、深化元认知。

**特色**：不给答案；分层解释；检查理解；在对话内完成「教—练—测」。

**证据（强/中）**

- 塞拉利昂 1,763 名初中生，8 周内使用 Guided Learning ≥12 小时，数学从第 50 百分位升到第 64 百分位，折算约 **1.8–2.5 年**学习进度（Google × Fab AI，预注册 RCT）。
- 与 Eedi 合作的英国课堂试点：全部消息中仅 **0.1%** 含事实错误；接受短程辅导的学生在**后续新题**上比纯人类辅导组高 **5.5 个百分点**。
- Tutor CoPilot（斯坦福，1,800 名学生 RCT）：给辅导者实时建议，学生掌握率 **+4pp**；评分最低的辅导者组 **+9pp**，追平高分同行；成本 **$20/辅导者/年**。

**边界**：时间压力下学生会嫌它绕（多份家长评测提到「孩子想要答案，不要教练」）；一旦脱离课程锚定，幻觉率上升；「不给答案」是产品选择，不是模型属性——这意味着它可以被 prompt injection 绕过，需要对话监控。

### 范式 B · 学习者模型驱动（learner model）

**代表**：Duolingo Birdbrain、ALEKS、OATutor、松鼠 AI

**怎么实现的**

- **Birdbrain V1**：给「用户能力」和「题目难度」各一个标量，用国际象棋 Elo 的方式更新——答错则能力下调、难度上调；「惊讶越大，更新越大」（新手做对难题，双方都大幅移动）。**V2** 换成 LSTM，把整个交互史压成 **40 维向量**，每答一题更新一次；每天处理约 **10 亿**次作答，单次决策约 **14ms**。Session Generator 再用这个状态挑「刚好在你最近发展区内」的题。
- **OATutor**（UC Berkeley，MIT 许可）：教科书式的 ITS。知识点在**步骤级**标注（`skillModel.json`），用 **BKT**（四参数 HMM：已掌握概率 / 学习率 / 失误率 / 猜测率）估计掌握度；每次作答后跑 BKT 更新，下一题选「所有未掌握题里掌握度最低的」；提示系统分三层：hint（纯文本）→ scaffold（带输入的引导步骤）→ bottom-out hint（直接给答案，防卡死）；`variabilization` 用模板变量把一道题扩成多道；作者用 Google Sheets 写内容，夜间脚本转 JSON 并做质量检查。
- **松鼠 AI**：把知识点拆到「纳米级」，用 **MCM**（思维 Model of Thinking / 能力 Capacity / 方法 Method）做三维能力画像；架构是数据层（题库 + 知识图谱 + 行为数据）→ 模型层（内容推荐、用户画像、目标管理）→ 应用层（路径规划、情感干预）。它最出名的能力是**前置知识溯源**：一道二次函数总错，系统顺着图谱追到「分数约分」的认知断层，先补两年前的地基。

**特色**：知道「你会什么」（状态估计）+ 知道「这题多难」（题目标定）+ 知道「下一步该做什么」（策略）。

**证据（中）**

- 公开数据集上知识追踪的 AUC 区间：BKT **0.71–0.76**、DKT **0.76–0.82**、SAKT **0.81–0.84**、SAINT **0.82–0.85**、AKT **0.80–0.83**（行业综述汇总，非单一论文）。
- OATutor：课堂试点 150 人、累计 **7 万+** 次提交；16 名作者 6 个月完成一门大学代数课，人均培训 **2.27 小时**、单题 **11 分钟**。
- Birdbrain 的 D7 留存 +12% 属厂商/二手材料，**证据强度弱**，只作方向参考。

**边界**：冷启动（没有作答就没有状态）；强依赖「题目 ↔ 知识点」映射的质量；深度模型在小数据上打不过 BKT——**样本量决定模型选型，不是先进程度决定**；松鼠 AI 的多数指标来自厂商材料。

### 范式 C · 闭环语料 RAG（closed-corpus grounding）

**代表**：NotebookLM（2026 年更名 Gemini Notebook）、Coursera Coach

**怎么实现的**

标准五步：**ingest → chunk → embed → retrieve → grounded generation → citation**。真正的设计决策在第四步之后：模型被明确要求「只用检索到的段落回答」，检索不到就说不知道；每个结论回指到具体段落，用户可点开核对。音频概览不是另一套系统，而是**同一语料**上的脚本生成 + TTS；思维导图、测验、闪卡也是同一语料的再渲染。

**特色**：低幻觉、逐句可核。封闭语料既是可靠性来源，也是能力天花板——它只懂你给的东西，而且**语料是静态快照**，会过期。

**证据（中）**：官方文档 + 多份独立拆解一致；**没有**学习增益的 RCT，它的价值是「读得动、查得到」，不是「学得会」。

**边界**：这是研究/阅读工具，不是教学法。它能帮你理解一份材料，但不能诊断你的误解、不能安排复习、不能判断你是否真的掌握。

### 范式 D · 题目银行工业（item bank + rationale）

**代表**：UWorld、AMBOSS、Osmosis

**怎么实现的**

- **UWorld**：Step 1 约 3,600 题，每道题的**每一个选项**都有 rationale（为什么对、为什么错），配图、表、流程图；界面按 NBME 复刻（mark、strikeout、block 计时）；自测后给**预测分**；解析可一键转 SmartCard，进入 FSRS 排期。官方称 **90%+** 美国医学生用它的 Step 1 题库。
- **AMBOSS**：核心不是题，是**双向交叉链接**——每道题对应一篇 Learning Card，每篇文章反向挂题；做错的知识点会在文章里被 **Learning Radar** 标红；High-Yield 模式把文章压到考点；每道题带 1–5 的「锤子」难度、Attending Tip（资深医生会怎么想）、Key Info 标注；Score Predictor + 同侪对比；与 AnKing 牌组打通。
- **Osmosis**：视觉优先。1,700+ 基础科学视频、2,700+ Step 1 风格题、决策树、闪卡；产品页把学习科学标签直接写出来——chunking、active recall、spaced repetition、interleaving、spiral curriculum、elaborative rehearsal。

**特色**：解析的**教育密度**（每个错选项都教一次）+ 内容互联（题→文→卡）+ 心理测量学（难度、预测、同侪）。

**证据（中/强）**

- 产品文档与官网（中）。
- AI 生成 MCQ 的系统综述（Oxford Academic, 2026）：AI 题的**区分度偏低、无效干扰项常见**，整体像「新手写的题」；提示词约束了蓝图/格式/认知层级时可用率显著提高（强）。
- 一项 65 题的实测：**49%** 至少有一处命题缺陷，**60%** 干扰项不当，**22%** 存在事实/概念错误（强，但样本小、模型代际旧）。

**边界**：内容成本极高（150+ 医生、1,400+ 篇文章），个人项目不可能复制；对「你们学校老师划的重点」无解。

### 范式 E · 模拟与推理训练（simulation & reasoning drill）

**代表**：Geeky Medics、Quesmed OSCE-AI、iatroX、LLM 虚拟病人

**怎么实现的**

- **LLM 虚拟病人**：一份病例脚本（主诉 / HPI / PMH / 用药 / 查体 / 化验）+ 角色约束（只回答被问到的，不主动倾倒信息）+ 语气与情绪设定；对话结束按量表给反馈。JMIR 2025 的前瞻研究：盲评医生给真实度 **4.7/6**，单次对话成本 **$0.51**，98% 的对话能体现不同的病人偏好。
- **OSCE-AI**：AI 病人 + AI 考官 + 真实 mark scheme 打分。Geeky Medics 已做到 1,300+ 站、900+ 虚拟病人，支持语音；Quesmed 把它接在题库之后，形成「知识练习 → 站点演练」的管道。
- **iatroX**：反其道而行——不模拟病人，只在**错误发生的那一刻**做苏格拉底式追问：「你的首要诊断是什么 / 哪个特征让替代诊断可能性下降 / 什么结果会改变你的概率」，逐层暴露推理断点，命名误解，引用指南，安排重测。它的定位很准确：**知识 → 检索 → 推理 → 模拟 → 反馈 → 反思**，每一层不同工具。

**特色**：承诺再揭示（commit then reveal）；量表化反馈；可重复、零社交成本。

**证据（强）**

- AI 反馈组 OSCE 得分 7.39 vs 6.68（/10），**d=0.74**；通过率 **96.7% vs 79.6%**（每 6 人多过 1 人）。
- 247 名医学生 RCT：AI 模拟病人组 OSCE 中位数 11.4 vs 10.7（/20），**缺考率 4.9% → 0.8%**，44% vs 10% 表示「心理上准备好了」。
- 39 项研究的系统综述：LLM 虚拟病人的 top-k 诊断准确率 0.45–0.98；有监督微调后幻觉率低至 **0.31%**；**接入知识图谱让诊断准确率再 +16.02pp**。

**边界**：模拟练的是「表现层」，不是「知识层」。学生可能流利地问出自己解释不了的体征——「练站不练底」是这类产品最常见的误用。

### 五范式横向对照

| 维度 | A 约束式导师 | B 学习者模型 | C 闭环 RAG | D 题目银行 | E 模拟训练 |
|---|---|---|---|---|---|
| 核心资产 | 教学策略编排 | 学习者状态 + 题目参数 | 你的语料 | 题 + 解析 + 内容网 | 病例 + 量表 |
| 知道「你会什么」 | 弱（对话内推断） | **强** | 无 | 中（统计） | 中（单次表现） |
| 知道「这题多难」 | 无 | **强** | 无 | **强** | 中 |
| 内容从哪来 | 平台课程 | 平台题库 | 用户上传 | 自建（数百人） | 自建病例 |
| 幻觉控制 | 中（约束 + 过滤） | 不涉及 | **强**（闭卷 + 引用） | 强（人审） | 中（脚本约束） |
| 长期记忆 | 弱–中 | **强** | 无 | 强（统计） | 弱 |
| 教学法深度 | **强** | 中 | 弱 | 中（解析即教学） | **强**（反馈） |
| 单用户可复制性 | 高 | 中 | **高** | 极低 | 中 |
| 典型证据 | RCT（学习增益） | benchmark（预测精度） | 无学习增益 | 系统综述（题目质量） | RCT（OSCE） |

**这张表的读法**：没有一种范式同时占住「个性化」「可验证」「可复制」。MedKit 的机会在**交叉点**——它有 C 的可验证性（自有语料 + 引用）、D 的内容生成能力、B 的数据原料，缺的是把三者接起来的那根轴。

## 2. 技术底座的六个关键决策

这一节回答「它们到底怎么实现的」，只保留对 MedKit 有移植价值的判断。

### 2.1 知识追踪：模型选型由样本量决定，不由先进程度决定

| 模型 | 结构 | 公开 AUC | 适用门槛 |
|---|---|---|---|
| BKT | 每知识点一个 4 参数 HMM | 0.71–0.76 | **< 50 万**交互；可解释、可手调 |
| DKT | LSTM/GRU | 0.76–0.82 | 跨知识点迁移、有遗忘曲线需求 |
| SAKT | Transformer 自注意力 | 0.81–0.84 | 1–5 百万交互 |
| SAINT | 双编码器 Transformer | 0.82–0.85 | > 1,000 万交互、有 ML 工程师 |
| AKT | 注意力 + IRT 难度 | 0.80–0.83 | 需要难度建模的自适应测评 |

行业里的共识很务实：**50 万交互以下用 BKT，1–5 百万上 SAKT，1,000 万以上才谈 SAINT**；`simpleKT` 这类工作也证明，调好的标准基线常常打平自研架构，而维护成本差一个量级。

**对 MedKit**：单用户本地数据永远到不了 10 万级。正确答案是 **BKT + 逻辑回归混合**，参数用经验贝叶斯从「人群先验」收缩到「个人后验」——先验可以内置（医学知识点的典型学习率/失误率），后验随作答更新。这恰好是 MedKit 能做的：它不需要海量数据，它需要**每个用户自己的曲线**。

### 2.2 题目标定：单用户场景下，「个人难度」比「群体难度」更可行

经典做法是 IRT（1PL/2PL/3PL）：难度 b、区分度 a、猜测 c，能力 θ 与题目参数在同一潜在尺度上。CAT（计算机自适应测试）就是它的应用：每次选「在当前 θ 处信息量最大」的题，直到能力估计的标准误足够小。

但 IRT 的硬门槛是**每题 300–500 份作答**。单用户本地永远达不到。可行的替代：

1. **p 值 + 点二列区分度**：题目的历史正确率、与同卷总分的相关。样本少时用**经验贝叶斯收缩**（向 0.6 的正确率先验收缩），并显式标注置信度。
2. **LLM 预估 + 实测校准**：出题时让模型给 1–5 难度（AMBOSS 的锤子），上线后用实测 p 值回归校正——这既是难度标定，也是**出题质量的反馈信号**。
3. **个人难度而非群体难度**：同一道题对 A 是 0.8、对 B 是 0.3，这在本场景不是噪声，就是我们要的信号。

**对 MedKit**：`bank_attempts` 已经在记 `correct`，只要补一个 `item_stats` 聚合（p 值、区分度、作答数、置信区间），就能做三件事：自动识别坏题（p<0.2 或区分度为负）、按难度分层抽卷、给「这题对你偏难」的提示。**零新模型，纯 SQL + 收缩公式。**

### 2.3 检索：FTS 够用，向量是补充，图谱只在「概念对齐」时值得

- NotebookLM 的可靠性来自**闭卷**，不是来自向量库。FTS5 + jieba 已经能覆盖「我记得那句话里有『湿啰音』」这类查询。
- 向量的价值在**同义/跨语言/概念级**召回（「心衰」↔「heart failure」↔「HFrEF」）。本地可跑 bge-m3 / bge-small-zh，成本可控。
- 医学本体（UMLS / SNOMED / ICD-11 / MeSH）的正确用法是**概念对齐与归一**，不是「建一个 45K 节点的 Neo4j」。GraphRAG 的实证收益是 **+6–7% 相对准确率**（LLaMA3-8B：PubMedQA 51.2→54.4，BioASQ 75.0→80.0），代价是一整套图维护管线。对 MedKit，先把 `syllabus_items` 的稳定 id 用好，比引入 UMLS 划算一个数量级。

### 2.4 教学策略：EDF 循环 + 四类支架 + 显式 fading

这是最被低估的一层。研究给出的可操作框架是 **Evidence–Decision–Feedback**：

1. **Evidence**：从作答、停留时间、对话、自评置信度里估计「当前认知状态」（= 最近发展区）。
2. **Decision**：选择教学意图（探查理解 / 纠正误解 / 给程序性步骤 / 促元认知反思），对应四类支架——**概念支架、程序支架、策略支架、元认知支架**。
3. **Feedback**：把意图落成具体话术（talk moves），并在掌握度上升时**执行 fading**：减少提示、从「评估型」转向「推动你自己往下走」。

关键实证：**fading 是「支架」与「拐杖」的分界线**。土耳其的近千人实验里，GPT-4 辅导让数学成绩提升 48%–127%，但**撤掉 AI 后下降 17%**——学生把它当拐杖。带 safeguard 的组没有这个回退。另一项元分析指出，受损最重的恰恰是**基础最弱、元认知最差**的学生：他们跳过「合意的困难」，并把 AI 的成功误当成自己的能力。

**对 MedKit**：这不是 prompt 技巧，是**状态机**。必须持久化 `scaffold_level`（每个知识点 0–3），并且有明确的降级规则（连续两次独立做对 → 降一级；被提示后做对 → 不降）。

### 2.5 评测：LLM-as-judge 不够，要有「延迟后测」

- 题目质量：用 golden set（人工标注的 200–300 题）+ 自动指标（答案可溯、干扰项功能、选项长度均衡、答案位置分布）+ 人评抽检。
- 教学质量：五维 rubric——**有据（grounded）/ 不泄题 / 回应学生原话 / 支架适配 / 有迁移检查**。让另一个模型盲评，再人工抽 5%。
- 学习效果：**延迟后测**（同一知识点 7 天后出新题）。即时正确率会被「刚讲过」污染，是最不可靠的指标。

### 2.6 成本：任务路由，不是「全用最强模型」

成熟做法是按轮次类型路由：简单确认/召回用便宜模型（约 70% 的轮次），苏格拉底对话用强模型（约 20%），多模态/长文用专用模型（约 10%）。单会话成本落在 $0.005–0.02，比全量走前沿模型省 70–85%。

**对 MedKit**：`core/llm.py:83` 是单模型客户端，配置里一个 model 走到底。加一层 `router(task_type)` 即可——出题/质检用强模型，复习提示/闲聊用便宜模型，成本立刻下来，而用户体验几乎无感。

## 3. MedKit 现状审计

### 3.1 它已经做对的六件事（这些是资产，不要动）

1. **本地优先 + BYOK**：素材、产物、Key 全在本机（`~/.medkit/`），Key 走 DPAPI 加密。在一个「什么都要上云」的赛道里，这是**真差异化**，不是保守。
2. **引用纪律 + 拒答**：「结论必须带 `[来源: 路径#小节]`」「无依据必须说不知道」「编造引用被剔除并回报 `dropped_citations`」（`medkit/prompts/mistake_agent.md:25-36`）。这比绝大多数教育 AI 更硬——**它把「不可证伪的流畅」当成缺陷，而不是卖点**。
3. **可证伪的工程文化**：1190 项测试、零断言审计、skip 审计、前端分域耦合守卫、发布五件套一致性。这套东西在个人项目里极罕见，是后续所有改造的安全网。
4. **文件即真身**（vault）：错题是 markdown，SQLite 只是可弃索引，删库可全量重建。用户可手改、可 Git、可丢进网盘。这是**数据主权**的具体实现。
5. **生成链的工程化**：切片配额、三线程并发、四道门禁、LLM-as-judge、定向修复、渲染前终检 + 人工复核清单。这条链的成熟度超过大多数商业产品的「AI 出题」功能。
6. **成本透明**：创建前预估、跑完记实际 usage、折算金额。BYOK 产品里这是信任的基础设施。

### 3.2 断点 A：作答流水没进学习者模型

**事实链**

```
刷题判分 → routers/bank.py → bank_attempts（append-only，correct 0/1）
判错     → library.sync_from_paper()（library.py:726）→ mistakes
错题入库 → library._touch_knowledge_in()（library.py:1353）→ knowledge 行
掌握度   → library.get_mastery_view()（library.py:1431）
         → compute_score(correct, total, last_tried)（library.py:350）
```

关键在 `_touch_knowledge_in` 的归并逻辑（`library.py:1382-1387`）：

```python
# 归并一个样本：learned/答对 → 记 correct；未掌握 → 记 miss
if learned:
    kp["correct"] = kp.get("correct", 0) + 1
else:
    kp["miss"] = kp.get("miss", 0) + 1
```

而这个函数**只**从 `add_mistake`（`library.py:610`）和错题更新路径（`library.py:790`）被调用。
也就是说 `knowledge.correct` 的语义不是「答对的次数」，而是「**曾经是错题、后来被标记为已掌握的次数**」。

于是 `compute_score` 里那个 `correct / total` 算出来的其实是**错题攻克率**，不是知识掌握率。

而且这不是疏漏，是**写下来的设计决定**——`core/bank.py:22` 原文：

> 「何时该复习」一律交给既有的知识点级调度（`review` / `cards`），**题库域不实现第二套 SM-2/FSRS**（两套调度器并存是维护灾难）。`bank_attempts` 只回答「这道题做过几次、对了几次」。

后果：

- 答对 50 题：掌握度不动（不产生错题记录，`bank_attempts` 不进模型）。
- 答错 1 题：`miss` +1，这条错题此后一直占着分母。
- 想让掌握度回升：只能重练这道错题并判对（错题重练的「已掌握」归档）。

**这是一个只见过失败样本的学习者模型**。统计上叫选择偏差：用「错题集」估计「能力」，等于用「住院病人」估计「人群健康水平」。

**为什么这是最该先修的**：不需要新模型、不需要新 UI、不需要新 LLM 调用。只需要让 `bank_attempts` 也写一次 `kc_state`，保留旧字段做兼容。改动面小，收益覆盖全部学习视图。

### 3.3 断点 B：题目没有稳定的知识点身份

现状是三层各自为政：

| 层 | 键 | 稳定性 |
|---|---|---|
| 大纲 `syllabus_items` | `id = sha1(source|kind|subject|chapter|item)[:16]` | **稳定**（这正是我们要的） |
| 题库 `bank_items` | `topic TEXT` | 自由字符串 |
| 生成题 `QuestionItem` | `subtopic: str` | 自由字符串 |

结果：同一个考点在三个题库里是「慢阻肺的诊断」「COPD 诊断」「慢阻肺 诊断标准」三个字符串，`knowledge` 表按 `name` 聚合（`library.py:223` 按知识点名取行），于是它们永远不会合并。

**这就是为什么 MedKit 做不了知识追踪**——不是缺算法，是缺**主键**。

补法很轻：加一张 `item_kc(item_id, kc_id, confidence, source)`，`kc_id` 指向 `syllabus_items.id`；映射用「规则优先 + LLM 兜底 + 人工确认」三段式（和现有 `syllabus.py` 的 confirm 门同构）。存量数据用 `subtopic` 字符串匹配 + 编辑距离回填，匹配不上的进「待确认」队列。

### 3.4 断点 C：错题之后是「问答」，不是「教学」

现在的错题助手很强，但强在**检索纪律**：

- 三个只读工具：`search_my_mistakes` / `get_topic_stats` / `read_file`
- 四条硬约束：引用可核、无据拒答、先回应学生原话、工具失败显性
- ≤5 轮，JSON action 协议

它缺的是**教学策略**：

| 教学动作 | 现在 | 应该 |
|---|---|---|
| 诊断误解类型 | 无（用户自己写「我的理解」） | 五类错因：知识缺口 / 概念混淆 / 审题偏差 / 推理跳跃 / 记忆衰退 |
| 提示梯度 | 无（要么答，要么不答） | L0 反问 → L1 概念提示 → L2 步骤提示 → L3 直接讲 |
| 支架衰减 | 无 | 连续两次独立做对 → 降级；被提示后做对 → 不降 |
| 让学生教回 | 无 | 「假设我是同学，你讲一遍这道题的机制」→ 按 rubric 指出漏洞 |
| 迁移检查 | 无 | 「换一个临床表现，你还成立吗」→ 出新题验证 |
| 状态写回 | 只有「存入错题」 | 每次对话更新 `kc_state` 与 `scaffold_level` |

**这就是「RAG agent」与「tutor agent」的区别**：前者优化「答得对」，后者优化「你学会了」。前者只需要检索，后者需要**状态 + 策略 + 动作空间**。

### 3.5 断点 D：溯源是字符串对齐，不是语义蕴含

```python
# gates/trace_check.py:14
def _align_hit(sub, text):
    if sub in text: return True
    return len(sub) >= 2 and sub[:2] in text   # 前两个字命中即过
```

这意味着：题目写「COPD 最主要的致病因素是吸烟」，引用切片里只有「吸烟与 COPD 相关」，门禁照样 PASS。**引用存在 ≠ 内容被支持**。

NotebookLM 之所以可信，不是因为它有引用 UI，是因为它把「只答检索到的段落」作为生成约束；iatroX 之所以可信，是因为它「引用指南」而不是「引用自己的话」。MedKit 需要的是**蕴含级校验**：拿 `analysis` 里的每个断言，回到被引切片做一次 NLI/LLM-judge（「这段文字是否支持这句话？」），不支持的进人工复核，而不是直接渲染。

### 3.6 断点 E/F：解析粒度与排期粒度

- **解析**：`QuestionItem.analysis` 是一整块。UWorld 的护城河是「每个错选项都解释一次」。补 `option_rationales: dict[str, str]` + `misconception: dict[str, str]` + `source_quote: str`（原文那一句）即可，渲染层按选项展开。
- **排期**：`core/vault_index.py:415-446` 用 SM-2（`ease/interval/reps/lapses`），且**每道错题一个文件 = 一张卡**。同一考点的五道错题会被当成五个独立记忆，重复复习。应改成 **FSRS-6 + 按 `kc_id` 合并**：一个知识点一张卡，错题是这张卡的「证据」。

### 3.7 断点 G：一次「正确精简」留下的悬空依赖

这一条不是设计缺陷，是**删除顺序**造成的结构性漂移，值得单独记一笔。

时间线：

| 时间 | 事件 | 证据 |
|---|---|---|
| 2026-08-27 | ADR-004 决策：定义 `core/scheduler.py` 协议，**默认实现 py-fsrs**，SM-2 降级为 legacy | `docs/adr/ADR-004-fsrs-scheduler.md`（状态：已接受） |
| 2026-10-15 | 奥卡姆精简 T2：实测 `cards=0` / `review_cards=0` / `explains=0` / `tutor_sessions=0`，**删 `core/{explain,tutor,cards,review,scheduler}.py`** | `CHANGELOG.md:313-318` |
| 同日 | SM-2 纯函数搬进 `core/vault_index.py`，注释自称「**本域唯一实现**」「常量与 `core/review.py` 逐值一致」 | `core/vault_index.py:415-421` |
| 今天 | `core/bank.py:22` 仍写「交给既有的知识点级调度（`review` / `cards`）」——**这两个模块已经不存在** | `core/bank.py:22` |

三个后果：

1. **FSRS 从未接到线上路径。** ADR-004 是「已接受」状态，实现模块却随 `core/cards.py` 一起被删（因为 `cards` 零使用）。现在跑在生产上的是 `vault_index.py` 里逐值复制的 SM-2 常量（`INIT_EASE=2.5` / `GRADE_PASS=3` / `INTERVAL_FIRST=1` / `INTERVAL_SECOND=6`）。
2. **README 与实现不符。** README 目录树里仍写着「`scheduler(FSRS·SM-2)`」，实际 `core/scheduler.py` 不存在。这会误导后来的自己。
3. **「不实现第二套调度器」的原则在删除后反而成了路障。** 当年拒绝在 bank 域做调度是对的（避免两套真相），但它的委托目标被删后，没人补上那一层——于是复习排程退回到「每条错题一张 SM-2 卡」的最朴素形态。

> 这一条同时提示了一个流程问题：**删除模块时，应当 grep 所有指向它的注释与文档**。注释里的悬空引用不会让任何测试变红，但它会让下一个读者（包括未来的自己）按错误的架构前提做决策。

## 4. 目标架构：三环一图

```
                    ┌──────────────────────────────┐
                    │        KC 图谱（一张图）       │
                    │  kc_id / parent / prerequisite │
                    │  weight / source / item_kc     │
                    └───────────┬──────────────────┘
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
   ┌─────────────┐       ┌─────────────┐       ┌─────────────┐
   │  内容环      │       │  学习环      │       │  元认知环    │
   │ generate    │       │ attempt     │       │ confidence  │
   │ → verify    │       │ → diagnose  │       │ → calibration│
   │ → calibrate │       │ → tutor     │       │ → plan      │
   │ → repair    │       │ → schedule  │       │ → reflect   │
   └──────┬──────┘       └──────┬──────┘       └──────┬──────┘
          │                     │                     │
          └─────────────────────┴─────────────────────┘
                       每次读写都落 kc_state
```

**这张图的核心不是三个环，是中间那张图。** 内容环产出「题 → 知识点」的边，学习环产出「人 → 知识点」的状态，元认知环产出「人 → 自己判断」的偏差。三条边共享同一个 `kc_id`，才可能互相校准。

### 4.1 数据模型（最小改动）

```sql
-- 新增 v11
CREATE TABLE kc_edges (          -- 知识点之间的关系
  src TEXT, dst TEXT,            -- syllabus_items.id
  kind TEXT,                     -- prerequisite / related / contrast
  weight REAL, source TEXT,
  PRIMARY KEY (src, dst, kind)
);

CREATE TABLE item_kc (           -- 题 → 知识点（多对多）
  item_id TEXT, kc_id TEXT,
  confidence REAL,               -- 映射置信度，低于阈值进人工确认
  source TEXT,                   -- rule / llm / human
  PRIMARY KEY (item_id, kc_id)
);

CREATE TABLE kc_state (          -- 人 → 知识点（BKT 后验）
  kc_id TEXT PRIMARY KEY,
  p_mastery REAL,                -- 掌握概率
  p_transit REAL, p_slip REAL, p_guess REAL,
  scaffold_level INTEGER,        -- 0..3，fading 用
  attempts INTEGER, correct INTEGER,
  last_seen TEXT, due TEXT,
  stability REAL, difficulty REAL,   -- FSRS
  updated_at TEXT
);
```

三张表，全部可由现有数据回填：`item_kc` 从 `subtopic` 匹配 `syllabus_items.item`；`kc_state` 从 `bank_attempts` 回放；`kc_edges` 先用「同章相邻 + 章间前后」的规则边，LLM 只用来补「易混淆」这类语义边。

### 4.2 三个环的具体动作

**内容环**

| 步 | 现在 | 目标 |
|---|---|---|
| generate | MedGen 按切片配额出题 | 不变（这条链是资产） |
| verify | 门禁查「有没有 `[源:…]`」 | 加**蕴含校验**：断言级 NLI，不支持 → 人工复核 |
| calibrate | 无 | `item_stats`：p 值、区分度、答案位置分布、选项长度均衡 |
| repair | MedFix 按 issue 定向修 | 用 calibrate 的结果反哺：坏题自动进重掷队列 |

**学习环**

| 步 | 现在 | 目标 |
|---|---|---|
| attempt | 点选项即判分 | 加**作答前置信度**（1–5），只多一个点击 |
| diagnose | 无 | 五类错因，单次 LLM + 一键确认，写回 vault front matter |
| tutor | 问答 | EDF 状态机：诊断 → 支架梯度 → 教回 → 迁移检查 |
| schedule | SM-2 / 每题一卡 | FSRS-6 / 每 KC 一卡 |
| retest | 错题重练 | 同 KC 新题（不是原题），7 天后 |

**元认知环**

| 步 | 现在 | 目标 |
|---|---|---|
| confidence | 字段存在但置空（EP-01 移除后） | 作答前采集，默认 3，可跳过 |
| calibration | 无 | 校准曲线（自评 vs 实际）+ Brier score |
| plan | 无 | 每日 20 分钟任务单：到期复习 + 最弱 KC + 考频加权 |
| reflect | 无 | 周报：「你以为会但错了的 3 个点」 |

## 5. 改造路线

排序原则：**先修「模型看不见的数据」，再修「模型做出的动作」，最后修「内容与形态」。**
每项都给**验收守卫**——没有守卫的改动，在这个仓里不算完成。

### P0（2–3 周，零新模型，收益覆盖全部学习视图）

## 6. 不建议做的事（反面清单）

1. **不要做通用聊天助手。** MedKit 的护城河是「你的教材 + 你的错题 + 可核引用 + 本地」，不是「什么都能聊」。和 ChatGPT 比开放域知识，是拿自己的短板打别人的长板。
2. **不要自建内容库。** AMBOSS 是 150+ 医生、1,400+ 篇文章。个人项目不可能复制，也不该复制——你的差异是「老师划的重点」。
3. **不要做多智能体剧场。** 有研究直接比较「聊天机器人」与「智能体」条件，学习增益**没有统计显著差异**；另一项医学课程研究里，平台分数给 8 个教学智能体的排名与专家 rubric 排名不一致（平台第 3 的，教学质量垫底）。自主性不应超过证据的成熟度。
4. **不要做没有常模的分数预测。** AMBOSS 的 Score Predictor 背后是大量考生数据。本地单用户没有常模，做「预测分」是不诚实的；做「准备度指数」并明确标注「非预测」，才是可辩护的。
5. **不要先做云多租户。** 数据根请求级化是 1–1.5 周的深水区，且会改写 README 的隐私承诺。先做局域网 PWA（2–4 天），验证「手机上到底用不用」，再决定。
6. **不要把「AI 生成」当成质量保证。** 系统综述说得很直白：AI 题的区分度偏低、无效干扰项常见，像新手写的题。MedKit 的门禁文化是对的，但要从「格式合规」升级到「心理测量学合规」。

## 7. 怎么知道改对了

| 层级 | 指标 | 采集方式 | 目标 |
|---|---|---|---|
| 内容 | 答案可溯率 | 蕴含校验通过率 | ≥95% |
| 内容 | 干扰项功能率 | 每个干扰项被选中比例（p 值） | 每个干扰项 5%–40% |
| 内容 | 坏题率 | p<0.2 或区分度<0 | <5% |
| 学习 | 延迟后测增益 | 同 KC 新题，7 天后 | 相对基线 +10pp |
| 学习 | 复习负担 | 每日到期卡数 / 保持率 | 同保持率下卡数 −20% |
| 学习 | 迁移率 | 新情境题正确率 | ≥60% |
| 元认知 | 校准误差 | Brier score（自评 vs 实际） | 逐月下降 |
| 教学 | rubric 均分 | 40 场景 × 5 维，LLM 盲评 + 5% 人评 | ≥4.0/5，且不下降 |
| 体验 | 首次价值时间 | 安装 → 第一道题判分 | <5 分钟 |

**最重要的一条**：所有指标都必须在**离线回放**上先跑通（用历史 `bank_attempts` 模拟），再上线。MedKit 有这个条件——它的作答流水是 append-only 的，可以重放。
