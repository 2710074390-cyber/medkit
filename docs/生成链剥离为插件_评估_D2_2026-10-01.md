## 0. 结论先行（三句话）

1. **Python 侧几乎不用动**：EP-01 域与生成链**双向零耦合**（唯一的 `vision → mineru` 是
   OCR 兜底通道，属**共享基础设施**，不是生成链）。
2. **前端有一处真违规 + 两处登记项**：EP-01 片引用插件符号 **1 处**（已修）、
   外壳 → 插件 **8 处**、插件 → EP-01 **2 处**。
3. **真正的成本不在"解开耦合"，而在信息架构**：`app.js`（外壳）的 **tab 结构、仪表盘、
   「最近项目」、新建向导**都长在生成链上——**「题库」本身就是一个 tab**。
   所以 D2 不是重构任务，而是**产品决策**：要不要把「题库」这个一级入口从产品里摘掉。

**⇒ 建议：不启动剥离。** 若将来确实要「让生成链可缺席」，正确的前置动作是
**把外壳对插件的 8 处调用改成"优雅缺席"**（7 处未守卫），而不是先搬文件。

## 1. 评估方法

用 AST 建**模块级导入图**（Python）与**顶层声明引用图**（前端，因为经典脚本共享全局作用域，
跨文件引用不体现在 `import` 里），按"域"统计三个方向的耦合：

| 域 | 范围 |
|---|---|
| 生成链（待剥离的插件） | `core/{orchestrator,syllabus,websearch,mineru,realexams,slice}.py` · `gates/*` · `agents/{medgen,medqc,medfix,medreview,medcards}.py` · `routers/{projects,pipeline,parse,syllabus,realexams}.py` · `render/{qbank_html,review_html,apkg,pagechrome}.py` · `web/js/review-desk*.js` |

## 2. 测量结果

### 2.1 Python：双向零耦合 ✅

```
EP-01 模块是否依赖生成链：9/10 不依赖（唯一：vision.py → mineru.py）
生成链是否依赖 EP-01：orchestrator / syllabus / websearch / mineru 全部（无）
```

- `vision.py → mineru.py` **不算违规**：MinerU 是**OCR 客户端**，是 EP-01 图像录入的
  **兜底通道**（方案 §2.3 明写「② OCR 兜底」），属共享基础设施。若要严格剥离，
  它该被划进共享基础而不是生成链。
- 路由层同结论：`routers/errors.py` 只 import `core`（`apkg_import, errsearch, kpid, metacog,
  vision, errorpipe, errors, library, tutor`），**不 import 任何生成链域**。

### 2.2 规模与依赖

| | 文件 | 行数 |
|---|---|---|
| 生成链（Python） | 25 | **7517** |
| 生成链（前端） | 4 | **2362** |
| EP-01（Python） | 14 | 4622 |
| EP-01（前端） | 7 | 3598 |

**依赖差**（AST 取顶层 import 名，扣掉 stdlib）：

| | 独有第三方依赖 |
|---|---|
| 生成链 | `fitz`（PyMuPDF）· `genanki` · `httpx` · `markdown` |
| EP-01 | **（无）** |

⇒ 剥离能去掉 **4 个第三方包**（`PyMuPDF` 是体积大头）。这是剥离的**唯一硬收益**，
且对"安装包体积"有意义——但 `pack/` 的发布流程本就在做纯净打包，需另算净收益（**未验证**）。

### 2.3 前端：一处真违规 + 两处登记项

实测（`tests/test_frontend_domain_coupling.py` 就是这套判据的固化）：

| 方向 | 处数 | 明细 |
|---|---|---|
| **EP-01 → 插件** | **1 → 0** | `learn-review.js` 的 Anki 卡样预览调 `letters()`，而它当时定义在 `review-desk.js`。**已修**：移到共享基础片 `app.js` |
| **外壳 → 插件** | 8 | `loadProjects` / `ratioSum` / `bloomSum` / `updateReady` / `loadPrompts` / `stopPoll` / `showProject` / `wzClose`（明细见守卫的 `SHELL_TO_PLUGIN`） |
| 插件 → EP-01 | 2 | `ankiPreview` / `ankiHelp`（**允许**：插件依赖核心是正常方向） |

**为什么这条真违规危险**：加载期闸门 `test_v15_frontend_split.py` 只看**加载期**前向引用，
而跨域耦合多在**调用时**（函数体里调另一个域的顶层函数）——闸门管不到；
删掉另一个域只在**点击时**炸（`ReferenceError`）。且实测这三个符号
（`letters` / `ankiPreview` / `ankiHelp`）在 `tests/browser/` 里**零出现** ⇒ 没有用例兜底。

### 2.4 真正的成本：外壳长在生成链上

`app.js`（外壳）的 8 处引用**不是疏忽，是架构事实**——外壳负责：

- **tab 结构**：`showTab("bank")` 切到「题库」（生成链的主入口，`index.html:240` 起整个 panel）
- **仪表盘**：「最近项目」卡片 → `showProject(pid)` 直接打开建课页
- **新建向导**：`wzClose()`（向导本身就是"从教材出题"的入口）
- **成本预估**：`ratioSum()` / `bloomSum()`（出题比例条，服务商/模型变化时重算）

⇒ **剥离生成链 = 摘掉「题库」tab + 仪表盘的最近项目 + 新建向导 + 成本预估**。
这是**信息架构与产品范围**的改动，不是代码搬运。

## 3. 三种粒度的方案与成本

| 粒度 | 做什么 | 成本 | 风险 |
|---|---|---|---|
| **A. 物理拆包**（把生成链移进 `plugins/` 目录 + 入口按开关注册） | 移动 ~7500 行 Python + 2362 行前端；`main.py` 的条件注册；`app.js` 的 8 处调用改"优雅缺席"；前端 tab 按开关隐藏 | **大**（跨 40+ 文件） | 中：经典脚本的加载顺序即契约，动态加载片会破坏「族内有序」闸门 |
| **B. 依赖隔离**（保留代码位置，把 `fitz/genanki/httpx/markdown` 的 import 全部改成懒加载） | 只在真正用到时 import | **小**（局部） | 低：收益是"未用生成链时不加载这些包"，但**安装包体积不变**（PyInstaller 仍会收集） |
| **C. 只做前置**（不改结构，只把外壳的 8 处调用改成"优雅缺席"） | 7 处加 `typeof X === "function"` 守卫（`updateReady` 已有） | **极小** | 极低：零行为变化 |

**A 的隐藏成本（实测）**：`index.html` 的前端加载是**静态 `<script src>`**，
族内顺序是契约（`test_v15_frontend_split.py` 守）。要做"按开关加载生成链"，
就得改成动态注入 `<script>`，那会**破坏既有闸门的判据口径**（闸门读的是静态 HTML 里的
`<script>` 列表）。⇒ A 不是"搬文件"，是要**连带重做前端加载契约**（**未验证**其复杂度）。

---

## 4. 建议

1. **不启动 A**。它的收益（4 个第三方包）与成本（跨 40+ 文件 + 重做前端加载契约 +
   摘掉一个一级 tab）严重不对称。按《总纲》§2.1「停手信号」，这属于**无依据改动**。
2. **C 现在也不做**。它只在"生成链**可能缺席**"成为真实场景时才有意义；
   今天插件永远在场，加守卫的唯一效果是**代码噪音**。
   ⇒ **C 是 A 的前置动作**：等 A 有了依据（比如真要出"纯错题版"安装包）再一起做。
   （唯一的例外是 `updateReady` 已有守卫——那是**历史遗留**，同一行里补了它没补邻居，
   属于既有不一致，但**不改**：改了就是无依据改动。）
3. **B 视需要再做**：只有在"用户没配生成链相关能力时不想加载 PyMuPDF"成为真实痛点时才做。
4. **无论做不做，耦合清单已固化**：`tests/test_frontend_domain_coupling.py` 把
   「EP-01 → 插件 = 0」「外壳 → 插件 = 8（登记）」「插件 → EP-01 = 2（登记）」变成
   **机械可核对**的性质。新增一处跨域引用即红 ⇒ 这份评估**不会随时间腐烂**。
   登记表里的「处置」列（加守卫 / 摘功能）就是将来做 A 时的**待办清单**，已写好。
