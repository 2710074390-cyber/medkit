# MedKit 网页版竞品设计分析与改进方案

> 分析日期：2026-10-29  
> 分析对象：`medkit-web-contest`（MedKit 医学题库工坊网页版，线上 `medkit-study-app.app.workbuddy.host`）  
> 对照竞品：UWorld、AMBOSS、Osmosis、医考帮、蓝基因、Anki、Quizlet、Duolingo  
> 交付物：本 Markdown 清单 + 同目录 HTML 报告

---

## 0. 结论先行

### 0.1 一句话判断

**MedKit 网页版已经是一条能跑通的学习闭环，但它的「书桌」目前只换了桌布，还没换陈设；学习深度也只到「做完对答案」，还没到「知道为什么错、下次什么时候再错」。**

现版的真实资产是：11 个题库 2350 题、点选判分、答题卡、断点续做、错题回流、SM-2 复习、可选账号同步、390px 无横向溢出、44px 触控目标、零构建零 CDN。它的问题不是「功能太少」，而是**视觉概念没有落到组件、学习闭环没有形成诊断、数据层还撑不住长期使用**。

### 0.2 三个战略判断

1. **不要选单一竞品当母本。**  
   UWorld/AMBOSS 的深度、医考帮/蓝基因的组织、Anki 的调度、Duolingo 的启动，是四种不同能力。MedKit 该走「轻量入口 + 临床严谨解析 + 记忆算法」的混合路线，而不是把自己做成任何一家的缩小版。

2. **品牌与美术必须先做，但美术不是贴纸。**  
   你的选择是「书桌深化」。正确做法是把纸、墨、红笔、荧光笔、书脊做成**组件语义**，而不是加木纹、胶带、手绘小人。书桌是底，不是装饰。

3. **学习效果的核心不是「更多题」，而是「更准的复习」。**  
   当前复习卡直接显示答案，用户只能自评「记住/模糊/忘记」；这不是主动回忆。逐选项解析覆盖率只有 20.8%，大多数题仍然只给整题解析。先把这两件事修好，比加模考、加社区更值。

### 0.3 本轮已确认的决策

| 决策点 | 你的选择 | 对方案的影响 |
|---|---|---|
| 竞品范围 | 推荐组合 8 款 | 医学考试、记忆算法、学习激励三类都有对照 |
| 分析对象 | 网页版 `medkit-web-contest` | 本地桌面版只作为能力参照，不纳入改造成本 |
| 交付形式 | HTML 报告 + Markdown 清单 | HTML 用于评审，MD 用于后续任务拆分 |
| 产品定位 | 混合路线 | 不追求单一竞品全量复制，按能力分层借鉴 |
| 美术方向 | 书桌深化 | 继续纸/墨/红笔/宋体，补组件与插图系统 |
| 投入范围 | 体验 + 数据层 | 不新建内容生产链，但要把 IndexedDB、同步、导出修到可用 |
| 优先级 | 品牌与美术优先 | P0 先做视觉地基，P1 学习闭环，P2 数据与架构 |
| 社区/UGC | 不做 | 不引入评论、审核、运营成本 |
| 模考 | 不做 | 不把「全真模考/排名」纳入本轮 |
| AI | 稳定性 + 引用校验 | 不做云端额度与教学式 AI 大改 |
| 账号 | 修同步冲突与数据安全 | 不做邮件找回/删除账号等完整生命周期 |

### 0.4 明确不做

- 题目评论区、学习社区、排行榜、组队。
- 全真模考、万人排名、分数预测。
- 吉祥物、角色立绘、惩罚式连胜、满屏手写体。
- Web Font、CDN、构建步骤。
- 为「像竞品」而增加的功能；每一项改动都要能回答「解决谁的什么问题」。

## 1. 调研方法与证据边界

### 1.1 方法

- **外部**：阅读 8 款产品的官方功能页、官方帮助中心、官方博客与公开品牌资料；辅以应用商店/第三方介绍，仅用于补充功能维度。
- **内部**：读 `medkit-web-contest` 的 `index.html`、`js/`、`css/`、`server.py`、`tests/`、`docs/体验测试_2026-10-29.md`；用脚本统计题库字段覆盖率；用 8 张真实截图做视觉审计。
- **证据分级**：
  - **A** 官方产品文档/帮助中心/官方博客；
  - **B** 官方营销页上的数字与能力声明（未独立验证）；
  - **C** 第三方测评、应用商店介绍；
  - **D** 本仓代码、测试、截图与脚本统计（可直接复核）。

### 1.2 边界

- 没有登录竞品的付费题库做逐题实操；交互结论来自公开页面、演示视频与官方说明。
- 竞品的内部架构不可见，文中「架构推断」标注为推断，不作为事实。
- 营销页数字可能随时间变化；本报告只取「设计选择」和「能力维度」，不把数字当疗效证据。
- 本报告不复制任何竞品的受版权保护内容或界面资产。

## 2. 竞品深描

### 2.1 UWorld：把练习做成考试，把解析做成教材

**一句话定位**：高利害医学考试的「考试仿真 + 深度解析」工具。  
**证据等级**：A（官方功能页、官方 flashcards 说明）；B（官方学生数量声明）。

**核心闭环**：  
`Create Test（按学科/系统组卷）→ Tutor 或 Timed 作答 → 逐题解析 → Performance 报告 → Previous Tests 回看/重做 → 自评考试估分`

**关键交互**

- **Tutor / Timed 双模式**：Tutor 每答一题立即给解析；Timed 更接近真实考试，交卷后再看。这个分离非常重要——学习和检测不能混在同一个节奏里。
- **Create Test**：按 subject/system 组卷，支持自定义题量；Previous Tests 可恢复未完成测试、回看已完成测试。
- **逐选项解析**：每个选项都解释为什么对/错，配插图、图表、临床场景；官方明确说「explains why answer options are right or wrong」。
- **Performance 三层**：Overall（总量/正确率）、Reports（按 subject/system/topic 拆）、Graphs（按日期/测试的进展）。
- **Peer 比较**：提交后显示每个选项的选择比例；Performance 里有 percentile 与平均用时。
- **Self-assessment**：四段 60 分钟、每段 40 题，交卷后给解析、排名、估算分数。
- **SmartCards / ReadyDecks**：题目可转卡片，卡片按自评难度做间隔重复；有 Flashcards 进度与统计。
- **My Notebook / Dynamic Study Planner**：可把题面与图形摘到笔记；按可用时间生成每日计划。
- **跨设备**：桌面/平板/手机，进度自动保存并同步；需要联网。

**架构推断**

- 中央内容库 + 组卷引擎 + 作答/判分 + 性能分析 + 跨设备同步。
- 内容（题、解析、插图、统计口径）是护城河；界面只是内容的外壳。
- 题库元数据（subject/system/topic）是报告与组卷的前提。

**视觉 DNA**

- 考试软件式布局：题号、计时、选项、Next/Previous、Lab 值表；蓝白为主，信息密度高但分区明确。
- 解析页像教材：题干、选项、正确项、逐项解释、插图/表格；视觉重点在「读」，不在「装饰」。
- 品牌色（Brandfetch 公开资料）为棕金 `#B37E56` 与亮黄 `#FACC34`；产品内界面以蓝白为主，品牌色更多出现在品牌资产上。

**该借**

- Tutor / Timed 的双节奏（即使不做模考，也可以做「练习/检测」切换）。
- 逐选项解析、Previous Tests 回看、Performance 三层报告。
- 选项选择分布（没有用户规模时，可先用「班级/小组」或本地统计替代）。
- 题目 → 卡片 → 复习的衔接。

**不该借**

- 依赖大规模用户才能成立的 percentile 与 peer 比较。
- 高成本的内容生产与插图团队。
- 把界面做成「医院考试系统」的冷。

**对 MedKit 的启示**：  
现版已经有「练习/背题」，但缺少「检测」节奏；解析只有整题 + 部分逐项；报告只有单库正确率。**先把「逐选项解析 + 单卷报告 + 题目转复习」做扎实**，比做排名更实际。

### 2.2 AMBOSS：一个连通的系统，而不是五个订阅

**一句话定位**：医学图书馆 + QBank + 学习计划 + 分析 + AI，全部互链。  
**证据等级**：A（官方 features / USMLE 页）；B（官方数字）。

**核心闭环**：  
`设定考试目标/日期 → Study Plan → Adaptive Session（按掌握度与难度出题）→ 作答 → Key Info + Attending Tip + 图像标注 → 链接到 Library 文章 → Readiness/Score 更新 → 下一轮补弱`

**关键交互**

- **Library 与 QBank 互链**：每道题的解析都能跳到对应 Library 文章；文章里也能回到题。题目不是孤岛。
- **Key Info / Attending Tip / 图像标注**：解析分层——先给考点，再给临床推理提示，再给影像/心电图/病理标注。
- **难度 1–5 hammers**：每题有难度，Adaptive Session 会按表现调整难度曲线。
- **Adaptive Session**：按「你会的、考试考的、难度曲线」选未做题；不是随机抽题。
- **Study Plan**：按考试日期与可用时间生成每日高产出计划；有 200 Concepts、High-Yield 等主题计划。
- **Readiness 三件套**：Equated Percent Correct（答 40 题后开始估计）、Self-Assessment（计时模拟）、Score Predictor（输入练习考试结果，给分数区间与通过概率）。
- **AI Mode**：只从 AMBOSS Library 取答案，并链接到源文章；明确区别于开放网络聊天。
- **Anki 插件**：卡片里的术语悬停可看 Library 定义/图片；题目与卡片双向连接。
- **App 离线**：App 可离线看 Library；QBank 利用碎片时间；Web/App 进度同步。

**架构推断**

- 内容图谱：文章、题目、概念、图像、考试大纲之间有多对多关系。
- 事件流：每道题的作答、用时、难度、考试相关性进入模型，驱动 Adaptive Session 与 Readiness。
- 集成层：Anki、Chrome 扩展、移动 App、AI Mode 都读同一份内容图谱。

**视觉 DNA**

- 青绿 + 黑为品牌基调（公开 logo 资料）；产品内是临床信息密度：细规则线、标签、表格、图像标注。
- 「High-Yield」把长文压成考点；「Key Info」把解析压成可扫读块。
- 视觉服务于「快速定位」，不是「氛围」。

**该借**

- 题目 ↔ 知识点/教材原文的双向链接。
- 解析分层：结论 → 逐项 → 临床提示 → 原文。
- 难度标定与自适应选州题（可先做规则版）。
- Readiness 概念：没有数据时明确说「样本不足」，不编分数。
- AI 只依据本地题库/教材，并给可核对引用。

**不该借**

- 自建完整医学图书馆。
- 没有足够样本时做「分数预测」。
- 过度密集的临床后台感。

**对 MedKit 的启示**：  
现版有 `source_ref`（教材页码）但没有 `source_quote`，也没有知识点映射。**先把「题 → 考点 → 原文 → 掌握度」这条链打通**，比增加题库更接近 AMBOSS 的真正价值。

### 2.3 Osmosis：视觉优先，把机制讲成画面

**一句话定位**：用插画/视频 + 测验 + 卡片，把复杂机制讲清楚。  
**证据等级**：A（官方 flashcards / 制作说明 / App Map）；B（官方学生规模声明）。

**核心闭环**：  
`看视频/图文 → 做 Case Questions → 闪卡自评 → 每日重复测验 → 掌握度报告 → 学习计划调整`

**关键交互**

- **视觉优先**：官方说视频「uniquely-illustrated, concise」；插画卡通但要求准确，先脚本再分镜再绘制。
- **闪卡 + 间隔重复**：按「快要忘记前」重复；每张卡自评信心。
- **每日重复测验**：当天做过的题会进入 daily repetition quiz；系统按到期时间安排卡片。
- **Study Schedule 拖拽**：可把 Case Questions / Flashcards 排进日程，按天执行。
- **Mastery 报告**：Dashboard 显示理解如何随时间增长、下一步该补哪里。
- **High-Yield Notes**：图文、表格、示意图并置，服务视觉学习者。

**架构推断**

- 视频/图文内容库 + 题目 + 闪卡调度 + 学习计划 + 掌握度分析。
- 内容生产是重资产；调度与计划是轻资产。
- 视觉不是装饰，是解释机制的主要载体。

**视觉 DNA**

- 插画/动画为主，色彩明快；用画面建立「机制记忆」，文字做辅助。
- 学习路径以「主题 → 视频 → 题 → 卡」组织，而不是以「题库列表」组织。

**该借**

- 机制类题目配一张「解释图」，而不是只有文字解析。
- 每日重复队列、信心自评、学习计划拖拽。
- 掌握度报告用「趋势 + 下一步」而不是「总正确率」。

**不该借**

- 自建视频/动画生产线。
- 用可爱插画消解医学严肃性。

**对 MedKit 的启示**：  
现版没有任何题目图片字段（统计为 0），解析全靠文字。**至少给高频/机制题补「一张解释图 + 图注」**，比全站插图更有效。

### 2.4 医考帮：把「考点」做成可检索、可讨论、可模考的内容体系

**一句话定位**：面向中国医学考试的大体量题库与备考社区。  
**证据等级**：A（官方功能介绍）；B（官方数字：360 万题、300+ 考试学科、500 万用户、30 万 DAU）；C（应用商店描述）。

**核心闭环**：  
`选考试/学科 → 章节练习 → 作答 → 考点还原 + 全选项解析 → 错题/收藏/笔记 → 模考 → 题目评论/论坛`

**关键交互**

- **按学科、年份、系统、题型、考频筛题**：题库不是平铺，而是多维索引。
- **四种刷题模式**：练习、快刷、测试、背题；不同场景不同节奏。
- **考点还原**：把题目考点还原到教材/大纲位置，减少「做了不知道考什么」。
- **全选项标准解析**：官方称为业内首创；每个选项都有解释。
- **题目评论区**：每道题是一个独立主题，用户可看学霸口诀、名师解析；学习与社区混合。
- **错题、收藏、笔记、AI 自助组题、刷题统计**：围绕「查缺补漏」组织。
- **万人模考**：定期组织，模拟考试环境。

**架构推断**

- 大内容 CMS + 多维题目元数据（考试/学科/章节/年份/题型/考频）+ 作答流水 + 错题本 + 模考 + UGC 评论 + 账号。
- 内容规模与元数据粒度是壁垒；社区是留存层。

**视觉 DNA**

- 蓝白主色、入口密集、章节/考点/评论/打卡同屏；效率优先，情绪其次。
- 题目页信息密度高：题干、选项、答案、解析、考点、评论、纠错入口。
- 移动端优先，桌面像「放大版手机」。

**该借**

- 多维筛选（学科/章节/题型/考频/年份）。
- 考点还原、全选项解析、错题按章节归集。
- 练习/快刷/测试/背题四种节奏。
- 刷题统计「查缺补漏」而不是「炫成绩」。

**不该借**

- 把社区、广告、打卡塞进做题主路径。
- 用体量代替结构；题库大不等于好复习。

**对 MedKit 的启示**：  
现版题库只有「科目 → 题库」两层，题目有 `topic/subtopic` 但没用于筛选。**先把 `topic/subtopic` 变成可筛选、可统计、可组卷的维度**，再谈更大的题库。

### 2.5 蓝基因：错题闭环 + 高频考点 + 离线/夜间

**一句话定位**：300+ 医学考试题库，强调真题乱序、错题闭环、必背考点。  
**证据等级**：B/C（官方商品页、第三方应用介绍）。

**核心闭环**：  
`选考试 → 章节真题（顺序/乱序）→ 作答 → 错题自动归集 → 错题组卷 → 模考 → 必背考点（高/中/低频）`

**关键交互**

- **真题乱序**：章节内智能乱序，打破「记住题号」的虚假掌握。
- **真题评论**：题目下挂大量口诀、思路、方法。
- **随机组题 / 错题组卷**：按章节、题量、难度、题型自由组卷。
- **必背考点分层**：高/中/低频一目了然，支持背诵、自测、听题、做题。
- **错题闭环**：错题自动同步错题本，按章节归集；一键组卷。
- **模考测试**：考前密卷、考后估分、分数排名。
- **离线下载、夜间模式**：移动场景友好。
- **3D 解剖**：第三方介绍提到，作为差异化内容。

**架构推断**

- 内容库 + 真题元数据 + 错题本 + 组卷 + 模考 + 离线包 + 账号。
- 「乱序/组卷/高频」都是元数据与规则驱动的，不是纯 UI。

**视觉 DNA**

- 蓝色品牌（官方品牌释义明确「蓝色代表纯净、智慧、希望」）。
- 第三方称其「界面清爽如医学版 INS」；整体偏轻、碎片化。
- 夜间模式与离线是移动端体验的一部分，不是附加功能。

**该借**

- 错题按章节归集 + 一键错题组卷。
- 高频/中频/低频考点标签，用于排序与降权。
- 真题乱序，避免题号记忆。
- 离线与夜间模式。

**不该借**

- 分数排名带来的焦虑。
- 用 3D/视觉噱头替代内容结构。

**对 MedKit 的启示**：  
现版错题本只有「全部/待巩固/已掌握」+ 搜索，没有按章节归集、没有错题组卷、没有高频标签。**错题组卷是低成本高收益的改进**。

---

### 2.6 Anki：算法可信，界面不必可爱

**一句话定位**：本地优先的间隔重复工具，算法与可定制性是核心。  
**证据等级**：A（官方手册、FAQ、Stats 文档）。

**核心闭环**：  
`建卡/导入 → 每日到期队列 → 看正面 → 回忆 → 翻面 → 评分 → 调度下一日`

**关键交互**

- **FSRS**：以 Stability/Difficulty/Retrievability 建模；可设 Desired Retention；可优化参数。
- **Daily Limits**：每日新卡/复习上限；可按 deck 设限；Easy Days 调整负载。
- **Leeches**：反复失败的卡会被标记/暂停，避免无限循环。
- **Learning/Relearning Steps**：学习步长、毕业间隔、最小间隔。
- **Stats**：到期预测、复习时间、稳定性/难度分布、遗忘曲线。
- **Add-ons**：FSRS Helper 等可做 postpone/advance/load balance/disperse siblings。
- **本地优先 + 同步**：集合是本地 SQLite；AnkiWeb 同步；可导出。

**架构推断**

- 本地集合（cards/notes/reviews）+ 调度器 + 同步服务 + 插件 API。
- 数据模型围绕「卡片状态」而不是「题库」；复习历史是核心资产。
- 算法可替换（SM-2 → FSRS），但数据字段要能并存/迁移。

**视觉 DNA**

- 功能主义、灰白、密集表单；第三方评价「nobody falls in love with Anki's looks」。
- 复习界面只有卡片正反面 + 评分按钮；把配置项当界面是它的问题。
- 用户自定义卡片模板，视觉不统一。

**该借**

- FSRS 默认、Desired Retention、每日上限、Leech、Easy Days。
- 复习历史是核心数据，要可导出、可重建。
- 键盘效率、算法诚实、明确显示间隔。

**不该借**

- 把配置项当界面。
- 让用户先学一套调度术语。

**对 MedKit 的启示**：  
现版 SM-2 的 `reviewCard` 只有三档，且「连续 2 次记住」才掌握；没有每日上限、没有 leech、没有间隔预览。**FSRS + 队列上限 + leech 是复习模块的三件基础设施**。

### 2.7 Quizlet：把「学习路径」做成可解释的进度

**一句话定位**：卡片集合 + Learn 个性化路径 + 多活动进度。  
**证据等级**：A（官方帮助中心）。

**核心闭环**：  
`选 set → 设目标 → Learn 逐步加难 → 答题/书写 → 进度可视化 → Test`

**关键交互**

- **Learn**：基于熟悉度生成个性化学习路径；答对越多，题目越难/越少提示。
- **Answer Streaks**：连续答对形成 streak，属于 Learn 的一部分。
- **Write 模式**：第一轮每词答一次；错过的词进入第二轮；要完成整轮，每个词要答对两次。
- **进度可视化**：按熟悉度分组，显示哪些已掌握、哪些还需练。
- **多活动**：Learn / Test / Write / Spell / Flashcards，同一份内容不同练法。
- **班级**：教师可建 class、加 set，班级成员免费使用 Learn/Test。

**架构推断**

- 以 set 为内容单位，多个活动共享同一份熟悉度状态。
- 机器学习排序 + 活动结果回写进度。
- 订阅制 gate 高级模式。

**视觉 DNA**

- 亮蓝 `#4255FF` 为主色，扁平卡片、圆角、轻松；学习路径用进度条与分组呈现。
- 视觉不追求临床严肃，追求「低门槛开始」。

**该借**

- 「答对两次才算过」的掌握口径。
- 同一内容多活动：看卡、选择题、书写、测试。
- 进度按熟悉度分组，而不是一个总百分比。

**不该借**

- 订阅 gate 把核心学习能力锁住。
- 过度简化医学内容。

**对 MedKit 的启示**：  
现版「答对一次即归档已掌握」过于宽松；可以借「连续两次正确」+「错题回到第二轮」的口径，但不要做成订阅制。

---

### 2.8 Duolingo：把「开始」做得比「学」更容易

**一句话定位**：用路径、连胜、提醒与游戏化把学习变成日常习惯。  
**证据等级**：A（官方博客/帮助中心）；C（第三方设计分析）。

**核心闭环**：  
`打开 → 一条路径上的下一课 → 2–5 分钟练习 → 即时反馈 → 连胜/XP → 明天再来`

**关键交互**

- **Path**：把课程排成一条可见的路径，永远知道「下一课在哪」。
- **Streak**：连续天数；**Streak Freeze** 可提前购买，漏一天不清零。
- **Friend Streak / 社交**：与朋友一起保持连续；也有排行榜/联盟。
- **Notifications**：用 bandit 算法优化提醒时间；提醒文案个性化。
- **小步课**：每课 2–5 分钟，降低开始门槛。
- **失败反馈**：先接住情绪，再讲内容；角色出现在失败/成功/离开时刻。

**架构推断**

- 路径图（课程单元依赖）+ 练习类型库 + 事件流 + 通知/实验平台 + 游戏化状态。
- A/B 测试驱动；提醒时间是算法问题，不是文案问题。

**视觉 DNA**

- 饱和绿、圆角、角色 Duo、大按钮、路径节点；视觉语言统一且高识别。
- 字体：Feather Bold（标题）+ DIN Next Rounded（正文），圆润、友好。
- 动效与角色承担情绪，不靠文案堆感叹号。

**该借**

- 首启「先体验，后建档」；分布式引导。
- 一条可见的「今天下一件事」路径。
- 连胜宽限/冻结，而不是惩罚。
- 2 分钟小步启动。

**不该借**

- 排行榜、联盟、 hearts 惩罚。
- 角色抢内容焦点。
- 用愧疚感驱动通知。

**对 MedKit 的启示**：  
现版有「今天任务单」和「宽容连续天数」，方向对；但任务只有固定 20 题 + 复习，缺少「早上 10 分钟」「考前 7 天」这类时间窗规则。**把任务单做成规则引擎，而不是模板文案**。

### 3.3 十二条经市场验证的最佳实践

1. **先给价值，再要承诺**：Duolingo 首课在注册前；MedKit 已有「先做 3 道示例题」，应保留并强化。
2. **一屏一个主动作**：Duolingo 每屏一个绿色按钮；MedKit 今天页方向对，但刷题页仍有三块入口。
3. **学习节奏与检测节奏分离**：UWorld Tutor/Timed；MedKit 可做「练习/检测」而非全真模考。
4. **逐选项解释**：UWorld/AMBOSS/医考帮都做；MedKit 只有 20.8% 覆盖，是最大内容债。
5. **结论先行 + 依据可查**：医疗产品的三条硬约束；MedKit 已有 `source_ref`，但缺原句。
6. **难度标定**：AMBOSS 1–5 hammers；MedKit `difficulty` 字段全为 0。
7. **自适应/补弱**：AMBOSS Adaptive、Osmosis daily repetition、Quizlet Learn；MedKit 仍是随机/全量。
8. **准备度而非预测分**：AMBOSS Readiness 明确样本门槛；MedKit 没有准备度，也不该编分数。
9. **主动回忆优先**：Anki/Osmosis 先回忆再翻面；MedKit 复习卡直接给答案。
10. **算法诚实 + 队列上限**：Anki FSRS/leech/daily limits；MedKit SM-2 无上限无 leech。
11. **连胜可断，习惯不断**：Duolingo streak freeze；MedKit 已有宽容口径，可补「本周目标」。
12. **跨设备可续**：UWorld/AMBOSS 进度同步；MedKit 有账号快照，但冲突未解。

#### 3.4.1 七种视觉谱系

#### 3.4.2 MedKit 的美术定位

**一句话：纸张编辑部 + 临床图表 + 手作痕迹。**

- **纸张编辑部**（Readwise / Bear / iA）：米纸、宋体、窄阅读列、单一强调色。解决「读得下去」。
- **临床图表**（UWorld / AMBOSS）：对齐、单位、出处、考频、细规则线。解决「数据可信」。
- **手作痕迹**（红笔 / 荧光笔 / 印章 / 页边注）：只在判分、批改、出处、笔记这些语义时刻出现。解决「有人批改过」。

**不是**：游戏化角色、医院信息系统、文创贴纸、满屏手写体。

#### 3.4.3 十条美术规则

1. **纸是底，不是贴纸。** 噪点只铺页面底，不铺卡片；纹理透明度 ≤ 3%；不用木纹、胶带、拍立得。
2. **三种字，各司其职。** 界面黑体、阅读宋体、页边注楷体；衬线只出现在「读」的地方，按钮/标签/导航不碰。
3. **三色语义，不扩充。** 墨绿 = 主行动；红笔 = 批改/错误；荧光黄 = 原文/出处。其余颜色只做数据与科目识别。
4. **12 栏 + 8px 栅格。** 阅读列 720–840px；数字右对齐 + `tabular-nums`；表格用规则线，不用大圆角卡片。
5. **一屏最多两张纸。** 一张主纸（任务/题目/批改），一张副纸（统计/列表）；其余收进折叠或抽屉。
6. **书脊认书，不靠封面装饰。** 每个科目一个低饱和色，4px 书脊 + 书封 + 进度书边；用户能「认出内科学那本」。
7. **插图解释机制，不做吉祥物。** 空态/首启用桌面物件线稿；题目优先补「一张机制图 + 图注」，而不是全站插画。
8. **数据图像账簿。** 细规则线、右对齐、单位、`n=`、参考线、小倍数图；不用通用圆角进度条。
9. **动效像纸，不像弹球。** 90ms 按下、140ms 红笔描边、220ms 解析展开、240ms 盖章；只动 `transform/opacity`；`prefers-reduced-motion` 归零。
10. **暗色是台灯，不是反色。** 暖黑页面底 + 暖光池 + 纸面提暖；不用纯黑 + 纯白文字；对比度仍要 ≥ AA。

#### 3.4.5 五个反常识

1. **视觉识别不靠插画多，靠一个可重复的语义。** MedKit 的红笔与书脊，比十张插画更像品牌。
2. **信息密度不是敌人，无层级才是。** AMBOSS 很密，但每块都有标签与对齐；现版不密，却每张卡一样重。
3. **完成感来自动效与节奏，不来自徽章。** 批改页的印章 + 停住，比彩带更符合备考场景。
4. **专业感来自对齐与单位，不来自冷色。** 冷白不等于临床；数据右对齐、单位、出处才是。
5. **纸感来自 1px 规则线与留白，不来自纹理图。** 纹理只是 3% 的底，结构才是纸。

| 产品 | 看什么 | 借什么 | 不借 |

## 4. 现版基线

### 4.1 已经做对的事

- **数据资产**：11 个题库、2350 题、7 个科目组；A1/A2/X/B1/A3/A4/判断/案例多种题型。
- **作答闭环**：点选判分、集合判分、答题卡、键盘、计时、断点续做、错题自动回流。
- **复习**：SM-2、今日到期、三档自评、错题本筛选/搜索/重练。
- **账号**：可选 FastAPI 服务，PBKDF2 200k、HMAC cookie、每用户 SQLite、4.5MB 快照上限。
- **工程**：零构建、零 CDN、1 CSS + 1 JS、59 项 Node 测试 + 8 项 pytest、390px 无溢出、44px 触控目标。
- **设计令牌**：OKLCH 双主题、5 档字号、语义色、焦点环、骨架屏、错误态三段式。
- **语气**：首启单动作、深夜模式、允许停下、不排名、不惩罚断签。

### 4.4 设计规格与实现漂移

`docs/0.23.0-前端重设计_活人感_2026-10-29.md` §4 定义了完整的书桌系统，但实现只落地了一部分：

| 规格 | 实现状态 | 证据 |
|---|---|---|
| 纸面噪点 `feTurbulence` | 未实现 | CSS 中无 `feTurbulence` |
| 荧光笔 `--highlight` | 未实现 | tokens 无该变量；`source_quote` 为 0 |
| 书脊 `Spine` | 未实现 | 无科目色/书脊组件 |
| `Seal` 印章 | 部分 | 仅批改页 `.finish-seal` |
| `Keycap` 键帽 | 未实现 | 底部只有一行 hint |
| 红笔描边从左到右 | 未实现 | 无 `scaleX` 判分动效 |
| 页面切换 200ms | 未实现/部分 | 需核查 |
| 卡片圆角 10px | 未实现 | tokens 仍 12/16px |
| 宋体阅读面 | 已实现 | `--font-read` 用于题干/解析 |
| 双主题对比度 | 已实现 | tokens 行尾有实测对比度 |

**结论**：不是没有设计，而是**设计没有变成组件**。这就是为什么截图看起来仍像「后台」。

### 4.5 痛点排序

**P0 品牌与美术**

1. 书桌概念未组件化：纸、红笔、荧光笔、书脊、键帽大多停留在文档里。
2. 题库/科目没有视觉身份：书架没有书，卡片没有封面，用户无法「认书」。
3. 空态/首启/批改页缺少插图与情绪锚点；完成页是一张孤立小卡。
4. 暗色主题是反色，不是「台灯下的桌面」；缺少暖光池与材质层次。
5. 移动底栏拥挤：5 个导航 + 命令面板/主题/反馈/版本，图标与文字挤在一行。
6. 设置页原生控件与长页破坏质感；BYOK/危险操作与普通卡片同权重。
7. 数据图表缺少临床语言：进度条是通用 UI，不是病历/账簿式对齐。

**P1 学习闭环与信息架构**

8. 复习不是主动回忆：先给答案，再自评；无法检验「是否真的想起」。
9. 逐选项解析覆盖 20.8%，核心教学版 0–6%；「逐项」目前是局部卖点，不是普遍能力。
10. 没有知识点掌握度/准备度；薄弱项按 `subtopic` 聚合，未映射时为「未分类」。
11. 没有错因分类、错题组卷、同类题推荐；错题本只是列表。
12. 没有 FSRS、每日上限、leech、间隔预览、撤销。
13. 今天任务单只认第一个题库；无「早上 10 分钟」「考前 7 天」规则；「今天到这儿」只是 toast。
14. 刷题页三块入口重复；错题页聊天优先于复习；书架与管理重复；设置页过长。
15. 没有跨题目/错题/考点的内容搜索；命令面板只搜动作。

**P2 数据与架构**

16. localStorage 5MB/8000 条上限；无 IndexedDB。
17. 题目 id 是 `题库名#序号`，导出丢 id，导入静默去重；内容更新会让历史作答错位。
18. 账号同步是整包 last-write-wins；无版本号/墓碑/冲突 UI；4.5MB 上限。
19. 无 Service Worker/离线；PWA 只有 manifest。
20. BYOK Key 明文存 localStorage；CSP 允许 `unsafe-inline`；XSS 面需再评估。
21. AI 无流式/取消/超时/成本预估/引用校验。
22. 性能与可访问性只做了局部验证：无视觉回归、无 WCAG 全量审计、无 CI 守卫。

## 6. 成本—收益—可行性评估

### 6.1 评分方法

- **成本**：S=1、M=2、L=4、XL=8（相对单位，不是工期）。
- **收益**：按本轮权重计算：品牌 35% + 学习 30% + 留存 20% + 信任 15%。表中「收益」是加权后的 1–5 分。
- **ROI**：收益 / 成本；只用于排序，不替代判断。
- **可行性**：高=现有栈可做；中=需迁移/新依赖/内容配合；低=需外部资源或规模。

### 6.2 先做：高收益 / 低成本（Quick Wins）

|---|---|---|---|---|

## 8. 验收与度量

### 8.1 品牌/美术

- 5 维评分（1–5）：识别度、层级、一致性、工艺、可访问性；Phase 0 前后各评一次。
- 截图基线：亮/暗 × 390/1280 × 8 屏；每次改版 diff。
- 组件覆盖率：规格中的 Sheet/Seal/Highlight/Spine/Rule/Tag/Keycap 是否都有消费者。
- 约束：无 Web Font、无 CDN、无新增图片请求；JS 单文件 ≤800 行；CSS 无孤儿。

### 8.2 学习效果

- 首次作答正确率 vs 7 天后同考点正确率（延迟后测）。
- 复习完成率、到期积压、平均复习用时。
- 错题重练正确率、错题组卷完成率。
- 自评校准 Brier 分数（样本 ≥10 才显示）。
- 逐选项解析覆盖率（全库/核心教学版）。

### 8.3 数据/信任

- 导出→导入往返逐题相等率 100%。
- 同步冲突数、覆盖事故数 0。
- 配额失败率、迁移回滚成功率。
- 离线可用页面数；断网错误提示准确率。

### 8.4 体验

- 从打开到第一题点击的步数/时间。
- 390px 横向溢出 0；<44px 可点元素 0。
- 键盘全链路；焦点陷阱；200% 缩放。
- 错误态：是否说清「发生了什么/影响什么/怎么恢复」。

### 11.5 用户反馈修复批次（2026-10-30）

> 对象是网页版 `medkit-web-contest`。五条反馈全部定位到具体代码并已修复，浏览器实测通过。

| # | 反馈 | 根因 | 修复 |
|---|---|---|---|
| 1 | 必须点「保存设置」才能获取模型列表；保存按钮位置不对 | 「获取模型列表」读的是 `Store.byok()` 已保存配置，不看表单；保存按钮却放在「模型与连接」卡里 | `AI.modelsDetailed(draft)` 接受表单当前值；保存按钮移到「选择服务商」卡内并改名「保存服务商配置」 |
| 2 | DeepSeek 只显示 chat / reasoner 两个模型 | `AI.models()` 对内置服务商**直接返回硬编码列表**，从不请求 `/v1/models` | 改为有 Key 就真实拉取，失败才回退内置列表并如实说明原因 |
| 3 | 书架与题库管理功能重合 | 同一页两个大卡片各列一遍题库 | 合并为「题库」页：书架在上，管理收进默认折叠的 details |
| 4 | 题库管理 ↑↓ 点哪个科目都说「已经在边界」 | 多数科目只有 1 个题库；且提示语不说明原因 | 单题库科目 ↑↓ 直接 disabled + 标题说明；提示区分「唯一题库 / 第一个 / 最后一个」；补 `.mini-btn:disabled` 视觉 |
| 5 | 做对后跳下一题被关掉了 | `_BANK_AUTO_SECS = 0` | 恢复为 3 秒，保留可取消与三条不做（判错/背题/最后一题不跳） |

**验证**：`node --test tests/*.test.mjs` 72 项全绿（新增 4 项变式 + 3 项排序 + 3 项模型目录）；浏览器实测五项逐条通过（含禁用态 `opacity: 0.45`、`cursor: not-allowed`）。

**教训**：`index.html` 引用的是 `assets/` 里的合并产物，改 `js/*.js` 后必须跑 `python tools/build_bundle.py`，否则浏览器仍加载旧代码——第一轮实测三项不通过正是这个原因。
