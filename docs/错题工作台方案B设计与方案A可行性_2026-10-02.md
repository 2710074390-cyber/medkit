## 一、MedKit 现有能力盘点（方案设计的起点）

MedKit（`~/.medkit/`，本地 FastAPI 4880 端口）已实现三大功能的完整底座。方案 B 必须建立在这些事实之上，不重复造轮子：

| 功能域 | MedKit 已实现 | 数据/接口资产 |
|---|---|---|
| **错题生成** | 五阶段出题管线（MedGen→门禁→MedQC→MedFix→MedReview）、薄弱组卷 `gap.py`（priority×考频×未覆盖）、试出一题、真题考频 `realexam_freq`、教材/教师重点解析 | `~/.medkit/projects/`、素材 `sessions/`、`realexam_freq` 表 |
| **错题管理** | 错题本（`mistakes` 快照 + `error_events` append-only 流水）、SM-2/FSRS 复习卡调度、Anki `.apkg` 双向、错题检索（检索面严格限定自己数据）、多格式导入（.json/.csv/.md/.txt） | `~/.medkit/library/medkit.db`（SQLite，schema v8）、JSONL 导出（唯一备份格式） |
| **元认知分析** | 五组统计（校准曲线+Brier+JOL 偏差 / 标签×科目热力图 / 跨轮次迁移矩阵 / 人工-AI 归因一致率 / 减法清单）、Markdown 复盘笔记（零 LLM 输出层）、大纲覆盖（306 大纲 1291 条/10 科）、掌握度 | `GET /api/errors/export/notebook`、`GET /api/errors/export/jsonl`、大纲覆盖导出 MD |

**MedKit 四条设计红线（方案 B 必须尊重）**：
1. **AI 不判对错**——正确答案必须由考生提供；归因只做"解释与定位"。
2. **复盘笔记零 LLM**——统计直述、不写自由文本建议（避免"要扎实基础"式废话）。
3. **检索面只在错题数据内**——不检索教材正文。
4. **错题导入不带 `confidence`/`my_reasoning` → `gate_ok=False`**——只入库、不进入 AI 归因（事后补填会让校准曲线失真）。

> 由此得出方案 B 的分工原则：**MedKit 是"统计与调度权威"，Cherry Studio 是"解读与编排层"**。统计数字一律以 MedKit 为准；Cherry Studio 负责把统计翻译成可执行的个性化动作，并补足 MedKit 检索面之外的知识问答与变式生成。

### 2.2 开源项目对比表（9 个，全部结论带来源）

| **Quizlet** | Learn 题型自适应递进（查证）；Q-Chat 对话式教练不直接给答案（查证） | **Learn=session 内 logistic 回归预测遗忘概率排序，非跨天 SM-2（查证）**；付费 Memory Score | Progress 追踪+Smart Grading（查证）；掌握判断基于答题速度与正确率（查证） |
| **Anki / AnkiWeb** | 无 AI 出题，卡片自制/共享导入（查证） | **官方 SM-2 调度（已集成 FSRS）（查证）**；自评驱动四键；AnkiWeb 跨设备自动同步（查证） | 无自动掌握度报告（刻意设计）；抗遗忘靠调度算法本身而非曲线报告 |
| **墨墨背单词** | 无变式题，按词书推词（查证） | **自研 MM 记忆算法：千亿级行为数据逐词拟合遗忘曲线（查证）**；反馈规则"首现影响长期规划"（查证）；KDD 论文背书 | 遗忘曲线/记忆持久度可视化（查证） |

**商业产品化模式归纳**（每条来自上述产品的实际机制）：
- **错题生成**：考点标签人工题库组卷是底座（全行业）；AI 变式题是新趋势（昭昭已查证，猿题库/作业帮/医考帮为宣传口径）；AI 对话答疑是第四形态（医考帮 AI 伴学、Quizlet Q-Chat）。
- **错题管理**：答错自动收录+考点/章节打标是全行业标配；间隔重复分两档——学术派（Anki/墨墨/Quizlet，有算法）与刷题派（医考垂直+猿题库/作业帮，无公开跨天算法）。
- **元认知分析**：正确率打底 + 薄弱知识点诊断（定位到考点级）+ 掌握度可视化（图标/颜色）+ 错因归类（会但粗心 vs 不会），是主流四件套。

### 2.4 关键洞察（决定方案设计）

1. **MedKit 的 FSRS/SM-2 调度反而是差异化优势**——商业医考产品普遍不做跨天调度；方案 B 不应在 Cherry Studio 侧重复实现调度算法，而应把 MedKit 的调度结果呈现到每日流程里。
2. **错题生成的可复制范式已闭环**：昭昭的"错题考点→AI 变式题"（已查证）+ AnkiBrain 的"temperature=0 只依据源材料"（已查证）+ anki-llm 的"人工闸门"（已查证）——方案 B 的 Skill 1 照此设计。
3. **元认知报告的最优分工**：统计直述由 MedKit 零 LLM 产出（可靠、口径可复核）；Cherry Agent 只做"基于统计的行动建议"，且必须标注"建议"而非"统计"——避免 MedKit 刻意防住的"要扎实基础"式废话。
4. **知识库是快照不是实时管道**：Cherry Studio 知识库靠"添加文件→向量化"，无自动监控目录；方案按"周刷新 + 提醒任务"管理，不承诺实时同步（诚实边界）。
5. **错因分类学对齐**：MistakeLab 五分类（知识缺口/粗心/读错题/概念陷阱/时间压力）与 MedKit 6 类标签语义兼容，Agent 解读时可用五分类语言但**数字一律取 MedKit 口径**。

### 3.2 Agent 设计（3 个，Cherry Studio「工作→添加智能体」四步创建）

#### Agent 1：MedCoach 主教练（每日入口，总控）

- **基础信息**：名称 `MedCoach·西综教练`；模型建议：主对话用当前主力模型（如 DeepSeek v4 系列），高一致任务（出题）在生成师 Agent 上锁低 temperature。
- **人格**（可复制）：
  > 你是 MedCoach，一位陪伴 2027 考研考生备考西医综合（306）的全科方向教练。你了解首都医科大学全科医学的考情与北京就业环境，但**不编造任何医学知识**——一切医学结论必须以用户知识库中的教材原文为依据，知识库没有就明确说"没有依据"。
  > 你的工作原则：① 统计数字一律以 MedKit 导出的复盘笔记/错题档案为准，不估算、不美化；② 你给的是"方法建议"而非"判分结论"，判对错永远由用户或 MedKit 完成；③ 每次复盘只给 3 条以内可执行的建议，拒绝"要扎实基础"式空话；④ 保护用户的备考节奏，不制造焦虑。
- **技能**：全部 5 个 Skill（见 3.4）。
- **知识库**：KB-教材考纲、KB-MedKit 产物、KB-错题复盘档案（全部）。
- **权限模式**：读写文件（需要追加错题表、生成清单文件）。
- **指令结构**（工作流，可放人格或"技能"中）：`每日流程：① 读 KB-错题复盘档案 中最新复盘笔记 → ② 跑 Skill 到期提醒 → ③ 生成今日清单 → ④ 晚间引导录入 → ⑤ 周日触发周复盘。`

#### Agent 2：错题生成师（变式题 + 组卷，高一致）

- **基础信息**：名称 `错题生成师`；**模型建议：temperature=0~0.3**（对齐 AnkiBrain 防幻觉约束）。
- **人格**：
  > 你是错题生成师，职责是把一道错题或一个考点变成一组不重复的变式题。**硬约束：只能依据 KB-教材考纲 中的原文出题，禁止引入知识库外的医学知识（尤其是新药名、新剂量、新指南数字）；拿不准就写"待核"并跳过该点**。答案与解析必须与原文一致，且每题标注"AI 生成，需人工核对"。
- **技能**：Skill「错题变式生成」+ Skill「考纲缺口组卷」。
- **知识库**：KB-教材考纲（唯一事实源）+ KB-错题复盘档案（读错题输入）。
- **权限模式**：读写文件（写变式题文件到输出目录）。

#### Agent 3：元认知复盘师（周报 + 苏格拉底复盘）

- **基础信息**：名称 `元认知复盘师`。
- **人格**：
  > 你是元认知复盘师，负责把 MedKit 的五组统计翻译成人话并给出行动建议。你**不重新计算任何统计**——所有数字来自最新复盘笔记原文；你只做四件事：解读数字含义、指出值得警惕的模式（如过度自信、错因三轮未变）、给出 3 条以内行动建议、用苏格拉底式提问带用户回顾 1~2 道高价值错题（不先给答案，先问"你认为正确的是哪个，为什么"）。
- **技能**：Skill「元认知周复盘」+ Skill「苏格拉底讲解」。
- **知识库**：KB-错题复盘档案（主）+ KB-MedKit 产物（次）。
- **权限模式**：读文件为主（写周报文件）。

> 可选第 4 个 Agent「每日早间推送员」：仅跑 Skill 每日清单 + 定时任务，权限只读——若不想让主 Agent 被早间任务占用，可拆分。

### 3.3 知识库组织（3 个，Cherry Studio「知识库」创建，嵌入模型选 bge-m3 或同档本地嵌入）

| 知识库 | 内容 | 来源 | 刷新频率 | 绑定 Agent | 用途 |
|---|---|---|---|---|---|
| **KB-教材考纲** | 西综教材 PDF（人卫等）、贺银成讲义、教师重点、MedAgentWork 讲义素材（`知识库素材`/`复习资料`/`输入素材`）、306 大纲 MD | 教材电子版、MedAgentWork 素材、MedKit「大纲管理」导出 | 学期初/素材更新时（低频） | 错题生成师（唯一事实源）、MedCoach | 出题依据、讲解依据 |
| **KB-真题档案** | GoldenSet 配对后真题（按科目/年份分文件转 MD） | `MedAgentWork\GoldenSet`（配对脚本产出） | 配对完成后一次性 + 年度更新 | MedCoach、错题生成师 | "这个考点近十年怎么考"、考频检索、组卷依据 |
| **KB-题库** | AI 题库（MD/JSON，MedAgentWork 最终产物）+ MedKit 产物（题库/复习手册/押题卷 MD） | `MedAgentWork\archive\最终产物`、MedKit 项目导出 | 每次新增/更新题库后（中频） | MedCoach、元认知复盘师、错题生成师 | 跨题检索、答疑、变式生成参考、复习清单 |

**组织纪律**：
- 刷新 = 删除旧文件 → 添加新文件 → 重新向量化（知识库为快照模式，见 2.4 洞察 4）。
- **题库 MD/JSON 二选一导入，建议用 MD**（表格+段落结构对 bge-m3 切块检索最友好）；JSON 版保留为 MedKit 回灌用。
- 真题按科目/年份分文件转 MD（如 `真题-内科学-循环-2015~2024.md`），避免单文件过大淹没检索。
- 错题表 MD 只收录**近一轮/近一月**的错题（控制 token 与检索噪声），全量错题以 MedKit 为准；表头建议：`ID | 题干 | 答案 | 解析 | 系统→章节→考点 | 错因(MedKit口径) | confidence | 轮次 | 上次复习日 | 下次复习日 | 状态`。
- 复盘笔记 MD 原样收录（它已是五节结构化统计），**禁止 Agent 改写后覆盖**——保留 MedKit 零 LLM 口径。

### 3.4 Skills 清单（5 个，SKILL.md 声明式文件，装入 Cherry Studio skills 目录后全局启用并绑定到对应 Agent）

> Skills 均为 Markdown 声明（frontmatter + 指令文本），不含程序代码，符合方案 B"不写代码"边界。
> **SKILL.md 化捷径**：MedKit 已有 11 个生产级 prompt（`medkit\prompts\*.md`），本清单中每个 Skill 的出题/质检/归因/复习规则都直接改写自这些文件——复制其正文 + 加 frontmatter + 绑定知识库，成本极低，且规则已过 1438 项测试校验。

#### Skill 1：错题变式生成（`med-variant`，绑定错题生成师）
```markdown
---
name: med-variant
description: 输入一道错题或考点，基于 KB-教材考纲 生成 3 道不重复变式题（换数值/换病例/换干扰项），输出 MedKit 兼容 .md 错题文件。
---
# 错题变式生成
## 触发
用户说"变式/再来一题/同类题"或引用一道错题 ID 时。
## 输入
错题题干/考点/章节标签（从 KB-错题复盘档案 或对话中取得）。
## 步骤
1. 在 KB-教材考纲 中检索该考点原文（必须命中，否则输出"该考点无教材依据，跳过"）。
2. 生成 3 道变式：①换数值/剂量 ②换病例主诉 ③换干扰项方向；保持考点与难度不变。
3. 每题附：答案 + 解析（引用教材原文位置）+ 章节标签 + "AI 生成，需人工核对"标注。
4. 输出为 MedKit 兼容 .md（每道题用题号分隔，格式见示例），写入输出目录。
## 出题规则（直接引用 medkit\prompts\medgen.md，原样套用）
- HC-1 题型极性显式标记（反选题不变式）；HC-3 知识溯源强制（`[源:切片Sxxx]`）；HC-4 选项互斥唯一、禁绝对化用语；HC-5 禁止幻觉编造（素材查不到依据就**不出这道题**）；截断零容忍（诊断名/数值单位必须完整）。
## 红线
- 禁止引入知识库外医学知识（新药名/新剂量/新指南数字）。
- 禁止直接判对错；答案仅作为"待核答案"给出。
- 每次输出前自检：3 题考点一致、无重复题干。
```

```markdown
name: review-scheduler
```

```markdown
---
name: weekly-metacog
description: 每周日基于最新复盘笔记 + 错题档案生成周复盘报告（统计直述 + 行动建议双层），并按模板输出。

# 元认知周复盘

1. 读最新复盘笔记（MedKit 导出，零 LLM 统计）。
```

### 3.5 每日流程与定时任务设计（Cherry Studio「定时任务」按 Cron 配置）

| 时间 | 任务 | 执行 Agent | 调用 Skill | 输入 | 输出落点 |
|---|---|---|---|---|---|

**配置要点**：定时任务在「设置→定时任务」按 Cron 创建（如每日 07:30 = `30 7 * * *`），任务内容 = "执行 Agent X 的任务"；频道可选——把 MedCoach 派驻到微信/飞书等 IM，早间清单直接推到手机（对齐 Cherry Studio 频道能力）。**频道推送与"全本地"约束的调和：只推"提醒 + 数字摘要"（如"今日到期 12 题，薄弱考点：心律失常鉴别"），不推题目全文/答案/错题内容**——题目本体留在本机，IM 只承载提醒信号。

**手动兜底**：所有定时任务都可手动触发一次；知识库刷新是手动/提醒任务驱动的快照操作（每周日晚导出后顺手更新 KB-错题复盘档案）。

### 3.6 元认知分析报告模板（元认知复盘师输出，对齐 MedKit 五组统计）

```markdown
# 第 N 周西综元认知复盘（MM.DD ~ MM.DD）
> 统计来源：MedKit 复盘笔记导出（零 LLM，口径可复核）｜解读与建议：Cherry Studio 元认知复盘师
> 依据知识库：KB-错题复盘档案 / KB-MedKit 产物

## 1. 数据总览
- 本周错题数 / 累计错题数 / 各科分布
- 本周刷题量与正确率（若有）

## 2. 掌握度与校准（MedKit 统计①）
- 校准曲线结论：你的确信度准不准（Brier 分数、JOL 偏差，逐档表格摘要）
- 过度自信预警：confidence=5 但做错的比例（MedKit OVERCONFIDENCE_CEILING=0.90 口径）

## 3. 错因分布（MedKit 统计②）
- 标签 × 科目热力图摘要（主导错因占比）
- 一句话解读："你主要丢分是『不会』还是『会但粗心』——对策完全不同"

## 4. 跨轮次迁移（MedKit 统计③）
- 哪些错因三轮未变（MedKit 标红 = 换方法）
- 人工/AI 归因一致率；tag_match=0 的高价值题清单（1~2 道用于苏格拉底复盘）

## 5. 减法清单解读（MedKit 统计⑤）
- 本周建议别看什么（题量×正确率×近三年真题频次加权），并说明口径

## 6. 薄弱考点 Top 5（共性聚类，Agent 归纳）
- 考点 + 错题密度 + 建议动作（回看哪个章节/做哪类题）

## 7. 下周行动建议（Agent 生成，标注"建议"非"统计"）
- ≤3 条，每条 = 做什么 + 怎么验证（如："重做循环系统错题 20 道，周六看正确率是否 ≥80%"）

## 附录：口径说明
- 数字来自哪份导出、排除条目、频次缺失项
```

### 3.7 两套接法

**接法一：已有数据资产（MedKit 已在用 + MedAgentWork 题库/真题，本机已有 `~/.medkit/library/medkit.db`）**
1. **首次建库**（一次性）：
   - **题库**：MedAgentWork\archive\最终产物 各 batch 题库（MD 优先；JSON 版作为 MedKit 回灌源保留）→ 放入 KB-题库；MedKit 项目详情 → 下载题库/复习手册/押题卷（MD）→ 追加进 KB-题库。
   - **真题**：GoldenSet 配对（跑 `parse_goldenset.py` 或人工核对上下册）→ 按科目/年份转 MD → 放入 KB-真题档案；同时把配对后的完整真题（题干+选项+答案+解析）经 MedKit「真题考频」粘贴/上传导入 → **人工确认** → 激活 `realexam_freq`（减法清单与 gap 薄弱组卷从此有真题依据）。
   - **错题档案**：MedKit「学习中心」→ 元认知视图 → 导出复盘笔记（.md）→ 放入 KB-错题复盘档案；错题本 → 导出 JSONL → 整理成错题表 MD（让 MedCoach 读取 JSONL 文件内容并按 3.3 表头整理，只取近一轮/近一月，控制 token）→ 同入 KB-错题复盘档案。
   - **教材考纲**：讲义 PDF 与教师重点（MedAgentWork 知识库素材/复习资料/输入素材）→ KB-教材考纲；MedKit「大纲管理」→ 导出大纲覆盖 MD → 同入。
2. **日常更新**（每周日晚，配合定时任务提醒）：
   - 重新导出复盘笔记/错题 JSONL → 删除知识库旧文件 → 添加新文件 → 重新向量化（快照刷新）。
   - 新课题生成后，把新题库 MD 追加进 KB-题库；MedAgentWork 新 batch 产物同样追加。
3. **回灌闭环**（生成→确认→导入）：
   - 错题生成师输出变式题 .md → 你确认答案无误 → MedKit「错题本→批量导入」（.md 按题号切块；若用 JSON 则需按 MedKit 官方结构 `stem/options[{label,text}]` 做字段映射）→ 走 MedKit 管线（无 confidence/my_reasoning 的条目只入库不归因——符合 MedKit 红线，AI 生成题本就不该自动归因）。

**接法二：从零建（MedKit 尚未积累数据 / 概念验证阶段）**
1. 先在 Cherry Studio 建好 3 个 Agent + 3 个知识库 + 5 个 Skill（按 3.2~3.4）。
2. KB-教材考纲 先放教材 PDF 与 306 大纲 MD（MedKit「大纲管理」可一键导入官方大纲后导出）；KB-MedKit 产物 / KB-错题复盘档案 留空模板（错题表空表头 + 复盘笔记空模板）。
3. 用 MedKit「载入示例体验」跑通一次出题 → 得到第一批题库产物 → 填入 KB-MedKit 产物，即可开始使用；错题档案从第一道错题开始积累。
4. 两套接法共用同一套 Agent/Skill/流程，差异只在数据填充路径。

### 3.8 红线与边界（方案 B 的诚实边界）

1. **AI 不判对错**：Cherry 侧一切答案标注"待核"，判对错永远走 MedKit 或用户。
2. **知识库是快照**：不是实时管道；统计数字以 MedKit 为准，知识库可能滞后一周。
3. **医学防幻觉**：temperature=0~0.3 + 只依据 KB-教材考纲 + "没有依据就说没有"。
4. **两套调度不打架**：MedKit 管调度与统计；Cherry 的 review-scheduler 只读展示，不写 S/D。
5. **复盘笔记原文件不可覆盖**：MedKit 零 LLM 口径保留，Agent 只在其上叠加解读。
6. **隐私与本地化（硬约束）**：全程本地——题库、错题、真题、档案全部存本机（MedKit 本地 + Cherry Studio 本地存储，无官方云同步）；**不启用任何远程共享/云端同步，WebDAV/S3 仅作可选备份手段**；方案 A 的移动端远程版（数据出本机）与本地化约束冲突，不推荐（见 5.2 第三步）。
7. **不写代码**：本方案仅用 Cherry 配置界面 + SKILL.md 声明文件，无 Python/JS、无 MCP 服务器。
8. **真题可用性**：GoldenSet 真实真题需先配对（上册题目 + 下册精析）并人工抽检质量后再启用；配对完成前，"考频/减法清单"不得当作有真题依据（MedKit 的 `realexam_freq` 以人工确认为准）。

## 四、方案 A（自研 MedKit MCP Server）可行性

> 本节基于《MCP-Server-可行性调研报告》（2026-10-02，路径见附录 A）。证据等级标注沿用该报告。

### 4.1 MCP Server 的成熟架构模式（已查证）

**传输层（一个常见误解的澄清）**：MCP 现行规范标准传输只有两种——**stdio**（本地、客户端拉起子进程、零网络、免鉴权）与 **Streamable HTTP**（远程、单端点 HTTP POST、支持 Bearer/API Key/OAuth）；旧版"HTTP+SSE"已官方废弃，新实现不应采用（来源：modelcontextprotocol.io 2026-07-28 spec transports 页）。

**实现框架**：
- **FastMCP** 是 Python 侧事实标准（已并入官方 SDK 路线；2026-05 已到 v3.3.x），对"给已有 HTTP API 套 MCP 壳"这类需求完全够用；
- 官方 Python SDK（PyPI `mcp`）**至今自标 Beta**（1.17.0，2025-10），协议半年内连续迭代（2025-11-25 → 2026-07-28，有 breaking change）——**个人项目要锁版本**（来源：pypi.org/project/mcp/1.17.0、blog.modelcontextprotocol.io sdk-betas）。
- **对 MedKit 的关键含义**：不需要重写业务——MCP Server 的每个 tool 内部就是一次 `localhost:4880/...` 调用，把现有 FastAPI 端点翻译成 MCP tool 即可（Anki 系桥接项目同构，见 4.2）。

**工具设计规范（已查证 + 社区共识）**：动词开头 snake_case 命名（`get_due_quiz`、`record_answer`）、一句话描述（模型据此决定是否调用）、扁平 JSON Schema 参数 + enum 防幻觉、**错误放 result 的 `isError: true` + 可读消息**而非协议层错误（模型才能自纠重试）、长操作用进度上报（来源：modelcontextprotocol.io tools 页、awslabs/mcp DESIGN_GUIDELINES）。粒度建议**一个 tool 对应一个已有 HTTP 端点**。

**认证与部署模式**：
| 部署形态 | 传输 | 鉴权 | 对 MedKit 的意义 |
|---|---|---|---|
| 本地 stdio（桌面） | stdio | 无需 | **桌面首选**：Cherry Studio 拉起即用，零配置 |
| 局域网 HTTP | Streamable HTTP | 可加 Bearer Token | 手机连家里电脑的折中 |
| 轻量云/VPS | Streamable HTTP + HTTPS | Bearer Token / OAuth | 需把数据复制上云，隐私边界重画 |
| Serverless | Streamable HTTP（无状态） | Bearer Token | **不适合**：MedKit 是本地有状态 SQLite |
| 常驻进程 + 内网穿透 | Streamable HTTP | Bearer Token | Anki 社区做法；等同把本地库暴露公网，风险高 |

鉴权规范：远程每个请求必须 `Authorization: Bearer <token>`，token 禁止放 URL query string；失败返回 401 + WWW-Authenticate（来源：modelcontextprotocol.io authorization 页）。

**持久化**：MCP 不规定持久化方式，惯例是 server 自管——官方 memory reference server 用本地 JSONL + 知识图谱；社区成熟做法用 SQLite（WAL 并发、sqlite-vec 向量检索）。MedKit 本就是 SQLite，**这是最顺的一点**：MCP Server 直接读写同一库（注意 SQLite 多进程写要开 WAL）。

**日志与排错**：stdio 传输下日志必须写 stderr（stdout 是协议通道，写日志会污染 JSON-RPC 帧）——这是 stdio MCP 最常见的坑。

### 4.2 开源 MCP Server 项目（5+ 个，逐项成熟度评估）

| 项目 | 核心机制 | 技术栈 | 成熟度 | 可借鉴点 |
|---|---|---|---|---|
| **ankimcp / anki-mcp-server** | 在 Anki 内嵌 MCP server，建卡/按到期出题/评级/复习分析，细粒度权限 | Node/TS，npm；本地 SSE | ☆ 活跃社区项目，有商业化官网 | **"在已有应用内嵌 MCP server"正是 MedKit 该走的路**；Web 模式 ngrok 隧道是移动端远程的现成参考 |
| **mcp-server-anki** | 通过 AnkiConnect（Anki 端 HTTP）桥接，MCP 再包一层 | Node ≥16 | ☆ | "已有 REST → MCP 桥"与 MedKit"4880 HTTP → MCP"完全同构 |
| **anki-connect-server** | 无 Anki 桌面直接读 `.anki21` SQLite 收藏库暴露 MCP | Python，uvx | ☆ 早期（v0.2.0） | **Python 侧直接读 SQLite 的参考实现**，与 MedKit 架构最接近 |
| **官方 Memory reference server** | 知识图谱持久记忆（entities/relations/observations），本地 JSONL | TS | ★ 官方 reference | 官方钦定的"持久化记忆"范本 |
| **@memorygraph/server** | better-sqlite3(WAL) + sqlite-vec 本地向量 + 本地 embedding，零外部依赖 | TS/Node | ☆ | 单文件 SQLite + 本地向量零运维，个人项目可抄 |

| **medadapt-content-server** | 聚合 PubMed/NCBI Bookshelf 与用户文档做医学学习 | Python | ☆ 个人早期项目 | "医学学习 + MCP"直接先例，与 MedKit 互补而非竞争 |

**成熟度结论**：Anki 系项目（★☆ 级）可直接借鉴"已有本地 HTTP/SQLite → 包一层 MCP"架构，但**都不能直接装来管 MedKit**（绑死 Anki 格式）；**公开生态没有现成的"西综错题本 + 元认知统计"MCP**（负面检索结论）——方案 A 必须自研，但自研是"抄 Anki 桥接模式"而非从零发明。

### 4.3 MCP 生态与商业采用现状

- **已查证**：官方 MCP Registry 已上线；GitHub MCP Registry 已推出（2025-09）；主流客户端（Claude Desktop/Claude.ai、Cursor、VS Code、Cline 等）官方收录支持 MCP；**Cherry Studio 属"支持但需开关/特定版本"一档**；Syracuse University 把"Anthropic 开放发布 MCP"列为部署 Claude 的选型理由之一（高校认可其开放性的一手案例）。
- **宣传/待查**：所谓"edtech 官方 MCP server 首批"（EduBase 等）只见二手博客，未找到官方一手公告——**决策时不要当作已证实事实**。
- **结论**：教育垂直行业的"机构级 MCP 落地"案例仍少；扎实信号是"协议被主流客户端广泛支持 + 高校选型认可开放性"，协议仍在快速演进（双刃剑：生态热但版本迭代快、官方 Python SDK 仍 Beta）。

### 4.4 增量价值 vs 代价（决策矩阵）

| 增量价值 | 说明 | 代价项 | 评估 |
|---|---|---|---|
| **真持久化（可写回）** | AI 能 `add_wrong`/`record_answer`，错题与统计随复习真实增长（知识库只读做不到） | **开发量** | 小到中：给现有 4880 API 套 FastMCP 壳，约 1–3 个工作日（推测量级）；无需重写业务 |
| **可计算、统计严谨** | 元认知统计由代码确定性计算（SQLite 精确数字），LLM 估算不可靠 | **部署（桌面）** | 极简：stdio 一条命令拉起，无端口无鉴权 |
| **多端数据统一** | 一份 SQLite 真相源，桌面/手机走同一 MCP 读写，避免知识库副本漂移 | **维护** | 中：协议快速演进 + 官方 SDK Beta，需锁版本、最小化接口面 |
| **低延迟本地调用** | stdio 同机零网络开销；localhost 级延迟 | **鉴权（仅远程）** | 桌面无需；远程需 Bearer Token + HTTPS |
| **工具可组合** | 出题/错题/统计工具可与 @cherry/memory、PubMed MCP 自由组合 | **移动端** | 见 4.5，主要风险所在 |

### 4.5 移动端连接远程 MCP 的可行性与风险（重点）

- **可行性**：技术上成立——手机上的 Cherry Studio 移动端（v0.1 公测）支持 MCP，走远程 **Streamable HTTP/SSE + Bearer Token** 即可调用（已查证规范支持该鉴权；Cherry Studio 支持自定义 header 配置 `Authorization: Bearer`，有旁证来源）。
- **硬约束**：手机无法跑本地 stdio 进程 → 移动端 = 必须远程暴露，**没有"本地零配置"选项**。
- **主要风险（按严重度）**：
  1. **隐私风险（最高）**：错题本/元认知数据是高度个人化学习画像（暴露薄弱考点、备考节奏），远程 = 本地数据库经公网暴露——必须 HTTPS + 强随机 Token + **最小权限（先只暴露读工具）**。
  2. **暴露面**：Anki 社区远程方案依赖 ngrok 类隧道，意味着本机对互联网可达，扩大攻击面。
  3. **数据边界被打破**：MedKit 数据原本"纯本地、无云同步"；远程 MCP 后数据经公网（甚至云 VPS），隐私边界从"不出本机"变"出本机"——与方案 B（数据同样本地）在隐私模型上是本质差异。
  4. **成熟度风险**：Cherry Studio 移动端是 v0.1 公测，MCP 在移动端形态（能否自定义 header、能否绑 Agent）需以实际版本验证，不要假设与桌面端完全一致。

## 五、A/B 对比与推荐

### 5.1 A/B 对比表

| 维护成本 | 低（配置与提示词） | 中（跟协议升级、锁版本） |
| 外部知识扩展 | ✅ 知识库可随时加文档 | ✅ 可与 PubMed MCP 等组合 |
| 一句话定位 | **被动、只读的教练问答层** | **主动、可计算、可积累的个人学习引擎** |

### 5.2 推荐：混合路径（A、B 并存，分三步走）

1. **第一步（现在，零风险）**：按第三章实施方案 B——3 Agent + 3 知识库 + 5 Skill + 定时任务，先跑通"MedKit 快照 → 教练层 → 每日流程"闭环。**成本为零、数据不出本机、不依赖任何新代码**。
2. **第二步（可选，桌面 stdio）**：如果使用中觉得"AI 只能读快照、不能写回错题本/算实时统计"是硬伤，再给 MedKit 的 4880 API 套一层 FastMCP 壳做**桌面 stdio 版 MCP**（1–3 天量级，推测）：错题本可写回、统计可计算，隐私零暴露。这步与方案 B 的 Agent/知识库/Skills 完全兼容——MCP 工具只是多给 Agent 一只手。
3. **第三步（暂缓，移动端——受"全本地"硬约束限制）**：远程 Streamable HTTP 版意味着错题/真题数据经公网（或云 VPS），与"所有数据必须本地"的硬约束冲突，**默认不做**；若未来确有手机复习需求且接受隐私边界变化，再评估"局域网 + Bearer Token"的折中（手机连家里电脑，数据不出家庭网络），并先确认 Cherry Studio 移动端实际版本对自定义 header 与 Agent 绑定的支持形态。

> **决策依据**：方案 B 覆盖"解读、编排、问答"三类高频需求且零成本；方案 A 的独有增量（可写回、实时统计、跨端统一）在桌面 stdio 版上以极小代价获得；远程移动版是唯一有实质隐私代价的部分，应最后做且默认只读。若第一步做完发现核心诉求其实是"被动问答"，则方案 B 已足够，无需再投入 A。
