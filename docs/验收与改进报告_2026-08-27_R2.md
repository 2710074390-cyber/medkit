## 1.3 遗留问题、风险与返工指令

### R-1【高 · 发布未闭环】16 commits 未推送，GitHub Release 停留 v0.6.0
- **现状**：本地 `master` 领先 `origin/master` 16 个 commit（含整个 v0.8 + IMP 全套）；GitHub 最新 Release = v0.6.0（2026-08-26）。
- **影响**：① 内置更新检查（`core/update.py` 比对 Releases）对 v0.7/v0.8 用户永远静默；② 协作者/CI 基线落后；③ v0.7「待打包发布」从上一轮遗留至今，v0.8 又叠加——发布债持续累积。
- **返工指令**（NX-01）：`git push` → `pack/build.bat` 打包 → exe 冒烟（启动/六视图/FTS 检索/出题离线 mock）→ 建 GitHub Release `v0.8.0`（CHANGELOG 0.8.0 节作 release notes + 挂安装包与绿色版 zip）→ 真机验证 `/api/update/check` 提示新版本。

### R-2【中 · 契约层未闭环】软校验只观测不修复
- **现状**：见 IMP-03 偏差。`chat_json(schema=)` 零实际调用；medgen/medqc 失败仅告警，告警进 `~/.medkit/logs/` 用户不可见。
- **影响**：ADR-003 承诺的「校验→修复→复核兜底」闭环未形成；prompt 漂移或模型变更导致的结构性劣化只能事后翻日志发现。
- **返工指令**（NX-03）：① medqc 试点硬闭环——`agents/medqc.py` 判分 JSON 改走 `validate_or_repair(raw, QcVerdict, repair_fn)`，仍失败批次按既有「score=-1 不计分」兜底语义进人工复核；② medgen 维持软校验（论证：下游四门禁+D2 终检已是硬兜底，双写修复成本高），但在 `core/dashboard.py` 增加「契约告警计数」聚合（读 logs 或在 orchestrator 计数落 meta），学习中心概览可见——把「观测层」的观测结果真正暴露给用户；③ `chat_json(schema=)` 参数若持续无调用，下下一轮评估移除（YAGNI）或在 medqc 接入时启用。

### R-3【高 · 打包必坏风险】medkit.spec 未收集 jieba 数据文件与子模块
- **现状**：IMP-06 引入 `jieba` 依赖，但 `medkit.spec` 的 `hiddenimports` 无 jieba 子模块（`jieba.posseg`/`jieba.finalseg` 为运行时动态导入）、`datas` 无 jieba 词典（`dict.txt` 约 5MB，PyInstaller 不会自动携带）。开发环境 277 测试全绿**掩盖不了**打包产物缺词典——绿色版/安装包的 FTS 检索必坏（jieba 初始化失败或静默退化为单字切分，且当前 `fts_search` 的 bigram 回退是否兜住 jieba 导入异常未验证）。
- **返工指令**（NX-02）：spec 增加 `from PyInstaller.utils.hooks import collect_data_files, collect_submodules` → `hiddenimports += collect_submodules("jieba")`、`datas += collect_data_files("jieba")`；打包后冒烟必须包含「学习中心 → 复习卡查看提示（触发 explain/slices FTS 检索）」一步。
- **附带**：`core/explain.py` 的 jieba 导入建议改懒加载 + ImportError 兜底（直接落 bigram 回退），双保险。

### R-4【低】`docs/superpowers/specs/` 空目录残留
- 空目录入版本库无意义。返工：`git rm -r docs/superpowers`（如无隐藏文件）。

### R-5【低】CI 不跑 browser 层
- 方案允许本地闸门，但 16 commits 未推送的现实说明「本地自律」不可靠。建议 NX-05 在 CI 加 ubuntu + playwright job（`actions/cache` 缓存浏览器二进制，失败不阻塞 windows 矩阵）。

### R-6【低】jieba pkg_resources deprecation warning
- 测试输出 warning（setuptools≥81 将移除 pkg_resources）。建议 `requirements-dev.txt` 加 `setuptools<81` 注释说明，或关注 jieba 新版；暂不影响功能。

### R-7【低】a11y 残留盲区
- ① 题库 HTML（`render/qbank_html.py` 题库页部分）的搜索/过滤工具区无 aria 标注（判分区已覆盖）；② `medkit.spec:25` 注释「四个提示词模板」过时（实为 6 个：medexplain/medfix/medgen/medqc/medreview/medtutor）——纯注释漂移，功能无碍（datas 整目录递归），顺手改。

### R-8【低】prompts 版本治理半落地
- §6.2 要求「prompt 版本号进 docs」：fixtures 已建 ✅，但 CHANGELOG 无任何 prompt 变更记录规范。本轮 prompts 未改动故无实际损失；建议 NX-06 定规范：凡 `prompts/*.md` 改动，CHANGELOG 当版必须含 `### Prompts` 小节。

# 三、架构与设计审查

> 以下问题按「不合理之处 → 影响 → 改进建议 → 借鉴与匹配度」组织。均不阻塞当前发布，列入 v0.9 前评估。

## A-1 `_run_project_impl` 452 行上帝函数（orchestrator）
- **问题**：`core/orchestrator.py:190-641` 单一函数内联了断点恢复、五阶段编排、并发控制、配额、门禁循环、补足/截断、终检、渲染触发、记账——阶段逻辑无法独立单测，改动任一阶段都要在 452 行上下文里推理；WP-05/06 接入后将进一步膨胀。
- **改进建议**：抽 `PipelineContext` dataclass（proj_dir/meta/config/log/cancel_event）+ 每阶段独立函数 `stage_generate(ctx) / stage_gates(ctx) / stage_qc(ctx) / stage_fix(ctx) / stage_review(ctx) / stage_render(ctx)`，主函数只做串联与断点记录。行为零变化（纯结构重构），browser + 离线管线测试（test_pipeline_offline）即安全网。
- **借鉴**：LangChain/Temporal 的 pipeline-stage 显式建模（匹配度高——本项目已是事实上的阶段管线，只差显式化）；不借鉴其框架本体（零新依赖原则，匹配度低）。

## A-2 `core/library.py` 768 行多域混杂
- **问题**：39 个公开函数横跨错题 CRUD、掌握度状态机、优先级推荐、数据卫生（heal/scan）、批量导入、存储路由（`_store/_load/_save` 咽喉）五个域；单一文件同时是「领域层」与「存储适配层」。
- **改进建议**：拆 `core/library/` 包——`store.py`（咽喉路由+事务）、`mistakes.py`（CRUD+同步）、`mastery.py`（score/state/priority）、`maintenance.py`（heal/scan/import）；`core/library.py` 保留为 facade 重导出（routers 零改动，沿用 S0「迁移伤面藏在模块内」惯例）。
- **借鉴**：Anki 的 collection 分层（sched/decks/cards 分域， facade 对外）——匹配度高；Zotero 的 DAO 层亦可参考。

## A-3 双模存储（JSON 兼容读 + SQLite）应设下线时间表
- **问题**：ADR-001 定 JSON 为「一次性导入源」，但 `_load/_save` 咽喉的 JSON 分支长期存在 → 每个域模块永远维护两套路径，测试面×2（test_library + test_library_sql 并存）。
- **改进建议**：定 v0.9 里程碑——JSON 模式只保留「检测到 *.pre-db-*.bak 时的一次性导入」，删除运行期 JSON 读写分支与对应测试（保留导入幂等测试）；CHANGELOG 明示。
- **借鉴**：Logseq/Obsidian 的存储迁移策略（迁移完成后旧格式只读导入）——匹配度高。

## A-4 FTS 双轨检索缺「旧轨删除检查点」
- **问题**：IMP-06 承诺「双轨一个版本，测试锁定后删旧轨」，但无机制保证执行 → 技术债登记缺失，bigram 回退路径可能永久残留。
- **改进建议**：CHANGELOG `[Unreleased]` 登记「v0.9 评估删除 bigram 回退（保留 ImportError 兜底分支）」；删除标准 = FTS 在打包环境实测稳定（NX-01 冒烟覆盖）+ 30 天无回退触发日志。
- **借鉴**：骨干项目的 feature-flag/toggle 生命周期管理（Martin Fowler 的 toggle 退役实践）——匹配度中，本项目用 CHANGELOG 登记即可，不必引入债管理工具。

## A-5  routers 层偏胖（library.py 573 / projects.py 401 行）
- **问题**：部分路由函数内含业务判断（如 gap.py 的配题参数处理、projects.py 审核台批量写逻辑），与「routers 只写 HTTP 语义」的 S2 约定有出入。
- **改进建议**：随 WP-05/06 新增路由时执行「瘦路由」规则——凡超过 20 行的业务判断下沉 core 层；既有胖路由不专项重构，触碰时顺手下沉（boy-scout rule）。
- **借鉴**：FastAPI 官方推荐的「router-service 分层」——匹配度高。

## A-6 前端 `review-desk.js` 1795 行是下一个单文件风险点
- **问题**：拆分后审核台逻辑（过滤/批量/编辑/重掷/状态对账）集中在单文件，增速与当初 index.html 同构。
- **改进建议**：下轮触碰审核台时按 `rd-toolbar.js / rd-batch.js / rd-editor.js` 二次拆分；不阻塞。
- **借鉴**：VS Code 的按 feature 分文件（editor/contrib）——匹配度中。

## A-7 契约/门禁告警缺统一可观测面
- **问题**：软校验 warning、门禁剔除、人工复核清单分散在 logs、项目 meta、产物 MD 三处，用户无单一入口感知「本次生成质量」。
- **改进建议**：随 NX-03 在概览卡做「质量面板」雏形（契约告警数/门禁剔除数/复核清单条数三指标聚合），后续 WP-07 洞察直接复用该面板。
- **借鉴**：instructor 的 validation telemetry（匹配度中——只借鉴「校验结果计数外显」，不引入其库）；Grafana 式 RED 指标思路（匹配度低，过重）。
