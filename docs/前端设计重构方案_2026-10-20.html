前端设计重构方案 · 评审稿

把 MedKit 从「功能面板的集合」
改造成一间安静的学习工作台

先诊断设计债，再给出目标设计语言与分阶段落地路径。本文不含任何代码改动—— 按你的要求，确认之后才开工。

日期 2026-10-20 对象 MedKit v0.18.1 · medkit/web 证据 实跑截图 8 张 · 源码实测 · 对比度计算 · 5 轮外部检索

结论先行

  1. 功能是好的，形态是错的。主闭环（导入题库 → 刷题 → 判错回流 → 错题复盘）扎实； 但界面把实际零使用的「出题工坊」放在了最显眼的位置，而把每天要用的「错题」藏在二级页签里。
  2. 亮色主题是残的。实测：亮色下卡片底色与页面底色都是 #ffffff，分离度 1.00:1，整个界面塌成一张白纸；控件边框对比度只有 1.26:1，远低于非文本对比要求的 3:1。
  3. 层级靠字号，而字号挤在一起。实测现状共有 16 档字号 （10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15 / 16 / 17 / 20 / 21 / 22 / 24）， 正文 14px——相邻档常只差 0.5px，撑不起层级，读起来是"糊"的。
  4. 一切都是卡片。「设置」一屏纵向 8 张卡，「错题本」6 张卡（含 1 张默认隐藏的详情卡）； 而布局只有一条 1000px 单栏——卡片替代了本该由间距和排版完成的组织工作， 空间也没有被用来承载"列表 + 详情""主区 + 上下文"这种本应并置的结构。
  5. 好消息：不需要推倒重来。暗色对比度已经过硬（正文 14.87:1）、图标体系统一、 零构建零 CDN 的架构天然适合"令牌化重写"。核心是三件事： S1 令牌与主题重写 · S2 排版与间距收敛 · S3 信息架构收敛。

1产品形态再确认

设计重构的前提是先把"这东西到底是什么"说准。以下结论全部来自仓库内可复核的记录，不是推测。

1.1 交付与技术形态

  • 本机回环单用户 Web 应用：FastAPI + uvicorn 监听 127.0.0.1:4880~4889， 前端是纯静态资源（medkit/web），由浏览器承载；Windows 上以绿色版/安装包交付 （run_medkit.py 自动开浏览器）。
  • 零构建 / 零 CDN / 经典脚本：13 个 JS 分片按固定顺序加载并共享全局作用域；CSP 全同源。 这是本方案的硬边界——任何引入打包器、CDN 字体、UI 框架的"现代化"都被排除。
  • 规模纪律：每个 web/js 文件 ≤800 行；CSS 类必须有消费者； index.html 的内联 on* 调用的函数必须有顶层声明。
  • 未来分叉：docs/网页版可行性分析_2026-10-16.md 已论证托管多用户版的可行性 （做题闭环 100% 可复现，阻断项是用户体系）。本方案的令牌与主题系统对桌面版与网页版同时成立， 不构成未来迁移的负担。

1.2 用户与真实场景

目标用户是临床医学本科生/规培，备考执业医师、期末或考研西综。典型使用场景是晚上 1~2 小时连续刷题 加错题复盘，偶发在手机浏览器上翻错题（桌面已过 768/390 响应式测试）。这意味着：

  • 界面必须有"专注模式"——做题时不应该被导航和状态面板干扰；
  • 错题复盘是粗读—筛选—精读—复述的来回动作，列表与详情的切换成本要接近零；
  • 长时间阅读的眼部负担是关键指标——正文 14px、次要信息 11~12px 偏小。

结论：MedKit 的真实形态是「刷题工具 + 错题复盘本」，出题工坊是可选插件。 这一点决定了后面信息架构收敛的方向——不是砍功能，而是把零使用的功能从视觉高位撤下来， 把高频功能从深层次提上去。

1.4 设计定位（一句话）

安静的学习工作台（Calm Study Workbench）。 它应该像一本排版考究的讲义，而不是一块状态大屏。三条原则贯穿全案：

  • 层级先行，装饰殿后。先用字号、字重、间距把主次分清，再谈颜色和圆角。
  • 一屏一个主任务。同一屏不做两件事，"该做什么"要在两秒内看得出。
  • 颜色只承担语义。强调色稀缺才有力；语义色不可只靠色相区分。

反模式判定：没有 AI 味，但"没有味道"

这版界面通过了"看起来不像 AI 生成"的检测——它没有 2024–2025 年那套典型指纹 （渐变文字、发光强调、玻璃卡片、hero 指标堆砌）。但它因此撞上了另一个问题： 把它换皮给任何一个桌面工具都不违和。克制是对的，但没有用排版、留白和节奏立起自己的性格。 这是本方案里最需要"做加法"的一处。

问题清单（按严重度）

P0 亮色主题下卡片与页面同色

  • 位置：medkit/web/css/base.css 亮色块 --bg1:#ffffff、 --card:#ffffff（文件头两处 :root[data-theme=light] 内），消费点 .card。
  • 影响：亮色是多数人的默认（跟随系统），而这一主题下所有卡片、节标题区、数据区 全部融进同一张白纸。用户只能靠 1.26:1 的发丝线猜测"哪里是一块内容"——这就是截图里"白得发慌"的成因。
  • 修法：把亮色关系反过来——页面底用浅灰（#F4F7F6），卡片保持纯白（#FFFFFF）， 分离度 1.08:1 时卡片自然浮起，发丝线只做"内部分隔"而不再承担"识别卡片"的职责。

P1 亮色控件边框对比度不足，交互控件识别性差

  • 位置：--line:#e5e5e5 被输入框 / 下拉框 / .bank-opt（选项行）/ .dc-cell（答题卡格子）/ .fbox（拖拽区）同时用作控件边界。
  • 实测：#e5e5e5 对白底 1.26:1，对卡片2 1.16:1。 暗色侧 #404040 对卡片 1.50:1。均低于 WCAG 1.4.11（非文本对比 3:1）。
  • 影响：选项行的边界、答题卡格子的边界、输入框的边界都属于"识别控件所必需的视觉信息"， 对比度不足会让视线扫不过去，也影响低视力与强光环境。
  • 修法：拆成两级描边令牌—— --line-hair 发丝（装饰性分组，允许 1.3:1）与 --line-ctl 控件描边（必须 ≥3:1）。 实测 #858F8D 对白底 3.04:1，暗色 #77817E 对 #1a1f1d 4.16:1，可用。

P1 亮色「成功」状态文字低于 AA

  • 位置：--good:#4a8f45（亮色）被 .hint.good、.ready .ok、 .substep.done > summary、.ocrst.done 用作 12~13px 正文。
  • 实测：3.96:1 < 4.5:1。暗色侧 #6ccb62 对底色达到 11.86:1，对比之下亮色这一档明显欠调。
  • 修法：亮色成功色压深到 #257944（提案实测 5.39:1）， 同时把"淡底 + 深字"的组合固定成一个语义色对（--good-fg / --good-bg），不再散落地用 rgba 调。

P1 字号档位过多，正文偏小，层级撑不起来

  • 位置：base.css + learn.css 合计出现 16 档字号：10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15 / 16 / 17 / 20 / 21 / 22 / 24。
  • 影响：12 / 12.5 / 13 / 13.5 / 14 这五档全挤在 2px 区间内，肉眼几乎无法当作不同层级； 而 10.5~12px 的说明文字在整屏铺开，长时间阅读明显吃力。层级实际上靠"有没有加粗"在硬撑。
  • 修法：收敛到 5 档（12 / 13.5 / 15 / 19 / 28），正文从 14 → 15px。 相邻档之间保持 ≥1.3 倍以上的可辨间距。

P1 信息架构与真实使用错位

  • 证据：出题工坊产物为 0，「启用出题工坊」却是设置页的首张卡； 「题库」是一级页签（默认隐藏），而每天要用的「错题」在学习中心里排第二。
  • 影响：新用户第一眼看到的是自己不会用、也不需要用的东西； 而他真正每天要点的东西要多一次点击才能到达。零使用功能占据了最贵的版面。
  • 修法：把出题工坊整组折叠进「设置 → 进阶功能」，位置落到末位； 「错题」提升为一级页签（详见 §5）。

P2 一切皆卡片，一屏塞多张，宽屏留死区

  • 位置：.card 只有一种视觉权重；main{max-width:1000px;margin:0 auto}。
  • 实测：1440×900 下主内容列宽 1000px，两侧各留约 113px，页面右侧实际空白 151px（截图像素实测）； 设置页纵向 8 张卡、错题页 6 张卡。也就是说：问题不是"屏幕没填满"， 而是卡片内部与卡片之间留了大片空白，却没有用这些空间承载更多结构。
  • 影响：读者要靠滚动来拼凑信息，同一屏内没有重点；而"列表 + 详情""主区 + 上下文" 这类本应并置的关系被拆成了上下堆叠。
  • 修法：宽屏 ≥1360px 时"今天/错题"改为两栏栅格（主区 + 320px 上下文栏）； 设置页由 8 卡改为 4 个分组；错题页保持聊天主位，但把"新建/薄弱项/今日复习"收进右栏或折叠区（详见 §5）。

P2 透明色硬编码，对比度不可预测

  • 位置：--good33、--good14、--infobg、--badbg、 --errbg，以及散落的 rgba(251,191,36,.12) 等十余处内联 rgba。
  • 影响：半透明叠加让文字对比度随底色漂移，同一语义在卡片、面板、浮层里表现不一致； 也让"这套颜色到底达标没"变成无法手算的事。
  • 修法：为每个语义定义具名实色对（前景 / 淡底），需要半透明时只保留在焦点环与 交互态图层——那是唯一"看得见底下"是有意义的场景。

P2 单个决策点的选项超过 4 项

  • 位置：题库行 .bank-item 并列 6~7 个按钮 （开始练习 / 管理题目 / 统计 / 导出押题卷 / 重新解析 / 重命名 / 删除）； 服务商卡一张卡承载 5 类信息（名称 / 网络检索徽标 / 官网注册 / 已配置 Key / 模型名）。
  • 修法：题库行收敛为「主操作 + ⋯ 菜单」；服务商卡先给"名称 + 一行能力 + 状态点"， 模型与注册链接移入展开态。

P2 死控件与空态空洞

  • 位置：index.html 的 #studynav 分段控件当前只有「做题」一项， 构成一个"永远只有一个选项"的选择器；错题聊天空态被放在 min-height:280px 的框里， 首屏剩下半个屏的空白。
  • 修法：单选项分段控件直接移除，等真有第二项再加； 空态改为"图标 + 一句为什么空 + 一个动作"，并让首屏在空态时也能露出「今日复习」。

P2 动效在用布局属性，且无时长/曲线令牌

  • 位置：进度条 transition:width（.segbar i、.pvbar i、 .ocrbar i）；全仓只用裸 ease/linear，无统一时长变量。
  • 影响：动画 width 每帧触发重排，在这些条同时动（生成/OCR 页）时有实际开销； 时长与曲线各处不一，同一类反馈的快慢不一致。
  • 修法：改用 transform:scaleX()；建立 3 档时长与 1 组曲线令牌。 值得注意的是 prefers-reduced-motion 已经全局关闭动画，这一点做对了、保留。

P3 圆角、层级与语义细节

  • 圆角取值 6 / 7 / 8 / 9 / 10 / 11 / 14 共 7 种，无阶梯规律；建议收敛到 6 / 8 / 12 / 16 四档 + 全圆。
  • z-index 出现 99 / 110 / 120 / 300 等绝对值，无命名阶梯；建议改为 sticky 100 → overlay 200 → modal 300 → toast 400 → tooltip 500。
  • 页面级导航使用 role="tablist"（aside.side 的 .tabs、 .learnnav、.css-pills）。页签语义适合"同一视图内切换面板"， 而这里切换的是整页——更贴近 <nav> + 链接。建议修正语义而非视觉。
  • 聊天里的用户气泡使用 --infobg（信息蓝）配 --accent（青绿）描边， 两个语义色混用，同一元素承担了两套含义。

值得保留的部分（不要改坏）

  • 暗色的正文与次级文字对比度已达标甚至优秀（14.87:1 / 6.15:1）——新主题不能低于这个水平。
  • SVG symbol 图标系统：统一 15px、stroke 1.8、round linecap，风格一致，直接沿用。
  • 键盘可达性基础：全局 :focus-visible 2px + offset 2，以及 a.skip 跳到主内容——这是很多产品没做的，继续维护。
  • 沉浸式做题层：覆盖式作答 + 答题卡侧栏 + 计时 + 背题模式切换，范式正确，只需视觉打磨。
  • 空态与说明文案的质量高于平均（如"只看未掌握（隐藏已归档…）"），有解释、有边界说明。
  • 响应式断点体系齐全，含 390/420 的窄屏处理。

3对标研究

多轮检索的取舍标准：只取与本产品同构（本地工具、高信息密度、长时间使用）的案例， 以及能被具体动作翻译过来的原则。每条结论都标注了"适用于 MedKit 的那一半"，以及"明确不适用"的部分。

案例它做对了什么对 MedKit 的迁移动作
Linear
2026 界面刷新		 两条原则："不要让没挣得注意力的元素争抢注意力"（侧栏整体调暗、图标缩小、 去掉无意义的彩色图标底）与"结构应被感知而非被看见"（减少分隔线、圆角化边框、降低线对比度）。 侧栏从"和内容同等亮度"退到静默；.navsep、卡片框线、各处 .tag 描边 统一收敛；标题图标不再一律上色。
Linear
主题系统		 整套主题由 3 个变量（基色 / 强调色 / 对比度）生成，共 98 个具体色值； 使用感知均匀的 LCH 色彩空间，使不同色相在相同明度下看起来一样亮， 并因此能自动产出高对比度主题。 MedKit 现在是"每个主题手写约 40 个色值"。改为 primitive → semantic 两层令牌， 明暗只重绑语义层；强调色一个 ramp 派生全部档位。
Arc / Raycast
应用外壳		 竖排侧栏承载"空间/上下文"而不是"功能清单"；命令栏（cmd-K）成为真正的导航脊柱。 保留侧栏（MedKit 的目的地少且稳定，适合保留），但把它从"交通系统"降级为"礼貌的提醒"； 命令面板作为可选加速器加入，且必须保留可见导航作为兜底。
The Death of the Sidebar
2026-05		 给出侧栏替代的五种模式，并诚实指出三种仍然该保留侧栏的场景： 文件树、有稳定深分类的参考内容、20+ 目的地的管理台。同时警告四类失败模式 （隐形导航焦虑、移动端失效、把侧栏改成七个悬浮按钮等）。 MedKit 属于"参考内容 + 少数目的地"→ 保留侧栏，收窄并降噪， 而不是做无侧栏的炫技。失败模式里的"隐形导航焦虑"正是本方案拒绝"纯命令栏"的理由。
2026 暗色趋势
分层 surface		 明暗不是翻转：暗色用 3~4 级层次化表面（用 oklch 与 color-mix 计算） 表达高度，阴影退场；底色不是纯黑，而是 12~18% 明度。 暗色底从 #0a0a0a 抬到 #121614；建立 surface-0/1/2/3 四级； 放弃"靠 3 个灰色值硬撑"的现状。
Bento 模块化栅格
2026 趋势		 用不等跨度的模块化栅格组织混合内容，最重要的块获得最大空间； 用 CSS Grid 的跨度而不是固定断点实现。 只用在「今天」页：把 4 个等重 hero 数字 + 大按钮，改成一主两辅的模块化栅格。 明确不适用于做题区与错题列表——高密度列表需要的是稳定节奏，不是不等跨度。
Anki / Quizlet
导入与刷题范式		 导入对话框一律预览在上、目标与确认在下；导入必选牌组/科目； 闪卡手势的同时保留按钮等价路径（手势绝不能是唯一路径）。 对齐项目内既有质检结论：预览表前置、补科目输入、判分反馈同时给图标与颜色 （不只靠红绿，色盲用户同样可读）。
shadcn/ui
令牌分层		 语义令牌（--primary / --muted / --border）与原始令牌分离， 切主题只重绑语义层；主题切换不触碰组件逻辑。 直接对应 MedKit 的现状命名问题——--card/--card2/--card3、 --good33/--good14 是"按外观数量命名"而不是"按角色命名"，这是主题难维护的根因。

提炼：可迁移到 MedKit 的 8 条原则

  1. 支持性元素主动退场。导航、分隔、图标都该比内容暗一档。
  2. 结构靠间距和排版，而不是框线。框线是最后手段。
  3. 暗色不是亮色取反。暗色用表面层次表达高度；亮色用"底灰卡白"表达层次。
  4. 令牌按角色命名，按明暗重绑。一个角色一个名字，两套值。
  5. 强调色稀缺才有效。它属于"主要动作、当前选中、焦点"，不属于所有标题图标。
  6. 颜色不能是唯一的信息载体。状态必须配文字或图形。
  7. 高密度列表用稳定节奏，混合内容用模块化栅格。两种布局服务于两种信息结构，不可互换。
  8. 任何手势/快捷键都要有可见的等价路径。否则新用户会卡在"这里没有菜单"的焦虑里。

4目标设计语言

以下是可执行的设计处方。所有色值都经过对比度实测（数字附在每块之后）， 挑出来的取值已经满足目标门槛，不存在"看着还行但上不了线"的情况。

4.1 色彩：三层令牌 + 感知均匀授权

授权空间用 OKLCH（现代 Chromium 原生支持；本应用的承载环境是浏览器， 可放心使用，同时保留十六进制回退注释以便排查）。理由很实际：固定明度步进在人眼里才是等距的， 而现状的纯灰 #242424（chroma = 0）没有任何品牌倾向， 换成带极轻青绿底色的中性灰之后，整个界面会自然"贴"到主色上——这一步几乎不花钱，但消除"通用感"的效果最直接。

4.2 字体与字阶：16 档收敛为 5 档

--fs-1 · 12px 注释、图例、极其次要的元信息（上限：整屏不超过 4 处）
--fs-2 · 13.5px 元信息、卡片副标题、标签、表格
--fs-3 · 15px 正文：题干、解析、说明文字、按钮（现状 14px）
--fs-4 · 19px 卡片标题、区块标题、指标数字
--fs-5 · 28px 页面标题（现状 21px）

这一组的要点不是"倍率多大"，而是不再存在 0.5px 级的相邻档：5 档里最小的倍率是 1.12（12→13.5）， 最大 1.47（19→28），相邻两档的绝对差都 ≥1.5px。字重收敛为 400 / 600 / 700 三档（现状 600 与 700 混用）。 字体栈沿用系统栈（不引入 Web 字体，这是零 CDN 约束下的正确选择，也省掉字体未到达时的重排）； 中文优先 Microsoft YaHei UI，等宽补上 Cascadia Mono。数字统一 tabular-nums（现状已用，保留）。

  • 同步改动：index.html 结构、showTab 与各域视图映射、 tests/browser 的选择器断言、docs/AGENT_HANDOFF.md；
  • 约束检查：每个 JS 文件仍 ≤800 行；内联 on* 调用的函数保持顶层声明；
  • 验收：浏览器用例（含窄屏 768/390）+ 键盘走查（Tab 序、skip link、焦点环）+ 截图回归 + 全量闸门。

S4动效与微交互 风险：低

  • 时长/曲线令牌落地；进度条改 transform；三处骨架屏；空态统一为"图标 + 为什么空 + 一个动作"；
  • 可选：Ctrl+K 命令面板（独立验收，包含可见导航兜底与首次使用提示）；
  • 验收：prefers-reduced-motion 复测 + 动效属性守卫 + 首屏加载截图对比。

S5收尾与守护 风险：低

  • 双主题 × 宽/窄屏截图回归基线；无障碍复测（对比度、焦点、语义）；
  • 同步 CHANGELOG.md、README.md 与设计文档；
  • 重建本地发布产物，跑完发布守卫（这是仓库既有的必经环节）。

不做什么（边界）

  • 不引入构建工具、UI 框架、CDN 或 Web 字体——零构建零 CDN 是硬约束，也是这个项目的优势；
  • 不重命名既有 CSS 类（除非同一提交内同步守卫与消费者）；
  • 不碰后端、不动数据模型、不改任何业务逻辑与文案含义；
  • 不删除出题工坊的任何功能，只调整它的位置与呈现层级。

7风险与取舍

风险说明对策
亮色主题变化幅度大底灰卡白是观感上的明显改变，可能"看起来不是同一个软件了"。 把新亮色与旧亮色各出一张同屏对照，纳入 S1 验收；不满意可只改 --surface-0 一档回退。
中英文字体混排基线差Segoe UI 与 Microsoft YaHei UI 的行内基线不同，行高可能需实测微调。 在 S2 用真实中文段落做行高扫描（1.5 / 1.6 / 1.65 三档选一），以截图比对定案。
改 IA 会牵动测试浏览器用例按 data-tab / data-lv 选择器断言，页签收敛会连带失败。 S3 与测试改动同批提交；先跑一遍现有用例摸清受影响面，再动手。
命令面板的隐形门槛键盘加速器对没用过的人等于不存在。 只在 S4 作为可选项；保留可见导航；首次使用给一次提示。
卡片改少 → 分组变弱去卡片化后如果间距不足，内容会粘成一片。 用"间距 + 发丝分隔 + 字号"三件套替代卡片的分组职责，S2 结束时逐屏核对分组是否仍成立。

8待你拍板的决策点

下面 6 项我无法从代码或数据里推断，需要你定。确认之后我再开工，并按你的选择裁剪落地范围。

1. 主色：保留青绿，还是换一支？
A 保留 #2A6B5A 青绿家族（提案：亮 #276B5A / 暗 #5CC0A4） · B 换成更中性的石墨绿 · C 换成墨蓝
我的建议：A。它已是 PRD 指定色且跑通了全部对比度；换色不解决当前任何问题。
2. 一级页签 5 → 4，并把「错题」提为一级？
A 接受（今天 / 刷题 / 错题 / 设置，题库随工坊出现） · B 保留 5 个页签，只改视觉
我的建议：A。这是本方案里对使用效率影响最大的一条，且与仓库已有的精简结论一致。
3. 暗色底从 #0a0a0a 抬到 #121614？
A 抬起（更接近"表面层次"而非纯黑） · B 保持近纯黑（OLED 偏好）
我的建议：A。但如果你的显示器偏 OLED，B 也成立——代价是层次只能靠卡片区分。
4. 气质：安静克制，还是更有性格？
A 安静克制（用排版与留白立个性） · B 更强对比与更明显的品牌印记
我的建议：A，但"克制"不等于"平庸"——本次在字阶跨度、间距节奏、 模块化栅格三处做加法，这是它区别于同类工具的地方。
5. 要不要 Ctrl+K 命令面板？
A 要（S4 独立实现，含可见导航兜底与首次提示） · B 不要
我的建议：可以做，但放在最后。它对每天用两小时的用户回报很高， 对偶尔用一次的用户等于不存在。
6. 范围：只做视觉系统，还是连信息架构一起改？
A 只做 S1+S2（视觉系统与排版，零 JS 风险） · B 做 S1–S3（含 IA 收敛与页面重构） · C 做 S1–S5（全套）
我的建议：先 B。S1+S2 是地基，S3 是真正让"找不到东西"消失的部分； S4/S5 可以随后跟进。
