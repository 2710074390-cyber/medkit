MedKit 可玩性升级 · 结构化执行方案

版本：v1.0（2026-08-25） · 目标：让用户「看得到」提示词与规则、「改得动」生成要求、「玩得转」试错闭环 · 前置：建议先完成《全面审查报告》P0 修复（尤其 A4 XSS、A1 X 型判分）——本方案的试出题卡片与押题卷直接复用相关渲染逻辑

一、方案总览

设计原则（三条）：

  1. 单点注入：所有自定义能力最终汇聚到 medgen.generate_slice() 的 system 提示词末尾追加一个「附加生成要求」块——不改内置模板结构，影子副本、旋钮、自由文本共用同一通道；
  2. 硬约束优先：用户要求与 HC 规则冲突时，注入文案显式声明「硬约束优先」，门禁照常拦截——可玩性不以产物质量换；
  3. 先试后买：任何影响生成的配置（要求/旋钮/自定义提示词）都能用「试出一题」在 30~60 秒内验证，再决定是否跑全量花大钱。

def build_extra_block(requirements: str, knobs: dict[str, str] | None = None) -> str:
    """用户自定义 → 追加在 system 末尾。追加而非改模板：影子副本/旋钮/自由文本共用同一通道，
    且不触碰内置模板结构，避免占位符漂移。"""
    parts: list[str] = []
    req = (requirements or "").strip()
    if req:
        parts.append("## 用户附加生成要求（优先级高于默认风格；"
                     "与上方硬约束冲突时，以硬约束为准）\n" + req[:500])
    if knobs:
        for key, val in knobs.items():
            frag = KNOB_FRAGMENTS.get(key, {}).get(val, "")
            if frag:
                parts.append(frag)
    return ("\n\n" + "\n\n".join(parts)) if parts else ""

1B. 试出一题（试玩闭环的灵魂）

实现（main.py，同步 def 自动进线程池不阻塞事件循环）

class TrialBody(BaseModel):
    subject: str
    exam: str = "期末"
    requirements: str = ""
    ratios: dict[str, int] = {"A1": 40, "A2": 30, "B1": 20, "X": 10}
    slice_sid: str = "TRIAL"
    slice_title: str = ""
    slice_text: str
    teacher_text: str = ""

@app.post("/api/trial")
def trial(body: TrialBody) -> dict[str, Any]:
    c = cfg.load()
    if not c.get("api_key"):
        raise HTTPException(400, "请先在「① 连接服务商」保存 API Key，再试出题")
    if not body.slice_text.strip():
        raise HTTPException(400, "切片内容为空")
    from ..agents import medgen                       # main.py 中用相对导入包内路径
    client = medgen.make_client()
    client.timeout = 90                               # 试玩不陪跑长任务
    slice_ = {"sid": body.slice_sid, "title": body.slice_title,
              "text": body.slice_text[:6000]}
    qs, _ = medgen.generate_slice(client, body.subject, body.exam, slice_, 1,
                                  body.ratios, body.teacher_text[:2000],
                                  requirements=body.requirements)
    if not qs:
        raise HTTPException(502, "模型未返回有效题目，请重试或检查模型配置")
    issues = options_check.check_all(qs)["issues"]    # main.py 已 import 需补充
    issues += trace_check.check_trace(qs, {body.slice_sid})["issues"]
    return {"question": qs[0], "issues": issues,
            "from_slice": f"{body.slice_sid} · {body.slice_title}"}
注意：main.py 目前只 import 了 extract/slice/quota 等，需补 from .gates import options_check, trace_check 与 from .agents import medgen。

@app.get("/api/prompts")
def prompts() -> dict[str, Any]:
    PROMPTS_DIR = Path(__file__).parent / "prompts"
    ROLE = {"medgen.md": "MedGen · 出题", "medqc.md": "MedQC · 质检",
            "medfix.md": "MedFix · 修复", "medreview.md": "MedReview · 复习手册"}
    out = []
    for name, role in ROLE.items():
        content = (PROMPTS_DIR / name).read_text(encoding="utf-8")
        out.append({"name": name, "role": role, "content": content,
                    "placeholders": sorted(set(re.findall(r"\{[a-z_]+\}", content)))})
    return {"prompts": out}

3A. 影子副本：运行时覆盖，安装目录零写入

关键前提：打包后内置提示词位于 _internal/prompts/（安装目录，Program Files 下只读）——因此用户自定义必须落 ~/.medkit/prompts/，这正是影子副本的设计动机。

# config.py 增加常量
PROMPTS_DIR_USER = CONFIG_DIR / "prompts"

# agents/__init__.py：load_prompt 改 4 行（唯一提示词入口，全项目都走它）
def load_prompt(name: str) -> str:
    user = cfg.PROMPTS_DIR_USER / name
    if user.exists():
        return user.read_text(encoding="utf-8")
    return (PROMPTS_DIR / name).read_text(encoding="utf-8")

保存校验（防改坏的第一道闸）

@app.put("/api/prompts/{name}")
def put_prompt(name: str, body: PromptBody) -> dict[str, Any]:
    if name not in PROMPT_NAMES:
        raise HTTPException(404, "未知提示词")
    builtin = (PROMPTS_DIR / name).read_text(encoding="utf-8")
    required = sorted(set(re.findall(r"\{[a-z_]+\}", builtin)))
    missing = [p for p in required if p not in body.content]
    if missing:
        raise HTTPException(400, "缺少必需占位符：" + "、".join(missing)
                            + "（占位符会被运行时替换，删除将导致管线失败）")
    cfg.PROMPTS_DIR_USER.mkdir(parents=True, exist_ok=True)
    (cfg.PROMPTS_DIR_USER / name).write_text(body.content, encoding="utf-8")
    _save_prompt_meta(name, builtin)     # 记录 base_hash，供漂移检测
    return {"ok": True}

漂移检测：影子元数据 ~/.medkit/prompts/.meta.json 记 {"medgen.md": {"base_hash": "sha256(内置版)"}}；GET 时重算内置哈希比对——你升级软件后用户副本仍指向旧内置版时，UI 显示「官方提示词已更新」+ 展示新版差异（左右两栏 diff，前端逐行对比即可，无需后端算法）。

3B. 前端编辑体验

  • 「④ 提示词」tab 升级：每个提示词头部状态徽标（使用内置 / 已自定义 / 官方已更新）；

迭代 3 验收清单

迭代 4（可选）逐题审核台 + 单题重掷≈ 3 天

定位：生成后的「最后一公里」可控性——数据基础已具备（questions_final.json 本就是结构化数组），缺的只是一层编辑 UI。建议排在管线取消/断点续跑（审查报告 U1/U2）之后做，否则审核期间重跑整卷的代价太高。

三、风险与兜底

风险兜底措施（已内建于方案）
附加要求与硬约束冲突
（如用户要求「允许以上都对」）		 注入文案显式声明「硬约束优先」；门禁 R7 规则照常 fail 拦截；试出一题即时暴露冲突，用户在花钱前就能看到
requirements 过长撑爆 token 后端截 500 字 + 前端 maxlength + 实时字数计数
试出题单次等待 30~90 秒，用户以为卡死 同步调用 + spinner 文案「首次约 30~60 秒」+ client.timeout=90 + 失败可一键重试；超时错误信息可读
用户改坏提示词（删占位符/破坏 JSON 输出要求） 三道闸：保存时占位符校验（400 列明缺失）→ 保存后引导「先试出一题」→ 「恢复默认」一键回滚
影子副本版本漂移（软件升级后用户仍是旧版） .meta.json 记 base_hash；GET 比对内置哈希返回 drifted；UI 显示「官方已更新」+ 双栏 diff
Bloom 自定义配比合计 ≠100 复用题型配比模式：前端实时合计变色禁用 + 后端 400 校验（双保险）
打包后 _internal/prompts 只读 影子副本全部落 ~/.medkit/prompts（机制本身规避，无需额外处理）
trial 渲染 LLM 输出的 XSS 红线：一律 esc() 转义（依赖 P0 的 A4 修复同步完成）
预设 payload 含非法值（导入坏 JSON） 导入时 pydantic 校验 + 忽略未知字段 + 失败 toast「预设文件不合法」

四、执行顺序与暂停点

  1. 第 0 步（半天）：先修审查报告 P0 中与本方案相关的两项——A4（产物/卡片 XSS 转义）与 A1（X 型判分），因为试出题卡片与押题卷直接复用这些渲染逻辑；
  2. 迭代 1（2 天）：1A 附加要求 → 1B 试出一题 → 1C 查看器，按此顺序（1A 是 1B 的依赖，1C 独立可并行）；此为第一个可发布暂停点——三件套上线即可收集真实反馈；
  3. 迭代 2（1.5 天）：旋钮 → Bloom → 预设；其中预设依赖前两者的字段齐备；
  4. 迭代 3（1.5 天）：影子副本机制 → 校验 → 漂移提示；发布前建议观察迭代 1/2 用户是否真的需要编辑提示词——若 textarea + 旋钮已满足 80% 需求，本迭代可降级或缓做；
  5. 迭代 4（3 天，可选）：建议插队在管线取消/断点续跑（U1/U2）之后——审核台的存在放大了「重跑整卷」的成本痛感。
核心链路只有 3.5 天（迭代 1+2）：textarea 让普通用户表达诉求，旋钮让懒人一键调风格，trial 让所有人零成本试错，查看器让透明度建立信任——这四件事构成完整的「可玩性最小闭环」，其余都是放大器。
