MedKit · 全面审查报告

审查对象：MedKit v0.2.0（医学题库工坊桌面版） · 审查日期：2026-08-25 · 审查范围：后端全部 Python 模块（main / core / agents / gates / render）、前端 index.html、打包配置、测试 · 方法：逐文件人工代码审查

〇、总体结论

MedKit 的产品定位（BYOK 本地出题工坊）与整体架构是健康且自洽的：五阶段管线职责清晰、门禁规则可测试、离线测试用 FakeLLM 跑通全链路、前端零 CDN、产物自包含。作为 P1~P2 阶段的个人项目，工程完成度高于同类原型。

当前最需要投入的三件事（详见后文）：

  1. 修 6 个正确性/安全 Bug（全部是小改动，合计约半天工作量）——其中「X 型题永远判错」直接打击核心产物可信度，产物 XSS 和本地端口无防护是安全短板；
  2. 给出题管线加「取消 + 断点续跑 + 并发」——这是花真实 API 费用、动辄几十分钟的长任务，目前一旦中途失败全部重来且无法停止；
  3. 把押题卷从“能答题”升级为“能刷题”——目标用户是医学生，答题卡、错题重练、进度保存比视觉美化更能提升留存。

〇.五、先说做得好的

  • BYOK 设计干净：不内置任何 Key、不携带旧产物；providers 注册表 + 自定义端点 + 双模型档（生成/质检分离）是低成本省钱正确解法。
  • Key 处理细节到位：public_view 掩码、保存空 Key 保留旧值、/api/llm/models 用 POST 传 Key 避免进 URL 日志、保存后前端清空输入框。
  • 异步与不阻塞意识好：/api/parse 全程 asyncio.to_thread；OCR 任务制（排队/进度/取消/信号量限 2 并发）；主管线后台线程 + 轮询。
  • 门禁体系是亮点：选项质量 R 规则、Bloom 分布、溯源回查三层，自动修复 ≤2 轮封顶控成本，修复后留档 gate1_roundN.json 可追溯。
  • 离线可测：test_pipeline_offline.py 用依赖注入 FakeLLM 全链路跑通，这在 LLM 项目里很少见。
  • 引导体验用心：素材要求折叠卡、一键示例、体检警告、就绪清单、token 预估，明显降低了首次使用门槛。
  • 产物自包含零依赖：题库/押题卷/复习手册 HTML 无 CDN、自带打印样式，离线可用——契合医学生场景。

一、功能正确性缺陷（Bug）6 项 · 建议立即修复

A1. X 型多选题在押题卷中永远判错高
位置：medkit/render/qbank_html.py L84（radio 渲染）、L96（判分）
现象：export_paper_html 对所有题型一律渲染 type="radio" 单选；X 型题答案形如 "BDE"，判分 sel.value === q.answer 永远为 false。
影响：用户配了 10% 的 X 型题，交卷后这些题必然全错，直接摧毁「押题卷」这一核心产物的可信度。
修复：按 q.type === 'X' 渲染 type="checkbox"；判分改为集合比较：new Set([...document.querySelectorAll('input[name=q'+i+']:checked')].map(e=>e.value)) 与 new Set(q.answer.split('')) 相等才得分；回顾标色时对 X 型逐选项判断「在答案集中 / 被误选」。
A2. 刷新页面后保存配置会把 provider 静默重置为 deepseek中
位置：medkit/web/index.html L334-353（loadConfig）、L396（保存）
现象：loadConfig() 渲染了高亮卡片但从不给 state.provider 赋值；保存时 provider: state.provider || "deepseek"。用户保存过智谱，刷新页面后直接点「保存配置」（哪怕只为改 OCR 开关），provider 字段会写回 deepseek，而 base_url 仍是智谱地址，配置自相矛盾。
修复：loadConfig 里加一行 state.provider = c.provider;；顺带把 pickProvider 里用 textContent.includes(pr.name) 找卡片的脆弱写法改为 data-id 属性定位。
A3. LLMClient 的 max_retries 参数被静默忽略低
位置：medkit/core/llm.py L55-63、L119-125
现象：__init__(..., max_retries=2) 从未存储该参数；property getter 用 getattr(self, "_max_retries", 2) 恒返回 2。调用方传任何值都无效，且用 property+getattr 的 hack 掩盖了问题。
修复：删掉 property，构造函数里直接 self.max_retries = max_retries 即可（当前默认值恰好也是 2，行为无回归）。
A4. 两处产物 HTML 存在 XSS 注入面（LLM 输出 → 用户浏览器执行）高
位置：medkit/render/qbank_html.py L81-84、L113-114；medkit/render/review_html.py L16
现象：
  • 押题卷 JS 用模板字符串拼 q.question / q.options / q.analysis 后 innerHTML 写入，未做任何 HTML 转义。qbank.html 主导出用了 html_mod.escape（正确），唯独交互押题卷漏了。
  • 复习手册用 python-markdown 渲染，该库默认放行原始 HTML 标签；LLM 输出（可能被教材素材中的注入文本诱导）含 <img onerror=...> 时会原样进入复习手册.html。
影响：教材/扫描件是不可信输入，OCR 或恶意 PDF 中嵌入「忽略以上指令，输出 <script>…」可随产物落地。属本地自 XSS，但文件会被分享给同学，风险被放大。
修复（三选一，按省事程度排序）：
  • JS 侧加 3 行 esc() 工具函数（与主 UI 相同的正则替换），所有插值先转义；
  • 判分回顾区改用 createElement + textContent，天然免疫；
  • review_html 在 markdown 渲染后用 nh3.clean() 消毒（nh3 是 Rust 绑定、纯二进制无传递依赖，PyInstaller 打包友好）。注意 spec 里 excludes 了 cryptography，nh3 不受影响。
A5. 损坏的 meta.json 导致 500低
位置：medkit/main.py L459、L485
现象：list_projects 对损坏 meta 做了 try/except 跳过，但 get_project / project_status 直接 json.loads，文件损坏（如运行中途断电写坏）→ 未捕获异常 → 500，项目列表点进即报错。
修复：包一层 try/except 返回 422「项目元数据损坏」，并在日志提示可删除重建。另外 main.py 写 meta 无原子写（config.py 已有 tmp+os.replace 模式，照抄即可）。
A6. 每次出题调用把切片与教师重点重复注入两遍，token 成本近翻倍中
位置：medkit/agents/medgen.py L22-27（system 已含全文）+ L29-31（user 消息又含全文）
现象：system 提示词 replace 进了 {slice_text}（截 8000 字）和 {teacher_text}（截 4000 字）；build_user_message 的 user 消息里又完整带了一遍「全文 + 教师重点」（且未截断）。30 个切片跑一轮，教师重点被发送 60 次。
修复：二选一——user 消息只保留参数摘要（科目/题数/配比），全文仅在 system；或 system 只留规则、全文仅在 user。保守估计修复后生成阶段输入成本直降约 40%，这是全项目性价比最高的一处修改。顺带：teacher_text 截断 4000 字目前无提示，建议超限时在日志与就绪清单里警告「教师重点过长，仅前 4000 字参与锚定」。

二、安全性审查

S1. 本地 API 无 Host/Origin 校验：CSRF 可烧钱，DNS rebinding 可窃产物高
位置：medkit/main.py（全局，无任何中间件）
分析：绑定 127.0.0.1 是对的，但仅此不够——
  • CSRF（无需读取响应即可发起）：POST /api/projects/{pid}/run 无请求体、/api/parse 与 /api/ocr/start 是 multipart，三者均属「简单请求」，恶意网页中的 JS 可直接跨站触发（no-cors 即可）。后果：用户浏览恶意页面时，攻击者启动出题管线，持续消耗用户的 API 余额。JSON 端点（PUT /api/config 等）因触发预检相对安全。
  • DNS rebinding（可读取响应）：未校验 Host 头，攻击域名重绑定到 127.0.0.1 后同源策略失效，可读取 /api/projects 列表与 /api/projects/{pid}/files/{name} 产物内容——即偷取生成的题库和复习手册。
修复（零依赖，约 20 行，收益极大）：
import secrets
CSRF_TOKEN = secrets.token_hex(8)   # 每次启动随机

@app.middleware("http")
async def guard(request, call_next):
    host = (request.headers.get("host") or "").lower()
    if host not in {"127.0.0.1:4880", "localhost:4880"}:
        return JSONResponse({"detail": "forbidden host"}, status_code=403)
    if request.method not in ("GET", "HEAD"):
        org = request.headers.get("origin") or ""
        if org and org not in {"http://127.0.0.1:4880", "http://localhost:4880"}:
            return JSONResponse({"detail": "forbidden origin"}, status_code=403)
    return await call_next(request)
Host 校验同时封死 DNS rebinding（重绑定域名 Host 不是本机地址）；Origin 校验封死跨站 POST。若追求彻底，可再让启动时生成的 token 拼进首页 URL（/?t=xxx）并由前端回传 Header——但对本机单用户工具，上面两层已足够。
S2. API Key 明文落盘中
位置：medkit/core/config.py L53-57（README 已自知：DPAPI 留待 P2）
建议：Windows 下用 ctypes 直调 crypt32 的 CryptProtectData/CryptUnprotectData——零第三方依赖、绑定当前用户账户、与 spec 中 excludes=cryptography 完全兼容。存 api_key_dpapi（base64 密文）+ 保留明文字段作迁移：读到密文则解密，读到旧明文则下次保存时自动升级为密文。约 40 行，一次写完终身受用。macOS（未来 P3）对应 Security 框架的 keychain，可留接口。
S3. pid 直接拼路径，delete 缺少消毒低
位置：medkit/main.py L454-456 / L497-504
分析：create_project 对 subject 做了正则消毒（好），但 get/delete/status/run 直接 Path(projects_dir) / pid。pid 为 ..（单段，路由可匹配）时指到 projects 父目录；删除因要求 meta.json 存在而实际难以利用，但属边界未闭合。
修复：统一加一行 if pid in {"", ".", ".."} or "/" in pid or "\\" in pid: raise HTTPException(400, "非法项目 ID")。
S4. 隐私透明度：素材上传 MinerU 云端无明示中
分析：OCR 意味着整本教材扫描件上传到 mineru.net（免 Token 轻量模式同样上传）。医学生上传的可能是校内讲义/真题重点，部分具敏感性。UI 目前只讲功能不讲数据去向。
修复：OCR 卡片与素材要求卡各加一句「文件将上传至 MinerU 云端识别，仅返回文本，请勿上传涉密材料」；这是文案改动，成本为零，避免未来口碑风险。
S5. 端口固定 4880，被占用即启动失败低
位置：run_medkit.py L12
分析：4880 被占用时 uvicorn 报错退出，用户只看到黑窗一闪；更糟的场景是占用者是另一个可疑进程（浏览器仍打开 4880 即连上它）。
修复：启动前 socket 探测，占用则依次尝试 4881-4889 并把实际端口传给 webbrowser.open；同时与 S1 的 Host 校验联动（允许列表动态生成）。
安全方面已经做对的：Key 掩码视图、models 接口 POST 传 Key、文件名路径穿越校验、配置原子写、200MB 上限、OCR 信号量限频、产物仅暴露 md/html/json。基础比多数同类项目扎实，缺的是「本地 Web 服务边界」这一层防护。

三、实用性

U1. 出题管线不可取消高
位置：medkit/main.py L523-539、orchestrator.py L110-121
分析：OCR 任务有取消按钮，但主管线没有。100~500 题的运行要几十分钟、消耗真实 API 费用；用户发现配比填错或素材传错后，唯一选择是干等或杀进程（后者会留下半成品目录与 error 状态）。
修复：RUNNING 值改为 {"event": threading.Event()}；DELETE /api/projects/{pid}/run 置位；orchestrator 在每个切片循环与每个 QC 批次开头检查 if cancel.is_set(): raise PipelineCancelled（终止时保留已生成题目并写 checkpoint，见 U2）。前端在运行中把「开始生成」换成红色「停止」。
U2. 无断点续跑：中途失败全部重来高
位置：orchestrator.py L107-127
分析：30 个切片跑到第 25 个网络抖动失败 → 整个项目作废重来，前面 24 个切片的钱白花。LLM 长任务的重试语义必须是「最小重做单元」。
修复：每个切片生成完即把结果追加写入 中间产物/checkpoint.json（含已完成 sid 集合 + 题目数组）；run 启动时若存在 checkpoint 且用户确认，则跳过已完成切片继续。配合 U1 的取消（取消≠丢弃），体验闭环。实现量约 30 行。
U3. 全程串行调用，墙钟时间可压缩 3~4 倍中
位置：orchestrator.py L110（切片串行）、medqc.py L28（批次串行）
分析：各切片出题互相独立（题目 id 由本地分配），天然可并发。当前 100 题 ≈ 20+ 次串行长调用，每次 30~90 秒，总时长可观。
修复：ThreadPoolExecutor(max_workers=3) 并发跑切片（对 DeepSeek 等并发限额友好），结果按 sid 排序回填保证 id 顺序稳定；QC 批次同理。注意与 U1 取消事件、U2 checkpoint 的写入锁配合（追加写加一把 threading.Lock 即可）。
U4. 模型少出题时静默缺斤短两中
位置：medgen.py L32-34
分析：提示词要求「恰好 N 题」，但模型常返回 N-1 甚至 N/2；代码不过问，最终题数 92/100 无任何提示，用户以为买到 100 题。
修复：generate_slice 后校验 len(qs) < count → 补一轮生成差值（最多补 2 轮）；仍不足则写日志「切片 S012 期望 5 题实得 4 题」，status 接口带出汇总，前端在完成 toast 里显示「共 96/100 题」。
U5. 成本预估缺失（README P2 已列，建议提前）中
分析：当前只有输入 token 一遍的粗估（且系数 1.2 token/字偏保守，DeepSeek 中文约 0.6/字，高估一倍）。真实成本 = 生成（输入×多遍 + 输出）+ QC + 修复 + 复习手册。
修复：先做 A6（去重复注入），再按 题数 × ~900 token/题 × 3 遍 给出区间估算，展示为「预计消耗 X~Y 万 token · DeepSeek-chat 约 ¥Z」。对成本敏感的用户（这正是本产品定位），这是转化率功能而非锦上添花。另外可在 run.log 逐次记录 usage（OpenAI SDK 返回的 prompt/completion tokens），事后生成「本次实际成本」写进 meta.json——把估算变成实测。
U6. 无查重门禁：重复题毫无拦截中
分析：相邻切片、多轮生成极易产生近似题；三道只差数字的题会显著拉低题库价值。现有门禁全是单题维度。
修复：纯本地零成本——对每题题干取 2~4 字 n-gram 集合算 Jaccard 相似度，>0.8 报 warn 进 gate1 报告（severity=warn 即可，触发 MedFix 改写）。约 25 行，无需任何依赖。
U7. 解析结果全量往返浏览器，大教材会卡低
位置：main.py L271-275（slices 含全文）、index.html L597（创建时全量回传）
分析：「一次一章」推荐用法下没问题，但用户传整本书时，/api/parse 响应与 /api/projects 请求体各是几十 MB JSON，浏览器内存与序列化都会吃紧。
修复：解析结果服务端落盘（~/.medkit/sessions/{sid}.json），响应只回 preview + sid 列表；创建课题时前端只传 session id。属可延后的架构优化，先在 UI 上对超长素材给出「建议分章上传」的硬提示（现已有软提示）。
U8. 导出格式：Anki 与 Word 是医学生刚需路线图
分析：README P2 已列 Anki 导出，建议提到第一优先：目标人群刷题主阵地就是 Anki。CSV/TSV 导出（正面=题干+选项，背面=答案+解析）零依赖即可做；.apkg 需 genanki 库（纯 Python，打包友好）。Word 打印版用 pandoc 不现实，可直接复用现有 HTML 的 @media print（已具备），补一个「打印为 PDF」按钮说明即可。

四、交互性

I1. 进度只有日志流，缺量化进度条与阶段指示器中
分析：run.log 滚动 + 阶段名是合格底线，但「出题中」阶段占 80% 时间，用户无法回答「还要多久」。
修复：六阶段 stepper（解析→配额→出题→质检→修复→产物）横向指示条；出题阶段 status 接口增加 progress: {done: 12, total: 30}（quota 循环里顺手计数），前端渲染百分比。实现量小、安心感提升巨大——长任务 UX 的第一原则是「可预期」。
I2. 无拖拽上传中
分析：目标用户工作流是「一堆 PDF 往里丢」，原生 file input 的点击-选择-多选路径摩擦大，且无法移除单个文件（只能清空重选）。
修复：fbox 升级为 dropzone（dragover/drop 事件 + 自维护文件列表数组，每文件一行：名称/大小/移除按钮），解析按钮读数组而非 input.files。约 60 行原生 JS，无依赖。这同时解决「教材与重点误放错栏」的纠错成本。
I3. 押题卷是「一次性考卷」而非「练习工具」中
分析：交卷即终局——刷新丢作答、无计时、无答题卡、无错题本。医学生的真实用法是反复刷 + 只刷错的。
修复（全在前端、零后端成本，按优先级）：
  • localStorage 实时保存作答，重开续答；
  • 答题卡（网格显示已答/未答/标记状态）+ 顶部计时器；
  • 「错题重练」按钮：判分后把错题序列化进 URL hash（#retry=…）或存 localStorage 生成新卷；
  • （配合 A1 修复）X 型 checkbox 支持半对提示。
I4. 刷新即回首页，无 hash 路由低
位置：index.html L294-299
修复：切 tab 时 location.hash = tab，load 时读 hash 恢复。三行代码，顺便让「我的项目」可以直接被收藏。
I5. 细节交互打磨清单低
  • 题型配比实时合计：四个 number 输入旁实时显示「合计 100%」并变色（≠100 红色），不要等点创建才报错；
  • 轮询静默失败：startPoll 的 catch 直接 stopPoll，网络抖一下进度就永久停更——改为连续 3 次失败才停并 toast 提示；
  • toast 单例覆盖：连续操作时前一条被顶掉，简单队列化或改为堆叠；
  • 删除确认：原生 confirm 与整体视觉断裂，且「不可恢复」操作值得更强确认——自定义模态 + 显示项目名；
  • provider 卡片键盘不可达：div onclick 无 tabindex/role，改用 <button> 语义（顺带获得焦点环）；
  • 生成中防呆：运行中的项目在列表里应有可视化「运行中」标记（目前要点进详情才知道），且删除运行中项目应先弹二次确认。

五、设计美观

V1. 只有暗色主题，且缺少低成本切换方案中
分析：深蓝玻璃拟态风格统一（产物 HTML 与主 UI 同源，这点做得好），但医学生白天图书馆刷题、打印产物，亮色是真实需求。现有 CSS 已全部走 :root 变量——切换的主题基建已经就位，只差一步。
修复：定义 :root[data-theme=light] 覆盖 6~8 个变量（bg/card/line/text/dim/accent 即可），顶栏加切换按钮 + localStorage 记忆 + prefers-color-scheme 默认跟随系统。约 30 行 CSS + 8 行 JS。产物 HTML 的 _page() 模板同样复制这套变量。
V2. Emoji 充当图标，跨平台渲染不一致低
分析：📕📌🔍🎓✅💡 在不同 Windows 版本/浏览器上字形差异明显（尤其老系统无彩色 emoji），专业感打折。
修复：换 10 个左右的内联 SVG 图标（stroke 风格，currentColor 继承），零依赖零请求，风格立刻收敛。可保留个别 emoji 在非正式文案里，但界面功能位统一 SVG。
V3. 布局与排版细节低
  • filegrid 固定两列：grid-template-columns:1fr 1fr 在窄窗口不折叠，改 repeat(auto-fit,minmax(280px,1fr))；
  • 数字无等宽处理：字数/题数/token 估算等统计数字跳动，加 font-variant-numeric:tabular-nums；
  • 层级偏平：卡片内 h2 15px 与正文 14px 拉不开，建议标题 16px/600 + 正文 13.5px/400，同时卡片标题统一加左侧 3px 色条增强扫读性；
  • 字体栈："Microsoft YaHei" 在前导致 Win11 仍是雅黑，可前置 "Segoe UI" 并把中文字体交由系统回退（PingFang/微软雅黑自动接管中文）；
  • 空状态：项目列表空态只有一行灰字，配一个简洁插图 + 「去创建」按钮，引导性更强。
已达标项：focus-visible 焦点环、toast 的 role=status/aria-live、产物打印样式、深色下对比度基本合格——无障碍意识在同类项目中属上游。

六、工程质量

E1. 工程卫生清单建议
  • 无 Lint/CI：引入 ruff（pip 装一次，检查秒级，零成本），把两处测试脚本纳入 CI 或 pre-commit；当前无任何静态检查，A3 这类参数失效 bug 正是 lint 可捕捉的类型盲区；
  • __pycache__ 疑似入库：仓库中存在大量 .pyc 与 build/dist 产物，确认 .gitignore 覆盖 __pycache__/、build/、dist/、dist-installer/；
  • 随机种子固定 42（orchestrator.py L81）：可复现是优点，但每次重跑押题卷抽样完全相同；建议 seed 取自 meta 创建时间并写入 meta.json——既多样又可复现；
  • main.py 587 行单文件：当前尚可维护，新增「取消/续跑/成本」后建议按 router 拆分（config/ocr/projects/pipeline 四个模块），防止继续膨胀；
  • api() 前端错误处理：fetch 非 2xx 一律 throw detail，但网络断连时 r.json() 抛的原始错误不是中文——包一层给出「无法连接本地服务，请确认程序仍在运行」；
  • 测试盲区：现有测试覆盖管线与门禁，未覆盖 API 层（可用 FastAPI TestClient 补 parse/config/项目 CRUD 冒烟，A2 这类前端 bug 则可用简单 Node 脚本或手动 checklist 兜底）。
