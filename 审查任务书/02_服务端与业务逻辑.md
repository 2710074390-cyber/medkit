## 一、任务目标

以「攻击者（含恶意网页、本机其他进程、畸形输入）触达本地服务」为视角，找出**本地服务边界绕过、付费 API 滥用面（烧用户 Key 余额）、文件解析、业务逻辑与并发状态缺陷**，产出可复现的缺陷清单。

- `medkit/routers/*`：config / data / diagnostics / gap / library / ocr / parse / pipeline / presets / projects / prompts / realexams / review / search / syllabus / update（共 16 个）

- `tests/`（API 层 TestClient 与管线层）

| 编号 | 检查项 | 验证动作 |

## 五、通用规则（强制）

**只读边界**：不修改任何源码/配置/数据文件；发现疑似缺陷只记录，不「顺手修复」。允许静态走读、离线测试、git 取证；确需启动服务观察时使用 `MEDKIT_PORT=4999 MEDKIT_NO_BROWSER=1` 且不指向真实 HOME。

**证据规范**：每条发现必须给出 `文件:行号` + 关键代码/调用链 + 最小复现或推理步骤；明确区分「已验证可利用」与「理论风险」；外部事实给出来源链接，不得用搜索结果代替代码事实；同一问题跨多处出现时报告所有位置。

**严重性分级**：
- S0 阻断：Key/素材/产物被窃取、付费额度被恶意耗尽、错误医学内容系统性流出
- S1 高：特定输入可稳定利用（XSS/注入/路径穿越/越权读产物）、门禁系统性绕过、关键数据丢失
- S2 中：加固不足、边界未覆盖、竞态/可靠性风险、合规缺失
- S3 低：体验、文案、文档、规范性问题

**问题条目模板**（输出 `问题清单_服务端与业务逻辑.md`）：
```
| 编号 | 标题 | 路径(file:line) | 证据/复现 | 影响 | 严重性 | 修复建议 | 状态(已验证/理论) |
```

## 六、已知加固点（只验证真实性与可绕过性，不重复上报为「新发现」）

- Host/Origin 守卫中间件（含 IPv6 `[::1]`，封 DNS rebinding 与跨站 CSRF）
- 统一异常体 + `errs.redact` 脱敏；未捕获异常结构化 500 + traceback 入日志
- 流式断线不自动降级非流式（防双扣费）；去重锁绑流生命周期
- 成本预估前置（创建前显示、参考价标注）；Key 不进 URL；配置深拷贝防默认值污染
- 端口 4880~4889 自动回退；pid 路径消毒；损坏 meta.json 容错（422）
- 并发 100/100 无丢失（既有测试声明）；迁移/原子写见路 4 范围
