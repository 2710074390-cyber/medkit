## 三、职责

1. **去重合并**：跨路重复发现统一编号（保留证据最完整的位置与 `file:line`），合并到主条目，保留各路原始编号对照。
2. **攻击链串联**：把单路看不全的跨层链拼成完整攻击路径，例如：
   - 前端产物 XSS → 本地 API 调用 → 读取/删除项目或触发付费管线（烧 Key）
   - 恶意网页跨站触发 GET/表单端点 → 外呼 / 产物下载 / OCR 上传
   - 检索素材注入 → 渲染进产物 HTML → XSS；检索素材注入 → 出题内容污染（医学错误）
   - 上传解析（DOCX/图片）→ 路径穿越/解压炸弹 → 读 `~/.medkit` 或写任意文件
3. **覆盖度核对**：按第二节资产清单逐项打勾，标出**未被任何路覆盖**的资产与边界盲区；发现缺口即补记一条「覆盖缺口」条目（不补做审查，只标记）。
4. **风险定级与总报告**：统一按分级定义复核各路严重性（允许跨路调整口径，须注明调整理由）。
5. **与历史对照**：标注每条发现与既有报告（R4~R7 / 工程审查改进指南 / docs/reviews/）的重叠关系：新增 / 回归 / 既有已知。

## 四、分级与证据复核（汇总 Agent 复核标准）

**严重性分级**：
- S0 阻断：Key/素材/产物被窃取、隐私数据非预期外传、付费额度被恶意耗尽、错误医学内容系统性流出
- S1 高：特定输入可稳定利用（XSS/注入/路径穿越/越权读产物）、门禁系统性绕过、关键数据丢失
- S2 中：加固不足、边界未覆盖、竞态/可靠性风险、合规缺失
- S3 低：体验、文案、文档、规范性问题

**证据复核**：每条发现必须有 `file:line` + 证据/复现；状态必须标注「已验证/理论」。**发现违反证据规范（缺位置、未标状态、以搜索代替代码事实）的条目，退回对应路补充，不自行代写。**

## 五、输出模板

### 5.1 总报告结构 `审查报告_<日期>.md`

1. 执行摘要：S0/S1 计数 + 一句话结论（每级一句，附代表性问题）
2. 发现明细：按严重性排序，每条含完整证据与修复建议
3. 按路修复优先级：可执行、可验证、含回归测试建议
4. 覆盖度矩阵：第二节资产清单 × 五路，标注 已覆盖 / 未覆盖 / 边界盲区
5. 复测清单：修复后需要重跑的命令与验证点

### 5.2 风险矩阵表

```
| 发现(编号) | 触发条件 | 后果 | 可利用性(已验证/理论) | 影响面 | 建议优先级(P0/P1/P2) |
```

## 六、输出物与交接

1. `审查报告_<日期>.md`（总报告，唯一权威结论）
2. `风险矩阵.md`（可按优先级过滤）
3. 移交说明：S0/S1 摘要 + 建议的修复批次划分，交回任务发起人。
